# 参考分析：Harsha（mycodeschool）《Introduction to linked list》

分析对象是录屏 `harsha linklist.mp4`，17 分 13 秒，白板手绘风格。这一课接在"用数组实现动态列表"后面。

分析方法：
- 每 10 秒截一帧，拼成联系表；
- 用 faster-whisper 转写配音，和画面按时间对齐。

本文只记分析结果，不收配音原文。引用原话不超过一句。

**这一课的知识类型**：链表是**发明**出来的，是为了解决"数组不能原地变长"这个问题想出来的办法。这一课是推导框架的经典实例。

## 二、知识单元

| 单元 | 内容 | 讲法 |
|---|---|---|
| 模型 | 内存格子、地址、内存管理员 | 拟人化的规则 |
| 旧办法 | 变量、数组：连续一块，常数访问 | 在模型里演一遍，先讲好处 |
| 问题 | 数组不能原地变长 | 让问题自然发生，出路逐条走完，落到两难 |
| 新办法（核心） | 一次申请一个 → 散开 → 记下一个的地址 → 结点、链表、头结点、NULL | **推导**：改动 → 后果 → 补救 → 命名 → 收拢 |
| 检验和得失 | 末尾插入；访问、插入、删除、内存和数组对照 | 用新办法做一次，再逐项对照 |

## 三、写作手法

**铺垫**
1. **先说清楚：要理解新办法，得先理解旧办法的局限。** 学生一开始就知道这一课的逻辑是"旧办法不够用 → 新办法"。
2. **先搭一个能推理的模型**：字节格子加地址。模型里的规则（申请、分配、位置由别人定）都是后面推导要用的约束。
3. **把约束拟人化**：内存管理员。规则变成对话（"你可以告诉我新大小，我另开一块"），约束就不是抽象的条文。
4. **在模型里先演旧办法，而且先讲它的好处**（常数时间访问）。这样后面的得失比较是公平的。

**问题**
5. **问题从一个具体需求里自然冒出来**：再多放一个数。
6. **把出路逐条走完**：原地加长不行 → 另开一块再复制 → 开多大？开大了浪费，开小了又得复制。走到无路可走，学生自己就想要一个新办法。

**推导**
7. **可以先报总名字**（"解法叫链表"），当作要去的目标；部件的名字留到推出来之后再给。
8. **每一步 = 一个改动 + 它的直接后果**："一次只要一个"→"大概率不相邻"。
9. **新做法带来的新问题，用一个改动补上**："散开后不知道谁第一"→"每块多记下一个的地址"。推导是"改动 → 后果 → 新问题 → 补救"的链条，每一环都有因果，没有凭空出现的步骤。
10. **补救参照旧办法**：数组靠位置算出顺序，散开以后算不出来了，所以要把顺序明着记下来。
11. **边界情况在推导里顺手解决**：最后一块没有下一个，写 0。

**命名和收拢**
12. **推出来之后才给部件命名**："我们把这块叫结点"，并且立刻落成代码。
13. **收拢成一句定义**，再加上从定义直接推出的结论：只要记住头结点；只能从头走。
14. **两种视图对照**：内存视图（真实地址）和逻辑视图（箭头）并排，说明是同一个东西。

**检验和得失**
15. **用新办法做一次操作**（末尾插入），证明它真能用。
16. **得失和旧办法逐项对照**：访问、插入、删除、内存。复杂度相同的（插入都是 O(n)），要说清差别在哪（不用挪动）。
17. **用生活比喻帮助理解代价**：寻宝游戏。
18. **最后一条得失回到开头的问题**：不用事先猜大小。问题在开头提出，在得失的最后被回答。

**贯穿**
19. **同一组数据从头用到尾**：6、5、4、2，后来加 3、加 10；地址都是具体数字。

## 四、画面层的观察（只供动画参考，不进写作方法）

- 白板手绘，内存是一条横向的格子带，整段都在画面上方，所有变化都在这条带上发生。
- 角色（Albert、内存管理员）是简笔画，固定在左边和下方。
- 左边逐行写代码（`int x;`、`struct Node`），代码和内存里的块一一对应。
- 后半段在格子带下面另画逻辑视图，两种视图上下并排。
- 复杂度结论用红字写在画面右下角，逐条累加。

## 五、借用时要注意的前提

- **节奏慢、单段长**：一段 17 分钟，口语化，有不少重复的话。用到书稿里要压缩，保留每一步的因果，去掉口头的重复。
- **前一课已经用数组做过动态列表**，所以"数组不能变长"这个问题学生已经有体会，问题段可以很快进入。没有这个前提时，问题要铺得更充分。
- **拟人化的"内存管理员"**适合口语视频。书稿里是否保留角色，要按整本书的语气定；约束必须讲清楚，角色只是手段。
- **只演了末尾插入和中间插入的链接调整**，没有演删除，删除是一句话带过。
