起点是 3f08de7（2026-10-11，第2章概念目标改版合并时）的 2.1，终点是现在的书稿 `book/chapters/ch02.md` 和双栏稿 `docs/course/2-1.md`。参考分析见 `gauth-sets.md`。

每条经验后面标了来源：**Gauth**（照参考改的）、**作者**（作者自己的判断）、**审稿**（审分镜或听配音时发现的）。

## 一、书稿改了什么

### 1. 新增章首引言，2.1 删掉自己的问题页

**改前**：2.1 第一页是问题页"单行编辑器里的一行字"：只演示敲 c、a、t，最后问"这一行字是什么样的数据？"。

**改后**：问题放到第2章章首（`/ch02/` 页），按五步写：
1. 日常场景：搜索框、聊天框、文件名框；
2. 演示：编辑器完整的一串动作；
3. 点名：这样排成一列的数据叫线性表；
4. 学完能做什么；
5. 三个小问（记住什么 / 做哪些事 / 怎么放进内存），加一句"先记住，从第一个开始"。

2.1 直接从"什么是线性表"开始，共 4 页。2.2、2.3 的问题页开头各用一句话回扣第二、第三问。2.20 问题链第一行改成和章首一致。

**为什么改**：
- 原问题的答案就是概念名，"问"和"答"之间没有东西可学。（审稿）
- Gauth 的开场管的是一节大课，问题要靠后面几小节才能答完。对应过来，开场应该管一段课程，而不是一节。（Gauth）
- 开场只管 2.1–2.6 这一段，问题在这一段内答完，不用整章的顶层问题，也不提前摆出后面的问题链。整章问题要悬挂太久，还会剧透 2.7"量一量才发现慢"。（作者）
- 三个小问要具体到能先猜一下，而且各有确定答案。"怎么做编辑器"太泛，学生无从猜起。（作者）

### 2. 学习目标从"做出编辑器"改成"学会线性表"（cbb202a）

**改前**：学完会用 C 亲手做出这个编辑器的第一版。
**改后**：学完会判断什么样的数据是线性表，对它做插入、删除、查找，并用 C 把它放进内存；编辑器是检验这些本事的第一个地方。

**为什么改**：Gauth 的饮品摊只是场景，目标是学会集合。编辑器同样是检验台，不是学习目标。（作者）

### 3. 节末回扣改成指名章首的问题

**改前**：回到开头的问题……
**改后**：回到本章开头的第一个问题：程序要记住这一行字的什么？……所以程序得记住三样东西：有哪些元素，它们的先后，现在有几个。

**为什么改**：问题已经挪到章首，回扣要说清是哪一个问题。答案"三样东西"和问题一一对应。（Gauth：问题挂起，讲完回来作答）

### 4. 章首末尾补一句过渡（2026-10-24）

**改前**：先记住这三个问题。我们从第一个开始。
**改后**：再加一句"要回答它，先得把'这一行字'说精确"，同时删掉和前文重叠的"屏幕每变一次，程序都在背后干活"。

**为什么改**：Gauth 在定义之前用一句话说明为什么需要这个概念（先得学会集合的语言），2.1 原来缺这一句。（Gauth）

## 二、书稿没改什么（这一点同样是证据）

"什么是线性表"的正文、例题、两道练习都**没有改**。它们本来就符合 Gauth 的做法：

| Gauth 的做法 | 2.1 原稿已有的写法 |
|---|---|
| 先给实物再起名 | "这一行字可以看成一个线性表"，再给一般定义（写法库第 2 条：演绎式） |
| 一条性质配一个最小对照 | 每个要点都按"特点 → 编辑器例子 → 程序为什么在乎"写；一个接一个配 cat ≠ act，可以重复配 book 的两个 o |
| 定义说完回到场景 | (c, a, t)、长度 3、空表就是刚启动的编辑器 |
| 例题把判断画出来，正例加反例 | 通话记录（正例）和家谱（反例），三步检查，每步一个"是/否"，第二个对象在"否"处停下 |
| 练习前给方法口诀，练习和例题同型 | 练习1 判断的正是例题那三条；整题解析就是口诀 |
| 每个干扰项违反一个条件 | 文件夹、地铁违反"一个接一个"；号码球没有先后；正整数违反"个数有限" |

结论：演绎式的概念页，加上正反例的例题，就是 Gauth 介绍概念的写法。2.1 要补的只是"开场"这一层。

**Gauth 有、2.1 没有的一处**：例题后的验算（数一数，一个不漏、一个不重）。2.1 例题用"两样东西差别只在是不是一个接一个"收尾，作用是归纳，不是验算。判断型的概念不一定需要验算，这一处不补。

## 三、做成动画时，旁白改了多少

双栏稿共 90 拍：
- 原样 57 拍（63%）；
- 小改 30 拍（33%），都是机械改动：删指代词、删画面已经显示的半句、写清符号念法、给要点名加序数；
- 新写 3 拍（3%）："轮到你了""再来一题"和一句改成问句的题干。

配音（fish 整屏合成）约 3 分 10 秒。

**结论**：书稿按上面的写法写好之后，旁白只需轻微调整。前提是书稿本身符合"能念出来"的要求（见 `docs/methods/narration-ready.md`）。这个结论目前只在 2.1 这一节验证过。

## 五、2.1 的概念清单

按 `docs/methods/plan-section.md` 拆：
- **核心概念**：线性表，属于描述型；
- **术语、记号**：aᵢ、长度、前驱、后继、空表；
- **特性**：同类型、一个接一个、个数有限、可以重复；
- **判断**：能不能看成线性表，是描述型概念自带的例题。

术语、记号和特性都嵌在线性表这个单元里，用 `docs/methods/deductive.md` 的"是什么"讲。2.1 **没有"怎么做"的单元**，所以没有出现 Gauth 那种"用例题讲一个新概念"的单元。例题和练习检验的是核心概念本身。

## 六、经验汇总

**能用于以后写描述型概念的（已收进 `docs/methods/`）**：
- 开场管一段课程，用五步；问题具体、能猜、在这一段内答完。（Gauth + 作者）
- 场景是检验台，不是学习目标。（作者）
- 概念页用演绎式：一条性质配一个最小对照，定义说完立刻回到场景。（Gauth，原稿已有）
- 例题用正例加反例，逐项检查，步骤名和要点名一字不差。（Gauth，原稿已有）
- 练习和例题同型，干扰项各违反一个条件。（Gauth，原稿已有）
- 书稿要写得能直接切成节拍、念成旁白。（2.1 实测）

**只适用于 2.1 或第2章的**：
- 单行编辑器场景、cat 和 book、通话记录和家谱这些具体例子；
- 三个小问和 2.1–2.6 的分段；
- 线性表"一个接一个"这个术语。

**属于画面层、不进写作方法的**：
- 一屏一到两种版面、质感层、比喻换成直接演示、手风琴改成左右两栏。这些见 `docs/course/visual-spec.md`。
