# 演绎框架：介绍约定类知识

**适用范围**：**约定类**知识，也就是人为规定的语言、模型或操作。它们没有一个问题能"逼出来"，只能先说清楚，再用例子让它具体。比如集合、线性表、列举法、交集、并集、线性表的基本操作。

**和其他方法的区分**：
- 为解决一个问题而**发明**出来的办法（顺序存储、链式存储、头结点），用推导框架 `derive.md`。
- 改变数据的算法（比如顺序表插入时挪动元素），目前用写法库第 5 条"一个问题，一步一图"。它可能属于"发明 × 怎么做"（为什么要从最后一个开始挪，可以从问题推出来），这一点还没核对，整合时再定。
- 一节怎么编排见 `plan-section.md`；写作要求见 `narration-ready.md`。

**证据**：规则来自 Gauth 集合课（集合、列举法、交集与并集）、2.1 和 2.2。
- "是什么"这一种已在 2.1 完整验证。
- "怎么做"这一种部分已在 2.2 验证：一句规则、场景详做、例题、验算、同型练习；"换数据略做"在 2.2 没有用，还是推测。

完整案例见文末"范例"。

---

## 一、目标

让读者知道这个约定是什么，并能**用它**：判断一样东西算不算 X，或者照着它做出结果。

约定**用演绎的方式给出**：先说名字和定义（或规则），再代入场景具体化。场景可以先提问题，但问题只用来**引出需要**，不用来推出概念。场景是**带入**，不是推理的来源。

## 二、骨架

| 步 | 做什么 |
|---|---|
| 1. 点名 | 给名字，加一句定义或规则 |
| 2. 具体化 | 代入场景，让它变具体。按知识是"是什么"还是"怎么做"，分两种做法，见第三部分 |
| 3. 换干净材料 | 场景里做不干净的，换成更干净的材料，比如纯数字、另一个例子 |
| 4. 检验 | 和例题同型的练习 |

**两种具体化**：

| | 是什么（例：2.1 线性表） | 怎么做（例：Gauth 交集、并集） |
|---|---|---|
| 怎么具体化 | 实例加最小对照：看清"什么算、什么不算" | 完整做一遍：看动作一步步发生 |
| 步骤 | 定义加场景实例 → 特性逐条配最小对照 → 判断例题（正例加反例） | 详做一例 → 略做一例 → 验算 |
| 练习考什么 | 判断一样东西是不是 X | 照着做出结果 |

一节里如果"是什么"后面紧跟着"怎么做"，前者的判断例题和练习可以省掉，由后者检验（Gauth：集合后面接列举法）。

## 三、细则

### 1. 点名（两种共用）

- 开场已经给了场景时，这一步只要一句。开场怎么写见 `plan-section.md`。
- **是什么**：用"**可以看成**"，不说"叫"，因为具体的东西不等于抽象模型。名字后面紧跟一个最关键的特征，比如"这一行字可以看成一个线性表……一个字符接一个字符排成一列"。
- **怎么做**：说出名字，再加一句规则，或者说出"从什么转成什么"。规则里带上限定词，比如"两个集合都有的元素，而且只有这些"。不展开解释，不讲为什么。
- 名字或符号前面已经出现过的，这里点名就行。
- 前面如果挂了问题，加一句过渡，说明为什么需要它，比如"要回答它，先得把'这一行字'说精确"。

### 2a. 具体化：是什么

**定义加实例**
- 定义只写一句。核心是**可判定**：读了定义，就能判断一样东西是不是 X。
- 术语和记号随定义点名，每个配一个场景里的实例：元素、长度、aᵢ……
- 定义说完，**立刻用场景写出一个实例**。

**特性**
- 先报要点数："这个定义里有四个要点，逐条看。"
- 每个要点写成一段，分三步：
  1. 特点，一两句；
  2. 一个**最小对照**：能用一对东西说明，就不写一段话；
  3. 为什么在乎：落到实际用处上，比如"程序要记住什么"。
- 要点名全书一字不差。
- 结尾回答开场的那个小问，答案和问题一一对应。

**判断例题**
- 两个对象：一个是，一个不是。反例只在**一个**特性上不满足，这样能看出这个特性的作用。
- 按特性逐项检查，编号列表。步骤名和要点名一字不差，每步以"是"或"否"结尾，遇到"否"就停。
- 收尾一句点出差别在哪一条。
- 格式：`> **题目**：` → 分析 → `> **答案**：`。

### 2b. 具体化：怎么做

**详做一例**
- 一拍判断一个元素，每一步一句，句型固定，比如"x 行""x 只在 A，跳过"。
- 做法有固定步骤的，先说步骤，比如"先把 A 全部抄进去，再逐个加 B 的"。
- 每一步都能画出来，一步一个对象（见 narration-ready 第 3 条）。

**略做一例**：换一组数据，一句带过，提示减少，给读者留出自己补全的空间。

**验算**：标准简单，能数、能对；顺手回扣前面的规则或特性，比如"一个不漏、一个不重"。

**变体**（按需要加）：
1. **有容易错的规则**：做之前先点名，比如"每个元素只写一次"；详做时故意犯一次错，再纠正。只在真有人常犯这个错时才用。
2. **成对的过程**：放在同一个单元。先各自详做，再一起略做，最后用一道一题两空的练习同时检验。
3. **略做时给一个技巧**，比如"按从小到大写，就不会漏也不会重"。
4. **详做里放一个反例**：放在边界上，让读者看到条件在起作用。

### 3. 换干净材料（两种共用）

- 开场、问题、定义的第一个实例、详做，都放在场景里；详做的结果回答开场挂起的问题。
- 场景里做不干净的，换更干净的材料：反例在场景里找不到，就换一个例子（2.1 用家谱）；略做换成纯数字（Gauth）。

### 4. 检验（两种共用）

- 练习和例题同型：问法一样，作答方式一样。
- 练习前一句口诀或提醒，就是例题里做过的动作或守过的规则。
- **每个干扰项对应一种具体的错误**：
  - 是什么：每个特性都有一个干扰项违反它；
  - 怎么做：违反一个条件、漏掉一个、出现重复、做成了另一种过程。另一个空的正确答案本身也可以当干扰项。
- 再加一题考最常见的误解，比如"有序 = 排好序"。

## 四、易错

- **归纳式**：先列特点再命名（作者否决过）。约定是规定出来的，不是观察出来的。
- **照搬参考课程的对照物或干扰项**。参考学科的性质不一定在本学科成立。
- **同一件事在讲解里和练习解析里各讲一遍**。讲解里讲清；练习的选项解析只写一句，指出错在哪，不再展开（2026-10-24 作者定）。

## 五、自检

- [ ] 这是约定类知识（不是为解决问题发明的办法）。
- [ ] 点名：名字加一句定义或规则；是什么用"可以看成"。
- [ ] 是什么：定义可判定，定义后立刻有场景实例；先报要点数，每个要点都有"特点 → 最小对照 → 为什么在乎"；判断例题的反例只在一个特性上不满足。
- [ ] 怎么做：详做每一步都写出来，句型固定；略做比详做简短；有验算。
- [ ] 练习和例题同型，每个干扰项都对应一种具体的错误。
