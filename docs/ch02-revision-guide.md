## 一、改版目标

1. **每节一个概念目标。** 一节讲清一个概念知识点（或一组紧密相关的概念），节标题就写这个概念。单行编辑器从"本节的目标"降为"把概念具体化的例子"：它是贯穿全章的场景，不是每节要完成的任务。
2. **每节都由"问题、概念、练习"组成，页数不固定。** 一节切成几页，在同一个网址里翻页；问题可以单独一页，也可以和概念同页；概念多的节可以有好几页。
3. **用交互练习检验理解。** 节末是一页一道的交互题（单选、多选、填空），取代原来文字版的"练一练"。
4. **全文为完整阅读而写，同时能当配音讲稿。** Brilliant 式的卡片、动画、配音是以后从每页全文生成的讲课形式。书本身必须是完整可读的正文，不能为了像卡片而压缩。

## 二、结构模板

### 2.1 节和页

- **节标题只写概念**："2.1 线性表""2.3 顺序存储与顺序表""2.5 传值与传地址""2.8 动态数组"。不放问题场景，不放副标题式的口号。编辑器的版本名（编辑器1.0、1.1、2.0……）只在正文里出现，因为后文按版本号互相称呼。
- **分页**：节内单独一行 `<!-- 分页 -->`（前后各空一行）。
- **每页一个页标题**：页首一行独占的加粗段落 `**…**`，会进右栏"本节目录"，点它能翻到那一页。命名方式：
  - 问题页写场景名或问题，如"单行编辑器里的一行字""数组满了怎么办"；
  - 概念页写概念问句，如"什么是线性表""什么是传值"；
  - 过程页写操作名，如"在第i个位置插入"；
  - 练习页写"练习N：简短的问题"。
- **页内的小要点用段首加粗**（`**同类型**。c、a、t……`），不单独成行，否则会和页标题一起进目录。
- **分页的节，页面上不显示节名**：h1 视觉隐藏，仍留在页面结构里给读屏软件和评论定位用。最醒目的位置给页标题。理由：读者从目录点进来，本来就知道在哪一节。

### 2.2 一节的页序

```
问题页  →  概念页（一页或几页）  →  [例题页]  →  [过程页 / 代码页]  →  练习页 × N  →  节尾卡片
```

- **问题页**
  - 用编辑器场景加内存格子图，把问题具体化。
  - 问题卡片 `> **本节问题**：…` 放在页末，先给场景再问。
  - 只放本节需要的场景，不提前放后面节的内容。例如 2.1 只演示敲字，光标移动、插入、退格留给 2.2。
- **概念页**：演绎式，写法见第三部分。
- **例题页（按需）**：只有当练习要用到概念页没演示过的判断或步骤时才加。例如 2.1 的练习要判断"不是线性表"，概念页只给了正例，所以加了一页正例加反例的例题。不是固定模板。
- **过程页（实现、代码）**：写法见 2.4 节。
- **练习页**：一页一题；题型和格式见第四部分。
- **节尾卡片**：放在最后一道题之后，写"到这里你有了 / 下一步"。改版后的节不再写"练一练"。

### 2.3 分层：概念 → 语言工具 → 代码

同一件事先讲概念（与语言无关），再讲 C 的工具，最后写代码，三者分页。

| 节 | 概念页 | C 工具页 | 代码页 |
|---|---|---|---|
| 2.3 | 什么是顺序存储（含"长度"） | 用C语言表示顺序表（数组、结构体） | 例题：放进去再读出来 |
| 2.5 | 什么是传值 / 什么是传地址（只讲思路和格子图） | 地址与指针（`&`、`*`、`->`） | 用传地址实现顺序表的操作 |
| 2.8 | 什么是动态数组（运行时申请、长度与容量） | 向系统申请空间（malloc/free/realloc） | 定义和初始化 / 操作 |
| 2.9 | 什么是链式存储（结点、链表、头指针、箭头图） | 用C语言表示链表（`Node, *LinkList`、一步步搭出 cat）、输出链表 | 在 2.10：通用的初始化、求长度、取元素、插入、删除、销毁 |

**属于概念本身的东西放概念页**，不要放进"用 C 表示"那页。例如"长度"属于顺序存储本身：不记长度就不知道读到哪里停，和用不用 C 无关。**C 的表示放 C 页**，例如"`data` 要变成指针"。

**概念节讲完立刻用 C 做出第一个实例，通用操作放实现节**（2.9 作者定，见 3.1 节后的规则）。2.9 的 C 页把 cat 搭成链表并输出；2.10 写成通用操作。

### 2.4 过程页（操作的实现、编辑器的指令）

- **页标题写操作名**，不用"例题N"格式：怎么插入、为什么倒着挪，本身就是要教的内容，套例题格式等于"没讲就先考"。
- **每个操作当成一个问题来解**（2.10–2.12 作者定，来自 2.9"用C语言表示链表"把 cat 存进链表的写法）。第一个操作点出一次，后面照做：
  1. 问题：用编辑器场景提出（"光标在行首 `|cat`，敲 b"），画出操作前和要达到的样子，用一句"对照两张图，变了……"点出差别；
  2. 第一步……第N步：段首加粗"**第一步：申请b结点**"，每步一到三行具体代码（接着上一节的例子写，具体的字符和地址直接写进注释），紧跟一张这一步做完后的图；关键推理写在对应那一步（"先让新结点指向后一个"）；
  3. 写成函数：把具体的换成一般的（'b' 换成 x，"走1步"换成走 i−1 步的循环，main 的 L 换成 `*L`），注释和步数一一对应；
  4. 其他情形由简到繁：先讲简单的（第0个），再讲多一步的（中间）；和前面相同的步骤说"同理"，末尾这类不需要新代码的情形一句话并入；语法细节（如 `*L`）放说明块；
  5. 带入例子走一遍：只在循环处简短做（如 Get(L, 5) 走到 NULL），不重复画图。
- **每讲完一件事，就紧跟着给代码**（2.6 作者定）。初始化讲完给初始化代码，每条指令讲完给那几行代码。最后一页只做装配，把前面的代码装进循环。
- **有了逐条代码，就不再放汇总表**：main 的 switch 本身就是汇总。
- **约定放在第一次用到的地方**，不写单独的方法页。例如全局变量 L 的约定放在第一段代码前；"返回 1/0 报告成败"放在第一个可能失败的操作（插入）那里。
- **对已有代码的修改，用"原来 / 现在"对照**（2.8 的结构体、Init、Insert）。
- **操作的机制放实现节**（2.9 作者定，2026-10-09，取代之前"概念节讲取元素、插入、删除的机制"）。取元素、插入、删除的"改前 → 改后"在 2.10 每个操作的"操作前和操作后"里讲一次，不在 2.9 先讲一遍。
- **概念节讲完，立刻用 C 做出第一个实例**（2.9 作者定，2026-10-09，取代 10-07 的"C 页只讲表示、造结点和遍历放 2.10"）。2.9 讲完链式存储，马上把编辑器的 `cat` 一步步搭成链表（空链表 → 第一个结点 → 第二个结点 → 同理第三个，每步一张箭头图，代码和图一一对应），再用指针从头走到 NULL 把它输出，给出能运行的完整程序。让读者立刻看到"这个问题确实能被解决"，和 2.3 的例题"放进去再读出来"对称。手工搭只能演示，通用操作放实现节，实现节可以引用"2.9 搭 cat 时做过"。
- **链表用教材写法 `typedef struct Node {…} Node, *LinkList;`，不再包一层结构体**（2.9 作者定，2026-10-09）。包一层 `LinkList { Node *head; }` 只为和 SeqList 对称，对学习者多一层概念，后面代码也多一层 `->head`。定义处就把 `*LinkList` 展开成 `typedef Node *LinkList;` 讲明白（LinkList 就是 `Node *`），并交代习惯：指一个结点写 `Node *`，代表整个链表写 `LinkList`。图里的头指针在 C 里叫 L。函数要改头指针时，参数写 `LinkList *L`，按 2.5"要改谁就传谁的地址"讲，`*L` 就是头指针本身；main 仍是 `Init(&L)`、`Insert(&L, …)`，和顺序表版只差类型名。**改 2.10 起要把 `L->head` 全部换成 `*L`**（2.10 及以后目前仍是结构体写法）。
- **辅助函数不在正文引入**（2.10 作者定，2026-10-09 再次确认）。NodeAt、NewNode 只是把几行收成函数，是抽象，不是实现链表必需的，对学习者是新概念的负担。操作内联写，每个函数自足，和 2.4 一样；"从头走 i 步"的循环在 Get、Insert、Delete 里各写一遍。真有动机时再抽。
- **实现节沿用概念节的例子和图，重点讲"怎么变成代码"**（2.10 作者定）。2.9 讲过的机制一句话带过；2.9 刻意没讲的（从 head 走到前一个结点、两句赋值的先后、第 0 个位置改 head、走着看位置合不合法、malloc 造结点）才是实现节的主体。图沿用 2.9 的地址（c100、a109、t105、x102、b112），结点下面标出 p、prev、q，每句赋值配一张改完的图，让代码和格子一一对应。
- **链表插入、删除按情形讲，每种情形讲完紧跟代码**（2.10 作者定，2026-10-09）。插入顺序是中间 → 第0个 → 末尾：先讲一般情况（接 2.9 的插入页，补上找前一个结点和两步的先后），再查两头。第0个没有前一个结点，改头指针 `*L`；末尾套中间的代码正好对，不用新代码，由此得出"三种其实是两种"，最后合成带 if 的完整 Insert。删除沿用同一个套路。
- **一页太长就拆**：2.6 的五条指令拆成"敲字符和退格""移动光标、退出和显示"两页。

### 2.5 复杂度分析的写法（2.7）

- **方法只用一段话点出**：第1章已经讲过完整的方法，2.7 不重讲。参考说法："时间复杂度描述的是：当输入规模 n 增大时，算法执行的基本操作次数随 n 增长的趋势……忽略常数和低阶项，3n²+5n+2 记作 O(n²)。"同时补一句 O(1) 的含义。
- **逐个操作量**：每个操作讲完立刻给出它的复杂度，再讲下一个。
- **一个操作有几种情况时拆成子操作逐个分析**，例如插入分尾部、头部、中间，各给结论；每个操作单独一张只含时间复杂度的表（不写"挪几个"），最后一张五个操作的总表。点明三种情况就是最好、最坏、平均，并说明"通常看最坏情况"。
- **始终说"步数"**：挪动元素只是"步数花在哪里"，不能把衡量标准换成"挪几个"。
- **编辑器的每条指令分"改这一行"和"显示"两部分说**：显示每次 O(n)，是本书为了程序简单每次打印整行，不是要解决的问题。
- **选讲内容（平摊分析）只用一句话，放进提示框**；但不能省到让前后矛盾。例如 2.8 必须交代"触发扩容的那一次是 O(n)，平均仍是 O(1)"，否则和 2.7"尾部插入 O(1)"看起来冲突。

## 三、写作风格与语气

跨章节可复用的讲解写法（推出办法再命名、一个问题一步一图、情形由简到繁等），已整理到 `docs/teaching-patterns.md`，按知识类型挑写法。下面是第2章的具体规范和决定记录。

### 3.1 概念页：演绎式

- **先点出概念，再逐条讲**："这一行字可以看成一个**线性表**。"然后讲定义和每个要点。不用归纳式（先观察出几个特点再命名）：读者并不能从三行屏幕里自己"发现"这些特点，那是作者先知道答案再挑出来的观察，不诚实，也让读者没有框架。
- **例外：概念是"解决问题的办法"时，先推出办法，再命名**（2.9 作者定）。链式存储、顺序存储、动态数组都属于这一类：办法从问题里推出来，每一步都有理由（关系丢了就记下来，不知道从哪开始就记一个头），读者先有解决问题的经验，再给它起名字。命名时回指图里的东西，一句一个；命名后用一句话收拢成完整定义（"一个链表，就是一串用地址连起来的结点，加上一个头指针"）。2.1 否决的是"让读者从例子里观察出特点"，不是这种推导。
- **每个要点三步**：特点 → 编辑器例子 → 程序为什么在乎。例如"有先后"之后要说：`cat` 和 `act` 是两行不同的字，只记住"有 c、a、t"打印不出这一行。
- **结尾回到问题页的问题**："回到开头的问题。这一行字可以看成一个线性表。要一直记着它，程序就得记住三样东西……"

### 3.2 措辞要准

- **"可以看成一个线性表"**，不说"叫线性表"：具体的东西不等于抽象模型。练习题干也用"看成"，前后一致。
- **术语全章一字不差**：例题的步骤名必须和概念页的要点名一样。线性关系统一叫**"一个接一个"**（除首尾外恰好一个前驱、一个后继）。
- **用"传值""传地址"**，第一次出现时说一句"教材里也叫值传递、地址传递"。并讲清"传地址其实也是传值，只是传的值是地址"：C 只有传值。
- **光标记成"光标左边有几个字符"**（整数 cursor）。空行 0、`ca|t` 是 2、`cat|` 是 3，没有特例；敲字是 Insert(L, cursor, c)，退格是 Delete(L, cursor−1)。
- **不写不精确的说法**。例如"取第 i 个，算一次加法就知道在哪"：真实地址是起始地址加 i 乘元素大小，只说"直接就能找到它所在的格子，不用从头数"。
- **说"返回"，不说"交回"**（2.10 作者定，全章已统一）："返回0""返回`'\0'`""没有返回值"；需要名词时说"返回值为0"。"返回"是 C 的标准说法，读者在教材和编译器提示里看到的都是它。
- **页标题和段首说全对象**（2.10 作者定）：写"删除第0个结点""在中间位置插入结点""销毁链表"，不写"删除第0个""删中间的"。标题进右栏目录，脱离上下文也要看得懂。术语仍用"结点"，不用"节点"。
- **"写成函数"从目标说起**（2.12 作者定）：先说"要删的是第i个结点，第一步先走i−1步，到它前一个结点"，条件随之说清（"第i−1个和第i个结点都要存在，否则返回0"），不写"'走1步'一般是走i−1步"这种要读者回头对照的说法。
- **ADT 记号和 C 写法分开**：概念、指令对应关系里写 `Insert(L, 2, x)`（2.2 的记号）；C 代码里写 `Insert(&L, 2, 'x')`。

### 3.3 一稿两用：能念出来

正文以阅读为主，以后再从每页全文生成配音讲稿和卡片动画，所以现在就要写得能念出来：

1. 一段只讲一件事。以后一段对应一个动画步骤。
2. 句子短，少用括号和嵌套。补充说明单独成句。
3. 符号第一次出现时先用文字说："第0个元素记作 a₀"。
4. 论证写在段落里，不放在表格里。表格只做汇总或对比。
5. 交叉引用（"2.9节会讲"）单独成句，讲稿里整句删掉不影响意思。

代码节的讲稿以后单独写：C 代码和跟踪表念不出来。

### 3.4 语气

- 平实、具体，用 cat、x、book 这类同一组例子贯穿全章。例子要和前几节衔接（cat → `ca|t` → `cax|t`）。
- 不写拦不住读者的提示，例如"先自己判断一下，再往下看"：答案就在同一页。要让读者先想，以后用交互实现。
- 不写读者用不上的叮嘱，例如"看完把这行打印删掉"。引入时说清"临时加一行"就够了。
- 不重复演示同一件事：练习或运行结果已经演示过的过程，正文不再"走一遍"。

## 四、格式约定

### 4.1 代码

- 代码块用 ```` ```c ````。函数名后的空参数写 `void`：`Init(void)` 表示不接受参数，`Init()` 在 C23 之前表示"参数不定"，会漏掉错误调用；第一次出现时说一句 `void` 的含义。
- 用到的语法必须前面讲过。**概念页不写还没讲的语法**：2.5"什么是传地址"只讲思路和格子图，`&`、`*`、`->` 下一页才讲。
- 过程页的代码，见第二部分 2.4 节。

### 4.2 图示（内存格子图）

- 用制表符画格子，无语言标记的围栏会自动按字符画处理，等宽字体严格对齐。中文按 2 列算。构建时会提示没对齐的地方（`[diagram]` 开头）。
- 地址用小的十进制数，全章一脉相承：100、200、300、500、700。正文交代一句：真实地址是 `0x7ffd…` 这样的十六进制。
- 常用画法：
  - 顺序表：`data │ c │ a │ t │   │   │   length = 3`，下面一行写下标。
  - 不知道内容的格子画 `?`，例如 Init 前的数组。
  - 光标画在两个格子之间的竖线下面：`▲` 加 `cursor = 2`，左边有几个格子就是几。
  - 挪动画 `└──►`，每个元素一段，从它原来的下标指向新的下标。
  - 指针画格子加箭头 `◄────`，箭头从指针格子指向它指的变量；图和代码一一对应。
  - 双向链表的结点画成五行：上框、空行、值行（`│ 120 │ c │ 109 │`，三格的值在同一行）、空行、下框。值行上面一行，左结点右边框写 `├`，接 `────►` 表示 next；值行下面一行，右结点左边框写 `┤`，接 `◄────` 表示 prior。箭头被改掉时，那一行只留边框（2.17 作者定）。
- 抽象内容（地址、指针、传值、传地址）一定配图。图解释清楚的，不再贴屏幕输出（2.8 第1页删掉了会话）。

### 4.3 卡片与提示框

| 写法 | 用途 |
|---|---|
| `> **本节问题**：…` | 问题卡片，放在问题页末 |
| `> **题目**：…`，后面不带标签的行逐行显示 | 例题的题目卡片 |
| `> **答案**：…` | 例题的答案卡片（虚线框） |
| `> **到这里你有了**：…` 换行 `> **下一步**：…` | 节尾卡片，放在最后一道题之后 |
| `::: tip 标题` … `:::` | 小字提示：选讲、补充说明（如"为什么容量翻倍"）；也用来注解正文代码里的语法细节，正文只留和图对应的主线（2.9 作者定：`next` 指向自己这种结构体、`LinkList` 就是 `Node *` 各一个框，紧跟在结构体代码后面） |
| `::: warning 标题` … `:::` | 小字提示：容易写错的地方（如"realloc 的返回值先存临时变量"） |

主线内容不要放进提示框。

### 4.4 例题页

1. 页标题写具体的题，如"例题：通话记录和家谱能看成线性表吗？"。
2. `> **题目**：` 卡片。
3. `**分析**。` 直接针对题目逐步写。用编号列表，每步开头是步骤名，步骤名和概念页的要点名一字不差，如"看元素 / 看是不是一个接一个 / 看个数"。不写抽象的通用方法段。
4. `> **答案**：` 卡片。
5. 一句具体的对比收尾，如"两样东西的元素都是同一种，也都有先后，差别只在是不是一个接一个"。

### 4.5 习题

- **一页一题**，页标题就是问题本身。题干只给判断需要的信息，不重复页标题。
- **三种题型**：
  - `::: quiz 单选`：只考一个点。
  - `::: quiz 多选`：识别、辨析。
  - `::: quiz 填空`：成对对比（传值和传地址）、多步跟踪（光标、扩容的变化）。一题 2～4 个空。空写 `[[答案]]`，干扰项写在 `**其他选项**：甲、乙` 一行。
- **每个错误选项都要写解析**（选项下一行缩进两格），说清楚错在哪。列表后面写整题解析。
- **选题时说清每道题考什么、为什么选它**（2.8 起作者要求）。不考选讲内容（例如平摊分析）。避免和正文、和别的题重复。
- **练习只考本节讲过的内容，不出为后文埋伏笔的假设题**（2.15 作者定）。例如 2.7 原练习3"假如 Get 变成 O(n)，Show 会怎样"：读者在 2.7 没有任何理由想到 Get 会变慢，已删；到 2.15 真遇到时直接分析。
- **一节两到三道。**旧"练一练"里的好题优先改成交互题。

## 六、容易出错的地方

### 6.1 内容

- **节号变动的连锁影响。**拆分或合并节，会牵动：
  - 正文里的"x.y节""x.y.z的"引用；
  - 后文"2.7练习3的答案"这类题号引用（"练一练"删掉后题号会变）；
  - e2e 测试里的 `/ch02/2-N`；
  - 评论迁移。
- **编辑器版本号和节号撞车。**"编辑器2.1""（2.0）"是版本号，批量改节号时要排除。规则：紧跟在"编辑器"后面的、表格里的版本列，一律不动。
- **分页后小节号消失。**原来"2.5.2的程序"这类引用要改成"2.5的…"或具体说明。xref 插件只认两段号加"节/的/练一练"，以及紧跟汉字的写法，构建末尾会列出没解析的引用（目前应只有 4 处：第3、4、7、8章）。
- **前后结论要一致**，改一处要查后文：
  - 显示 O(n) 和"行尾插入 O(1)"（2.7、2.13、2.15）；
  - 扩容那一次 O(n)（2.8）；
  - 2.6"main 只调用五个操作"是 2.12"main一行不改"的前提。
- **例子要能演示出过程。**插入要挪两个以上元素，才看得出"必须倒着挪"；只挪一个时两个方向结果一样。

### 6.2 工程

- **不要用 `node -e '…'` 把正文内嵌在 shell 里写。**`\0` 会变成 NUL 字符，`\n` 会变成真换行（2.4、2.5 都出过事）。正文一律用 Write 工具写临时文件，再用脚本拼接。拼完检查文件里没有 `\x00`。
- **评论迁移 `db/migrations/005_ch02_renumber.sql` 还没上线**，所有映射都直接改这一个文件。映射按"改版前的节号 → 最终节号"写，步骤顺序不能换：先把目标位置上的原评论挪走，再挪别处的进来，否则会重复挪。每改一节，同步 `tests/unit/server/renumber-migration.test.ts`。
- **dev 服务器侧栏不更新**：一次重新生成会接连改写好几个 generated/*.json，VitePress 连续重启时可能读到旧状态。`scripts/dev.ts` 已经加了"改写停下后再碰一下 config.ts"的补救；若仍看到旧标题，重启 dev。
- **e2e 测试拿某节当"普通的、没分页的节"**：该节分页后，改成兼容分页的写法（先打开 `#p最后一页` 再测已读、翻节），不要一直换节。还没改版的节（2.11 起）暂时承担"有练一练""有宽代码""有 ### 小节锚点"的测试（随着改版从 2.9、2.10 移到了 2.11），改到它们时要再处理。全章改完后，"练一练"的固定锚点 `#practice` 功能要重新评估。
- **长代码折叠的 e2e 会挑第一个带折叠块的节**：2.13 末尾的完整代码超过 40 行，被它选中；分页节里的折叠块可能在后面的页上，测试已改成先翻到那一页（2.13 改版时修）。
- **WebKit 并发跑会超时误报**，用 `--workers=1` 复核；步骤多的用例用 `test.slow()`。本机内存小，vitest 用 `--maxWorkers 4`。
- **页标题只能是纯文本**：练习3的标题原来带了反引号包着的 head->next->next，带行内代码就不会被识别成页标题，那一页在目录里消失。页标题里不要用反引号。
- **加粗收尾紧跟标点再接汉字会失效**：`**……指向新结点。**这是` 渲染成字面的星号。把句号移到外面：`**……指向新结点**，这是`。
- **重新构建后，已经开着的 preview 服务器要重启**：否则页面拿到旧资源，客户端功能（搜索、折叠、右栏大纲、字号）全部失灵，e2e 会大面积误报。
- **填空题的选项顺序**：构建时按题目固定打乱，并保证不恰好按答案顺序排在最前面。
- **字体子集**：等宽字体只覆盖代码和图示里出现的字符，新图里用到新符号（▲、►）时，构建会自动纳入；如果构建报字形缺失，看 `npm run build:font` 的输出。
