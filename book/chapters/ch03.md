# 第3章 栈和队列

## 3.1 栈

**铁路调度站**

火车站里有一种调度站，用来给车厢重新排顺序。它是一段尽头线：一头接着主线，另一头是死的。

<RailYard />

车厢从右边的主线开进尽头线。要出来，只能倒回同一个口，开到左边的主线上去。

学完这一节，你能一眼看出一个出站顺序调不调得出来。

现在右边开来三节车厢，按1号、2号、3号的顺序进站。进出可以交替：开进几节之后，可以先开出几节，再接着开进。

调度员要把它们排成新的顺序开出去。他得先知道：按2、1、3开出去，能做到吗？按3、1、2呢？

> **本节问题**：哪些出站顺序做得到，哪些永远做不到？

<!-- 分页 -->

**调一调**

先试2、1、3。

第一个要开出的是2号。2号还没进站，先让1号、2号开进去。这时2号在最外面，开出去。接着1号在最外面，开出去。最后3号开进来，再开出去。

<RailYard ops="1进 2进 2出 1出 3进 3出" />

2、1、3做得到。

再试3、1、2。

第一个要开出的是3号。先让1号、2号、3号都开进去，3号在最外面，开出去。下一个要开出1号，可是1号在最里面，2号挡在它外面。

<RailYard ops="1进 2进 3进 3出 1卡" />

尽头线只有一个口。1号要出去，得先让2号出去，那样开出的顺序就成了3、2、1。所以3、1、2做不到。

两次试下来，规律是：**每次只能开出最外面那一节**。

回到本节问题。按要开出的顺序，一节一节看。轮到的车厢还没进站，就让它和排在它前面的车厢依次开进来；它已经在站里，就必须在最外面。每一节都做得到，这个顺序就调得出来。只要有一节轮到时被挡在里面，这个顺序就永远做不到。

<!-- 分页 -->

**什么是栈**

这样的调度站可以看成一个**栈**。

栈是只能在一端插入和删除的线性表。把调度站和栈的示意图放在一起，对照着看：

<div class="figure-pair">
<RailYard ops="1进 2进 3进" last terms />
<StackFigure items="1 2 3" />
</div>

**线性表**。站里的车厢一节挨一节，排成一列：(1, 2, 3)。除了最里面和最外面的两节，每节车厢里面恰好挨着一节，外面恰好挨着一节，一个接一个。所以站里的车厢可以看成一个线性表。

线性表在2.1节讲过。

**只能在一端插入和删除**。能进出的那一端叫**栈顶**，另一端叫**栈底**。尽头线的开口是栈顶，尽头是栈底。现在3号在栈顶，1号在栈底。

插入叫**入栈**，删除叫**出栈**。车厢开进来是入栈，开出去是出栈。一节车厢都没有的时候，叫**空栈**。

普通的线性表可以在任意位置插入和删除。比如编辑器可以在一行字的中间插入一个字符。栈不行，只能动栈顶。所以栈是操作受限的线性表。

**后进先出**。上一页的规律是：每次只能开出最外面那一节。换成栈的说法，就是每次只能出栈栈顶。栈顶总是最后入栈的那一个，所以最后入栈的，最先出栈。这叫**后进先出**，也说成先进后出。

3号最后开进来，停在最外面，最先开出去。1号最先开进来，被2号、3号挡着，要等它们都出去。

## 3.2 栈的操作与抽象数据类型

**调度员要对调度站做什么**

3.1节把1、2、3调成了2、1、3开出。看其中一个时刻：1号、2号已经开进站，3号还在右边等着，现在轮到开出2号。

<RailYard ops="1进 2进" waiting="3" asks last />

开出之前，调度员要先看一眼：站里还有没有车？最外面是几号？确认最外面就是2号，才让它开出去。开出之后，他要记下开出的是几号，才知道开出的顺序对不对。接下来，3号还要开进来。

这些事都从一个空的调度站开始。

> **本节问题**：把调度站看成栈，调度员的这些动作，栈要提供哪些操作？

<!-- 分页 -->

**栈的五个操作**

2.2节给线性表定了五个操作。栈是线性表，只是只能动栈顶。把这五个操作逐个改成栈的，就得到栈的五个操作。下面把栈记作S。

**InitStack(S)：建立一个空栈**。对应线性表的Init，没有变。调度站开始时空着，一节车厢都没有。

**StackEmpty(S)：栈空返回1，不空返回0**。对应线性表的Length。栈用不着说第几个，也就用不着数一共有几个，只要知道空不空。调度员问"站里还有没有车"，问的就是这个。

**GetTop(S, &x)：取栈顶元素，用x带回**。对应线性表的Get。线性表可以取第几个，栈只能取栈顶，所以不用说第几个。取完之后栈不变，就像调度员只是看一眼最外面是几号，车不开走：

<StackFigure items="1 2 3" ops="gettop" />

**Push(S, x)：把x放到栈顶**。对应线性表的Insert。线性表要说插在第几个，栈不用说，位置只能是栈顶。x放进来之后，就是新的栈顶。3号开进，就是Push(S, 3)：

<StackFigure items="1 2" ops="push:3" />

**Pop(S, &x)：删除栈顶元素，用x带回**。对应线性表的Delete。同样不用说删第几个，只能删栈顶。和Delete不同的是，Pop还要告诉调用者删掉的是谁，因为调度员得知道开出去的是几号。3号开出，就是Pop(S, &x)，x是3：

<StackFigure items="1 2 3" ops="pop" />

GetTop和Pop为什么用x带回，不像线性表的Get那样直接返回？因为空栈时，它们做不成。线性表的Get做不成时返回'\0'，可栈里放的是车厢编号，任何一个整数都可能是编号，挑不出一个数专门表示"做不成"。所以返回值留着报告做成没做成，栈顶元素用x带回。x前面的&，就是2.5节讲的传地址。

五个操作和线性表的对应如下：

| 线性表 | 栈 | 含义 |
|---|---|---|
| Init(L) | InitStack(S) | 建立一个空栈 |
| Length(L) | StackEmpty(S) | 栈空返回1，不空返回0 |
| Get(L, i) | GetTop(S, &x) | 取栈顶元素，用x带回，栈不变 |
| Insert(L, i, x) | Push(S, x) | 把x放到栈顶 |
| Delete(L, i) | Pop(S, &x) | 删除栈顶元素，用x带回 |

栈的操作都没有i，因为位置总是栈顶。空栈没有栈顶，所以不能GetTop，也不能Pop。栈满了怎么办，是实现时的事。

3.1节说的是栈"是什么"：只能在一端插入和删除的线性表。这五个操作说的是栈"能做什么"。两样合起来，就是栈的**抽象数据类型**。和2.2节线性表的抽象数据类型一样，它只说是什么、能做什么，不说元素怎么存、操作怎么做。

**例题：用五个操作调出2、1、3**

> **题目**：1号、2号、3号车厢按这个顺序开到调度站。把调度站看成栈S，要按2、1、3的顺序开出，依次调用哪些操作？每次开出时，x是几？

**分析**。按要开出的车厢，一节一节写。

1. 开始：调用InitStack(S)，S是空栈。
2. 开出2号：2号还没进站，先让1号、2号入栈，调用Push(S, 1)、Push(S, 2)。这时栈顶是2，调用Pop(S, &x)，x是2。
3. 开出1号：1号现在是栈顶，调用Pop(S, &x)，x是1。
4. 开出3号：3号还没进站，调用Push(S, 3)。它就是栈顶，再调用Pop(S, &x)，x是3。

<StackFigure ops="init push:1 push:2 pop pop push:3 pop" />

> **答案**：依次调用InitStack(S)、Push(S, 1)、Push(S, 2)、Pop(S, &x)、Pop(S, &x)、Push(S, 3)、Pop(S, &x)。三次Pop带回的x依次是2、1、3。

调度员的每一个动作都是五个操作之一，没有一步需要知道车厢存在哪里。下一节给栈选一种存法，这串调用不用改。

## 3.3 顺序栈

**栈顶放在哪一头**

3.2节只说了栈能做什么，没说怎么存。现在把栈放进内存。

栈是线性表，2.3节的顺序表可以直接拿来用：一段连续的格子，元素从第0格开始一个挨一个放。只剩一个问题：栈只在一端进出，这一端放在数组的哪一头？

两种放法都试一下。站里已经有1号、2号、3号，3号是栈顶，现在Push(S, 4)。

放法一：栈底在第0格，栈顶在末尾。

```
         0   1   2   3   4
       ┌───┬───┬───┬───┬───┐
Push前 │ 1 │ 2 │ 3 │   │   │
       ├───┼───┼───┼───┼───┤
Push后 │ 1 │ 2 │ 3 │ 4 │   │
       └───┴───┴───┴───┴───┘
```

4直接放进第3格，谁都不用挪。

放法二：栈顶在第0格。

```
         0   1   2   3   4
       ┌───┬───┬───┬───┬───┐
Push前 │ 3 │ 2 │ 1 │   │   │
       ├───┼───┼───┼───┼───┤
Push后 │ 4 │ 3 │ 2 │ 1 │   │
       └───┴───┴───┴───┴───┘
```

要先把1、2、3各往后挪一格，才能空出第0格放4。Pop也一样，删掉第0格之后，后面的都要往前挪一格。

这和2.7节的结论一样：顺序表在末尾插入、删除，一个都不用挪；在开头插入、删除，要挪n个。栈的进出全在栈顶，所以栈顶放在末尾，栈底放在第0格。

> **本节问题**：栈底在第0格、栈顶在末尾，栈的五个操作怎么用C语言写出来？

<!-- 分页 -->

**顺序栈**

用顺序存储的栈叫**顺序栈**。它和顺序表一样，是一段连续的格子，再加一个数记着栈里有几个元素：

```c
#define MAXSIZE 100

typedef struct {
    int data[MAXSIZE];   /* 存放元素的连续空间，栈底在第0格 */
    int top;             /* 栈里元素的个数 */
} SeqStack;
```

元素是整数，因为要放的是车厢编号。

top就是顺序表的length，换个名字，是因为它正好指着栈顶：元素放在第0格到第top−1格，栈顶元素在第top−1格，第top格是下一个空格。下面的图只画5格，右边的箭头指着第top格：

<div class="figure-pair">
<StackFigure capacity="5" top bare />
<StackFigure items="1 2 3" capacity="5" top bare />
</div>

左边是空栈，top是0。右边放了1、2、3，top是3，栈顶3在第2格，箭头指着空着的第3格。

由此马上得到两个操作。初始化就是让top为0；判空就是看top是不是0：

```c
void InitStack(SeqStack *S) {
    S->top = 0;
}

int StackEmpty(SeqStack *S) {
    return S->top == 0;
}
```

S传的是地址，和2.5节以后的顺序表一样。

栈满时，top等于MAXSIZE。这一条Push会用到。

::: tip 另一种约定：top指着栈顶元素
有的教材让top等于栈顶元素的下标。这时空栈的top是−1，栈满的top是MAXSIZE−1；Push要先把top加1再放，Pop要先取再把top减1。两种约定都对，本书沿用顺序表的length，让top等于元素的个数。
:::

<!-- 分页 -->

**Push：放到栈顶**

栈里是1、2，top是2。现在Push(S, 3)。

**第一步：判断栈满**。top是2，不等于MAXSIZE，放得下。

**第二步：3放进第top格**。第top格就是下一个空格，也就是第2格：

```c
S->data[S->top] = 3;   /* data[2] = 3 */
```

<StackFigure items="1 2" capacity="5" top ops="set:2=3" />

**第三步：top加1**。现在有3个元素了：

```c
S->top++;              /* top = 3 */
```

<StackFigure items="1 2" capacity="5" top ops="set:2=3 top:3" skip="2" bare />

**先放，再加1，顺序不能反**。top指着的是空格。先加1，top就变成3，3会放进第3格；第2格空着没放东西，却已经算在栈里了。

写成函数。要放的是x，放进第top格，再把top加1。放不下返回0，放好了返回1：

```c
int Push(SeqStack *S, int x) {
    if (S->top == MAXSIZE) return 0;      /* 第一步：栈满，放不下 */
    S->data[S->top] = x;                  /* 第二步：x放进第top格 */
    S->top++;                             /* 第三步：top加1 */
    return 1;
}
```

<!-- 分页 -->

**Pop：删除栈顶，用x带回**

栈里是1、2、3，top是3。现在Pop(S, &x)。

**第一步：判断栈空**。top是3，不是0，有东西可删。

**第二步：top减1**。栈顶元素在第top−1格，也就是第2格。top减成2，第2格就不算在栈里了：

```c
S->top--;              /* top = 2 */
```

<StackFigure items="1 2 3" capacity="5" top ops="top:2" />

格子里的3还在，图里画成灰色。它不用擦掉：top以上的格子都算空，下次Push会直接把它盖掉。

**第三步：用x带回第top格**。top现在是2，第2格里就是刚删掉的3：

```c
*x = S->data[S->top];  /* x = data[2]，也就是3 */
```

<StackFigure items="1 2 3" capacity="5" top ops="top:2 read:2" skip="2" bare />

这里的顺序和Push正好相反：Push先放再加，Pop先减再取。因为top指着的是空格，栈顶在它下面一格。

写成函数。栈空返回0，删好了返回1，删掉的元素用x带回：

```c
int Pop(SeqStack *S, int *x) {
    if (S->top == 0) return 0;            /* 第一步：栈空，没有可删的 */
    S->top--;                             /* 第二步：top减1 */
    *x = S->data[S->top];                 /* 第三步：用x带回第top格 */
    return 1;
}
```

为什么x是`int *`，不是`int`？Pop要把删掉的元素交给调用者，也就是要改调用者自己的变量。如果参数写成`int x`，调用时复制给函数的是调用者那个x的值。函数里给x赋值，改的只是这份复制品，调用者的x不变，和2.5节的Inc1一样。

所以调用时传的是x的地址`&x`，参数用存地址的`int *`。`*x = …`顺着地址改的，就是调用者的x。

<!-- 分页 -->

**GetTop：取栈顶**

GetTop和Pop只差一点：只看，不删，所以top不变。栈顶元素在第top−1格，直接读出来：

```c
int GetTop(SeqStack *S, int *x) {
    if (S->top == 0) return 0;            /* 栈空，没有栈顶 */
    *x = S->data[S->top - 1];             /* 栈顶在第top-1格 */
    return 1;
}
```

**把五个操作合起来**

五个函数都写好了。再写一个main，照着3.2节的例题，用顺序栈把1、2、3调成2、1、3：

```c
int main(void) {
    SeqStack S;
    int x;
    InitStack(&S);
    Push(&S, 1);
    Push(&S, 2);
    Pop(&S, &x);  printf("%d ", x);
    Pop(&S, &x);  printf("%d ", x);
    Push(&S, 3);
    Pop(&S, &x);  printf("%d\n", x);
    printf("栈空吗：%d\n", StackEmpty(&S));
    return 0;
}
```

main里的调用和3.2节例题一一对应，只是S前面多了&，因为函数要的是地址。存法是这一节才定的，调用的顺序一个都没变。

五个操作都只碰栈顶那一格和top，一个元素都不挪，时间复杂度都是O(1)。

完整的程序放在下面，可以直接复制运行：

```c
#include <stdio.h>

#define MAXSIZE 100

typedef struct {
    int data[MAXSIZE];
    int top;
} SeqStack;

void InitStack(SeqStack *S) {
    S->top = 0;
}

int StackEmpty(SeqStack *S) {
    return S->top == 0;
}

int Push(SeqStack *S, int x) {
    if (S->top == MAXSIZE) return 0;      /* 第一步：栈满，放不下 */
    S->data[S->top] = x;                  /* 第二步：x放进第top格 */
    S->top++;                             /* 第三步：top加1 */
    return 1;
}

int Pop(SeqStack *S, int *x) {
    if (S->top == 0) return 0;            /* 第一步：栈空，没有可删的 */
    S->top--;                             /* 第二步：top减1 */
    *x = S->data[S->top];                 /* 第三步：用x带回第top格 */
    return 1;
}

int GetTop(SeqStack *S, int *x) {
    if (S->top == 0) return 0;            /* 栈空，没有栈顶 */
    *x = S->data[S->top - 1];             /* 栈顶在第top-1格 */
    return 1;
}

int main(void) {
    SeqStack S;
    int x;
    InitStack(&S);
    Push(&S, 1);
    Push(&S, 2);
    Pop(&S, &x);  printf("%d ", x);
    Pop(&S, &x);  printf("%d ", x);
    Push(&S, 3);
    Pop(&S, &x);  printf("%d\n", x);
    printf("栈空吗：%d\n", StackEmpty(&S));
    return 0;
}
```

## 3.4 链栈

**栈顶放在哪一头**

3.3节用一段连续的格子存栈。栈也可以用2.9节的链表来存：每个元素一个结点，用地址连起来。

和顺序栈一样，先要定栈顶放在哪一头。还是存1、2、3，3是栈顶，有两种放法。

放法一：第一个结点是栈底，栈顶在表尾。

```
L = 100
  │
  ▼
┌───┬─────┐     ┌───┬─────┐     ┌───┬─────┐
│ 1 │ 109 │────►│ 2 │ 105 │────►│ 3 │  0  │
└───┴─────┘     └───┴─────┘     └───┴─────┘
    100             109             105
```

Pop要删掉3结点，就得把2结点的地址格改成0。可2结点在哪？链表只记着第一个结点的地址，只能从L出发一个一个走过去。栈里有n个元素，就要走n−1步。

放法二：第一个结点是栈顶。

```
S = 105
  │
  ▼
┌───┬─────┐     ┌───┬─────┐     ┌───┬─────┐
│ 3 │ 109 │────►│ 2 │ 100 │────►│ 1 │  0  │
└───┴─────┘     └───┴─────┘     └───┴─────┘
    105             109             100
```

Pop删的是第一个结点：把S改成3结点地址格里的109，一步就到。Push也只是在最前面接一个结点，一步都不用走。

这和2.16节量出的结论一样：链表在头部插入、删除是O(1)，在尾部是O(n)，正好和顺序表相反。所以链栈的栈顶放在表头，也和顺序栈正好相反。两种存法，都把栈顶放在自己最省事的那一头。

**链栈**

用链式存储的栈叫**链栈**。栈顶就是第一个结点，所以头指针就是栈顶指针，记作S。

结点和2.10节的一样，只是数据格放整数：

```c
typedef struct StackNode {
    int data;                  /* 数据格 */
    struct StackNode *next;    /* 地址格：下面一个结点的地址 */
} StackNode, *LinkStack;
```

StackNode是结点类型，LinkStack是指向结点的指针类型，和2.10节的Node、LinkList是一个意思。

链栈也竖着画，栈顶在上。左边是空栈，右边放了1、2、3：

<div class="figure-pair">
<LinkStackFigure />
<LinkStackFigure items="1 2 3" />
</div>

空栈的S是NULL。放了1、2、3之后，S是105，指着栈顶3结点；3结点的地址格指着2结点，2结点指着1结点；栈底1结点的地址格是0，表示下面没有了。

**不要头结点**。2.14节给链表加了头结点，是为了让第0个结点也有前一个结点，插入、删除不用分情形。链栈只在第0个结点进出：Push是插在第0个，Pop是删第0个，从来不用找前一个结点。头结点在这里没有用处，所以链栈不加。

由此马上得到两个操作。初始化就是让S为NULL；判空就是看S是不是NULL：

```c
void InitStack(LinkStack *S) {
    *S = NULL;
}

int StackEmpty(LinkStack *S) {
    return *S == NULL;
}
```

::: tip 为什么写*S
Push、Pop都要改S本身，让它指向另一个结点。所以调用时传的是S的地址，参数是`LinkStack *`，函数里用`*S`取到S。这和2.11节的`*L`一样。
:::

链栈没有"栈满"：只要还申请得到结点，就能Push。

**Push：放到栈顶**

栈里是1、2，S是109。现在Push(S, 3)。这和2.12节"在第0个位置插入结点"是同一件事。

**第一步：申请结点q，放3**。假设申请到的是105号：

```c
StackNode *q = (StackNode *)malloc(sizeof(StackNode));
q->data = 3;
```

q的地址格还没填，画成问号。申请不到时malloc返回NULL，Push就返回0。

**第二步：q指向原来的栈顶**。原栈顶2结点的地址109正记在S里，抄给q的地址格：

```c
q->next = *S;    /* q->next = 109 */
```

<LinkStackFigure items="1 2" ops="new:3 link" skip="2" />

**第三步：S指向q**。3结点成了新的栈顶：

```c
*S = q;          /* S = 105 */
```

<LinkStackFigure items="1 2" ops="new:3 link move" skip="3" />

**先连上，再改S，顺序不能反**。先改S，原栈顶的地址109就从S里丢了，q的地址格再也抄不到它，1、2两个结点就找不回来了。

写成函数。要放的是x；申请不到结点返回0，放好了返回1：

```c
int Push(LinkStack *S, int x) {
    StackNode *q = (StackNode *)malloc(sizeof(StackNode));  /* 第一步：申请结点放x */
    if (q == NULL) return 0;
    q->data = x;
    q->next = *S;                         /* 第二步：新结点指向原栈顶 */
    *S = q;                               /* 第三步：S指向新结点 */
    return 1;
}
```

栈是空的时候，S是NULL，第二步让q的地址格得到NULL，正好表示下面没有了。不用另写代码。

**Pop：删除栈顶，用x带回**

栈里是1、2、3，S是105。现在Pop(S, &x)。这和2.13节"删除第0个结点"是同一件事，只多了一步：用x带回删掉的值。

**第一步：判断栈空**。S是105，不是NULL，有东西可删。

**第二步：q记下栈顶结点，用x带回它的值**：

```c
StackNode *q = *S;   /* q = 105 */
*x = q->data;        /* x = 3 */
```

<LinkStackFigure items="1 2 3" ops="take" />

**第三步：S指向下一个结点**。3结点的地址格是109，抄给S，2结点成了栈顶：

```c
*S = q->next;        /* S = 109 */
```

<LinkStackFigure items="1 2 3" ops="take next" skip="2" />

**第四步：释放q**。3结点已经不在栈里了，还给系统：

```c
free(q);
```

<LinkStackFigure items="1 2 3" ops="take next free" skip="3" />

**先改S，再释放，顺序不能反**。先free(q)，3结点就还给了系统，再读q->next，读的是已经不归你的内存，读到什么说不准。这也是第二步要先用q记下栈顶的原因：S改走之后，只有q还找得到3结点。

写成函数。栈空返回0，删好了返回1：

```c
int Pop(LinkStack *S, int *x) {
    if (*S == NULL) return 0;             /* 第一步：栈空，没有可删的 */
    StackNode *q = *S;                    /* 第二步：记下栈顶结点，用x带回它的值 */
    *x = q->data;
    *S = q->next;                         /* 第三步：S指向下一个结点 */
    free(q);                              /* 第四步：还给系统 */
    return 1;
}
```

**GetTop：取栈顶**

栈顶就是S指着的结点。GetTop只读它的数据格，S不动，也不释放：

```c
int GetTop(LinkStack *S, int *x) {
    if (*S == NULL) return 0;             /* 栈空，没有栈顶 */
    *x = (*S)->data;                      /* 栈顶就是S指向的结点 */
    return 1;
}
```

`(*S)->data`的括号不能省：先用`*S`取到S，再用`->`读它指着的结点。

**把五个操作合起来**

五个函数都写好了，还要写main。先别动手，预测一下：3.3节的main要改多少？

3.3节的main只调用了五个操作，没有碰过data和top。链栈的五个操作，名字和用法都和顺序栈一样。所以预测：main只改一处，把`SeqStack`换成`LinkStack`。

```c
int main(void) {

    InitStack(&S);
    Push(&S, 1);
    Push(&S, 2);
    Pop(&S, &x);  printf("%d ", x);
    Pop(&S, &x);  printf("%d ", x);

```


和3.3节一模一样，预测成立。这就是3.2节的抽象数据类型带来的好处：main只依赖"能做什么"，"怎么存"可以整个换掉。

两种栈的五个操作都是O(1)。区别在空间上：顺序栈事先定好MAXSIZE，放满就不能再放；链栈要多少申请多少，但每个元素多占一个地址格，每次Push还要申请一次结点。

完整的程序放在下面，可以直接复制运行：

```c
#include <stdio.h>
#include <stdlib.h>

typedef struct StackNode {
    int data;
    struct StackNode *next;
} StackNode, *LinkStack;

void InitStack(LinkStack *S) {
    *S = NULL;
}

int StackEmpty(LinkStack *S) {
    return *S == NULL;
}

int Push(LinkStack *S, int x) {
    StackNode *q = (StackNode *)malloc(sizeof(StackNode));  /* 第一步：申请结点放x */
    if (q == NULL) return 0;
    q->data = x;
    q->next = *S;                         /* 第二步：新结点指向原栈顶 */
    *S = q;                               /* 第三步：S指向新结点 */
    return 1;
}

int Pop(LinkStack *S, int *x) {
    if (*S == NULL) return 0;             /* 第一步：栈空，没有可删的 */
    StackNode *q = *S;                    /* 第二步：记下栈顶结点，用x带回它的值 */
    *x = q->data;
    *S = q->next;                         /* 第三步：S指向下一个结点 */
    free(q);                              /* 第四步：还给系统 */
    return 1;
}

int GetTop(LinkStack *S, int *x) {
    if (*S == NULL) return 0;             /* 栈空，没有栈顶 */
    *x = (*S)->data;                      /* 栈顶就是S指向的结点 */
    return 1;
}

int main(void) {
    LinkStack S;
    int x;
    InitStack(&S);
    Push(&S, 1);
    Push(&S, 2);
    Pop(&S, &x);  printf("%d ", x);
    Pop(&S, &x);  printf("%d ", x);
    Push(&S, 3);
    Pop(&S, &x);  printf("%d\n", x);
    printf("栈空吗：%d\n", StackEmpty(&S));
    return 0;
}
```

## 3.5 栈的应用：括号匹配

**括号配对吗**

写程序时，括号总是成对出现：圆括号`()`、方括号`[]`、花括号`{}`。编辑器会把配成一对的括号标出来；少了一个、多了一个，编译器就报错。

比如这一行：

```
a [ ( b + c ) * d ]
  │ └───────┘     │
  └───────────────┘
```

圆括号配圆括号，方括号配方括号，里面的一对整个套在外面那一对里。这一行是配对的。

下面三行都不配对，错法各不相同：

- `(]`：类型对不上，圆括号碰上了方括号。
- `())`：右括号多了一个，最后那个`)`找不到左括号。
- `(()`：左括号多了一个，第一个`(`一直没等到右括号。

学完这一节，你能写出一个函数，读进一行字，判断里面的括号配不配对。

> **本节问题**：程序从左往右读一行字，怎么判断括号配不配对？

<!-- 分页 -->

**方法一：数个数**

先只看圆括号。读`(()())`，它配对吗？

一个直接的想法：数一数还有几个左括号没配上。读到左括号，个数加1；读到右括号，配掉一个，个数减1。把读完每个字符之后的个数，写在这个字符下面：

```
字符   (  (  )  (  )  )
个数   1  2  1  2  1  0
```

读完时个数是0，所有左括号都配上了，配对。

再看两个错例。先看`())`：

```
字符   (  )  )
个数   1  0  ?
```

读到第二个`)`时，个数已经是0，前面没有还没配上的左括号，这个`)`配不上。右括号多了，表现为**减之前个数已经是0**。

再看`(()`：

```
字符   (  (  )
个数   1  2  1
```

读完时个数是1，还有一个左括号没配上。左括号多了，表现为**读完时个数不是0**。

于是得到方法一：用一个数count，记还没配上的左括号有几个。

```text
count = 0
for s 里的每个字符 c:
    if c 是 '(':
        count = count + 1
    else if c 是 ')':
        if count == 0: return 不配对     // 右括号多了
        count = count - 1
return count == 0                       // 不是0，就是左括号多了
```

这是**伪代码**：有循环、if和return，结构和C一样，但条件用中文说，先不管C怎么写。

只有圆括号时，这个办法完全够用。

<!-- 分页 -->

**方法二：配给最近的那一个**

现在加上方括号。读`([)]`，照方法一，圆括号、方括号各数各的：

```
字符       (  [  )  ]
圆括号个数 1  1  0  0
方括号个数 0  1  1  0
```

两个数都没有在0的时候再减，读完也都是0。照方法一，这一行配对。可它不配对：`)`来的时候，`(`和它之间还夹着一个没配上的`[`。

问题出在哪？个数只说了"还有几个没配上"，没说"最近一个没配上的是哪种括号"。而`)`该配谁，恰恰要看这个。

那就看看，读到右括号时，它到底该配谁。读`a[(b+c)*d]`，把还没配上的左括号按读到的先后摞起来，后读到的放上面：

<StackFigure ops="push:[ push:( pop pop empty" labels="开始|读到 [~摞上去|读到 (~摞上去|读到 )~拿走 (，是一对|读到 ]~拿走 [，是一对|读完~什么都不剩，配对" />

读到`)`时，摞着的是`[`和`(`。`)`配的是`(`，也就是上面那个、最近读到的那个。配上就拿走。再读到`]`，最上面剩下`[`，正好配上。

括号一层套一层，里面的一对必须先合上，外面的才能合上。所以：

**右括号总是和最近一个还没配上的左括号配。**

最近的先配，就是后进先出。刚才那一摞，就是一个栈：还没配上的左括号入栈；读到右括号，出栈一个，看是不是一对。

写成伪代码：

```text
InitStack(S)
for s 里的每个字符 c:
    if c 是左括号:
        Push(S, c)                         // 等着配
    else if c 是右括号:
        if StackEmpty(S): return 不配对    // 右括号多了
        Pop(S, &left)                      // 最近一个没配上的左括号
        if left 和 c 不是一对: return 不配对   // 类型对不上
return StackEmpty(S)                       // 栈不空，就是左括号多了
```

和方法一对照着看：count加1换成了Push，count减1换成了Pop，`count == 0`换成了StackEmpty。方法一的count，其实就是栈的高度。只有一种括号时，栈里放的都一样，记住高度就够了；括号一多，就得记住每一层放的是什么。

**三种错，在哪一步发现**

再看开头的三行错例。每一种错，都对应伪代码里的一个return：

<StackFigure ops="push:( pop empty" skip="3" bare labels="()) 读到第二个 )~栈空，没有左括号可配" />

**类型对不上**，在读到右括号、出栈之后发现：`(]`里，`]`让`(`出栈，两个不是一对。对应`if left 和 c 不是一对`那一行。

**右括号多了**，在读到右括号、栈却是空的时候发现：`())`里，第一个`)`已经把`(`配掉了，第二个`)`来时栈里什么都没有。对应`if StackEmpty(S)`那一行。

**左括号多了**，要读完才发现：`(()`里，读到最后，栈里还剩一个`(`。读的过程中看不出来，因为后面也许还会有右括号。对应最后一行`return StackEmpty(S)`。

三种错各有一个return把守，一种都不会漏。

**写成函数**

照方法二的伪代码，一行一行写成C。

栈要放的是括号，也就是字符。3.3节的顺序栈放的是int，要把元素换成char：结构体里的`data`，Push、Pop、GetTop的参数`x`，一共四处，把int改成char。五个函数的写法一个字都不用动。

::: tip 只改一处：typedef
如果当初写`typedef int ElemType;`，所有放元素的地方都写`ElemType`，换类型时只要把这一行改成`typedef char ElemType;`。很多教材就这样写。
:::

先写一个小函数，判断两个括号是不是一对：

```c
int Pair(char left, char right) {
    return (left == '(' && right == ')') ||
           (left == '[' && right == ']') ||
           (left == '{' && right == '}');
}
```

再照伪代码写Match，每一行都对得上。"c 是左括号"写成三个比较，"left 和 c 不是一对"交给Pair。配对返回1，不配对返回0：

```c
int Match(char *s) {
    SeqStack S;
    char left;
    InitStack(&S);
    for (int i = 0; s[i] != '\0'; i++) {
        char c = s[i];
        if (c == '(' || c == '[' || c == '{') {
            if (!Push(&S, c)) return 0;           /* 左括号：入栈（栈满就当不配对） */
        } else if (c == ')' || c == ']' || c == '}') {
            if (!Pop(&S, &left)) return 0;        /* 栈空：右括号多了 */
            if (!Pair(left, c)) return 0;         /* 出栈的左括号和它不是一对 */
        }
    }
    return StackEmpty(&S);                        /* 读完栈空，才算配对 */
}
```

Match只调用了InitStack、Push、Pop、StackEmpty，没有碰过`data`和`top`。所以把顺序栈换成3.4节的链栈，Match也一个字都不用改。

用几行字试一试：

```c
int main(void) {
    char *tests[] = {"a[(b+c)*d]", "(]", "())", "(()", "{[()()]}", "([)]", ""};
    for (int i = 0; i < 7; i++)
        printf("\"%s\" %s\n", tests[i], Match(tests[i]) ? "配对" : "不配对");
    return 0;
}
```

运行结果：

```
"a[(b+c)*d]" 配对
"(]" 不配对
"())" 不配对
"(()" 不配对
"{[()()]}" 配对
"([)]" 不配对
"" 配对
```

没有括号的空串也算配对：栈从头到尾都是空的。

::: warning 栈会满
栈只有MAXSIZE个格子。左括号一口气套了100层以上，Push就放不下了，Match会把它当成不配对。真要处理这么深的嵌套，把MAXSIZE改大，或者换成链栈。
:::

完整的程序放在下面，可以直接复制运行：

```c
#include <stdio.h>

#define MAXSIZE 100

typedef struct {
    char data[MAXSIZE];
    int top;
} SeqStack;

void InitStack(SeqStack *S) {
    S->top = 0;
}

int StackEmpty(SeqStack *S) {
    return S->top == 0;
}

int Push(SeqStack *S, char x) {
    if (S->top == MAXSIZE) return 0;
    S->data[S->top] = x;
    S->top++;
    return 1;
}

int Pop(SeqStack *S, char *x) {
    if (S->top == 0) return 0;
    S->top--;
    *x = S->data[S->top];
    return 1;
}

int GetTop(SeqStack *S, char *x) {
    if (S->top == 0) return 0;
    *x = S->data[S->top - 1];
    return 1;
}

int Pair(char left, char right) {
    return (left == '(' && right == ')') ||
           (left == '[' && right == ']') ||
           (left == '{' && right == '}');
}

int Match(char *s) {
    SeqStack S;
    char left;
    InitStack(&S);
    for (int i = 0; s[i] != '\0'; i++) {
        char c = s[i];
        if (c == '(' || c == '[' || c == '{') {
            if (!Push(&S, c)) return 0;           /* 左括号：入栈（栈满就当不配对） */
        } else if (c == ')' || c == ']' || c == '}') {
            if (!Pop(&S, &left)) return 0;        /* 栈空：右括号多了 */
            if (!Pair(left, c)) return 0;         /* 出栈的左括号和它不是一对 */
        }
    }
    return StackEmpty(&S);                        /* 读完栈空，才算配对 */
}

int main(void) {
    char *tests[] = {"a[(b+c)*d]", "(]", "())", "(()", "{[()()]}", "([)]", ""};
    for (int i = 0; i < 7; i++)
        printf("\"%s\" %s\n", tests[i], Match(tests[i]) ? "配对" : "不配对");
    return 0;
}
```

## 3.6 栈的应用：中缀表达式转后缀表达式

**算一个式子**

计算器要算`3+4*2-1`。人一眼就看出先算乘法，再从左往右算加和减：

```
3 + 4 * 2 - 1
    \___/          第1步：4*2 = 8
\_______/          第2步：3+8 = 11
\___________/      第3步：11-1 = 10
```

可程序是从左往右一个字符一个字符读的。读到`3+4`，它能马上算出7吗？不能。后面还有一个`*`，它比`+`先算，4要先给`*`用。

读到`3+4*2`，能先算`4*2`吗？这回可以，可程序得先读到后面的`-`，才知道没有比`*`更先算的了。

再看`(3+4)*2`。这一回又得跳进括号里，先算`3+4`。

同样是加和乘，先算哪一步，要看后面还有什么运算符、有没有括号。**计算的顺序和书写的顺序不一样**，程序读到一半，不知道手上的数能不能先算。

学完这一节，你能把平常写的式子改写成一种程序好算的写法：先用手改，再写成函数让程序来改。

> **本节问题**：能不能换一种写法，让书写的顺序就是计算的顺序？

<!-- 分页 -->

**把运算符写在后面**

麻烦出在运算符夹在两个运算对象中间：读到运算符时，它右边的运算对象还没读到，后面会不会冒出更先算的运算符也不知道。

那就把运算符挪到它的两个运算对象**后面**。读到运算符时，它要用的两个运算对象都已经读过了，可以马上算。

拿`3+4*2-1`试一试。先算的是`4*2`，写成`4 2 *`。再算3加它，`+`跟在它的两个运算对象后面：一个是3，一个是`4 2 *`，写成`3 4 2 * +`。最后减1，`-`跟在`3 4 2 * +`和1的后面：

```
3 + 4 * 2 - 1   →   3 4 2 * + 1 -
```

再试`(3+4)*2`。先算的是`3+4`，写成`3 4 +`；再乘2，写成：

```
(3 + 4) * 2   →   3 4 + 2 *
```

括号不见了。括号原本是用来说"先算这里"的，现在谁先算，看运算符排在哪就知道了。

运算符写在两个运算对象后面的式子，叫**后缀表达式**。我们平常写的、运算符夹在中间的，叫**中缀表达式**。

后缀式这样读：从左往右，碰到一个运算符，就拿它前面最近的两个运算对象来算，算出的数替换掉它们。读`3 4 2 * + 1 -`：`*`前面最近的是4和2，得8，式子变成`3 8 + 1 -`；`+`算3和8，得11；`-`算11和1，得10。和`3+4*2-1`一样。

后缀式里没有优先级，也没有括号，**运算符出现的顺序，就是计算的顺序**。这就回答了本节问题。

程序真能这样从左往右读一遍就算出来吗？能，这要用到栈，留到3.7节。这一节先解决另一半：人写的是中缀式，怎么把它变成后缀式？

::: tip 后缀式也叫逆波兰式
后缀表达式又叫逆波兰表达式，因为把运算符写在前面的"前缀表达式"是波兰数学家卢卡西维茨提出的。一些老式计算器就是让人按后缀式输入的。
:::

<!-- 分页 -->

**加括号法**

写后缀式，其实只做一件事：给每个运算符找到它的两个运算对象。人找的时候，每找到一个，就用一对括号把运算符和它的两个运算对象圈起来。这个办法叫**加括号法**。

拿`3+4*2-1`来找。

先找最先算的`*`。它的两个运算对象是4和2，圈起来：`3+(4*2)-1`。

再找`+`。它左边是3，右边是刚圈好的`(4*2)`，圈起来：`(3+(4*2))-1`。

最后找`-`。它左边是整个`(3+(4*2))`，右边是1，圈起来：`((3+(4*2))-1)`。

现在每对括号里，正好是一个运算符和它的两个运算对象。照后缀式的规定，运算符写在两个运算对象后面，那就把每个运算符挪到它那对括号的右括号后面。一次挪一个：

```
((3 + (4 * 2)) - 1)
((3 + (4 2)*) - 1)      挪 *
((3 (4 2)*)+ - 1)       挪 +
((3 (4 2)*)+ 1)-        挪 -
```

括号的任务完成了，去掉，得`3 4 2 * + 1 -`。和前面写的一样。

把做过的事收拢成三步：

1. 按先乘除、后加减，一样高的从左往右，逐个给运算符找两个运算对象，加一对括号；
2. 把每个运算符挪到它那对括号的右括号后面；
3. 去掉所有括号。

再做`(3+4)*2`。原来的括号已经管住了`3+4`，再给乘法加一对，得`((3+4)*2)`；挪运算符，得`((3 4)+ 2)*`；去掉括号，得`3 4 + 2 *`。

验算一下：照后缀式的读法，`+`算3和4得7，`*`算7和2得14。`(3+4)*2`也是14。

加括号法好用，是因为人一眼能看见整个式子：先找到`*`，再回头处理`+`，最后才轮到`-`。程序不行。它从左往右一个字符一个字符读，读到`+`时，还不知道后面有没有`*`，括号没法一次加好。

<!-- 分页 -->

**运算符什么时候写出去**

程序要找的，也是每个运算符的两个运算对象，只是它只能从左往右读。

先看数字。`3+4*2-1`的数字是3、4、2、1，后缀式`3 4 2 * + 1 -`里还是3、4、2、1。**数字的顺序一点没变**，读到就能写出去。

难的是运算符：`+`在中缀式里是第一个，到了后缀式里却排在`*`后面。程序读到`+`的时候，它怎么知道`+`要往后挪、挪到哪？

一切从后缀式的规定出发：**运算符写在它的两个运算对象后面**。从左往右读`3+4*2-1`，每读到一个运算符，就问：它的两个运算对象齐了没有？

**读到3**：数字，写出去。

**读到`+`**：左边是3，右边还没读到。不能写，先放着。

**读到4**：写出去。那`+`的第二个运算对象是4吗？还不一定，要看4后面跟的是什么。

**读到`*`**：`*`和`/`比`+`和`-`先算，我们说它们的**优先级**高。4要先给`*`用，所以`+`的第二个运算对象不是4，而是`4*2`算出来的数。照规定，`+`要写在`4 2 *`后面，现在还不能写，接着等。

`*`自己呢？左边是4，右边还没读到，也不能写，也放着。

现在有两个运算符在等：先放下的`+`，后放下的`*`。将来谁先写出去？`*`。`+`要用`*`算出来的数，`*`不先写出去，`+`的运算对象就不齐。**后放下的先写出去**，又是后进先出，所以用一个栈放还没写出去的运算符：

<StackFigure ops="push:+ push:*" skip="1" labels="读到 3，写出去~读到 +，入栈~输出：3|读到 4，写出去~读到 *，比 + 高，入栈~输出：3 4" />

**读到2**：写出去。输出是`3 4 2`。

**读到`-`**：`*`在等它的右边。`*`比`-`高，2要先给`*`用，所以`*`的第二个运算对象就是2。`*`的两个运算对象4和2都齐了，弹出，写出去。

新的栈顶是`+`，它在等`4*2`。`+`和`-`一样高，一样高的从左往右算，`+`先算，所以`+`的第二个运算对象就是`4*2`，也齐了。弹出，写出去。

栈空了。`-`的左边是`3+4*2`整个算出来的数，右边还没读到，入栈等着。

<StackFigure ops="push:+ push:* pop pop push:- pop" skip="3" labels="读到 2，写出去~读到 -，* 比它高~弹出 *~输出：3 4 2 *|+ 和它一样高~弹出 +~输出：3 4 2 * +|栈空了~- 入栈~输出：3 4 2 * +|读到 1，写出去~读完了，弹出 -~输出：3 4 2 * + 1 -" />

**读到1**：写出去。**读完了**：后面再没有数，`-`的两个运算对象都齐了，弹出，写出去。

得到`3 4 2 * + 1 -`，和加括号法得到的一样。

注意读到`-`这一步：弹出一个还不够。弹完`*`，要拿新的栈顶`+`接着和`-`比，一直比到栈空，或者栈顶比新来的低为止。栈顶比新来的低，就一个也不弹，比如读到`*`时栈顶是`+`。一样高也要弹：要是`+`接着等，就成了`3 4 2 * 1 - +`，算的是`3+(8-1)`。在这个式子里碰巧也是10，换成`8-2-1`就不对了：`8 2 1 - -`算的是`8-(2-1) = 7`，应该是5。

把做过的事收拢成三条：

1. 读到数字：直接写出去。
2. 读到运算符：栈顶比它高或一样高，就弹出写出去，再看新的栈顶；直到栈空，或者栈顶比它低，再把它入栈。
3. 读完了：栈里剩下的依次弹出写出去。

第2条保证了：每个运算符入栈时，栈顶都比它低。所以栈里从下往上，优先级一个比一个高，栈顶永远是最该先写出去的那个。用栈是对的。

写成伪代码（"输出"就是写到后缀式的末尾）：

```text
InitStack(S)
for 中缀式里的每个字符 c:
    if c 是数字:
        输出 c
    else:                                       // c 是运算符
        while 栈不空 且 栈顶优先级 >= c 的优先级:
            Pop(S, &t); 输出 t                  // 栈顶的两个运算对象齐了，写出去
        Push(S, c)                              // c 放着，等它右边的数
while not StackEmpty(S):                        // 读完了，剩下的依次写出去
    Pop(S, &t); 输出 t
```

`while`也是循环：条件成立就一直做，不成立就停。和`for`不同，它事先不知道要做几次，读到`-`时弹了两次，读到`*`时一次也没弹。

和3.5节对照：括号匹配的栈里放的是"还没配上的左括号"，这里放的是"还没写出去的运算符"。

<!-- 分页 -->

**括号**

再加上括号。拿`(3+4)*2`看：括号里的`3+4`本身就是一个没有括号的小式子，前面的办法就能转，得`3 4 +`。整个式子是它的结果再乘2，写成`3 4 + 2 *`。所以括号不用新办法，只要让括号里的小式子单独转一遍。

**读到`(`**：一个小式子开始了。把`(`入栈，当一堵墙。墙上面就像一个新的空栈：括号里的运算符入栈前只和墙上面的比，碰到`(`就停，好像墙下面什么都没有。

**读到`)`**：小式子读完了。照前面第3条，读完了就把栈里剩下的依次弹出写出去，只是这回只弹到墙为止。再把`(`弹掉，它不写出去，后缀式里没有括号。

<StackFigure ops="push:( push:+ pop pop push:* pop" skip="1" labels="读到 (~入栈当墙|读到 3，写出去~读到 +，栈顶是 (，入栈~输出：3|读到 4，写出去~读到 )，弹出 +~输出：3 4 +|弹出 (，不写出去~输出：3 4 +|读到 *，栈空，入栈~输出：3 4 +|读到 2，写出去~读完了，弹出 *~输出：3 4 + 2 *" />

拿规定核对一下：`*`的左边是`(3+4)`整个，所以`*`之前，`+`必须已经写出去。读到`)`时弹出`+`，正好做到了。

读到`)`，找的是最近的那个`(`，就是3.5节括号匹配的做法。

把括号加进伪代码：

```text
InitStack(S)
for 中缀式里的每个字符 c:
    if c 是数字:
        输出 c
    else if c 是 '(':
        Push(S, c)                              // 小式子开始：当墙
    else if c 是 ')':
        while 栈顶不是 '(':
            Pop(S, &t); 输出 t                  // 小式子读完：弹到墙为止
        Pop(S, &t)                              // 弹出 '('，不输出
    else:                                       // c 是运算符
        while 栈不空 且 栈顶不是 '(' 且 栈顶优先级 >= c 的优先级:
            Pop(S, &t); 输出 t
        Push(S, c)
while not StackEmpty(S):
    Pop(S, &t); 输出 t
```

**写成函数**

栈里放的是`'+'`、`'('`这些字符。不用像3.5节那样把栈改成char：字符在C里就是一个小整数（`'+'`是43），int放得下，3.3节的顺序栈原样拿来用。

为了把力气花在栈上，约定每个数只有一位，也就是0到9。这样后缀式里不用空格分开，`342*+1-`就是`3 4 2 * + 1 -`。

先写优先级，数越大越先算：

```c
int Prec(int op) {
    if (op == '*' || op == '/') return 2;
    if (op == '+' || op == '-') return 1;
    return 0;                                     /* 不是运算符 */
}
```

再照伪代码写转换。后缀式写进数组`out`，`k`记着下一个字写在哪，最后补上`'\0'`：

```c
int ToPostfix(char *in, char *out) {
    SeqStack S;
    int t, k = 0;
    InitStack(&S);
    for (int i = 0; in[i] != '\0'; i++) {
        char c = in[i];
        if (c >= '0' && c <= '9') {
            out[k++] = c;                         /* 数字：直接输出 */
        } else if (c == '(') {
            if (!Push(&S, c)) return 0;           /* 左括号：入栈当墙 */
        } else if (c == ')') {
            while (GetTop(&S, &t) && t != '(') {  /* 弹到左括号为止 */
                Pop(&S, &t);
                out[k++] = t;
            }
            if (!Pop(&S, &t)) return 0;           /* 弹不到左括号：右括号多了 */
        } else if (Prec(c) > 0) {
            while (GetTop(&S, &t) && t != '(' && Prec(t) >= Prec(c)) {
                Pop(&S, &t);                      /* 栈顶一样高或更高：先写出去 */
                out[k++] = t;
            }
            if (!Push(&S, c)) return 0;           /* 自己入栈等着 */
        } else {
            return 0;                             /* 不认识的字符 */
        }
    }
    while (Pop(&S, &t)) {                         /* 读完了：剩下的依次写出去 */
        if (t == '(') return 0;                   /* 还剩左括号：左括号多了 */
        out[k++] = t;
    }
    out[k] = '\0';
    return 1;
}
```

伪代码里的"栈不空"和"栈顶"，用一个`GetTop`就都有了：栈空它返回0，`while`停下；不空就把栈顶放进`t`。

括号不配对，转换时就能发现，正是3.5节说的两种错：`)`弹不到`(`，是右括号多了；读完还剩`(`，是左括号多了。运算符多了、数字多了，转换发现不了，要等3.7节求值时才查得出来。

> **到这里你有了**：后缀表达式：运算符写在两个运算对象后面，没有优先级和括号，书写的顺序就是计算的顺序。中缀转后缀，就是给每个运算符找它的两个运算对象：人能看见整个式子，用加括号法；程序从左往右读，运算符先放进栈里等，新运算符来时，把栈顶优先级一样高或更高的依次弹出写出去；括号里是一个小式子，`(`入栈当墙，`)`就是小式子读完了，弹到`(`为止。

## 3.7 栈的应用：后缀表达式求值

**读到哪算到哪**

3.6节说过，后缀式的书写顺序就是计算顺序，人从左往右就能读出它的值。现在让程序来算。

学完这一节，你能写出一个函数，读进一个后缀式，算出它的值。接上3.6节的ToPostfix，就是一个计算器。

> **本节问题**：程序怎么从左往右读一遍后缀式，就算出它的值？

从左往右读`3 4 2 * +`，看看程序怎么算。

读到3、4、2，都是数，先放着。读到`*`，它要用哪两个数？是4和2，最后放下的那两个。算出8，放回去，等着后面用。读到`+`，要用的是3和8，又是最后放下的那两个。算出11。

每个运算符要用的，总是**最近放下的两个数**。最近的先用，就是后进先出。所以用一个栈放数：

<StackFigure ops="push:3 push:4 push:2 calc:* calc:+" labels="开始|读到 3~入栈|读到 4~入栈|读到 2~入栈|读到 *~弹出 2、4，算出 8 入栈|读到 +~弹出 8、3，算出 11 入栈" />

读完了，栈里只剩一个数11，它就是结果。

写成伪代码：

```text
InitStack(S)
for 后缀式里的每个字符 c:
    if c 是数字:
        Push(S, c 代表的数)
    else:                          // c 是运算符
        Pop(S, &b)                 // 先弹出的是右边的数
        Pop(S, &a)                 // 再弹出左边的数
        Push(S, a c b)             // 算好放回去
Pop(S, &result)
return result
```

和3.5节对照：括号匹配的栈里放的是"还没配上的左括号"，这里放的是"还没用上的数"。都是先放着，等后面的东西来取最近的那一个。3.6节转换时，栈里放的是"还没写出去的运算符"。

**先弹出的是右边的数**

加法和乘法，两个数谁在左谁在右都一样。减法和除法不一样。算`8 2 -`：

<StackFigure ops="push:8 push:2 calc:-" skip="2" bare labels="读完 8、2~2 在栈顶|读到 -~先弹出 2，再弹出 8，8 - 2 = 6" />

8先入栈，2后入栈，2在栈顶。先弹出来的是2，它是减号**右边**的数；后弹出来的8是左边的数。所以是`8 - 2 = 6`，不是`2 - 8`。伪代码里先`Pop(S, &b)`、再`Pop(S, &a)`，算的是`a c b`，就是这个原因。

再看式子写错的两种情况。

**运算符多了**，比如`3 +`：读到`+`时栈里只有一个3，第二次Pop弹不出来。

**数字多了**，比如`3 4`：读完了，栈里还剩两个数，没有运算符把它们合起来，不知道哪个是结果。

把这两处检查加进伪代码：

```text
InitStack(S)
for 后缀式里的每个字符 c:
    if c 是数字:
        Push(S, c 代表的数)
    else:
        if 弹不出 b 或弹不出 a: return 写错了   // 运算符多了
        Push(S, a c b)
Pop(S, &result)
if not StackEmpty(S): return 写错了           // 数字多了
return result
```

**写成函数**

照伪代码写成C。栈里放的是数，3.3节的顺序栈原样拿来用，元素就是int。

照3.6节的约定，每个数只有一位，也就是0到9。字符`'7'`和整数7不一样，`c - '0'`把数字字符变成它代表的数：字符`'0'`到`'9'`在编码里是连着的，`'7' - '0'`正好是7。除法用C的整数除法，`9 / 2`得4。

式子写错了，函数要能说出来，所以结果用参数带回，返回值说算没算成，和3.2节的Pop一个道理：

```c
int Eval(char *s, int *result) {
    SeqStack S;
    int a, b;
    InitStack(&S);
    for (int i = 0; s[i] != '\0'; i++) {
        char c = s[i];
        if (c >= '0' && c <= '9') {
            if (!Push(&S, c - '0')) return 0;     /* 数字：入栈 */
        } else {
            if (!Pop(&S, &b)) return 0;           /* 先弹出的是右边的数 */
            if (!Pop(&S, &a)) return 0;           /* 再弹出左边的数；弹不出就是运算符多了 */

            if (c == '+')      v = a + b;
            else if (c == '-') v = a - b;
            else if (c == '*') v = a * b;
            else if (c == '/' && b != 0) v = a / b;
            else return 0;                        /* 除以0，或者不认识的字符 */
            Push(&S, v);                          /* 算出的数放回去 */
        }
    }
    if (!Pop(&S, result)) return 0;               /* 空串：没有结果 */
    return StackEmpty(&S);                        /* 还剩数，就是数字多了 */
}
```

```c
                out[k++] = t;
            }
            if (!Push(&S, c)) return 0;           /* 自己入栈等着 */
        } else {
            return 0;                             /* 不认识的字符 */
        }
    }
    while (Pop(&S, &t)) {                         /* 读完了：剩下的依次写出去 */
        if (t == '(') return 0;                   /* 还剩左括号：左括号多了 */
        out[k++] = t;
    }
    out[k] = '\0';
    return 1;
}

int main(void) {
    char *tests[] = {"3+4*2-1", "(3+4)*2", "8-2-1", "9/(1+2)", "2*(3+4)-5", "(3+4", "3+4)", "3++4"};
    char post[MAXSIZE];
    int v;
    for (int i = 0; i < 8; i++) {
        if (!ToPostfix(tests[i], post))  printf("%-10s 括号不配对\n", tests[i]);
        else if (!Eval(post, &v))        printf("%-10s → %-8s 写错了\n", tests[i], post);
        else                             printf("%-10s → %-8s = %d\n", tests[i], post, v);
    }
    return 0;
}
```

## 3.8 递归

**求阶乘**

从1一直乘到n，得到的数叫n的**阶乘**，记作n!。比如：

```
4! = 4 × 3 × 2 × 1 = 24
```

换个看法。把后面三个数括起来：

```
4! = 4 × (3 × 2 × 1)
   = 4 × 3!
```

括号里正好是3!。要算4!，先算出3!，再乘4。

4!里藏着一个3!。3!里又藏着2!：3! = 3 × 2!。一直拆到1! = 1，不用再拆。

一个问题，用小一号的同一个问题来解决，这种做法叫**递归**。

学完这一节，你能看懂、写出简单的递归函数，并能一步一步跟出它是怎么算出结果的。

先记住两个问题，这一节会回答：

> **本节问题**：用递归算4!，"同样的问题"一共要算几次？最先得出答案的是哪一个？

<!-- 分页 -->

**什么是递归**

上一页的拆法写成式子，就是两行：

```
n! = n × (n-1)!     当 n 大于 1
1! = 1
```

第一行用小一号的(n-1)!来算n!。第二行说，到1就停。

一个问题，用规模更小的同一个问题来解决，直到小到能直接给出答案，这就是**递归**。

这个定义有两个要点，逐条看。

**规模变小**：拆出来的问题，要比原来的小。n!拆出(n-1)!，4拆成3，再拆成2，越来越接近1。

```
n! = n × (n-1)!     4 → 3 → 2 → 1，越来越小
n! = n × n!         4 → 4 → 4 → …，一直在原地
```

规模不变，就要一遍遍算同一个问题，永远算不完。

**有出口**：小到一定程度，要能直接给出答案，不再往下拆。这个地方叫递归的**出口**。n!的出口是1! = 1。

```
有出口：   4! → 3! → 2! → 1! = 1，停
没有出口： 4! → 3! → 2! → 1! → 0! → (-1)! → …
```

没有出口，就会一直拆下去，停不下来。

两个要点缺一不可：规模变小，才能走到出口；有了出口，走到了才能停。

<!-- 分页 -->

**写成函数**

C语言里，一个函数可以调用它自己。照着上一页的两行式子，就能写出算阶乘的函数：

```c
int Fact(int n) {
    if (n == 1) return 1;          /* 出口：1! = 1 */
    return n * Fact(n - 1);        /* 规模变小：n! = n × (n-1)! */
}
```

两行代码对着两行式子。

`if (n == 1) return 1;`就是1! = 1，是出口。

`return n * Fact(n - 1);`就是n! = n × (n-1)!。Fact在自己的函数体里调用了自己，参数从n变成n-1，规模变小。

调用自己的函数，叫**递归函数**。

试一试：

```c
int main(void) {
    for (int n = 1; n <= 5; n++)
        printf("%d! = %d\n", n, Fact(n));
    return 0;
}
```

运行结果：

```
1! = 1
2! = 2
3! = 6
4! = 24
5! = 120
```

算阶乘，用循环也可以：

```c
int f = 1;
for (int i = 2; i <= n; i++) f = f * i;
```

两种写法都对。递归的好处是照着定义直接写：式子是什么样，代码就是什么样，不用另想"从几乘到几"。有的问题用递归说得很自然，用循环反而难写，第5章的树就是这样。

::: tip int 只装得下 12!
13!是6227020800，超过了int能表示的最大值，大约21亿。算出来会是一个错的数。
:::

**递和归**

跟着Fact(4)走一遍，看它是怎么算出24的。

Fact(4)要算4 × Fact(3)。Fact(3)还没有结果，Fact(4)只能停在这里等。

Fact(3)要算3 × Fact(2)，也停下来等。

Fact(2)要算2 × Fact(1)，也停下来等。

Fact(1)碰到出口，直接得出1。

这一路往下调用，叫**递**：

```
Fact(4) = 4 × Fact(3)                      等着
          Fact(3) = 3 × Fact(2)            等着
                    Fact(2) = 2 × Fact(1)  等着
                              Fact(1) = 1  出口
```

Fact(1)返回1。Fact(2)终于能算了：2 × 1 = 2，返回2。

Fact(3)接着算：3 × 2 = 6，返回6。

Fact(4)最后算：4 × 6 = 24，返回24。

这一路带着结果往回走，叫**归**：

```
                              Fact(1) = 1
                    Fact(2) = 2 × 1 = 2
          Fact(3) = 3 × 2 = 6
Fact(4) = 4 × 6 = 24
```

验算一下：4! = 4 × 3 × 2 × 1 = 24，对上了。Fact(3)也一样：递到Fact(1)，再归回来，依次得出1、2、6。

回到开头的两个问题。

同样的问题一共算了4次：Fact(4)、Fact(3)、Fact(2)、Fact(1)，就是4!、3!、2!、1!各算一次。

最先得出答案的是Fact(1)，也就是1!。它是出口，不用等别人。

让程序自己报告一下。在Fact里加两句打印：

```c
int Fact(int n) {
    printf("进入 Fact(%d)\n", n);
    if (n == 1) {
        printf("Fact(1) 返回 1\n");
        return 1;
    }
    int r = n * Fact(n - 1);
    printf("Fact(%d) 返回 %d\n", n, r);
    return r;
}
```

`printf("结果：%d\n", Fact(4));`的运行结果：

```
进入 Fact(4)
进入 Fact(3)
进入 Fact(2)
进入 Fact(1)
Fact(1) 返回 1
Fact(2) 返回 2
Fact(3) 返回 6
Fact(4) 返回 24
结果：24
```

看进入和返回的顺序：最后进入的Fact(1)最先返回，最先进入的Fact(4)最后返回。

**练习1：哪个能算出 4! ？**

::: quiz 单选
`int Fact(int n) { … }`的函数体写成哪一个，`Fact(4)`能正确得出24？

- [x] `if (n == 1) return 1; return n * Fact(n - 1);`
  出口是1! = 1，每次规模减1，两个要点都有。
- [ ] `return n * Fact(n - 1);`
  没有出口：会一直调用Fact(0)、Fact(-1)……停不下来。
- [ ] `if (n == 1) return 1; return n * Fact(n);`
  规模没有变小：Fact(4)又调用Fact(4)，一直在原地。
- [ ] `if (n == 0) return 0; return n * Fact(n - 1);`
  出口给错了答案：一路乘到最后乘上0，结果是0。

递归要同时有两样：规模变小，和一个给对答案的出口。
