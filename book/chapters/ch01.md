# 第1章 绪论

## 1.1 这门课解决什么问题，要学什么

> **本节问题**：数据结构这门课到底在研究什么？学完应该会什么？

数据结构这门课回答一个问题：程序里的数据该怎么组织，才能让管理和操作它更高效。

这个问题没有统一答案，因为数据不同、要做的事不同。一个单行编辑器里的字符排成一列，用户要在中间插入、删除；手机的拦截名单只需判断一个号码在不在；文件系统里的文件夹层层嵌套；地图上的路口四通八达。组织方式跟着数据的关系和要做的操作走：字符要排成序列，名单只要能快速查有没有，文件夹要能层层展开，路口要能找出一条路来。

所以这门课真正教的是一套分析方法，四步：

1. 看数据之间是什么关系（1.2）；
2. 定要对数据做哪些操作，关系加操作合起来叫抽象数据类型（1.3）；
3. 决定怎么放进内存（1.4）；
4. 用一把统一的尺子量效率，看这个选择对不对（1.5）。

每一种具体的结构——顺序表、链表、树、散列表——都是这套方法在某类问题上的答案。学会的是方法，具体的结构就不必背，遇到新问题也能自己推出来。

本书的取舍也由此而来。不把所有结构罗列一遍，每种结构只在一个真实问题需要它的时候出场；不把重点放在语言细节上，代码是把分析落地的工具；每一章围绕一个任务，读者要亲手把它做出来。第2章就从上面那个单行编辑器开始。

> **到这里你有了**：这门课的问题和四步方法，后面四节逐一展开。
> **练一练**：（1）想一个你每天用的软件（微信、日历、音乐播放器），它处理的数据是什么？你对这些数据做的最常见的三个操作是什么？（2）同样是"一堆联系人"，通讯录和拦截名单要做的操作有什么不同？这会不会影响它们该怎么存？

## 1.2 数据之间有哪几种关系

> **本节问题**：数据之间的关系五花八门，能不能归成几种基本形态？

看几个例子，只看数据之间是什么关系，暂时不管要对它们做什么。

**线性关系。** 单行编辑器里的一行文字，每个字符前面最多一个字符、后面最多一个字符，排成一列。顺序不能乱，`ab`和`ba`不一样；字符可以重复。这种一对一的前后关系叫线性关系，也叫序列：

```
┌───┐   ┌───┐   ┌───┐   ┌───┐
│ I │──►│ ␣ │──►│ l │──►│ o │──► …
└───┘   └───┘   └───┘   └───┘
```

**树形关系。** 电脑里的文件夹，文件夹下有文件和二级文件夹，二级文件夹下面可以继续包含文件和文件夹。一个文件夹可以有很多下级，但每个文件或文件夹只有一个上级，从最顶层到任何一个文件的路径是唯一的。这种一对多的层级关系叫树形关系：

```
          ┌───────┐
          │ 文档   │
          └───┬───┘
       ┌──────┼──────┐
   ┌───┴───┐ ┌┴────┐ ┌┴──────┐
   │ 工作   │ │论文 │ │ 照片   │
   └───┬───┘ └─────┘ └───┬───┘
    ┌──┴──┐            ┌─┴─┐
   ┌┴──┐ ┌┴──┐        ┌┴─┐┌┴─┐
   │周报│ │合同│        │春││夏│
   └───┘ └───┘        └──┘└──┘
```

**图关系。** 地图上的路口和地点通过一条条路段相互连接。一个路口可以通向多个方向，两个地点之间往往有多条走法，绕一圈还能回到原点。这种多对多、可以成环的关系叫图关系：

```
    ┌───┐        ┌───┐
    │ 家 │────────│ 超市│
    └─┬─┘        └─┬─┘
      │    ╲       │
      │     ╲      │
    ┌─┴─┐    ╲   ┌─┴─┐
    │学校│──────╲─│公司│
    └───┘        └───┘
```

它和树的本质区别是：树中任意结点只有一个上级、到它的路径唯一、不能成环；图中任意两个元素都可以有关联，而且可以绕回来。

**集合关系。** 我们在初高中数学里学过集合：一个元素要么属于某个集合，要么不属于；元素没有先后之分，{1, 2, 3}和{3, 1, 2}是同一个集合；也不会出现重复的元素。也就是说，集合里的元素之间除了"同属一个集合"外没有任何别的联系，这是最松散的一种关系。手机的骚扰电话拦截名单就是这样：名单里的号码谁先谁后、排在第几，都无关紧要，它们之间唯一的联系是"都在这份名单里"。

```
   ╭──────────────────────╮
   │  138…   150…         │
   │        186…    139…  │
   │  177…        155…    │
   ╰──────────────────────╯
```

不同的是，数学里的集合往往给定不变，程序里的集合会不断有元素加入或移出。

四种关系放在一起看是递进的：集合"只归属、无关联"，线性"一对一"，树"一对多"，图"多对多"。程序里的数据关系再复杂，也能归到这四种之一，或者由它们组合而成。

> **到这里你有了**：四种基本的逻辑关系，以及各自的典型例子。
> **练一练**：（1）下面几样东西各是哪种关系：一本书的目录、一个班的学生名单、地铁线路图、浏览器的历史记录、公司的组织架构？（2）"朋友关系"是树还是图？"上下级关系"呢？说出判断依据。（3）给每种关系再各举一个生活里的例子，并画出示意图。

## 1.3 关系加操作：抽象数据类型

> **本节问题**：知道了数据之间的关系，就知道怎么组织它了吗？还缺什么？

回到1.2的四个例子，这次看要对它们做什么。

编辑器里的一行文字，用户要在中间插入字符、删除字符、读出来显示。文件夹要新增、删除、读取、修改，还要一层层打开。地图要查"从家到公司怎么走"、"附近有哪些加油站"、某条路封了要改道。拦截名单要加入号码、移除号码、来电时判断这个号码在不在。

每个例子都是"一种关系"加"一组要做的事"。文件管理的问题可以描述为树形模型加一组操作，导航问题是图模型加一组操作，拦截名单是集合模型加一组操作。这一组要做的事叫**操作集**，逻辑关系加上操作集，就是描述一个数据模型所需的全部——这样一份描述叫**抽象数据类型**（Abstract Data Type，ADT）：

> 抽象数据类型 = 逻辑关系 + 操作集

它只说数据是什么关系、能做什么，不说怎么存、怎么做。"抽象"就是这个意思。

**同一种关系，不同的操作集，就是不同的抽象数据类型。** 光有关系不够，看线性关系：编辑器要在任意位置插入删除；浏览器的"后退"只需记住最近打开的页面、最后打开的最先退回，只在一端进出；打印机处理任务是先提交的先打印，一端进、另一端出。三者的元素之间都是一对一的前后关系，要做的事完全不同，于是是三个不同的ADT：任意位置插入删除的叫线性表，只在一端进出的叫栈，一端进另一端出的叫队列。集合关系也一样：拦截名单只要增、删、判断是否存在，是集合；通讯录要按姓名查号码，元素是"姓名→号码"的对子，是字典；社交软件判断两个人是否在同一个朋友圈、把两个圈子合并，是并查集。树形关系同样如此：文件夹管理关注遍历和增删结点，而按学号快速查找学生所用的二叉搜索树，关注的是按键查找。

有人可能会问：既然关系只有四种，为什么不在每种关系上把可能用到的操作全放进一个操作集，一种关系只定义一个ADT，岂不是更省事？

逻辑上这样定义并没有错，但有两个问题。

第一，从使用的角度，操作集越精简，含义越清楚。栈只允许在一端进出，不是因为做不到别的，而是这个约束本身在传递信息：看到"栈"，使用者立刻知道它处理的是"后进先出"的问题，也不会在中间随意插入元素而破坏这个性质。把所有操作都开放出来，这层含义就没有了。

第二，从实现的角度，回到这门课要解决的问题——"让管理和操作数据的效率更高"，关键词是效率。ADT最终要映射到计算机的存储上去实现，而几乎不存在一种存储方式能让所有操作都高效：让一部分操作快，往往要以另一部分操作慢为代价。操作集小而明确，才能针对它挑选最合适的存储方式。

那么，ADT是怎么映射到存储上的？效率又怎么量？这是接下来两节的事。

> **到这里你有了**：抽象数据类型的定义，以及"操作集决定ADT"这个判断。
> **练一练**：（1）撤销功能（Ctrl+Z）需要的操作集是什么？它和线性表、栈、队列哪个最接近？（2）"待办清单"通常需要哪些操作？如果加一条"按截止时间取最紧急的一项"，操作集变了，它还是同一个ADT吗？（3）给1.2练一练里你自己举的四个例子各列一个操作集。

## 1.4 关系怎么放进内存

> **本节问题**：内存只是一排格子，四种关系怎么放进去？

计算机的内存可以看成一长排编了号的格子，每个格子放一个字节，编号叫地址。这排格子只有一种天然的关系：前后相邻，100号后面是101号，仅此而已。内存本身是一维的、线性的。

数据本身放进格子没有困难，问题是关系放在哪。线性关系里"a在c后面"、树形关系里"b是a的孩子"、图关系里"a和b之间有条路"——这些信息不是数据本身，它们该存在什么地方？

办法只有两种。

一种是**用位置表示关系**：约定相邻格子放相邻元素，"a在c后面"就是把a放在c的下一格。关系不占任何空间，它藏在位置里。代价是位置一旦定了就不能随便动——中间要插一个元素，后面的都得挪。这叫顺序存储。

另一种是**用地址表示关系**：每个元素旁边多留几个格子，记下与它有关系的元素的地址。"a在c后面"就是在c旁边写下a的地址。元素可以散落在内存任何地方，插入删除只改几个地址，不挪动别人。代价是关系要占空间，而且要找第i个元素只能顺着地址一站一站走。这叫链式存储。

两种办法各有一头快、一头慢，没有哪一种全面占优。第2章会用一个真实的任务把两种存法都做一遍，把这句话变成具体的数字。

其他存储方式，比如索引存储、散列存储，本质上都是这两种手段的组合或变形，后面用到时再介绍。四种逻辑关系也都能用这两种手段装进一维的内存：线性关系对应数组和链表；树形关系每个结点记下孩子的地址；图关系用一张二维表记录任意两点之间有没有边，或者给每个顶点挂一条链；集合关系没有关系要记，关键是"判断在不在"要快，通常用散列表。这些都是后面各章的内容。

> **到这里你有了**："关系存在哪里"这个问题的两个答案，以及它们各自的代价。
> **练一练**：（1）一列火车的车厢是顺序存储还是链式存储？在中间加挂一节车厢，要动几节？（2）教室里的座位表按行列排，是哪种存储？如果每个学生手里拿着"下一个同学是谁"的纸条，又是哪种？（3）为什么链式存储"要找第i个元素只能一站一站走"？

## 1.5 效率怎么量

> **本节问题**：说一种存法"快"、另一种"慢"，用什么量？

最直接的想法是把程序跑一遍，看用了几秒。但同一段程序换台电脑时间就变了，换种语言也变了。秒衡量的是机器和语言，不是方法本身。要比较方法，需要一把和机器无关的尺子。

办法是不看时间，看步数：一次赋值、一次比较、读写一个格子，各算一步。步数只取决于方法和数据的规模，换台机器、换种语言都一样。

但真正关心的也不是具体几步，而是**步数随着数据规模n增长，增长得有多快**。数据结构要处理的是几万、几百万个元素，n很小时谁快谁慢无所谓，n很大时才拉开差距。所以常数和零头都可以抹掉：不管是2步还是30步，只要不随n变化，就记作**O(1)**，读"常数阶"；不管是n步、2n步还是2n+3步，只要和n成正比，就记作**O(n)**，读"线性阶"。这种只看趋势的写法叫大O记号，它写出来的量级叫渐进时间复杂度。第2章量线性表的每个操作时，会把这个方法用一遍。

除了O(1)和O(n)，后面还会经常遇到几种量级。表里的数字是n取不同值时步数的大致规模：

| 量级 | 读法 | n=10 | n=1000 | n=1000000 |
|---|---|---|---|---|
| O(1) | 常数阶 | 1 | 1 | 1 |
| O(log n) | 对数阶 | 3 | 10 | 20 |
| O(n) | 线性阶 | 10 | 1000 | 1000000 |
| O(n log n) | 线性对数阶 | 30 | 10000 | 20000000 |
| O(n²) | 平方阶 | 100 | 1000000 | 10¹² |

注意O(log n)这一行：n从10增长到一百万，增长了十万倍，步数只从3增长到20。把一个O(n)的操作改造成O(log n)，在大数据量下就是几万倍的提速——后面会看到，树这种结构之所以重要，很大程度上就是因为它能做到这一点。再看O(n²)：n为一百万时步数是一万亿，普通电脑要跑很久。一个O(n²)的算法在小规模测试时感觉不到问题，数据量上去后就无法忍受。这也是为什么不能只靠"跑一下看看"来判断好坏。

空间同样可以用大O衡量，叫空间复杂度。链式存储每个元素多占几个格子记地址，n个元素就多占O(n)的空间。时间和空间之间也常常要做取舍。

> **到这里你有了**：量效率的尺子——步数随n增长的量级，以及常见的几个量级。
> **练一练**：（1）从一叠打乱的试卷里找某个人的那份，最坏要翻多少张？是O(1)还是O(n)？如果试卷已按学号排好呢？（2）把n个人两两握手，一共握多少次？量级是什么？（3）查字典为什么不用从第一页翻起？这对应表里哪一行？

## 1.6 怎么学这门课，以及本书的组织

> **本节问题**：这些方法怎么学才学得会？

数据结构不是看会的。读懂一段链表代码和自己写出一个链表之间，隔着所有的坑：指针改错顺序、边界漏掉一个、内存忘了释放。这些坑只有亲手踩过才记得住。Andrej Karpathy——特斯拉前AI负责人、OpenAI创始成员——教神经网络时的做法是从零把一个最小的版本做出来，在做的过程中理解每一个部件为什么在那里。本书用同样的方式教数据结构。

具体到每一章：围绕一个真实任务展开，比如第2章的单行编辑器。每一节提出一个具体的问题，先分析、再引入需要的概念、然后动手解决、最后运行验证。每节结尾有三样东西：这一节你做出了什么，几道先预测再运行的变式题，以及下一节要解决的问题。读完一章，任务就做出来了，而途中引入的每一种结构、每一个概念，都是因为任务需要它。

**四层框架。** 1.1到1.5说的四步，就是全书的骨架：

> 逻辑结构 → 抽象数据类型 → 存储结构 → 算法

逻辑结构描述数据之间的关系，抽象数据类型在关系上加操作集，存储结构把ADT映射到内存，算法在存储结构上实现操作并用复杂度衡量。后面每一章都在回答同一个问题：某种逻辑关系上的某个抽象数据类型，用什么存储结构实现，效率如何。

**本书的组织。**

| 章 | 任务 | 逻辑关系 | 抽象数据类型 | 存储结构 | 效率上的主要问题 |
|---|---|---|---|---|---|
| 2 线性表 | 单行编辑器 | 线性 | 线性表 | 数组、单链表、双向链表 | 插入删除与按位置存取的取舍；接口怎么影响效率 |
| 3 栈和队列 | | 线性 | 栈、队列 | 数组、链表 | 限制操作集后两种存储都能做到O(1) |
| 4 树 | | 树形 | 树、二叉树 | 孩子指针、数组 | 层级关系的表示与遍历 |
| 5 集合与查找 | | 集合 | 集合、字典 | 有序数组→二叉搜索树→平衡树→散列表 | 查找从O(n)到O(log n)到O(1) |
| 6 优先队列 | | 集合 | 优先队列 | 堆 | 反复取最值的代价 |
| 7 图 | | 图 | 图 | 邻接矩阵、邻接表 | 遍历、最短路径、最小生成树 |
| 8 排序 | | 线性 | — | 数组为主 | 用前面的结构改进算法 |

第2、3章讲线性关系。线性表是最基本的ADT，两种存储方式的取舍在这里第一次完整呈现；栈和队列展示限制操作集之后实现可以变得多简单。第4章讲树形关系，除了表示层级数据，树更重要的用途是把查找加速。第5、6章回到集合关系："判断元素在不在"这一个操作，实现方式从有序数组的二分查找到二叉搜索树、平衡树、散列表，效率从O(n)逐步压到O(log n)和O(1)，这是全书最能体现"操作集决定存储选择"的部分；优先队列是集合关系上另一个操作集不同的ADT。第7章讲图，最一般的关系。第8章讲排序，不是新的关系，而是把前面学过的结构用起来。

全书读完，回头看1.1提出的问题——数据该怎么组织才高效——答案就是这张表：先弄清数据之间的关系，再根据需要的操作定义ADT，然后在顺序和链式两种基本手段中选择或组合出存储结构，最后用复杂度分析验证这个选择是否达到了目的。
