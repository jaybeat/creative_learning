# 第2章 线性表

## 2.1 线性表

**单行编辑器里的一行字**

这一章要做一个单行编辑器。它只管一行文字。

下面是用户依次敲入c、a、t时屏幕的变化。每一行是敲完一个字符之后的屏幕，`|`是光标：

```
|
c|
ca|
cat|
```

> **本节问题**：每敲一个字符，程序都要把整行重新显示出来，所以它得一直记着这一行字。这一行字是什么样的数据？

<!-- 分页 -->

**什么是线性表**

这一行字可以看成一个**线性表**。

把字符换成任意一种元素，n个同类型的元素排成一列，就是线性表。n叫表的**长度**。元素的位置从0开始编号：第0个元素记作a₀，第1个记作a₁，最后一个是第n−1个，记作aₙ₋₁。整个表写成(a₀, a₁, …, aₙ₋₁)。

屏幕上的`cat`看成线性表，就是(c, a, t)。它的长度是3，第0个元素a₀是c，a₁是a，a₂是t。

这个定义里有四个要点，逐条看。

**同类型**。表里的元素都是同一种东西。`cat`里的c、a、t都是字符，这一行里不会混进一个整数，也不会混进一张图片。所以程序只需要准备一种格子，专门放字符。

**一个接一个**。元素之间有先后，而且是一个接一个。一个元素前面紧挨着的那个元素，叫它的**前驱**；后面紧挨着的那个元素，叫它的**后继**。一个接一个的意思是：除了第一个，每个元素恰好有一个前驱；除了最后一个，每个元素恰好有一个后继。在(c, a, t)里，a的前驱是c，后继是t；c没有前驱，t没有后继。

程序为什么要在乎先后？因为`cat`和`act`是两行不同的字。程序如果只记住"有c、a、t三个字符"，就打印不出这一行。它还得记住谁在谁前面。

教材里常说线性表是"有序"的。这个"有序"指的是位置有先后，不是按大小排好了序。(c, a, t)没有按字母顺序排，照样是线性表。

**个数有限**。表的长度n是一个确定的数，可以是0。长度为0的表叫**空表**，记作()。编辑器刚启动时，屏幕上只有光标`|`，这一行就是空表。之后每敲一个字符，长度加1。程序任何时候都要知道现在有几个字符，否则就不知道显示到哪里为止。

**可以重复**。同一个元素可以出现在不同的位置。敲`book`时有两个o，两个都要记住，它们分别是第1个和第2个元素。

回到开头的问题。这一行字可以看成一个线性表。要一直记着它，程序就得记住三样东西：有哪些元素，它们的先后，现在有几个。

<!-- 分页 -->

**例题：通话记录和家谱能看成线性表吗？**

> **题目**：下面两样东西，能不能看成线性表？
> 手机里的通话记录，按时间从新到旧排。
> 一个家族的家谱。

**分析**。先看通话记录。

1. 看元素：每个元素是一条通话记录，都是同一种东西。是。
2. 看是不是一个接一个：通话记录本来就按时间从新到旧排着。除了最新和最旧的两条，每条记录恰好有一个前驱、一个后继。是。
3. 看个数：记录的条数是确定的，有限。是。

再看家谱。

1. 看元素：每个元素是一个人，都是同一种东西。是。
2. 看是不是一个接一个：家谱里辈分确实有先后，但一个人可以有好几个孩子，这个人的后继不止一个。否。到这里就能下结论，不用再看个数。

> **答案**：通话记录可以看成线性表。家谱不能，因为它不是一个接一个。

两样东西的元素都是同一种，也都有先后，差别只在是不是一个接一个。

## 2.2 线性表的操作与抽象数据类型

**编辑器要对这一行字做什么**

上一节敲出了`cat`，屏幕是`cat|`。编辑器除了敲字，还要能移动光标、在中间插入、按退格删除。

下面接着往下做：先把光标左移一格，再敲x，最后按一次退格。每一行是做完一个动作之后的屏幕：

```
cat|
ca|t
cax|t
ca|t
```

> **本节问题**：移动光标、在中间插入、退格，还有每一步之后把整行重新显示出来，分别要对这一行字做什么？要做到这些，线性表需要提供哪些操作？

<!-- 分页 -->

**线性表的五个操作**

编辑器对这一行字做的事，可以归结为线性表的五个基本操作。下面把表记作L，位置记作i，要插入的元素记作x。

**Init(L)：建立一个空表**。编辑器刚启动时，这一行一个字符都没有。程序先要有一个空表，之后才能往里放字符。

**Length(L)：返回表的长度n**。程序每一步都要把整行重新显示出来，它得知道一共有几个字符，显示到哪里为止。这就是上一节说的"现在有几个"，Length就是用来问这个数的。

**Get(L, i)：返回第i个元素**。知道了有几个，还要一个一个拿出来显示。显示`cat`，就是依次取第0个、第1个、第2个元素：c、a、t。i必须是已有元素的位置，也就是在0到n−1之间。

**Insert(L, i, x)：在第i个位置插入x**。原来第i个及之后的元素，位置都加1。在`ca|t`里敲x，x落在a和t之间，也就是第2个位置；原来在第2个的t变成第3个。这一步就是Insert(L, 2, x)，表从(c, a, t)变成(c, a, x, t)。

i可以等于n。在`cat|`的末尾敲一个s，就是Insert(L, 3, s)，s追加到最后。所以Insert的i在0到n之间。

**Delete(L, i)：删除第i个元素**。之后的元素，位置都减1。在`cax|t`里按退格，删掉的是x。x在第2个位置，这一步就是Delete(L, 2)。表从(c, a, x, t)回到(c, a, t)，t又回到第2个位置。

Delete的i不能等于n。第n个位置上没有元素，没有东西可删。所以Delete的i在0到n−1之间。

左右移动光标不改这一行字，表不变，所以不需要操作。

插在第几个、删第几个，由光标的位置决定。光标怎么用一个数记下来、怎么算出i，是编辑器自己的事。这一点留到2.6做编辑器时再讲。

五个操作汇总如下：

| 操作 | 含义 | i的范围 |
|---|---|---|
| Init(L) | 建立一个空表 | |
| Length(L) | 返回表的长度n | |
| Get(L, i) | 返回第i个元素 | 0 ≤ i ≤ n−1 |
| Insert(L, i, x) | 在第i个位置插入x，原来第i个及之后的元素位置都加1 | 0 ≤ i ≤ n |
| Delete(L, i) | 删除第i个元素，之后的元素位置都减1 | 0 ≤ i ≤ n−1 |

表满了怎么办、i超出范围怎么办，是实现时的事。这里只规定合法的i。

<!-- 分页 -->

**什么是抽象数据类型**

上一节说的是线性表"是什么"：同类型的元素，一个接一个，个数有限。上一页的五个操作说的是线性表"能做什么"。把这两样合起来写成一份描述，就是线性表的**抽象数据类型**。

抽象数据类型只说是什么、能做什么，不说元素怎么存、操作怎么做。比如Insert，它只规定插入之后表变成什么样，不规定元素放在内存的什么地方，也不规定它们是怎么挪过去的。

程序为什么要在乎这个区分？看编辑器。敲字是Insert，退格是Delete，显示是Length加上一个个Get。编辑器的每一个动作都只用到这五个操作，没有一个需要知道字符是怎么存的。

所以，只要五个操作的用法不变，字符的存法可以换，编辑器一行都不用改。这一章后面真的会换一次存法。

"抽象"说的就是这个意思：只留下"能做什么"，把"怎么做"藏起来。

<!-- 分页 -->

**例题：一串编辑动作对应哪些操作？**

> **题目**：编辑器刚启动，依次敲c、a、t，再在a和t之间敲x，最后按退格删掉x。每一步调用哪个操作？表变成什么？

**分析**。按动作的先后逐步写。

1. 启动：调用Init(L)，表是空表()。
2. 敲c：c放在第0个位置。调用Insert(L, 0, c)，表变成(c)。
3. 敲a：a接在c后面，是第1个位置。调用Insert(L, 1, a)，表变成(c, a)。
4. 敲t：t接在a后面，是第2个位置。调用Insert(L, 2, t)，表变成(c, a, t)。
5. 在a和t之间敲x：x落在第2个位置，t变成第3个。调用Insert(L, 2, x)，表变成(c, a, x, t)。
6. 退格删掉x：x在第2个位置。调用Delete(L, 2)，表变成(c, a, t)。

> **答案**：依次调用Init(L)、Insert(L, 0, c)、Insert(L, 1, a)、Insert(L, 2, t)、Insert(L, 2, x)、Delete(L, 2)。最后表是(c, a, t)。

每一步只说了插在第几个、删第几个，没有一步说到字符存在哪里。

- [ ] Insert(L, 3, x)

## 2.3 顺序存储与顺序表

**内存长什么样**

上一节只说了线性表能做什么，没说它怎么存。这一节讲怎么存：线性表怎么放进计算机的内存。

内存可以看成一长排编了号的格子。每个格子放一个字节，格子的编号叫**地址**。程序读写数据，就是按地址找格子。

下面画出其中一段，编号从100到115。两头的省略号表示前后还有很多格子：

```
  ┌───┬───┬───┬───┬───┬───┬───┬───┬───┬───┬───┬───┬───┬───┬───┬───┐
… │   │   │   │   │   │   │   │   │   │   │   │   │   │   │   │   │ …
  └───┴───┴───┴───┴───┴───┴───┴───┴───┴───┴───┴───┴───┴───┴───┴───┘
   100 101 102 103 104 105 106 107 108 109 110 111 112 113 114 115
```

这排格子只有一种天然的关系：前后相邻。100号后面是101号，101号后面是102号，仅此而已。

> **本节问题**：把`cat`的三个字符放进三个格子，没有困难。可是线性表除了元素，还有"a在c后面"这样的关系。这条关系放在哪里？

<!-- 分页 -->

**什么是顺序存储**

**顺序存储**就是：线性表里相邻的元素，放在内存里相邻的格子中。这样存的线性表叫**顺序表**。

以`cat`为例。c放100号，a放101号，t放102号。字符在内存里的先后，就是它们在线性表里的先后：

```
  ┌───┬───┬───┬───┬───┬───┬───┬───┬───┐
… │ c │ a │ t │   │   │   │   │   │   │ …
  └───┴───┴───┴───┴───┴───┴───┴───┴───┘
   100 101 102 103 104 105 106 107 108
```

关系没有单独占地方，它藏在位置里。a在101号，c在100号，两格相邻，"a在c后面"就成立了。

所以数据和关系都存下来了，而且关系一个字节都不占。另一个好处是，要取第i个元素，直接去找第i个格子就行，不用经过前面的元素。后面比较效率时，会用到这一点。

**长度**。上面的图还有个漏洞：103号往后的格子里是什么？没人知道，可能是这段内存上次留下的任何东西。要把这一行显示出来，从100号开始读，读到哪里停？

所以除了这段格子，还得另外记一个数：现在有效的元素有几个。`cat`是3，读三个就停。插入一个变成4，删掉一个变成2。这个数就是线性表的长度。

一个顺序表，就是一段连续的格子，加上一个长度。

<!-- 分页 -->

**用C语言表示顺序表**

一段连续的格子，在C语言里就是数组。数组的大小在编译时就要定下来，先定100，够不够用后面再说：

```c
#define MAXSIZE 100

char data[MAXSIZE];   /* 一段连续的格子 */
int  length;          /* 当前有效的元素个数 */
```

`data[0]`到`data[length-1]`是有效元素，`data[length]`往后是空闲的。`cat`存进去，就是`data[0]`到`data[2]`，length为3。

**结构体**。线性表是一个东西，现在却由两个变量表示：数组和长度。后面每个操作都要同时用到这两样，分开放很容易忘掉一个。C语言用**结构体**把几个变量装成一个整体：

```c
typedef struct {
    char data[MAXSIZE];   /* 存放元素的连续空间 */
    int  length;          /* 当前元素个数 */
} SeqList;
```

`SeqList`就是"顺序表"这个类型。一个`SeqList`类型的变量`L`里，有一个数组和一个长度，用点号访问：`L.data[i]`是第i个元素，`L.length`是长度。

元素类型写成`char`，是因为本章存的是字符。要存别的类型，把`char`换掉就行。

<!-- 分页 -->

**例题：把cat放进顺序表，再读出来**

> **题目**：定义一个`SeqList`类型的变量L，把c、a、t三个字符放进去。然后打印整行，再单独打印第2个元素。

**分析**。按存和取的先后逐步写。

1. 放元素：c、a、t依次放进`L.data[0]`、`L.data[1]`、`L.data[2]`，相邻的元素放在相邻的格子里。
2. 记长度：放了三个，`L.length`设为3。
3. 读整行：从`L.data[0]`开始，读到`L.data[L.length-1]`为止，一个一个打印。
4. 取第2个：直接打印`L.data[2]`，不用经过前面的元素。

> **答案**：程序如下，输出两行：第一行`cat`，第二行`t`。

```c
#include <stdio.h>

#define MAXSIZE 100

typedef struct {
    char data[MAXSIZE];
    int  length;
} SeqList;

int main(void) {
    SeqList L;
    L.data[0] = 'c';
    L.data[1] = 'a';
    L.data[2] = 't';
    L.length = 3;

    for (int i = 0; i < L.length; i++)    /* 读回整行 */
        printf("%c", L.data[i]);
    printf("\n");

    printf("%c\n", L.data[2]);           /* 直接取第2个 */
    return 0;
}
```

第一行说明关系没丢：按位置从0读到length−1，顺序和线性表一致，"a在c后面"不需要任何额外记录。第二行说明取第i个元素一步到位。

这里是手工把字符放进数组的，只为看清结构。下一节有了操作之后，就不再直接碰`data`和`length`了。

## 2.4 顺序表操作的实现

**初始化、求长度、取元素**

上一节有了顺序表的结构`SeqList`，但还是手工往数组里放字符。这一节把2.2的五个操作在这个结构上做出来。

> **本节问题**：结构有了，2.2的五个操作怎么在这个结构上做出来？

每个操作写成一个C函数。2.2只规定了操作"做什么"，函数体要回答"怎么做"。

**初始化**。编辑器刚启动时，这一行一个字符都没有，程序要先有一个空表。空表就是长度为0的表：

```
      ┌───┬───┬───┬───┬───┐
data  │ ? │ ? │ ? │ ? │ ? │   length = 0
      └───┴───┴───┴───┴───┘
        0   1   2   3   4
```

格子里画的问号，表示数组里原来有什么不知道，也无所谓。length为0，就表示没有任何格子是有效的。所以初始化只做一件事：把length设成0。

写成函数：不需要参数，也不交回什么，只把表变成空表。

这一节先把顺序表定义成一个全局变量L，函数直接用它，不通过参数传递。下一节再把它改成参数。

```c
SeqList L;    /* 全局的顺序表 */

void Init(void) {
    L.length = 0;
}
```

函数名后面括号里的`void`，表示这个函数不需要参数。

**求长度**。显示`cat`时，程序要知道一共有几个字符。表里放着`cat`时是这样：

```
      ┌───┬───┬───┬───┬───┐
data  │ c │ a │ t │   │   │   length = 3
      └───┴───┴───┴───┴───┘
        0   1   2   3   4
```

长度就记在length里，直接交回去。

写成函数：不需要参数，交回长度，表不变。

```c
int Length(void) {
    return L.length;
}
```

**取第i个元素**。显示时还要把字符一个一个取出来。还看上面这张图：第i个元素就在`data[i]`里，取第2个元素就是`data[2]`，也就是t。一次下标运算就拿到，不管表有多长。

i必须在0到length−1之间。上图中`data[3]`、`data[4]`不是有效元素，取它们没有意义。

写成函数：需要位置i，交回那个元素，表不变。i不合法时，交回`'\0'`表示出错。

```c
char Get(int i) {
    if (i < 0 || i >= L.length) return '\0';
    return L.data[i];
}
```

<!-- 分页 -->

**在第i个位置插入**

在`c|at`里敲x，x要插在c和a之间，也就是第1个位置。这一步就是Insert(1, 'x')，结果应该是`cxat`。插入前：

```
      ┌───┬───┬───┬───┬───┐
data  │ c │ a │ t │   │   │   length = 3
      └───┴───┴───┴───┴───┘
        0   1   2   3   4
```

x要放进`data[1]`，可是`data[1]`被a占着。占着那个位置的元素怎么办？

为了保持"相邻的元素放在相邻的格子里"，a和t都要往后挪一格，把`data[1]`腾出来。插入后：

```
      ┌───┬───┬───┬───┬───┐
data  │ c │ x │ a │ t │   │   length = 4
      └───┴───┴───┴───┴───┘
        0   1   2   3   4
```

挪动的顺序很关键。如果从前往后挪，先把`data[1]`的a挪到`data[2]`，`data[2]`原来的t就被覆盖，丢掉了。

所以必须**从最后一个元素开始，倒着往后挪**。先把t从`data[2]`挪到`data[3]`，再把a从`data[1]`挪到`data[2]`。这样每次挪动的目标格子都已经空出来了。挪完，把x放进`data[1]`，长度加1。

写成函数：需要位置i和字符x。插入可能失败，比如位置不合法、表满了，所以交回一个整数报告成败：1表示成功，0表示失败。成功时，数组和长度都变。

```c
int Insert(int i, char x) {
    if (i < 0 || i > L.length) return 0;      /* 位置不合法 */
    if (L.length == MAXSIZE)   return 0;      /* 表满 */
    for (int j = L.length; j > i; j--)        /* 从后往前挪 */
        L.data[j] = L.data[j - 1];
    L.data[i] = x;
    L.length++;
    return 1;
}
```

带入Insert(1, 'x')走一遍。j从3开始：`data[3] = data[2]`，把t挪到后一格。j=2：`data[2] = data[1]`，把a挪到后一格。j=1时不满足j>1，循环结束。最后`data[1] = 'x'`，长度变成4。

i可以等于length。这时循环一次都不执行，x直接放到末尾，就是追加。

插入的位置越靠前、表越长，要挪的元素就越多。2.7讲效率时会回来看这一点。

<!-- 分页 -->

**删除第i个元素**

在`cx|at`里按退格，删掉的是光标前面的x。x在第1个位置，这一步就是Delete(1)，结果应该回到`cat`。删除前：

```
      ┌───┬───┬───┬───┬───┐
data  │ c │ x │ a │ t │   │   length = 4
      └───┴───┴───┴───┴───┘
        0   1   2   3   4
```

x删掉之后，`data[1]`空出一格。按"相邻的元素放在相邻的格子里"，c的下一个应该是a，所以a要挪到`data[1]`，t跟着挪到`data[2]`。删除后：

```
      ┌───┬───┬───┬───┬───┐
data  │ c │ a │ t │ t │   │   length = 3
      └───┴───┴───┴───┴───┘
        0   1   2   3   4
```

这次挪动的方向和插入相反，要**从前往后**。先把a从`data[2]`挪到`data[1]`，直接覆盖掉要删的x，不需要先把x清空。再把t从`data[3]`挪到`data[2]`。挪完，长度减1。

注意`data[3]`里还留着一个t。它不用管：长度已经是3，`data[3]`在有效范围之外，下次插入会把它覆盖掉。有效范围靠长度来定，不靠格子里有没有东西。

写成函数：需要位置i。删除也可能失败，位置不合法时交回0，成功交回1。成功时，数组和长度都变。

```c
int Delete(int i) {
    if (i < 0 || i >= L.length) return 0;     /* 位置不合法 */
    for (int j = i; j < L.length - 1; j++)    /* 从前往后挪 */
        L.data[j] = L.data[j + 1];
    L.length--;
    return 1;
}
```

带入Delete(1)走一遍。j=1：`data[1] = data[2]`，把a挪过来。j=2：`data[2] = data[3]`，把t挪过来。j=3时不满足j<3，循环结束。长度变成3。

删除的位置越靠前、表越长，要挪的元素也越多，和插入一样。

<!-- 分页 -->

**把五个操作合起来**

五个操作到齐了。用它们把2.2例题的每一步在机器上重放一遍：编辑器启动，敲c、a、t，在a和t之间敲x，再退格删掉x。

```c
int main(void) {
    Init();
    Insert(0, 'c');            /* (c)          */
    Insert(1, 'a');            /* (c, a)       */
    Insert(2, 't');            /* (c, a, t)    */
    Insert(2, 'x');            /* (c, a, x, t) */
    Delete(2);                 /* (c, a, t)    */

    for (int i = 0; i < Length(); i++)
        printf("%c", Get(i));
    printf("\n");              /* 输出 cat */
    return 0;
}
```

程序输出`cat`。前三次Insert都是追加到末尾，挪动循环一次都不执行；第四次插在中间，t往后挪了一格；Delete又把它挪了回来。

上一节的程序是手工往数组里放字符。这个程序只调用操作，没有碰`L.data`和`L.length`。以后都这样写。

## 2.5 传值与传地址

**直接传结构体，Init为什么没生效**

上一节的五个函数都直接操作全局变量L。这一节把L改成函数的参数。

为什么要改？有三个原因。

第一，全局变量L只有一个，程序里就只能有一个表。第3章的栈和队列，要同时用好几个表。

第二，2.2定义的操作是Init(L)、Insert(L, i, x)，表是参数。代码理应和定义长得一样。

第三，全局变量谁都能改。main可以绕过操作，直接改`L.length`，"只通过操作访问数据"就没有约束力了。

最自然的改法，是给函数加一个参数。从最简单的Init试起：

```c
void Init(SeqList L) {
    L.length = 0;
}

int main(void) {
    SeqList L;
    L.length = 5;         /* 故意先放个数 */
    Init(L);
    printf("%d\n", L.length);
    return 0;
}
```

期望打印0，实际打印5。

> **本节问题**：Init运行了，也没报错，为什么main里的L没有变？

<!-- 分页 -->

**什么是传值**

用内存格子图看发生了什么。main里的L是一个结构体，占一段格子。假设它从200号开始，length那一格在300号：

```
main 的 L
         ┌───┬───┬─────┬─────┐
         │   │   │  …  │  5  │
         └───┴───┴─────┴─────┘
          200 201        300   ← length
```

调用Init(L)时，C语言把main的L这一整段的内容复制一份，放到另一处，比如从500号开始，作为Init的参数L：

```
main 的 L                          Init 的 L（复制品）
┌───┬───┬─────┬─────┐              ┌───┬───┬─────┬─────┐
│   │   │  …  │  5  │   复制 ──►   │   │   │  …  │  5  │
└───┴───┴─────┴─────┘              └───┴───┴─────┴─────┘
 200 201        300                 500 501        600
```

Init里的`L.length = 0`改的是600号，300号纹丝不动。函数一返回，复制品就被丢弃，main里看到的还是5。

调用函数时，把参数的值复制一份交给函数，这叫**传值**，教材里也叫值传递。函数拿到的是复制品，不是原件。

传值什么时候正合适？比如传一个int进去做计算。复制一个格子不费事，原件也不会被误改。

可这里不行，有两个原因。一是Init要改的是原件，改复制品等于白改。二是结构体有一百多个格子，每次调用都要整段复制，Length、Get这种不改表的操作，也白白复制一遍。

<!-- 分页 -->

**什么是传地址**

既然改复制品没用，就不要给函数复制品，而是告诉它原件在哪：只传一个数，200，也就是main的L的起始地址。

Init的参数变成一个格子，里面记着200。Init顺着200找到原件，把300号改成0：

```
main 的 L                          Init 的参数
┌───┬───┬─────┬─────┐              ┌─────┐
│   │   │  …  │  0  │ ◄──────────  │ 200 │
└───┴───┴─────┴─────┘              └─────┘
 200 201        300                  700
```

把原件的地址交给函数，函数顺着地址去改原件，这叫**传地址**，教材里也叫地址传递。

要注意，传地址其实也是传值，只不过传的值是一个地址。调用时，复制的是那个装着200的格子；函数顺着这个复制来的地址，改到的是原件。C语言只有传值这一种传法。

这也说明了传地址为什么省事：复制的只是一个数，不是一百多个格子。

要把这个思路写成C代码，还需要两样工具：怎么取到一个变量的地址，怎么顺着地址去访问它。这就是指针。

<!-- 分页 -->

**地址与指针**

如果你已经熟悉C语言的指针，可以直接翻到下一页。

2.3说过，内存是一排编了号的格子，编号就是地址。这不是比喻。定义一个变量，打印它的值和它的地址：

```c
int a = 10;
printf("%d\n", a);
printf("%p\n", &a);
```

第一行打印10，是a的值。第二行打印类似`0x7ffd5a3c9c04`的东西，这就是a所在格子的编号。`&`读作"取地址"，`%p`是打印地址的格式。

地址习惯用十六进制显示，`0x`是十六进制的标记，`0x64`就是100。你运行时看到的数字会和这里不同，每次运行也可能变，这没有关系。下面的图里，为了好读，地址都用小的十进制数。

一个int占4个字节，也就是4个格子。图里把这4个格子画成一个框，下面标出起始地址。a从100号开始，`&a`就是100：

```
a
┌─────┐
│ 10  │
└─────┘
  100
```

有了地址，就有了第二种访问变量的办法。除了用名字a，也可以先把它的地址存起来，再顺着地址去找：

```c
int *pa = &a;
printf("%d\n", *pa);      /* 10 */
```

`int *pa`定义了一个变量pa，它存放的是一个int变量的地址，这样的变量叫**指针**。pa自己也住在一个格子里，比如200号，格子里装着100：

```
a                pa
┌─────┐           ┌─────┐
│ 10  │ ◄──────── │ 100 │
└─────┘           └─────┘
  100               200
```

`*pa`读作"pa指向的那个变量"，也就是顺着箭头找到的a。读`*pa`就是读a，改`*pa`就是改a：

```c
*pa = 20;
printf("%d\n", a);        /* 20 */
```

```
a                pa
┌─────┐           ┌─────┐
│ 20  │ ◄──────── │ 100 │
└─────┘           └─────┘
  100               200
```

这和上一页的图是同一回事：Init的参数格子里装着200，顺着它找到main的L。

再看指向结构体的指针，这正是下一页要用的：

```c
SeqList L;
SeqList *p = &L;
L.length = 5;
printf("%d %d\n", (*p).length, p->length);   /* 5 5 */
```

p里装着L的起始地址200，箭头指向L：

```
L                                  p
┌───┬───┬─────┬─────┐              ┌─────┐
│   │   │  …  │  5  │ ◄──────────  │ 200 │
└───┴───┴─────┴─────┘              └─────┘
 200 201        300                  700
```

`(*p).length`是"p指向的结构体的length成员"，也就是顺着箭头找到L，再取它的length。这个写法太啰嗦，C语言提供了等价的简写`p->length`。后面所有通过指针访问结构体成员的地方，都用箭头。

最后看数组：

```c
int b[3] = {1, 2, 3};
int *pb = &b[0];
printf("%d %d %d\n", *pb, *(pb + 1), *(pb + 2));   /* 1 2 3 */
```

数组的三个元素紧挨着。一个int占4个字节，所以它们的起始地址依次加4：

```
b[0]  b[1]  b[2]
┌─────┬─────┬─────┐
│  1  │  2  │  3  │
└─────┴─────┴─────┘
 100   104   108
  ▲     ▲
  pb   pb+1
```

`pb + 1`不是把地址加1，而是往后挪一个元素，也就是加4个字节，指向`b[1]`。知道第一个元素的地址，就能一步算出任何一个元素的地址。顺序表的Get只要一次计算就能取到第i个元素，原因就在这里。

**用传地址实现顺序表的操作**

按传地址的思路改Init。参数不再是`SeqList`，而是指向SeqList的指针`SeqList *L`。调用时传`&L`，也就是L的地址。函数体里的L是一个地址，访问它指向的结构体的成员，用箭头`L->length`：

```c
void Init(SeqList *L) {
    L->length = 0;
}

int main(void) {
    SeqList L;
    L.length = 5;
    Init(&L);
    printf("%d\n", L.length);    /* 这次打印 0 */
    return 0;
}
```

这次打印0，第一页的问题解决了。想确认改的是原件，可以在main里打印`&L`，在Init里打印`L`，它本身就是地址，两个数字相同。

对比两个版本的Init，只有两处变化：参数类型多了一个`*`，`L.`变成了`L->`。最复杂的Insert也一样，函数体里的逻辑一个字不动：

```c
int Insert(SeqList *L, int i, char x) {
    if (i < 0 || i > L->length) return 0;
    if (L->length == MAXSIZE)   return 0;
    for (int j = L->length; j > i; j--)
        L->data[j] = L->data[j - 1];
    L->data[i] = x;
    L->length++;
    return 1;
}
```

只读的操作Length、Get也一律传地址。一是不用复制整个结构体，二是五个函数写法统一。

全局变量`SeqList L;`删掉。表由使用者自己定义，比如在main里写`SeqList L;`，然后`Init(&L)`。

从现在起，本章都用下面这一套：

```c
#define MAXSIZE 100

typedef struct {
    char data[MAXSIZE];
    int  length;
} SeqList;

void Init(SeqList *L) {
    L->length = 0;
}

int Length(SeqList *L) {
    return L->length;
}

char Get(SeqList *L, int i) {
    if (i < 0 || i >= L->length) return '\0';
    return L->data[i];
}

int Insert(SeqList *L, int i, char x) {
    if (i < 0 || i > L->length) return 0;
    if (L->length == MAXSIZE)   return 0;
    for (int j = L->length; j > i; j--)
        L->data[j] = L->data[j - 1];
    L->data[i] = x;
    L->length++;
    return 1;
}

int Delete(SeqList *L, int i) {
    if (i < 0 || i >= L->length) return 0;
    for (int j = i; j < L->length - 1; j++)
        L->data[j] = L->data[j + 1];
    L->length--;
    return 1;
}
```

int main(void) {

## 2.6 用顺序表实现编辑器

**编辑器要做什么**

前五节把顺序表和它的五个操作做出来了。这一节用它们实现2.1开头的那个单行编辑器。

为了把程序写得简单，我们用一行指令代替一次按键。用户能做的事只有五件：

| 指令 | 相当于 | 效果 |
|---|---|---|
| `i c` | 敲字符c | c插入到光标处，光标移到它后面 |
| `d` | 按退格键 | 删掉光标前面那个字符，光标跟着前移 |
| `l` | 按左方向键 | 光标左移一格，已在行首则不动 |
| `r` | 按右方向键 | 光标右移一格，已在行尾则不动 |
| `q` | 退出 | |

每处理一条指令，程序都把整行打印出来，光标位置用`|`标出。编辑器只管一行文字，字符只有英文字母和空格，空格用`_`输入。

把敲出`cat`、在a和t之间插入x再删掉这一串动作换成指令，就是下面这段会话。左边是输入的指令，右边是程序的输出：

```
i c       c|
i a       ca|
i t       cat|
l         ca|t
i x       cax|t
d         ca|t
r         cat|
q
```

> **本节问题**：用顺序表和它的五个操作，怎么把这个编辑器做出来？

<!-- 分页 -->

**编辑器的初始化**

编辑器要记两样东西：这一行字，和光标的位置。

这一行字用一个顺序表L记。编辑器刚启动时一个字符都没有，所以先调用Init，得到一个空表。

光标用一个整数cursor记。它的意思是：**光标左边有几个字符**。刚启动时，光标左边一个字符都没有，所以cursor是0：

```
      ┌───┬───┬───┬───┬───┐
data  │ ? │ ? │ ? │ ? │ ? │   length = 0
      └───┴───┴───┴───┴───┘
        0   1   2   3   4
      ▲
      cursor = 0
```

光标总是夹在两个字符之间，所以图里把它画在格子之间的竖线下面。

再看一个有字符的例子。屏幕是`ca|t`时，光标左边有c、a两个字符，cursor是2：

```
      ┌───┬───┬───┬───┬───┐
data  │ c │ a │ t │   │   │   length = 3
      └───┴───┴───┴───┴───┘
        0   1   2   3   4
              ▲
              cursor = 2
```

行尾也一样。屏幕是`cat|`时，光标左边有3个字符，cursor是3，正好等于长度。

光标是编辑器自己的东西，线性表里没有它。表只管存字符，光标由编辑器另外记着。

写成代码：定义一个顺序表L和一个整数cursor，cursor一开始是0；再调用Init，把L变成空表。

```c
SeqList L;
int cursor = 0;

Init(&L);
```

<!-- 分页 -->

**敲字符和退格**

五条指令里，只有敲字符和退格会改这一行字，先看这两条。每条指令要回答两件事：对表做什么操作，光标怎么变。想清楚之后，再写成代码。下面都从屏幕`ca|t`开始，这时cursor是2。

**敲字符：`i c`**。在`ca|t`里敲x，x要出现在光标的位置。光标左边有2个字符，所以x成为第2个字符，也就是调用Insert(L, 2, x)，原来的t被挤到第3个：

```
      ┌───┬───┬───┬───┬───┐
data  │ c │ a │ x │ t │   │   length = 4
      └───┴───┴───┴───┴───┘
        0   1   2   3   4
                  ▲
                  cursor = 3
```

x插在了光标左边，光标左边多了一个字符，所以cursor加1，变成3。屏幕是`cax|t`。

一般地，敲字符就是Insert(L, cursor, c)，然后cursor加1。

写成代码：敲进来的字符记在ch里，先把`_`换成空格。Insert可能失败，比如表满了，所以看它的返回值，成功才把cursor加1。

```c
if (ch == '_') ch = ' ';               /* 空格用_输入 */
if (Insert(&L, cursor, ch)) cursor++;
else printf("插入失败\n");
```

**退格：`d`**。在`cax|t`里按退格，删的是光标左边紧挨着的那个字符x。光标左边有3个字符，紧挨着的那个是第2个，也就是调用Delete(L, 2)：

```
      ┌───┬───┬───┬───┬───┐
data  │ c │ a │ t │ t │   │   length = 3
      └───┴───┴───┴───┴───┘
        0   1   2   3   4
              ▲
              cursor = 2
```

光标左边少了一个字符，cursor减1，变成2，屏幕回到`ca|t`。`data[3]`里留下的t不用管，长度说了算。

一般地，退格就是Delete(L, cursor−1)，然后cursor减1。cursor为0时，光标左边没有字符，什么都不做。

写成代码：

```c
if (cursor > 0) {
    Delete(&L, cursor - 1);
    cursor--;
}
```

<!-- 分页 -->

**移动光标、退出和显示**

剩下的三条指令都不改这一行字。再加上每条指令之后都要做的显示。

**左移、右移：`l`和`r`**。移动光标不改这一行字，所以不调用任何操作，只改cursor。左移减1，到0就不再动；右移加1，到长度就不再动。

写成代码，各是一行：

```c
if (cursor > 0) cursor--;              /* l：左移 */
if (cursor < Length(&L)) cursor++;     /* r：右移 */
```

**退出：`q`**。结束程序。它不改表也不改光标，在下一页读指令的循环里处理：读到`q`就不再往下读。

**显示**。显示不是一条指令，但每条指令之后都要做。从第0个到第Length−1个字符，逐个用Get取出来打印；走到第cursor个字符之前，先打一个`|`。光标在行尾时，cursor等于长度，循环里碰不到它，循环结束后要补一个`|`。

显示要在每条指令之后反复用，所以写成一个函数Show：

```c
void Show(SeqList *L, int cursor) {
    int n = Length(L);
    for (int i = 0; i < n; i++) {
        if (i == cursor) printf("|");
        printf("%c", Get(L, i));
    }
    if (cursor == n) printf("|");
    printf("\n");
}
```

<!-- 分页 -->

**把指令合在一起：编辑器1.0**

前三页的代码已经齐了：初始化、每条指令的代码、显示用的Show。剩下的是把它们装进一个循环。

编辑器从启动到退出，做的就是这个循环：读一条指令，执行它，把整行显示出来，再读下一条，直到`q`。

**读指令**。每条指令是一个字母，用`scanf(" %c", &cmd)`读。格式串开头的空格不能省：它让scanf跳过上一条指令留下的换行，否则换行会被当成一条指令。读到`q`就结束循环。`i`后面还跟一个字符，在`i`的分支里再读一次。

**执行**。按读到的字母选一段代码执行，用`switch`。每个分支就是前两页里对应指令的那几行代码，原样放进去。

**显示**。每轮循环的末尾调用一次Show。

合起来就是main：

```c
int main(void) {
    SeqList L;
    int cursor = 0;
    char cmd, ch;

    Init(&L);
    while (scanf(" %c", &cmd) == 1 && cmd != 'q') {   /* 读指令 */
        switch (cmd) {                                  /* 执行 */
        case 'i':
            scanf(" %c", &ch);
            if (ch == '_') ch = ' ';
            if (Insert(&L, cursor, ch)) cursor++;
            else printf("插入失败\n");
            break;
        case 'd':
            if (cursor > 0) { Delete(&L, cursor - 1); cursor--; }
            break;
        case 'l':
            if (cursor > 0) cursor--;
            break;
        case 'r':
            if (cursor < Length(&L)) cursor++;
            break;
        }
        Show(&L, cursor);                               /* 显示 */
    }
    return 0;
}
```

写进文件时，Show要放在main前面，因为C语言要求函数先定义后使用。

编译运行，逐条输入第1页的会话：

```
i c       c|
i a       ca|
i t       cat|
l         ca|t
i x       cax|t
d         ca|t
r         cat|
q
```

右边的输出和第1页的会话一模一样。这就是编辑器1.0。

再看一眼main和Show：它们只调用了Init、Length、Get、Insert、Delete，从头到尾没有直接读写`L.data`和`L.length`。编辑器不知道、也不需要知道字符是怎么存的。这正是2.2节说的抽象数据类型的好处，也是2.5坚持传地址、不用全局变量的目的之一。后面把存储结构换掉时，这段main会原样保留。

## 2.7 顺序表的时间复杂度

**时间复杂度看什么**

> **本节问题**：编辑器1.0在几十个字符上，每个动作都是瞬间完成。拿它编辑一个几万字的文档，哪个动作会变慢？能不能不靠运行，看代码就判断出来？

时间复杂度描述的是：当输入规模n增大时，算法执行的基本操作次数随n增长的趋势。对顺序表来说，n就是表长。

它不关心具体跑了多少毫秒，那取决于机器、语言和编译器；它只关心量级，所以用大O记号表示，忽略常数和低阶项。比如某算法执行3n²+5n+2次操作，就记作O(n²)。操作次数不随n变化，记作O(1)。

下面用这个方法，把顺序表的五个操作逐个量一遍。

**初始化**。Init只做一件事：把length设成0。不管表里原来有3个字符还是3万个，都只有这一步。操作次数不随n变化，所以Init是O(1)。

**求长度**。Length只做一件事：交回length。长度早就记在length里，不用一个一个去数。同样只有一步，所以Length是O(1)。

**取第i个元素**。表的字符放在一段连续的格子里，比如从100号开始：

```
  ┌───┬───┬───┬───┬───┐
… │ c │ a │ t │   │   │ …
  └───┴───┴───┴───┴───┘
   100 101 102 103 104
```

第0个字符在100号，第1个在101号，第i个就在100+i号。要取第i个，直接就能找到它所在的格子，不用从头一个一个数过去。不管n多大，都只要固定几步，所以Get是O(1)。

<!-- 分页 -->

**插入和删除的时间复杂度**

插入要走多少步？开头的检查、最后放入元素和长度加1，都是固定的几步。插入的步数主要花在挪动元素上：每挪一个元素，就是一步赋值。所以步数有多少，取决于要挪几个元素，也就取决于插在哪里。

```
      ┌───┬───┬───┬───┬───┐
data  │ c │ a │ t │   │   │   length = 3
      └───┴───┴───┴───┴───┘
        0   1   2   3   4
```

可以插在尾部、头部，或者中间的某个位置。逐个看。

**尾部插入**。在行尾追加s，就是Insert(3, 's')。s直接放进第3个格子，一个元素都不用挪，只走固定的几步：

```
      ┌───┬───┬───┬───┬───┐
data  │ c │ a │ t │ s │   │   length = 4
      └───┴───┴───┴───┴───┘
        0   1   2   3   4
```

表长换成1万、10万，尾部插入还是这几步。步数不随n变化，所以尾部插入是O(1)。

**头部插入**。在行首插入b，就是Insert(0, 'b')。为了把第0个格子腾出来，t、a、c都要往后挪一格：

```
      ┌───┬───┬───┬───┬───┐
data  │ c │ a │ t │   │   │   length = 3
      └───┴───┴───┴───┴───┘
        0   1   2   3   4
        └──►└──►└──►
```

挪完之后，b放进第0个格子：

```
      ┌───┬───┬───┬───┬───┐
data  │ b │ c │ a │ t │   │   length = 4
      └───┴───┴───┴───┴───┘
        0   1   2   3   4
```

表长为n时，头部插入要把n个元素全挪一遍，步数是n再加上固定的几步。n是3就要挪3次，n是1万就挪1万次，n是10万就挪10万次。步数和n成正比，所以头部插入是O(n)。

**中间插入**。插在中间的第i个位置。比如在第1个位置插入x，就是Insert(1, 'x')，a和t要往后挪，挪2次：

```
      ┌───┬───┬───┬───┬───┐
data  │ c │ a │ t │   │   │   length = 3
      └───┴───┴───┴───┴───┘
        0   1   2   3   4
            └──►└──►
```

一般地，在第i个位置插入，要挪第i个到第n−1个元素，一共挪n−i次。i越靠前，步数越多。如果每个位置被插入的机会一样，平均挪n/2次。忽略常数1/2，还是O(n)。

插入的三种情况：

| 插入的位置 | 时间复杂度 |
|---|---|
| 尾部 | O(1) |
| 头部 | O(n) |
| 中间第i个 | O(n) |

尾部是最好的情况，头部是最坏的情况，中间位置平均下来也是O(n)。说一个操作的时间复杂度，通常看最坏的情况，所以Insert是O(n)。

**删除**。删除的步数同样主要花在挪动元素上，只是方向相反：删掉一个元素之后，它后面的元素要往前挪，把空出来的格子补上。也分三种情况。

删尾部的元素，后面没有元素要挪，只走固定的几步，是O(1)。

删头部的元素，后面n−1个元素都要往前挪一格，步数和n成正比，是O(n)。

删中间的第i个，要把第i+1个到第n−1个往前挪，一共挪n−i−1次，平均下来也和n成正比，是O(n)。

删除的三种情况：

| 删除的位置 | 时间复杂度 |
|---|---|
| 尾部 | O(1) |
| 头部 | O(n) |
| 中间第i个 | O(n) |

和插入一样看最坏的情况，Delete是O(n)。

顺序表五个操作的时间复杂度汇总如下：

| 操作 | 顺序表 |
|---|---|
| Init、Length、Get | O(1) |
| Insert、Delete | O(n) |

<!-- 分页 -->

**编辑器各条指令的时间复杂度**

编辑器的每条指令，都是用顺序表的五个操作做的。上一页已经有了每个操作的时间复杂度，这里逐条套用。设这一行有n个字符。

**敲字符：`i c`**。调用Insert(L, cursor, c)。光标在行尾是尾部插入，O(1)；在行首是头部插入，O(n)；在中间也是O(n)。所以敲字符是O(n)。

**退格：`d`**。调用Delete(L, cursor−1)，删的是光标左边那个字符。光标在行尾是尾部删除，O(1)；光标越靠前，后面要往前挪的字符越多，最坏是O(n)。所以退格是O(n)。

**左移、右移：`l`和`r`**。只改cursor，右移前再调用一次Length看是不是到了行尾。都是固定几步，O(1)。

**显示**。Show调用一次Length和n次Get，每次都是O(1)，合起来是O(n)。

这是本书为了程序简单，每条指令之后都打印整行。真正的编辑器只重画屏幕上看得见的那几十个字符，所以显示不是要解决的问题。

回到开头的问题。拿编辑器1.0编辑几万字的文档，慢的是在开头附近敲字符和退格：每按一下，光标右边的几万个字符都要挪一遍。

这个问题的根源，是顺序存储"相邻的元素放在相邻的格子里"这条约定本身。只要坚持这条约定，在中间插入就必然要挪动。在顺序表的框架里没有办法，要换一种存储方式才能解决，这是2.9节的内容。

在那之前，编辑器1.0还有一个更急的问题要先解决。

## 2.8 动态数组

**数组满了怎么办**

顺序表的数组大小，在编译时就定死了。定100，第101个字符插不进去；定一万，大多数时候又是浪费。用户会输入多少，事先不知道。

先看问题有多真实。把`MAXSIZE`改成4，重新编译编辑器1.0。敲到第4个字符，数组就满了：

```
      ┌───┬───┬───┬───┐
data  │ c │ a │ t │ s │   length = 4
      └───┴───┴───┴───┘
        0   1   2   3
```

再敲第5个字符，Insert发现表满，返回0，屏幕上打出"插入失败"。

把`MAXSIZE`改回100也不能根治，敲到第101个字符时照样失败。

最直接的想法是：满了就把数组变长。但数组在内存里是一段固定的格子，比如从100号到103号。它后面的104号是谁的？可能已经被别的变量占了：

```
       data（4格，满了）          别的变量
  ┌───┬───┬───┬───┬───┬───┬───┐
… │ c │ a │ t │ s │ ? │ ? │ ? │ …
  └───┴───┴───┴───┴───┴───┴───┘
   100 101 102 103 104 105 106
```

要往104号写，就会把别人的东西覆盖掉。数组一旦定下来，两头的格子都不归它，没法就地变长。

> **本节问题**：数组满了，原地又不能变长，怎么办？

<!-- 分页 -->

**什么是动态数组**

**动态数组**就是：存放元素的那段连续格子，不在编译时定死，而是在程序运行时申请。装满了，就换一块更大的，把元素搬过去，再把旧的还回去。

比如4格装满了，就申请一块8格的新空间，把4个字符搬过去，然后把旧的4格还回去：

```
  旧空间（还回去）                新空间（8格）
  ┌───┬───┬───┬───┐              ┌───┬───┬───┬───┬───┬───┬───┬───┐
  │ c │ a │ t │ s │  搬过去 ──►  │ c │ a │ t │ s │   │   │   │   │
  └───┴───┴───┴───┘              └───┴───┴───┴───┴───┴───┴───┴───┘
   100 101 102 103                500 501 502 503 504 505 506 507
```

搬完之后，表的元素就从100号开始，变成了从500号开始。所以动态数组除了元素，还要记住三样东西：这段空间从哪里开始，现在实际放了几个元素，这段空间最多能放几个。

实际放了几个，就是**长度**。最多能放几个，叫**容量**。上图搬完之后，长度是4，容量是8。长度永远不会超过容量；长度等于容量时，就是满了，再插入就要先换更大的空间。

<!-- 分页 -->

**向系统申请空间**

要在程序运行时申请空间，C语言在`<stdlib.h>`里提供了三个函数：

- `malloc(n)`：向系统申请n个字节的连续格子，返回第一个格子的地址。申请不到时，返回NULL。
- `free(p)`：把以前申请的、起始地址为p的那段空间还给系统。
- `realloc(p, m)`：申请一块m个字节的新空间，把p指向的旧空间里的内容复制过去，释放旧空间，返回新空间的地址。申请不到时返回NULL，这时旧空间原样保留。

程序自己定义的变量和数组，大小在编译时就定了。`malloc`申请来的空间，大小在运行时才决定，用完要自己`free`。

上一页图里"申请8格、搬过去、还回旧的4格"这三步，`realloc`一个函数全包了。

<!-- 分页 -->

**动态数组的定义和初始化**

按动态数组的思路改顺序表。先改它的定义。

原来`data`是一个定长数组。现在它要记住"那段空间从哪里开始"，而这段空间搬家之后起始地址会变，所以`data`要变成一个指针，指向运行时申请来的空间。另外新增一个`capacity`，记录这段空间的容量：

```c
/* 原来 */
typedef struct {
    char data[MAXSIZE];
    int  length;
} SeqList;

/* 现在 */
#define INIT_CAPACITY 16

typedef struct {
    char *data;       /* 指向运行时申请的空间 */
    int   length;     /* 实际放了几个 */
    int   capacity;   /* 最多能放几个 */
} SeqList;
```

再改Init。原来数组是现成的，只要把长度清零。现在要先申请一块初始空间，比如16格。申请可能失败，所以Init改成返回是否成功：

```c
/* 原来 */
void Init(SeqList *L) {
    L->length = 0;
}

/* 现在 */
int Init(SeqList *L) {
    L->data = (char *)malloc(INIT_CAPACITY * sizeof(char));
    if (L->data == NULL) return 0;
    L->length = 0;
    L->capacity = INIT_CAPACITY;
    return 1;
}
```

<!-- 分页 -->

**动态数组的操作**

**插入**。上一页的思路是：表满了，就先换一块更大的空间，再往里插。写成代码，Insert只改一行：

```c
/* 原来 */ if (L->length == MAXSIZE)   return 0;
/* 现在 */ if (L->length == L->capacity && !Expand(L)) return 0;
```

长度等于容量，就是满了。满了先调用Expand扩容，扩容成功再往下走；扩容失败，才返回0。Length、Get、Delete一行都不用改。

**扩容**。Expand负责换空间：申请一块容量翻倍的新空间，把元素搬过去，旧的还回去。这三步，realloc一个函数全包了：

```c
int Expand(SeqList *L) {
    int newCap = L->capacity * 2;
    char *p = (char *)realloc(L->data, newCap * sizeof(char));
    if (p == NULL) return 0;
    L->data = p;
    L->capacity = newCap;
    return 1;
}
```

::: warning realloc的返回值先存进临时变量
realloc的返回值先存进`p`，确认不是NULL，再赋给`L->data`。如果直接写`L->data = realloc(...)`，一旦申请失败返回NULL，旧空间的地址就被覆盖丢掉了，里面的元素再也找不回来。
:::

::: tip 为什么容量每次翻倍
每次翻倍，而不是每次多一格，搬家就很少发生。触发扩容的那一次插入要把整个表搬一遍，是O(n)；但平均到每次插入上，仍是O(1)。这种分析方法叫平摊分析，有兴趣可以自行深入。
:::

**销毁**。申请了就要还。补一个销毁操作，程序退出前调用：

```c
void Destroy(SeqList *L) {
    free(L->data);
    L->data = NULL;
    L->length = L->capacity = 0;
}
```

这是动态申请空间带来的需要，2.2节的五个操作里没有它。凡是动态申请空间的实现，都得有这样一个操作。

<!-- 分页 -->

**动态数组实现编辑器**

有了动态数组和它的操作，编辑器这边改动很小。Init有了返回值，main开头改成`if (!Init(&L)) return 1;`；循环结束后加一行`Destroy(&L);`。其余原样。这就是编辑器1.1。

要亲眼看见扩容，把INIT_CAPACITY改成4，再在Expand里临时加一行打印：

```c
printf("[扩容] %d -> %d\n", L->capacity, newCap);
```

运行，输入五个以上的字符：

```
i c          c|
i a          ca|
i t          cat|
i s          cats|
i _          [扩容] 4 -> 8
             cats |
```

同样是第5个字符，1.0版插入失败，1.1版扩容后照常插入。再敲到第9个字符时，会看到`[扩容] 8 -> 16`。用户完全感觉不到这些，只是一直在打字。

## 2.9 链式存储与链表

**放弃"相邻"约定**

顺序表把关系藏在位置里：a在c后面，就把a放在c的下一格。这条约定不占空间，按位置取元素也一步到位。

可是挪动也是它带来的。在编辑器里，光标停在行首附近敲字，每敲一下，光标右边的字符都要往后挪一格。2.7节算过，这是O(n)。

放弃这条约定会怎样？

放弃之后，元素可以放在内存的任何地方。插入时随便找个空格子放进去，不用挪动任何字符。

各个字符是在不同时候放进去的，每次哪里有空就放哪里。于是`cat`的三个字符可能散成这样：c在100号，t在105号，a在109号。

```
┌───┬───┬───┬───┬───┬───┬───┬───┬───┬───┬───┬───┬───┬───┬───┬───┐
│ c │   │   │   │   │ t │   │   │   │ a │   │   │   │   │   │   │
└───┴───┴───┴───┴───┴───┴───┴───┴───┴───┴───┴───┴───┴───┴───┴───┘
 100 101 102 103 104 105 106 107 108 109 110 111 112 113 114 115
```

可是关系没了。按位置往后找，c的下一格并不是a。位置已经不能告诉我们谁在谁后面。

要读出`cat`，得有别的办法知道：c的下一个是a，a的下一个是t。

> **本节问题**：放弃"相邻格子放相邻元素"这条约定，"谁在谁后面"的关系存到哪里？

<!-- 分页 -->

**什么是链式存储**

办法是把关系明确地记下来：在每个字符右边的格子里，写上下一个字符的地址。

```
┌───┬───┬───┬───┬───┬───┬───┬───┬───┬───┬───┬───┬───┬───┬───┬───┐
│ c │109│   │   │   │ t │ 0 │   │   │ a │105│   │   │   │   │   │
└───┴───┴───┴───┴───┴───┴───┴───┴───┴───┴───┴───┴───┴───┴───┴───┘
 100 101 102 103 104 105 106 107 108 109 110 111 112 113 114 115
```

右格里的109、105不是数据，是另一个格子的编号。c的右格写着109，意思是"c的下一个在109号"。到109号，读到a。a的右格写着105，再到105号，读到t。

t的右格写着0，表示后面没有了。地址0不会放任何变量，所以用它做结束标记。

还差一样：从哪开始读？我们看图知道c在最前面，程序却不知道。所以还要另外记下第一个字符的地址：head等于100。

这就是新的存法。现在给它和它用到的东西起名字。

**链式存储**就是：每个元素旁边，记下它后一个元素的地址。元素本身放在哪个格子都行。

一格数据加一格地址，合起来叫一个**结点**。上图有三个结点，分别在100号、109号、105号。

结点用地址一个接一个串起来，这样存的线性表叫**链表**。

另外记下的第一个结点的地址head，叫**头指针**。

所以，一个链表，就是一串用地址连起来的结点，加上一个头指针。

结点和元素要分清。元素是c、a、t这些数据，结点是"数据加下一个地址"这两格。下文说"c结点"，指的是存放元素c的那个结点。说地址、说指向的时候，说的都是结点。

回到开头的问题。"谁在谁后面"不再靠位置，而是存在每个结点的地址格里。

格子图看得清"分开存"，却看不清顺序。把它简化一下：只画三个结点，按逻辑顺序从左往右摆，方框下面标出结点的地址；地址格里的数字画成箭头，指向那个地址上的结点。

```
head = 100
  │
  ▼
┌───┬─────┐     ┌───┬─────┐     ┌───┬─────┐
│ c │ 109 │────►│ a │ 105 │────►│ t │  0  │
└───┴─────┘     └───┴─────┘     └───┴─────┘
    100             109             105
```

这就是链表的**箭头图**。它和上面的格子图是同一份数据，只是画法不同。格子图按内存位置排，t在a前面；箭头图按逻辑顺序排，t在最后。

两张图一一对应。c结点的地址格写着109，箭头就指向109号的a结点；a结点的地址格写着105，箭头就指向105号的t结点。箭头只是地址的画法，改了地址格里的数字，箭头就跟着变。

后面讲链表，都画箭头图。

<!-- 分页 -->

**取第i个元素**

顺序表取第i个元素，直接就能找到它所在的格子。链表的结点散着放，第i个结点在哪，没法从i算出来。只能从head出发，顺着箭头一个一个数过去。

比如取`cat`的第2个元素t，也就是Get(L, 2)：

```
head = 100
  │
  ▼
┌───┬─────┐     ┌───┬─────┐     ┌───┬─────┐
│ c │ 109 │────►│ a │ 105 │────►│ t │  0  │
└───┴─────┘     └───┴─────┘     └───┴─────┘
    100             109             105
   第0个           第1个           第2个
```

一开始，head是100。到100号，是第0个结点，也就是c结点。

走第1步：c结点的地址格是109，顺着箭头到109号，是第1个结点，也就是a结点。

走第2步：a结点的地址格是105，顺着箭头到105号，是第2个结点，也就是t结点。数到了，取出t。

取第2个走了两步，取第i个就要走i步。位置越靠后，走得越远。这是链表的代价。

这笔账2.13节再算。

显示整行也是这样走：从head出发，每到一个结点就读出它的数据，一直走到地址格是0为止。走的路线是100、109、105，在内存里先往后跳，再往回跳，读出来正好是`cat`。

<!-- 分页 -->

**在中间插入一个字符**

屏幕上是`ca|t`，敲x，应该变成`cax|t`。顺序表要把t往后挪一格。链表不用挪：x放在哪个空格子都行，只要把它接到a和t之间。

假设x放在102号。插入之前：

```
head = 100
  │
  ▼
┌───┬─────┐     ┌───┬─────┐     ┌───┬─────┐
│ c │ 109 │────►│ a │ 105 │────►│ t │  0  │
└───┴─────┘     └───┴─────┘     └───┴─────┘
    100             109             105

                          ┌───┬─────┐
                          │ x │     │
                          └───┴─────┘
                              102
```

x要排在a后面、t前面。改两个地址格就行：

- x的下一个是t，所以x结点的地址格写t的地址105。
- a的下一个变成x，所以a结点的地址格从105改成x的地址102。

插入之后：

```
head = 100
  │
  ▼
┌───┬─────┐     ┌───┬─────┐     ┌───┬─────┐
│ c │ 109 │────►│ a │ 102 │     │ t │  0  │
└───┴─────┘     └───┴───┬─┘     └───┴─────┘
    100             109 │        ▲  105
                        │        │
                        │ ┌───┬──┴──┐
                        └►│ x │ 105 │
                          └───┴─────┘
                              102
```

从head出发：100、109、102、105，读出`caxt`。

c、a、t一个没动，还在原来的格子里。变的只有地址：给x结点的地址格填上105，把a结点的地址格改成102。这就是放弃相邻约定换来的：插入不用挪动元素。

a结点在哪，可以像上一页那样，从head出发走过去找到。

**删除一个字符**

a的下一个要变成t，所以a结点的地址格从102改成t的地址105。

删除之后：

**用C语言表示一个结点**

先只看一个结点。c放在100号，后面没有了，地址格写0。head记着它的地址100：

```
head = 100
  │
  ▼
┌───┬─────┐
│ c │  0  │
└───┴─────┘
    100
```

图里有两样东西：一个结点，一个头指针。下面逐个用C语言表示，再把这个结点造出来。

**结点**。一个结点有两部分：一个字符，一个下一个结点的地址。用2.3学过的结构体表示：

```c
typedef struct Node {
    char         data;    /* 数据格 */
    struct Node *next;    /* 地址格：下一个结点的地址 */
} Node;
```

数据格是`data`，地址格是`next`。`next`存的是地址，所以它是一个指针，箭头图里的箭头就是它。

这里有一处第一次见到的写法：结构体里有一个指向自己这种结构体的指针。下一个结点也是Node，所以`next`的类型是"指向Node的指针"。

名字写了两遍，是因为定义`next`那一行时typedef还没完成，`Node`这个简写还不存在，只能用完整的`struct Node *`。定义结束后，其他地方都可以用`Node`。

**头指针**。head存的是第一个结点的地址，也是一个指针：

```c
Node *head;
```

**造出结点**。顺序表的格子是一次申请一整段。链表的结点是零散的，多一个元素才需要一个结点，所以每个结点单独用2.8讲过的`malloc`申请：

```c
head = (Node *)malloc(sizeof(Node));   /* 申请一个结点，地址存进 head */
head->data = 'c';                      /* 数据格写 c */
head->next = NULL;                     /* 地址格写 0：后面没有了 */
```

`sizeof(Node)`是一个结点占的字节数。malloc返回新结点的地址，存进head，head就指向了这个结点。

`head->data`是"head指向的结点的data"，`head->next`是它的next。地址格里的0，C语言写作`NULL`。

三行代码和图一一对应：malloc造出方框，地址存进head就是从head出发的那个箭头，后两行填好方框的两个格子。

<!-- 分页 -->

**把两个结点连起来**

再敲一个a。分两步：先把a结点造出来，再把它接到c后面。

**造出a结点**。和造c结点一样，用malloc申请，再填好两个格子。这次地址不存进head：head要一直指着第一个结点。另用一个指针q记住新结点。假设a结点在109号：

```
head = 100                  q = 109
  │                           │
  ▼                           ▼
┌───┬─────┐                 ┌───┬─────┐
│ c │  0  │                 │ a │  0  │
└───┴─────┘                 └───┴─────┘
    100                         109
```

```c
Node *q = (Node *)malloc(sizeof(Node));   /* 申请 a 结点，地址存进 q */
q->data = 'a';
q->next = NULL;
```

这时a结点已经有了，但还没接上：c结点的地址格还是0，从head出发走不到它。

**接到c后面**。把c结点的地址格从0改成109，也就是改成q里存的地址。c结点的地址格，在C语言里是`head->next`：

```c
head->next = q;                           /* c 结点的 next 指向 a 结点 */
```

```
head = 100
  │
  ▼
┌───┬─────┐     ┌───┬─────┐
│ c │ 109 │────►│ a │  0  │
└───┴─────┘     └───┴─────┘
    100             109
```

接好之后，`head->next`是109，q也是109，都指向109号的a结点。所以`head->next->data`就是109号结点的data，也就是a；`head->next->next`就是109号结点的next。`->`可以这样连着写，顺着箭头一个一个往后找。

**输出**。从head出发，顺着next把这一行打印出来。完整程序如下，输出`ca`：

```c
#include <stdio.h>
#include <stdlib.h>

typedef struct Node {
    char         data;
    struct Node *next;
} Node;

int main(void) {
    Node *head = (Node *)malloc(sizeof(Node));   /* 造 c 结点 */
    head->data = 'c';
    head->next = NULL;

    Node *q = (Node *)malloc(sizeof(Node));      /* 造 a 结点 */
    q->data = 'a';
    q->next = NULL;
    head->next = q;                              /* 接在 c 后面 */

    for (Node *p = head; p != NULL; p = p->next) /* 顺着 next 打印 */
        printf("%c", p->data);
    printf("\n");                                /* 输出 ca */
    return 0;
}
```

打印用的for循环，就是"取第i个元素"那一页在箭头图上走的路。`p`从第一个结点开始，每次`p = p->next`跳到下一个，直到`p`变成`NULL`，说明走到头了。这是链表最基本的动作。

::: tip 也可以写成while
很多教材把这个循环写成while，两种写法完全等价：

```c
Node *p = head;
while (p != NULL) {
    printf("%c", p->data);
    p = p->next;
}
```

本书用for，是因为"从哪开始、走到哪停、怎么走一步"三件事挤在一行，一眼就能认出这是在遍历链表。两种写法都要能认出来。
:::

为了看清结构，这个程序省掉了两件事：没有检查malloc是不是申请成功，结束前也没有把结点还给系统。后面写成函数时会补上。

这种写法只能演示，不能用来干活：多一个字符，就要多写一层`->next`。把取元素、插入、删除写成通用的操作，是下一节的事。

## 2.10 链表的初始化、插入、取元素：把cat造出来

> **本节问题**：手工搭表要写一串`->next`，不能用来干活。要有通用的操作，而且签名得和顺序表的五个函数一样，编辑器才能原样搬过来。第一个问题：操作的参数——"表"——该是什么？

### 2.10.1 整个表用什么代表：LinkList

顺序表由数组和长度两样东西组成，2.3把它们装进了一个结构体`SeqList`，五个操作的参数都是`SeqList *L`。链表照此办理。

链表只需要记住一样东西：第一个结点的地址`head`。有了它，顺着next就能走完全表，有几个结点、第i个是谁，都能走出来。所以LinkList里只放一个head：

```c
/* 顺序表 */                      /* 链表 */
typedef struct {                  typedef struct {
    char *data;                       Node *head;     /* 第一个结点的地址 */
    int   length;                 } LinkList;
    int   capacity;
} SeqList;
```

链表不需要capacity——它没有"容量"，结点是一个个申请的，用多少申请多少；也不需要length——要知道有几个结点，从head数一遍就行。空表就是`head`为`NULL`。上一节手工搭的`ca`，就是一个`head`指向c结点的LinkList。

从现在起，五个操作的参数都是`LinkList *L`，和`SeqList *L`只差类型名。

**和其他教材的写法对照。** 很多教材不定义新的结构体，而是在定义结点的同时，直接把"指向结点的指针"叫作链表：

```c
/* 其他教材的写法 */
typedef struct LNode {
    char          data;
    struct LNode *next;
} LNode, *LinkList;        /* LinkList 就是 LNode *，和本书的 LinkList 不是一回事 */
```

这一个typedef同时定义了两个名字：`LNode`是结点类型，相当于本书的`Node`；`LinkList`是指向结点的指针。`LNode *p`和`LinkList p`其实是同一个类型，习惯上指一个结点时写前者，代表整个表时写后者。

在那种写法里，一个`LinkList L`本身就是头指针，相当于本书的`L.head`。函数要改头指针时，参数写成`LinkList *L`（C语言）或`LinkList &L`（C++的引用），函数里的`*L`或`L`就相当于本书的`L->head`。两种写法存的东西一样，都只有一个头指针；本书多包一层结构体，是为了让链表和顺序表的操作签名一致：顺序表是`SeqList *L`，链表是`LinkList *L`，只差类型名，编辑器换存储结构时只改这个词。

### 2.10.2 初始化、求长度、取第i个元素

**初始化。** 输入：无。输出：无。副作用：表变成空表。

```c
void Init(LinkList *L) {
    L->head = NULL;
}
```

**求长度。** 输入：无。输出：长度。副作用：无。

没有记长度，就从head出发数一遍：

```c
int Length(LinkList *L) {
    int n = 0;
    for (Node *p = L->head; p != NULL; p = p->next)
        n++;
    return n;
}
```

这和2.9打印`ca`的循环一模一样，只是把打印换成了计数。顺序表的Length是O(1)，这里要走n步，是O(n)；这笔账2.13再算。

**取第i个元素。** 输入：位置i。输出：那个元素。副作用：无。

顺序表的Get是一次下标运算。链表没有下标，第i个结点在哪只有一个办法知道：从head出发，顺着next走i步。以`cat`为例，Get(L, 2)要取t，走0步是c结点，走1步到a结点，走2步到t结点：

```
head
  │
  ▼
┌───┬───┐     ┌───┬───┐     ┌───┬───┐
│ c │ ●─┼────►│ a │ ●─┼────►│ t │ ╱ │
└───┴───┘     └───┴───┘     └───┴───┘
  p 第0步       p 第1步       p 第2步
```

用一个指针`p`记当前走到哪，每走一步`p = p->next`，走够i步停下。位置合不合法也只能走着看：顺序表拿i和length比一下就知道，链表没有记长度，要是还没走够i步p就成了NULL，说明表没有那么长：

```c
char Get(LinkList *L, int i) {
    if (i < 0) return '\0';
    Node *p = L->head;
    for (int k = 0; k < i && p != NULL; k++)
        p = p->next;
    if (p == NULL) return '\0';          /* 表不够长，没有第i个 */
    return p->data;
}
```

带入Get(L, 2)：`p`先指向c结点；k=0时走到a结点；k=1时走到t结点；k=2不满足k<2，循环结束，返回t。再带入Get(L, 5)：走到t结点后再走一步p成了NULL，k=3时p != NULL不成立，循环结束，返回`'\0'`。

"从head走到第i个结点"这个动作，插入和删除也要用，单独抽成一个函数：

```c
Node *NodeAt(LinkList *L, int i) {   /* 返回第i个结点的地址，没有第i个就返回NULL */
    if (i < 0) return NULL;
    Node *p = L->head;
    for (int k = 0; k < i && p != NULL; k++)
        p = p->next;
    return p;
}
```

有了它，Get里的循环就可以交给NodeAt，自己只剩下检查有没有和取数据：

```c
char Get(LinkList *L, int i) {
    Node *p = NodeAt(L, i);
    if (p == NULL) return '\0';          /* 没有第i个 */
    return p->data;
}
```

两个版本的Get做的事完全一样，只是走路那一段搬进了NodeAt。后面Insert和Delete也这样用它：NodeAt返回NULL，就说明位置不合法。

### 2.10.3 在第i个位置插入：三种位置

输入：位置i和元素x。输出：成功或失败。副作用：多了一个结点，长度加1——但和顺序表不同，不挪动任何已有结点，只改地址。改哪些地址取决于插入位置，分三种情况看。

**插在第0个位置。** 比如在`cat`最前面插入b。新造的b结点要成为第一个，那么b结点的next应该指向原来的第一个结点，也就是c结点，而head应该改为指向b结点：

```
head ──────────────┐
                   ▼
┌───┬───┐     ┌───┬───┐     ┌───┬───┐     ┌───┬───┐
│ b │ ●─┼────►│ c │ ●─┼────►│ a │ ●─┼────►│ t │ ╱ │
└───┴───┘     └───┴───┘     └───┴───┘     └───┴───┘
  ▲
  └── head 改为指向这里
```

空表也是这种情况：head是NULL，b结点的next得到NULL，正好是末尾标记；head改为指向b结点。

**插在中间。** 比如在a和t之间插入x，即Insert(L, 2, 'x')，结果应为`caxt`。要改的是x结点的next和a结点的next。但这里有一个顺序表没有的麻烦：手里只有head，a结点在哪并不知道。所以第一步不是改地址，而是找到a结点——NodeAt(L, 1)。找到之后才能改。下面几张图标出地址，看清右格里的数字怎么变。假设x结点放在102号。

第一步，从head走到第1个结点，也就是a结点，用prev记住它：

```
head = 100
  │
  ▼
┌───┬─────┐     ┌───┬─────┐     ┌───┬─────┐
│ c │ 109 │────►│ a │ 105 │────►│ t │  0  │
└───┴─────┘     └───┴─────┘     └───┴─────┘
    100             109             105
                   prev
```

第二步，造出x结点，此时它的next还是0：

```
┌───┬─────┐     ┌───┬─────┐     ┌───┬─────┐
│ c │ 109 │────►│ a │ 105 │────►│ t │  0  │
└───┴─────┘     └───┴─────┘     └───┴─────┘
    100             109             105
                   prev
                          ┌───┬─────┐
                          │ x │  0  │
                          └───┴─────┘
                              102
```

第三步，让x结点的next指向t结点。t结点的地址105现在记在prev的右格里，抄到x结点的右格：

```
┌───┬─────┐     ┌───┬─────┐     ┌───┬─────┐
│ c │ 109 │────►│ a │ 105 │────►│ t │  0  │
└───┴─────┘     └───┴─────┘     └───┴─────┘
    100             109          ▲  105
                   prev          │
                          ┌───┬──┴──┐
                          │ x │ 105 │
                          └───┴─────┘
                              102
```

第四步，让prev的next指向x结点。把a结点的右格从105改成102：

```
┌───┬─────┐     ┌───┬─────┐     ┌───┬─────┐
│ c │ 109 │────►│ a │ 102 │     │ t │  0  │
└───┴─────┘     └───┴───┬─┘     └───┴─────┘
    100             109 │        ▲  105
                   prev │        │
                        │ ┌───┬──┴──┐
                        └►│ x │ 105 │
                          └───┴─────┘
                              102
```

从head出发：100→109→102→105，读出`caxt`。c、t一个没动，只改了两个右格。

第三步和第四步的顺序不能反。如果先做第四步，把a结点的右格改成102，t结点的地址105就没人记着了——它原本只存在a结点的右格里。**先让新结点指向后一个，再让前一个指向新结点**，这是链表插入必须记住的顺序。

四步里只有后两步是真正的插入，第一步"找到前一个结点"是走出来的，位置越靠后走得越远。这一点量效率时会再说。

**插在末尾。** 比如在t后面插入s，Insert(L, 3, 's')。找到第2个结点，也就是t结点，让s结点的next指向t结点的next（是NULL），再让t结点的next指向s结点。和中间插入是同一套动作，只是"后一个"恰好是NULL。

**新建结点。** 不管插在哪，都要先造一个新结点：申请空间，填上字符，next置为NULL。2.9搭`ca`时，这三行写了两遍；以后每次插入都要写，所以把它抽成一个函数：

```c
Node *NewNode(char x) {
    Node *p = (Node *)malloc(sizeof(Node));
    if (p == NULL) return NULL;
    p->data = x;
    p->next = NULL;
    return p;
}
```

函数返回新结点的地址；申请不到时返回NULL，插入就报告失败。

所以三种情况其实是两种：第0个位置改head，其余位置找到第i−1个结点prev、改prev的next。位置合不合法，就看prev找不找得到：NodeAt返回NULL，说明表里没有第i−1个结点，插不进去（i是负数时NodeAt也返回NULL）：

```c
int Insert(LinkList *L, int i, char x) {
    Node *prev = NULL;
    if (i != 0) {
        prev = NodeAt(L, i - 1);         /* 先找到前一个结点 */
        if (prev == NULL) return 0;      /* 没有第i-1个：位置不合法 */
    }
    Node *q = NewNode(x);
    if (q == NULL) return 0;
    if (i == 0) {                        /* 插在最前面：没有前一个结点 */
        q->next = L->head;
        L->head = q;
    } else {
        q->next = prev->next;            /* 先：新结点指向后一个 */
        prev->next = q;                  /* 后：前一个指向新结点 */
    }
    return 1;
}
```

### 2.10.4 验证：用main从空表造出cat

## 2.11 链表的删除与头结点

> **本节问题**：编辑器的退格要删掉一个字符。链表里删掉一个结点，它前后的结点怎么重新连上？删掉的结点去哪了？

### 2.11.1 删除第i个元素

输入：位置i。输出：成功或失败。副作用：少了一个结点，长度减1——同样不挪动任何结点，只改地址，最后把结点的空间还给系统。

以`caxt`为例，删掉位置2的x，回到`cat`。要做的只有一件事：让a结点的next越过x结点直接指向t结点。x结点没人指向了，free掉。

和插入一样，第一步先要找到前一个结点，也就是a结点，NodeAt(L, 1)。改之前，就是2.10插完x的样子：

```
head = 100
  │
  ▼
┌───┬─────┐     ┌───┬─────┐     ┌───┬─────┐     ┌───┬─────┐
│ c │ 109 │────►│ a │ 102 │────►│ x │ 105 │────►│ t │  0  │
└───┴─────┘     └───┴─────┘     └───┴─────┘     └───┴─────┘
    100             109             102             105
                   prev              q
```

第二步，用q记住要删的x结点（它是prev的next）。第三步，把a结点的右格从102改成105——这个105在x结点的右格里，抄过来：

```
head = 100
  │
  ▼
┌───┬─────┐     ┌───┬─────┐                     ┌───┬─────┐
│ c │ 109 │────►│ a │ 105 │────────────────────►│ t │  0  │
└───┴─────┘     └───┴─────┘     ┌───┬─────┐     └───┴─────┘
    100             109         │ x │ 105 │         105
                   prev         └───┴─────┘
                                    102
                                     q
```

x结点还在102号，右格还记着105，但从head出发已经走不到它了：100→109→105，读出`cat`。第四步，free掉102号。这正是插入的后两步倒着走：插入是把t结点的地址从a结点抄给x结点、再让a结点指向x结点；删除是把t结点的地址从x结点抄回a结点、再释放x结点。

第二步"用q记住x结点"不能省。改完a结点的右格之后，x结点就没人指向了，事先没记下它的地址，就再也找不到它，既拿不到105，也没法释放。free也必须放在最后：释放之后q指向的空间就不属于我们了，再读`q->next`是错误。先取用、后释放。

删末尾的元素是同一套动作，只是q的next恰好是NULL。删第0个又是特殊情况：它前面没有结点，改的不是某个结点的next，而是head——让head直接指向第二个结点。和插入一样，需要一个if分支：

```c
int Delete(LinkList *L, int i) {
    Node *q;
    if (i == 0) {                        /* 删第一个：改head */
        q = L->head;
        if (q == NULL) return 0;         /* 空表，没有第0个 */
        L->head = q->next;
    } else {
        Node *prev = NodeAt(L, i - 1);   /* 第一步：找到前一个 */
        if (prev == NULL || prev->next == NULL) return 0;   /* 没有第i个 */
        q = prev->next;                  /* 第二步：记住要删的 */
        prev->next = q->next;            /* 第三步：越过q */
    }
    free(q);                             /* 第四步：释放 */
    return 1;
}
```

位置合不合法，和插入一样靠NodeAt判断，只是多一个条件：要删的是第i个，所以不光第i−1个要存在，它后面还得真有一个结点。

### 2.11.2 验证：插入x再删掉，再删第0个

接着2.10.4的程序：插入x得到`caxt`，删掉它回到`cat`，再删第0个得到`at`：

```c
int main(void) {
    LinkList L;
    Init(&L);
    Insert(&L, 0, 'c');
    Insert(&L, 1, 'a');
    Insert(&L, 2, 't');
    Insert(&L, 2, 'x');                   /* caxt */
    Delete(&L, 2);                        /* cat  */
    Delete(&L, 0);                        /* at   */

    for (int i = 0; i < Length(&L); i++)
        printf("%c", Get(&L, i));
    printf("\n");                          /* 输出 at */
    return 0;
}
```

跟踪Delete(&L, 2)：`prev = NodeAt(L, 1)`得到a结点；`q = prev->next`是x结点；`prev->next = q->next`把105赋给a结点的next；free掉102号。跟踪Delete(&L, 0)：`q = L->head`是c结点；`L->head = q->next`，head变成109，指向a结点；free掉100号。输出`at`。

五个操作到齐了。

### 2.11.3 头结点：去掉两个分支

Insert和Delete各有一个if分支：动第0个位置时改的是head，其余位置改的是某个结点的next。两处代码做的是同一件事——"改前一个的next"——只因为第0个前面没有结点，才不得不另写一遍。有个技巧能把分支去掉。

办法是在链表最前面固定放一个不存数据的结点，叫**头结点**。head永远指向头结点，真正的第0个元素是头结点的next：

```
head
  │
  ▼
┌───┬───┐     ┌───┬───┐     ┌───┬───┐     ┌───┬───┐
│   │ ●─┼────►│ c │ ●─┼────►│ a │ ●─┼────►│ t │ ╱ │
└───┴───┘     └───┴───┘     └───┴───┘     └───┴───┘
 头结点          第0个         第1个         第2个
```

这样第0个元素前面也有一个结点了。删第0个就是"找到它的前一个（头结点），改它的next"，和删其他位置一样；空表也不再是head为NULL，而是head指向一个next为NULL的头结点。

要改的地方：Init要造出头结点；NodeAt要能返回头结点；Length要从头结点的下一个开始数；Insert和Delete的if分支消失。

Init现在要申请一个结点，申请可能失败，所以改为返回是否成功：

```c
int Init(LinkList *L) {
    L->head = NewNode('\0');          /* 头结点，数据无意义 */
    if (L->head == NULL) return 0;
    return 1;
}
```

NodeAt现在从头结点出发。让k从−1开始数：k=−1时p是头结点，走一步k变0、p到第0个……走到k等于i时p就是第i个。这样NodeAt(L, −1)返回头结点，正好是"第0个的前一个"，Insert和Delete不用再区分i是不是0：

```c
Node *NodeAt(LinkList *L, int i) {   /* i=-1 时返回头结点；没有第i个返回NULL */
    if (i < -1) return NULL;
    Node *p = L->head;
    for (int k = -1; k < i && p != NULL; k++)
        p = p->next;
    return p;
}
```

Delete的分支没有了，删第0个时prev就是头结点，走的是同一条路：

```c
int Delete(LinkList *L, int i) {
    Node *prev = NodeAt(L, i - 1);    /* i=0 时得到头结点 */
    if (prev == NULL || prev->next == NULL) return 0;   /* 没有第i个 */
    Node *q = prev->next;
    prev->next = q->next;
    free(q);
    return 1;
}
```

Insert请自己改，Length和Get要注意跳过头结点。从现在起本章都用头结点版本。

**销毁。** 链表的结点是一个个申请的，也要一个个释放，包括头结点。这相当于把表删光，有个陷阱：free掉当前结点后就不能再从它读next了，要先记下下一个再释放当前：

```c
void Destroy(LinkList *L) {
    Node *p = L->head;
    while (p != NULL) {
        Node *next = p->next;         /* 先记下下一个 */
        free(p);
        p = next;
    }
    L->head = NULL;
}
```

> **到这里你有了**：链表的五个操作全部实现（无头结点版），以及头结点的思路和Init、NodeAt、Delete、Destroy。
> **练一练**：（1）实现无头结点版的Delete，用2.11.2的程序运行，确认输出`at`。（2）改成头结点版：Init、NodeAt、Delete照本节，Insert去掉if分支，Get从头结点后开始。用同一个程序运行，输出应仍是`at`；程序末尾加上`Destroy(&L)`。（3）Delete(&L, 5)的返回值是多少？（4）把Delete里的free挪到`prev->next = q->next`之前，程序还能跑对吗？为什么不能这样写？

## 2.12 编辑器2.0：main一行不改

> **本节问题**：链表的五个操作有了。编辑器1.1是搭在顺序表上的，换成链表，要不要重写一遍？

**一个预测**

2.6写编辑器时守了一条纪律：main和Show只调用Init、Length、Get、Insert、Delete，不碰`L.data`和`L.length`。现在链表的五个操作名字、参数、返回值和顺序表完全一样——头结点版的Init也返回成功与否，和2.8的Init一致，Destroy也都有。那么，只要把类型名`SeqList`换成`LinkList`，main应该原样能跑。这是一个预测，下面验证它。

**改动**

Show的参数类型改一个词，`SeqList *L`改成`LinkList *L`：

```c
void Show(LinkList *L, int cursor) {
    int n = Length(L);
    for (int i = 0; i < n; i++) {
        if (i == cursor) printf("|");
        printf("%c", Get(L, i));
    }
    if (cursor == n) printf("|");
    printf("\n");
}
```

main也只改一个词，`SeqList L;`变成`LinkList L;`：

```c
int main(void) {
    LinkList L;
    int cursor = 0;
    char cmd, ch;

    if (!Init(&L)) return 1;
    while (scanf(" %c", &cmd) == 1 && cmd != 'q') {
        switch (cmd) {
        case 'i':
            scanf(" %c", &ch);
            if (ch == '_') ch = ' ';
            if (Insert(&L, cursor, ch)) cursor++;
            else printf("插入失败\n");
            break;
        case 'd':
            if (cursor > 0) { Delete(&L, cursor - 1); cursor--; }
            break;
        case 'l':
            if (cursor > 0) cursor--;
            break;
        case 'r':
            if (cursor < Length(&L)) cursor++;
            break;
        }
        Show(&L, cursor);
    }
    Destroy(&L);
    return 0;
}
```

把这两段和链表的五个操作放在一起编译，顺序表的代码一行不要。

**为什么能这样**

这不是巧合，是从2.1到现在一路铺垫的目的。抽象数据类型把"能做什么"和"怎么做到"分开：编辑器只依赖前者，所以后者随便换。反过来想，如果2.6图省事写了`L.data[cursor] = ch`，现在就得重写整个main——链表根本没有`data`数组。

实际工程里通常把线性表的实现放在单独的文件里（比如`seqlist.c`和`linklist.c`），编辑器只包含一个头文件；换实现就是换一个文件。本书为了阅读方便把代码写在一起，思路是一样的。

## 2.13 链表的时间复杂度

> **本节问题**：用2.7的方法量链表：五个操作的步数和表长n各是什么关系？编辑器2.0到底快没快？

**数什么**

规则和2.7一样：读写一个格子、一次比较、一次赋值各算一步。链表的操作里，步数几乎全来自"顺着next走"的循环——每走一步读一次next。所以量链表，数走了多少步就够。设表长为n。

**逐个操作**

Init造一个头结点，固定几步，O(1)。

Length要从第0个结点数到最后一个，走n步，O(n)。

Get(L, i)的全部工作在NodeAt里：从头结点出发走i+1步。i最小是0，走1步；i最大是n−1，走n步。最坏O(n)，平均走n/2步，也是O(n)。这是链表和顺序表差别最大的地方：顺序表Get是一次乘法加一次加法算出地址（起始地址 + i × 每个元素的字节数），O(1)；链表没有地址可算，只能一站一站走。

Insert(L, i, x)分两段。第一段NodeAt(L, i−1)，走i步找到前一个结点，最坏O(n)；第二段造结点、改两个地址，固定几步，O(1)。加起来O(n)。

Delete同理，定位O(n)，越过并释放O(1)，合计O(n)。

Destroy要释放每一个结点，O(n)。

**和顺序表放在一起**

| 操作 | 顺序表 | 链表 |
|---|---|---|
| Init | O(1) | O(1) |
| Length | O(1) | O(n) |
| Get | O(1) | O(n) |
| Insert、Delete | O(n) | O(n) |

Insert和Delete两边都是O(n)，但慢的原因不同。顺序表定位是O(1)，慢在挪动后面的元素；链表不挪动任何元素，改地址只要O(1)，慢在定位——要从头走到第i−1个。也就是说，**链表的插入删除本身是O(1)，前提是已经站在前一个结点上**。如果不需要从头走，链表就赢了；如果每次都要从头走，链表并没有比顺序表好。

Get和Length则是链表单方面吃亏：顺序表O(1)，链表O(n)。Get慢，是因为放弃了"相邻格子放相邻元素"那条约定，按位置算地址的好处也就一并放弃了；Length慢，只是因为没有记长度，要记也可以，见练一练（4）。

**回到编辑器**

编辑器2.0的光标是一个整数。每敲一个字符，Insert要先用NodeAt从头结点走到光标位置，再改两个地址——定位那一段和顺序表的挪动一样是O(n)。换了链表，每按一个键还是O(n)，2.7的问题并没有解决。

更糟的是显示。Show从0到n−1逐个Get，链表的每次Get都从头走，n次Get合计约n²/2步，O(n²)；顺序表的Show是n次O(1)的Get，O(n)。编辑器每处理一条指令都要Show一次，换成链表之后显示反而慢了一个量级——这正是2.7练习3的答案。右移光标前要调Length看是不是已到行尾，这一下也从O(1)变成了O(n)。

问题出在哪？链表的优势是"站在前一个结点上时，插入删除O(1)"，而编辑器的光标是一个整数，每次都要重新从头走到那个位置，优势完全没用上。光标本来就一直停在编辑的位置，为什么不让它直接记住那个结点，而要记一个数字再从头找？这就是下一节要做的事。

> **到这里你有了**：链表五个操作的复杂度表，以及编辑器2.0并没有更快的结论。
> **练一练**：（1）在长度为n的链表上，在位置0插入和在位置n插入，NodeAt各走多少步？和顺序表的两种情况对照，哪头快、哪头慢正好怎样？由此回答2.12练一练（3）。（2）显示一个100字符的行，链表版的NodeAt总共走多少步？（3）如果Show不用Get，而是直接顺着next走一遍，Show是多少？这个改法和2.12练一练（2）的结论矛盾吗？（4）给LinkList加一个成员`int length`记结点个数，Length变成多少？Init、Insert、Delete、Destroy各要多做什么？忘了在某处维护它，会出什么错？
> **下一步**：让光标记住结点。

## 2.14 光标记住结点：编辑器2.1

> **本节问题**：让光标直接记住结点，每次插入就不用从头走了。可是五个操作只接受整数位置，光标手里拿着的是结点指针，调用不了它们。接口该怎么变？

### 2.14.1 光标记哪个结点

编辑器的插入点在`|`处。`|`前面那个字符的结点，正是"插入时的前一个结点"，让光标指向它最方便：敲字符就是在光标结点后面插入，然后光标移到新结点上。光标在行首时，`|`前面没有字符，让它指向头结点——头结点在这里又派上了用场，行首不再特殊。

```
                                cursor
                                  │
                                  ▼
┌───┬───┐     ┌───┬───┐     ┌───┬───┐     ┌───┬───┐
│   │ ●─┼────►│ c │ ●─┼────►│ a │ ●─┼────►│ t │ ╱ │
└───┴───┘     └───┴───┘     └───┴───┘     └───┴───┘
 头结点

屏幕显示：ca|t
```

### 2.14.2 接口要跟着变

现在的Insert(L, i, x)、Delete(L, i)只接受整数位置。这不是链表的问题，是2.2节定义操作集时默认了"位置就是整数"——对顺序表天然合适，对链表就不合适：整数位置每次都要从头数，而链表真正擅长的是"站在一个结点上，一步改邻居"。

所以要给线性表增加一组以结点为位置的操作。按编辑器的五件事来定：敲字符要"在光标后面插入"，退格要"删掉光标这个结点"，左移右移要"前一个、后一个"，显示要"从头开始逐个取"。六个操作：

| 操作 | 含义 | 前提 |
|---|---|---|
| Head(L) | 返回头结点，即第0个元素之前的位置 | |
| Next(p) | 返回p的后一个结点，p是最后一个时返回NULL | p是表中结点 |
| Prev(L, p) | 返回p的前一个结点，p是头结点时返回NULL | p是表中结点 |
| Data(p) | 返回p处的元素 | p是表中结点，不是头结点 |
| InsertAfter(L, p, x) | 在p后面插入x，成功返回1，失败返回0 | p是表中结点 |
| DeleteNode(L, p) | 删除p这个结点，成功返回1；p是头结点时不删，返回0 | p是表中结点 |

原来的五个整数位置操作一个不少，而且可以用新操作改写：Insert(L, i, x)就是InsertAfter(L, NodeAt(L, i−1), x)，Delete(L, i)就是DeleteNode(L, NodeAt(L, i))。两套接口是一套东西，只是位置的表示不同。

要说明的是，2.12能做到"main一行不改"，是因为只换了实现、没动接口；这次main要改，是因为接口变了。接口本身也会影响效率，2.16会回头讨论。

### 2.14.3 在单链表上实现

前四个和InsertAfter都很直接，InsertAfter就是2.10的Insert去掉定位那一段：

```c
Node *Head(LinkList *L) { return L->head; }
Node *Next(Node *p)     { return p->next; }
char  Data(Node *p)     { return p->data; }

int InsertAfter(LinkList *L, Node *p, char x) {
    Node *q = NewNode(x);
    if (q == NULL) return 0;
    q->next = p->next;
    p->next = q;
    return 1;
}
```

Prev和DeleteNode就没这么顺利。单链表的结点只记着后一个，前一个在哪没有任何记录，Prev唯一的办法是从头结点开始走，走到某个结点的next等于p为止。DeleteNode要把p从链上摘下来，必须改p前一个结点的next，所以它也得先调Prev：

```c
Node *Prev(LinkList *L, Node *p) {     /* 单链表上只能从头走 */
    Node *q = L->head;
    while (q != NULL && q->next != p) q = q->next;
    return q;                          /* p是头结点或不在表里时，走到头得到NULL */
}

int DeleteNode(LinkList *L, Node *p) {
    if (p == NULL) return 0;
    Node *prev = Prev(L, p);           /* 这一步是O(n)的 */
    if (prev == NULL) return 0;        /* p是头结点或不在表里，不能删 */
    prev->next = p->next;
    free(p);
    return 1;
}
```

Prev的循环条件里`q != NULL`不能省。p是头结点时，没有哪个结点的next等于它，q会一直走到最后一个结点、再走到NULL；这时如果不先判断，就会去读NULL的next，程序崩溃。空表最容易碰上：空表里只有头结点，传进来的p只可能是它。加上这个判断，Prev走到头就返回NULL，DeleteNode看到NULL就不删，返回0。

要看清楚：这两个函数从外面看和其他操作一样，一次调用；但里面各藏着一个从头走的循环，O(n)。接口对了，代价还在。

### 2.14.4 验证：编辑器2.1

main只用这六个操作。光标是`Node *cursor`，初始指向头结点；显示顺着结点走一遍，走到光标结点时在它后面打`|`，光标是头结点时`|`打在最前面：

```c
void Show(LinkList *L, Node *cursor) {
    if (cursor == Head(L)) printf("|");
    for (Node *p = Next(Head(L)); p != NULL; p = Next(p)) {
        printf("%c", Data(p));
        if (p == cursor) printf("|");
    }
    printf("\n");
}

int main(void) {
    LinkList L;
    Node *cursor;
    char cmd, ch;

    if (!Init(&L)) return 1;
    cursor = Head(&L);                     /* 行首 */
    while (scanf(" %c", &cmd) == 1 && cmd != 'q') {
        switch (cmd) {
        case 'i':
            scanf(" %c", &ch);
            if (ch == '_') ch = ' ';
            if (InsertAfter(&L, cursor, ch)) cursor = Next(cursor);
            else printf("插入失败\n");
            break;
        case 'd':
            if (cursor != Head(&L)) {
                Node *dead = cursor;
                cursor = Prev(&L, cursor);
                DeleteNode(&L, dead);
            }
            break;
        case 'l':
            if (cursor != Head(&L)) cursor = Prev(&L, cursor);
            break;
        case 'r':
            if (Next(cursor) != NULL) cursor = Next(cursor);
            break;
        }
        Show(&L, cursor);
    }
    Destroy(&L);
    return 0;
}
```

退格里的顺序有讲究：先把光标退到前一个，再删原来的光标结点；反过来先删，就没法再问它的前一个是谁了。

输入2.6的会话，输出仍然是`c|`、`ca|`、`cat|`、`ca|t`、`cax|t`、`ca|t`、`cat|`。功能对了，再看效率：

| 动作 | 2.0 整数光标 | 2.1 结点光标 |
|---|---|---|
| 敲字符 | O(n) | O(1) |
| 右移 | O(n) | O(1) |
| 显示 | O(n²) | O(n) |
| 退格 | O(n) | O(n) |
| 左移 | O(1) | O(n) |

敲字符、右移和显示好了，退格还是O(n)，左移反而从O(1)变成了O(n)——它们都要问"前一个是谁"，而单链表回答这个问题只能从头走。问题解决了一半。

> **到这里你有了**：结点位置的六个操作和编辑器2.1，敲字符、显示不再从头走。
> **练一练**：（1）实现六个操作，写出Show和main，输入2.6的会话，逐行核对输出。（2）光标在行尾时按一次`l`，Prev走多少步？光标在第2个字符后呢？（3）如果让光标记`|`右边那个字符而不是左边那个，敲字符时需要什么操作？行尾时光标记什么？（4）用InsertAfter和NodeAt重写Insert(L, i, x)，用2.10.4的程序验证。

## 2.15 双向链表：编辑器2.2

> **本节问题**：左移和退格都要问"p的前一个是谁"，单链表只能从头走一遍才能回答，O(n)。能不能让它也一步回答？

### 2.15.1 让结点也记住前一个

单链表的结点只记后一个，所以"后一个是谁"一步可答，"前一个是谁"要从头找。既然记一个地址就能一步找到后一个，那就再记一个地址，一步找到前一个：每个结点三格，中间是数据，两边各一个地址。这样的链表叫**双向链表**。头结点的prev是NULL，最后一个结点的next是NULL：

```
head
  │
  ▼
┌───┬───┬───┐    ┌───┬───┬───┐    ┌───┬───┬───┐    ┌───┬───┬───┐
│ ╱ │   │ ●─┼───►│   │ c │ ●─┼───►│   │ a │ ●─┼───►│   │ t │ ╱ │
│   │   │   │◄───┼─● │   │   │◄───┼─● │   │   │◄───┼─● │   │   │
└───┴───┴───┘    └───┴───┴───┘    └───┴───┴───┘    └───┴───┴───┘
    头结点
```

代价是每个结点多占一个地址的空间。换来的是：站在任何一个结点上，前一个和后一个都是一步可达。

接口不用变。2.14定的六个操作说的是"做什么"，双向链表只是换了一种"怎么做"——和2.12换存储结构是同一回事，所以编辑器的main应该又一次一行不改。要重写的只有四个实现：结点多了一根线，凡是接线、断线的函数都要照顾它。

### 2.15.2 重写四个实现

结点多一个成员：

```c
typedef struct Node {
    struct Node *prev;    /* 前一个结点的地址 */
    char         data;
    struct Node *next;    /* 下一个结点的地址 */
} Node;
```

NewNode多初始化一个prev：

```c
Node *NewNode(char x) {
    Node *p = (Node *)malloc(sizeof(Node));
    if (p == NULL) return NULL;
    p->prev = NULL;
    p->data = x;
    p->next = NULL;
    return p;
}
```

Prev一步完成。参数L用不上了，保留是为了签名和单链表版本一致，main不用改：

```c
Node *Prev(LinkList *L, Node *p) { return p->prev; }
```

InsertAfter在p后面插q，单链表接两根线，双向链表要接四根：q的prev和next，p的next，以及p原来的后一个（叫它r）的prev。p可能是最后一个结点，这时没有r，那一根不用接：

```
       p                q                r
  ┌───┬───┬───┐    ┌───┬───┬───┐    ┌───┬───┬───┐
  │   │ a │ ④─┼───►│ ① │ x │ ②─┼───►│ ③ │ t │   │
  │   │   │   │◄───┼── │   │   │◄───┼── │   │   │
  └───┴───┴───┘    └───┴───┴───┘    └───┴───┴───┘
  ① q->prev = p     ② q->next = r     ③ r->prev = q     ④ p->next = q
```

```c
int InsertAfter(LinkList *L, Node *p, char x) {
    Node *q = NewNode(x);
    if (q == NULL) return 0;
    q->prev = p;                              /* ① */
    q->next = p->next;                        /* ② */
    if (p->next != NULL) p->next->prev = q;   /* ③，p是末尾时跳过 */
    p->next = q;                              /* ④ */
    return 1;
}
```

顺序仍然要注意：②③都要用到`p->next`，也就是r，所以改`p->next`的④放最后，否则r就找不到了。

DeleteNode不再需要从头找前一个：让p的前一个越过p指向p的后一个，让p的后一个（如果有）越过p指回p的前一个，然后释放p。p是头结点时它的prev是NULL，没有前一个可改，直接返回0：

```c
int DeleteNode(LinkList *L, Node *p) {
    if (p == NULL || p->prev == NULL) return 0;   /* 头结点不能删 */
    p->prev->next = p->next;
    if (p->next != NULL) p->next->prev = p->prev;
    free(p);
    return 1;
}
```

Head、Next、Data、Length、Get、NodeAt、Destroy都不用改。整数位置的Insert和Delete改成调用新操作，prev指针就自动维护好了：

```c
int Insert(LinkList *L, int i, char x) {
    Node *prev = NodeAt(L, i - 1);       /* i=0 时得到头结点 */
    if (prev == NULL) return 0;          /* 位置不合法 */
    return InsertAfter(L, prev, x);
}

int Delete(LinkList *L, int i) {
    if (i < 0) return 0;                 /* 头结点不能删 */
    Node *p = NodeAt(L, i);
    if (p == NULL) return 0;             /* 没有第i个 */
    return DeleteNode(L, p);
}
```

### 2.15.3 验证：编辑器2.2，main一行不改

编辑器2.1的main和Show一个字不动，换上双向链表的实现重新编译，输入2.6的会话，输出完全相同。这就是编辑器2.2。

用这段会话跟踪一遍，看双向链表上光标怎么动：

- `i c`：光标在头结点，InsertAfter在头结点后面插入c：c结点的prev是头结点、next是NULL，头结点的next改为c结点；光标移到c结点。显示`c|`。
- `i a`、`i t`：同理，光标依次到a结点、t结点。显示`cat|`。
- `l`：光标从t结点退到Prev(t结点)，一步读到a结点。显示`ca|t`。
- `i x`：在a结点后面插x：x结点的prev是a结点、next是t结点，t结点的prev改为x结点，a结点的next改为x结点；光标到x结点。显示`cax|t`。
- `d`：光标结点是x结点，先退到Prev(x结点)即a结点，再DeleteNode(x结点)：a结点的next改为t结点，t结点的prev改为a结点，释放x结点。显示`ca|t`。
- `r`：光标到Next(a结点)即t结点。显示`cat|`。

每一步都只动了光标附近的几根线，和整行有多长没有关系。

**时间复杂度。** 六个结点位置操作在两种链表上：

| 操作 | 单链表 | 双向链表 |
|---|---|---|
| Head、Next、Data | O(1) | O(1) |
| InsertAfter | O(1) | O(1) |
| Prev | O(n) | O(1) |
| DeleteNode | O(n) | O(1) |

编辑器的四个版本放在一起：

| 动作 | 1.1 顺序表 | 2.0 链表，整数光标 | 2.1 单链表，结点光标 | 2.2 双向链表，结点光标 |
|---|---|---|---|---|
| 敲字符 | O(n) | O(n) | O(1) | O(1) |
| 退格 | O(n) | O(n) | O(n) | O(1) |
| 左移 | O(1) | O(1) | O(n) | O(1) |
| 右移 | O(1) | O(n) | O(1) | O(1) |
| 显示 | O(n) | O(n²) | O(n) | O(n) |

2.7提出的问题——在行首打字慢——到这里才真正解决：不管光标在哪，敲一个字符、退格、移动光标都是O(1)。显示O(n)无法避免，n个字符总要一个个打出来。

回头看这一路：换成链表本身并没有让编辑器变快（2.0），让它变快的是"让光标记住结点"这个改动，而它要求接口能表达"结点位置"（2.1）；接口定对之后，单链表上还有两个操作藏着O(n)，最后为了前后都能一步走，把链表改成了双向（2.2）。存储结构、接口、应用三者是一起变的。

> **到这里你有了**：双向链表，以及敲字符、退格、移动光标都是O(1)的编辑器2.2。
