# 第2章 线性表

## 2.1 任务：单行编辑器，以及怎么分解它

> **本节问题**：要做一个单行编辑器，它到底要做什么？这个任务怎么拆成程序能处理的东西？

### 2.1.1 任务是什么

这一章要做一个单行编辑器。它只管一行文字，用户能做的事只有五件。真正的编辑器直接读键盘，每按一个键立刻响应；为了把程序写得简单，我们用一行指令代替一次按键：

| 指令 | 相当于 | 效果 |
|---|---|---|
| `i c` | 敲字符c | c插入到光标处，光标移到它后面 |
| `d` | 按退格键 | 删掉光标前面那个字符，光标跟着前移 |
| `l` | 按左方向键 | 光标左移一格，已在行首则不动 |
| `r` | 按右方向键 | 光标右移一格，已在行尾则不动 |
| `q` | 退出 | |

每处理一条指令，程序都把整行内容打印出来，光标位置用`|`标出。

不做的事也说清楚：不换行，不保存文件，不选中、复制、粘贴，字符只考虑英文字母和空格（空格用`_`输入）。支持多行需要把"行"本身也组织起来，那是另一种结构，本章末尾的拓展会提一下。

程序运行起来应该是这样（左边是输入的指令，右边是程序的输出）：

```
i c       c|
i a       ca|
i t       cat|
l         ca|t
i x       cax|t
d         ca|t
r         cat|
q
```

本章结束时，我们要有一个能这样运行的程序。

### 2.1.2 分解：数据、关系、操作

程序要处理的是"一行文字"。这个东西怎么在程序里表示？先问三个问题。

**数据是什么？** 是这一行里的字符。上面的会话里，就是c、a、t三个字符，中途多过一个x。

**字符之间是什么关系？** 每个字符前面最多一个字符、后面最多一个字符，排成一列。顺序不能乱，`ca`和`ac`是两行不同的文字；字符可以重复，`aa`是合法的一行。所以这不是一堆无序的字符，而是一个有先后的序列，字符之间是一对一的前后关系。

**要对字符做什么？** 从五条指令反推：插入一个字符、删除一个字符、读出每个字符来显示。左右移动不改字符，只改一个位置。

三个问题的答案合起来，就是这个任务的模型：一个字符序列，加上插入、删除、读取这几个操作。把"字符"换成任意类型的元素，这个模型就是**线性表**：n个同类型元素排成一列，相邻元素之间是一对一的前后关系，记作 (a₀, a₁, …, aₙ₋₁)。n叫长度，n=0是空表。本书约定位置从0开始编号，和C语言数组一致。

线性表上要能做的最基本的操作有五个：

| 操作 | 含义 | 前提 |
|---|---|---|
| Init(L) | 建立一个空表 | |
| Length(L) | 返回表的长度n | |
| Get(L, i) | 返回第i个元素 | 0 ≤ i < n |
| Insert(L, i, x) | 在第i个位置插入x，原第i个及之后的元素依次后移 | 0 ≤ i ≤ n |
| Delete(L, i) | 删除第i个元素，之后的元素依次前移 | 0 ≤ i < n |

Insert允许i=n，表示追加到末尾；Delete不允许。表会不会满、位置越界了怎么办，是实现时的事，这里只规定合法的前提。

"元素之间的关系"加上"能做的操作"，这样一份描述叫**抽象数据类型**。它只说线性表是什么、能做什么，不说怎么存、怎么做——那是后面各节的事。

### 2.1.3 编辑器的指令落到操作上

线性表没有光标，光标是编辑器自己的东西。看一个具体状态就能弄清它该怎么记：

```
位置：   0   1   2
        c   a | t
```

三个字符占位置0、1、2，`|`夹在a和t之间。这时敲x，x要出现在`|`的地方，也就是插在a后面、t前面——t现在的位置是2，x插进去就占位置2，t被挤到3：

```
位置：   0   1   2   3
        c   a   x | t
```

所以`|`可以用一个数来记：它右边那个字符的位置。`ca|t`里是2，插入x就是Insert(L, 2, x)。插完之后`|`右边还是t，但t已经在3了，光标变成3。

退格删的是`|`左边那个字符。`ca|t`里左边是a，a在位置1，也就是光标减1：Delete(L, 1)，删完光标回到1，屏幕`c|t`。

把这个记法用到边界上：`|`在最后一个字符之后时右边没有字符，光标就是长度，`cat|`里是3；空行时光标是0，也就是行首。左右移动只是把这个数减1或加1，减到0、加到长度就不再动。

这个数叫`cursor`。五条指令逐一翻译：

| 指令 | 对线性表的操作 | 对光标的操作 |
|---|---|---|
| `i c` | Insert(L, cursor, c) | cursor加1 |
| `d` | Delete(L, cursor−1)，cursor为0时不做 | cursor减1 |
| `l` | 无 | cursor减1，已为0则不动 |
| `r` | 无 | cursor加1，已等于Length(L)则不动 |
| 显示 | 对i从0到Length(L)−1逐个Get(L, i)，在第cursor个字符前打`\|` | 无 |

每一条指令都只用到这五个操作，没有一条需要知道字符是怎么存的。

### 2.1.4 在纸上跑一遍

把2.1.1的会话按上面的表翻译一遍，看结果是否一致：

| 指令 | 调用 | 表的内容 | cursor | 屏幕 |
|---|---|---|---|---|
| 开始 | Init(L) | () | 0 | `\|` |
| `i c` | Insert(L, 0, c) | (c) | 1 | `c\|` |

| `d` | Delete(L, 2) | (c, a, t) | 2 | `ca\|t` |
| `r` | — | (c, a, t) | 3 | `cat\|` |

## 2.2 把线性表放进内存：顺序表

> **本节问题**：线性表怎么放进计算机的内存？数据要放进去，数据之间"谁在谁后面"的关系也要放进去。

**内存长什么样**

内存可以看成一长排编了号的格子，每个格子放一个字节，编号叫地址。程序读写数据就是按地址找格子。下面画其中一段，编号从100到115（省略号表示前后还有很多格子）：

```
  ┌───┬───┬───┬───┬───┬───┬───┬───┬───┬───┬───┬───┬───┬───┬───┬───┐
… │   │   │   │   │   │   │   │   │   │   │   │   │   │   │   │   │ …
  └───┴───┴───┴───┴───┴───┴───┴───┴───┴───┴───┴───┴───┴───┴───┴───┘
   100 101 102 103 104 105 106 107 108 109 110 111 112 113 114 115
```

这排格子只有一种天然的关系：前后相邻。100号后面是101号，仅此而已。

**最直接的放法**

以`cat`为例。三个字符放进三个格子没有困难，问题是"a在c后面"这条关系放在哪。最直接的想法是：让它就在c后面。c放100号，a放101号，t放102号——字符在内存里的先后，就是它们在线性表里的先后：

```
  ┌───┬───┬───┬───┬───┬───┬───┬───┬───┐
… │ c │ a │ t │   │   │   │   │   │   │ …
  └───┴───┴───┴───┴───┴───┴───┴───┴───┘
   100 101 102 103 104 105 106 107 108
```

关系没有单独占地方，它藏在位置里：约定"相邻格子放相邻元素"，那么a在101号、c在100号，两格相邻，"a在c后面"就成立了。数据和关系都存下来了，而且关系一个字节都不占。

这种存法叫**顺序存储**，这样存的线性表叫**顺序表**。

**还差一样东西**

上面的图有个漏洞。103号往后的格子里是什么？没人知道，可能是这段内存上次留下的任何东西。要把这一行显示出来，从100号开始读，读到哪里停？

所以除了这段格子，还得另外记一个数：现在有效的字符有几个。`cat`是3，读三个就停；插入一个变成4，删掉一个变成2。这个数就是线性表的长度。

**用C表示**

一段连续的格子，在C语言里就是数组。数组的大小编译时就要定下来，先定100，够不够用后面再说：

```c
#define MAXSIZE 100

char data[MAXSIZE];   /* 一段连续的格子 */
int  length;          /* 当前有效的元素个数 */
```

`data[0]`到`data[length-1]`是有效元素，`data[length]`往后是空闲的。`cat`存进去就是`data[0]`到`data[2]`，length为3。

**装成一个整体**

线性表是一个东西，现在却由两个变量表示：数组和长度。后面每个操作都要同时用到这两样，分开放很容易忘掉一个。C语言用结构体把几个变量装成一个整体：

```c
typedef struct {
    char data[MAXSIZE];   /* 存放元素的连续空间 */
    int  length;          /* 当前元素个数 */
} SeqList;
```

`SeqList`就是"顺序表"这个类型，一个`SeqList`变量里有一个数组和一个长度，用点号访问：`L.data[i]`、`L.length`。元素类型写成`char`是因为本章存的是字符，要存别的类型，把`char`换掉即可。

**验证：写第一个程序**

把`cat`手工放进一个顺序表，再读回来。读回整行就是从`data[0]`开始读`length`个；取第i个就是`data[i]`：

```c
#include <stdio.h>

#define MAXSIZE 100

typedef struct {
    char data[MAXSIZE];
    int  length;
} SeqList;

int main(void) {
    SeqList L;
    L.data[0] = 'c';
    L.data[1] = 'a';
    L.data[2] = 't';
    L.length = 3;

    for (int i = 0; i < L.length; i++)    /* 读回整行 */
        printf("%c", L.data[i]);
    printf("\n");

    printf("%c\n", L.data[2]);           /* 直接取第2个 */
    return 0;
}
```

输出：

```
cat
t
```

第一行说明关系没丢：按位置从0读到length−1，顺序和线性表一致，"a在c后面"不需要任何额外记录。第二行说明取第i个元素一步到位，不用经过前面的元素，后面比较效率时会再提这一点。

可以顺手试一下漏洞：把循环条件改成`i < 5`，多读两个格子，屏幕上会多出两个谁也说不准的字符——那两个格子里是这段内存上次留下的东西。这就是为什么必须有length。

这里是手工把字符放进数组的，只为看清结构。下一节有了操作之后，就不再直接碰`data`和`length`了。

> **到这里你有了**：顺序表的结构，和一个把`cat`放进去再读出来的程序。
> **练一练**：（1）把2.2的程序敲出来运行，确认输出`cat`和`t`。（2）把循环条件改成`i < 5`，多出来的两个字符是什么？再运行一次，还是同样的吗？（3）把`L.length`改成2，输出是什么？这说明长度和格子里的内容哪个说了算？

## 2.3 初始化、插入、取元素：把cat造出来

> **本节问题**：结构有了，五个操作怎么在这个结构上做？在中间插入一个元素，占着那个位置的元素怎么办？

操作是2.1.2那张表里的规定，只说"做什么"；在C语言里，每个操作用一个函数来实现，函数体说"怎么做"。从操作到函数，先要想清楚三件事：

- **输入**：调用它需要提供什么？这是函数的参数。
- **输出**：它要交回什么？这是函数的返回值。
- **副作用**：表本身变不变？变的是数组里的内容、长度，还是都变？

有的操作可能失败（位置不合法、表满了），这类函数的返回值用一个整数报告成败：1成功，0失败。

五个操作分两节做。这一节先做初始化、求长度、取元素、插入四个——有了它们就能从空表把一行字符造出来并显示；删除放到下一节。

为了先把注意力集中在操作本身，这一节把顺序表定义成一个全局变量`L`，函数直接访问它，不通过参数传递：

```c
SeqList L;    /* 全局的顺序表 */
```

结构体的成员用点号访问，`L.length`是长度，`L.data[i]`是第i个格子。

### 2.3.1 初始化、求长度、取第i个元素

**初始化。** 输入：无。输出：无。副作用：表变成空表。空表就是长度为0，数组里原来有什么无所谓，length为0意味着没有任何格子是有效的。

```c
void Init(void) {
    L.length = 0;
}
```

**求长度。** 输入：无。输出：长度。副作用：无。

```c
int Length(void) {
    return L.length;
}
```

**取第i个元素。** 输入：位置i。输出：那个元素；i不合法时返回`'\0'`表示出错。副作用：无。第i个元素就在`data[i]`，一次下标运算就拿到，不管表多长。

```c
char Get(int i) {
    if (i < 0 || i >= L.length) return '\0';
    return L.data[i];
}
```

### 2.3.2 在第i个位置插入

输入：位置i和元素x。输出：成功或失败。副作用：数组和长度都变——x进了数组，长度加1，而且原来第i个及之后的元素要依次后移。最后这一条是本节要仔细想的地方。

以`cat`为例，在位置1插入x，结果应为`cxat`。插入前：

```
      ┌───┬───┬───┬───┬───┐
data  │ c │ a │ t │   │   │   length = 3
      └───┴───┴───┴───┴───┘
        0   1   2   3   4
```

x要放进`data[1]`，但`data[1]`被a占着。为了保持"相邻格子放相邻元素"的约定，a和t都要往后挪一格，把`data[1]`腾出来：

```
      ┌───┬───┬───┬───┬───┐
data  │ c │ x │ a │ t │   │   length = 4
      └───┴───┴───┴───┴───┘
        0   1   2   3   4
```

挪动的顺序很关键。如果从前往后挪——先把`data[1]`的a挪到`data[2]`——`data[2]`原来的t就被覆盖丢掉了。所以必须**从最后一个元素开始，倒着往后挪**：先把t从`data[2]`挪到`data[3]`，再把a从`data[1]`挪到`data[2]`，这样每次挪动的目标格子都已经是空的。挪完把x放进`data[1]`，长度加1。

```c
int Insert(int i, char x) {
    if (i < 0 || i > L.length) return 0;      /* 位置不合法 */
    if (L.length == MAXSIZE)   return 0;      /* 表满 */
    for (int j = L.length; j > i; j--)        /* 从后往前挪 */
        L.data[j] = L.data[j - 1];
    L.data[i] = x;
    L.length++;
    return 1;
}
```

带入Insert(1, 'x')：j从3开始，`data[3] = data[2]`把t挪过去；j=2，`data[2] = data[1]`把a挪过去；j=1不满足j>1，循环结束；`data[1] = 'x'`，长度变4。

i允许等于length，这时循环一次都不执行，x直接放到末尾，就是追加。插入位置越靠前、表越长，要挪的元素就越多，这一点2.7节量效率时会回来看。

### 2.3.3 验证：从空表造出cat

四个操作够不够用？用它们做2.1.4纸上跑过的前三步：从空表开始，Insert三次造出`cat`，再用Length和Get把它显示出来：

```c
int main(void) {
    Init();
    Insert(0, 'c');            /* (c)       */
    Insert(1, 'a');            /* (c, a)    */
    Insert(2, 't');            /* (c, a, t) */

    for (int i = 0; i < Length(); i++)
        printf("%c", Get(i));
    printf("\n");              /* 输出 cat */
    return 0;
}
```

三次Insert都是追加到末尾，每次length加1，挪动循环一次都不执行。改一下试试在中间插：把第三次改成`Insert(1, 't')`，t会挤到a前面，输出`cta`——这正是2.3.2分析过的挪动。

上一节的程序是手工往数组里放字符，这个程序只调用了操作，没有碰`L.data`和`L.length`。以后都这样写。

## 2.4 删除

> **本节问题**：编辑器的退格键要删掉一个字符。在顺序表里删掉中间一个元素，它留下的空格子怎么办？

### 2.4.1 删除第i个元素

输入：位置i。输出：成功或失败。副作用：数组和长度都变——第i个元素没了，长度减1，之后的元素依次前移。

以上一节插入后的`cxat`为例，删掉位置1的x，结果应回到`cat`。删除前：

```
      ┌───┬───┬───┬───┬───┐
data  │ c │ x │ a │ t │   │   length = 4
      └───┴───┴───┴───┴───┘
        0   1   2   3   4
```

x删掉之后`data[1]`空了一格。按"相邻格子放相邻元素"的约定，c的下一个应该是a，a必须挪到`data[1]`，t跟着挪到`data[2]`：

```
      ┌───┬───┬───┬───┬───┐
data  │ c │ a │ t │ t │   │   length = 3
      └───┴───┴───┴───┴───┘
        0   1   2   3   4
```

这次挪动方向和插入相反，要**从前往后**：先把a从`data[2]`挪到`data[1]`——直接覆盖掉要删的x，不需要先"清空"它——再把t从`data[3]`挪到`data[2]`。挪完把长度减1。

注意`data[3]`里还留着一个t。它不用管：长度已经是3，`data[3]`在有效范围之外，下次插入会把它覆盖掉。这也再次说明为什么有效范围要靠length而不是靠格子里有没有东西。

```c
int Delete(int i) {
    if (i < 0 || i >= L.length) return 0;     /* 位置不合法 */
    for (int j = i; j < L.length - 1; j++)    /* 从前往后挪 */
        L.data[j] = L.data[j + 1];
    L.length--;
    return 1;
}
```

带入Delete(1)：j=1，`data[1] = data[2]`把a挪过来；j=2，`data[2] = data[3]`把t挪过来；j=3不满足j<3，循环结束；长度变3。

删除位置越靠前、表越长，要挪的元素越多，和插入一样。

### 2.4.2 验证：插入x再删掉

接着上一节的程序，做2.1.4的后半段：在位置2插入x得到`caxt`，再删掉它回到`cat`。这次插入的位置和2.4.1分析用的不同，正好对照2.1.1的会话：

```c
int main(void) {

    Insert(1, 'a');
```

## 2.5 把L变成参数

> **本节问题**：前两节的函数都直接操作全局变量L，所以程序里只能有一个表。要让函数能操作任意一个表，得把表作为参数传进去——可是直接传，改不到它。为什么？

### 2.5.1 直接传结构体：Init为什么没生效

先说为什么要改。三个原因：全局变量L只有一个，程序里就只能有一个表，第3章的栈和队列要同时用好几个；2.1.2定义的操作是Init(L)、Insert(L, i, x)，表是参数，代码理应和定义长得一样；全局变量谁都能改，main可以绕过操作直接动`L.length`，"只通过操作访问数据"就没有约束力。

最自然的改法是给函数加一个参数。从最简单的Init试起：

```c
void Init(SeqList L) {
    L.length = 0;
}

int main(void) {
    SeqList L;
    L.length = 5;         /* 故意先放个数 */
    Init(L);
    printf("%d\n", L.length);
    return 0;
}
```

期望打印0，实际打印5。Init运行了，没报错，但main里的L没有变。

用内存格子图看发生了什么。main里的L是一个结构体，占一段格子，假设从200号开始，length那一格在300号：

```
main 的 L
         ┌───┬───┬─────┬─────┐
         │   │   │  …  │  5  │
         └───┴───┴─────┴─────┘
          200 201        300   ← length
```

调用Init(L)时，C语言把这一整段的内容复制一份，放到另一处，比如从500号开始，交给Init里的参数L：

```
main 的 L                          Init 的 L（复制品）
┌───┬───┬─────┬─────┐              ┌───┬───┬─────┬─────┐
│   │   │  …  │  5  │   复制 ──►   │   │   │  …  │  5  │
└───┴───┴─────┴─────┘              └───┴───┴─────┴─────┘
 200 201        300                 500 501        600
```

Init里的`L.length = 0`改的是600号，300号纹丝不动。函数一返回，复制品被丢弃，main里看到的还是5。这叫**值传递**：传的是值的复制品，不是原件。

对int这样一个格子的东西，复制无所谓。对一个结构体，一是改不到原件，二是每次调用都要复制一百多个格子，Length、Get这种不改表的操作也白白复制一遍。

**换个思路。** 既然改复制品没用，就不要给函数复制品，而是告诉它原件在哪：只传一个数——200，main的L的起始地址。Init的参数变成一个格子，里面记着200；Init顺着200找到原件，把300号改成0：

```
main 的 L                          Init 的参数
┌───┬───┬─────┬─────┐              ┌─────┐
│   │   │  …  │  0  │ ◄──────────  │ 200 │
└───┴───┴─────┴─────┘              └─────┘
 200 201        300                  700
```

传的东西从一百多个格子变成一个数，而且改的就是原件。要把这个思路写成C代码，需要两样工具：怎么取到一个变量的地址，怎么顺着地址去访问它。这就是指针。

### 2.5.2 补充：地址与指针

如果你已经熟悉C语言的指针，可以直接跳到2.5.3。

2.2节说过，内存是一排编了号的格子，编号就是地址。这不是比喻。定义一个变量，打印它的值和它的地址：

```c
int a = 10;
printf("%d\n", a);
printf("%p\n", &a);
```

第一行打印10，是a的值；第二行打印类似`0x7ffd5a3c9c04`的东西，这就是a所在格子的编号。`&`读作"取地址"，`%p`是打印地址的格式。地址习惯用十六进制显示，`0x`是十六进制的标记，后面的数和十进制没有本质区别，`0x64`就是100。你运行时看到的数字会和这里不同，每次运行也可能变，这没有关系——我们关心的不是具体数值，而是"每个变量都住在一个有编号的格子里"。

有了编号，就有了第二种访问变量的办法。除了用名字a，也可以先把它的地址存起来，再顺着地址去找：

```c
int *pa = &a;
printf("%d\n", *pa);      /* 10 */
*pa = 20;
printf("%d\n", a);        /* 20 */
```

`int *pa`定义了一个存放int变量地址的变量，叫指针。`*pa`读作"pa指向的那个变量"，读它就是读a，改它就是改a。这就是2.5.1图里"顺着700号格子里的200找到原件"。

再看数组：

```c
int b[3] = {1, 2, 3};
printf("%p %p %p\n", &b[0], &b[1], &b[2]);
```

三个地址的末尾会是类似`c0`、`c4`、`c8`的样子，依次加4，因为一个int占4个字节。这是"相邻格子放相邻元素"的物理证据：数组就是一段连续的格子。既然连续，知道第一个的地址就能算出任何一个的地址：

```c
int *pb = &b[0];
printf("%d %d %d\n", *pb, *(pb + 1), *(pb + 2));   /* 1 2 3 */
```

`pb + 1`不是把编号加1，而是往后挪一个int，也就是加4个字节，指向`b[1]`。顺序表的Get只要一次计算就能取到第i个元素，原因就在这里。

最后是指向结构体的指针，这正是下面要用的：

```c
SeqList L;
SeqList *p = &L;
L.length = 5;
printf("%d %d\n", (*p).length, p->length);   /* 5 5 */
```

`(*p).length`是"p指向的结构体的length成员"。这个写法太啰嗦，C语言提供了等价的简写`p->length`。后面所有通过指针访问结构体成员的地方，都用箭头。

### 2.5.3 传地址版本的Init，以及其他五个

按2.5.1的思路改Init：参数不再是`SeqList`，而是"指向SeqList的指针"`SeqList *L`；调用时传`&L`，即L的地址；函数体里L是一个地址，要访问它指向的结构体的成员，用箭头`L->length`：

```c
void Init(SeqList *L) {
    L->length = 0;
}

int main(void) {
    SeqList L;
    L.length = 5;
    Init(&L);
    printf("%d\n", L.length);    /* 这次打印 0 */
    return 0;
}
```

想确认改的是原件，在main里打印`&L`，在Init里打印`L`（它本身就是地址），两个数字相同。

对比两个版本的Init，只有两处变化：参数类型多一个`*`，`L.`变成`L->`。最复杂的Insert也一样，函数体里的逻辑一个字不动：

```c
int Insert(SeqList *L, int i, char x) {
    if (i < 0 || i > L->length) return 0;
    if (L->length == MAXSIZE)   return 0;
    for (int j = L->length; j > i; j--)
        L->data[j] = L->data[j - 1];
    L->data[i] = x;
    L->length++;
    return 1;
}
```

只读的操作Length、Get也一律传指针：一是不用复制整个结构体，二是五个函数写法统一。全局变量`SeqList L;`删掉，表由使用者自己定义，比如在main里写`SeqList L;`，然后`Init(&L)`。

其余三个函数请先自己改，再对照下面的完整版本。从现在起本章都用这一套：

```c
#define MAXSIZE 100

typedef struct {
    char data[MAXSIZE];
    int  length;
} SeqList;

void Init(SeqList *L) {
    L->length = 0;
}

int Length(SeqList *L) {
    return L->length;
}

char Get(SeqList *L, int i) {
    if (i < 0 || i >= L->length) return '\0';
    return L->data[i];
}

int Insert(SeqList *L, int i, char x) {
    if (i < 0 || i > L->length) return 0;
    if (L->length == MAXSIZE)   return 0;
    for (int j = L->length; j > i; j--)
        L->data[j] = L->data[j - 1];
    L->data[i] = x;
    L->length++;
    return 1;
}

int Delete(SeqList *L, int i) {
    if (i < 0 || i >= L->length) return 0;
    for (int j = i; j < L->length - 1; j++)
        L->data[j] = L->data[j + 1];
    L->length--;
    return 1;
}
```

## 2.6 编辑器1.0：跑起来

> **本节问题**：五个操作有了，2.1.3把每条指令翻译成操作的表也有了，怎么把它们拼成一个能反复"读指令、执行、显示"的程序？

**程序的骨架**

编辑器从启动到退出，做的事是一个循环：读一条指令，按2.1.3的表执行，把整行显示出来，再读下一条，直到`q`。三块各自怎么写：

**读指令。** 每条指令是一个字母，用`scanf(" %c", &cmd)`读。格式串开头的空格不能省：它让scanf跳过上一条指令留下的换行，否则换行会被当成一条指令。读到`q`就退出循环。`i`后面还跟一个字符，在`i`的分支里再读一次。

**执行。** 就是2.1.3的表逐行翻译成`switch`的四个分支：`i`调Insert(&text, cursor, ch)然后cursor加1；`d`调Delete(&text, cursor−1)然后cursor减1，cursor为0时不做；`l`、`r`只动cursor，下限0、上限Length。Insert可能失败（表满），所以看它的返回值，成功才移动光标。空格按2.1.1的约定用`_`输入，读到`_`换成空格再插。

**显示。** 每轮循环末尾调一次。它从0到Length−1逐个Get，走到第cursor个字符时先打`|`再打字符；光标在行尾时cursor等于长度，循环里碰不到，循环结束后要补一次。这块单独写成函数Show。

按这三块写出来的main：

```c
int main(void) {
    SeqList text;
    int cursor = 0;
    char cmd, ch;

    Init(&text);
    while (scanf(" %c", &cmd) == 1 && cmd != 'q') {   /* 读指令 */
        switch (cmd) {                                  /* 执行 */
        case 'i':
            scanf(" %c", &ch);
            if (ch == '_') ch = ' ';
            if (Insert(&text, cursor, ch)) cursor++;
            else printf("插入失败\n");
            break;
        case 'd':
            if (cursor > 0) { Delete(&text, cursor - 1); cursor--; }
            break;
        case 'l':
            if (cursor > 0) cursor--;
            break;
        case 'r':
            if (cursor < Length(&text)) cursor++;
            break;
        }
        Show(&text, cursor);                            /* 显示 */
    }
    return 0;
}
```

Show按上面说的写：

```c
void Show(SeqList *L, int cursor) {
    int n = Length(L);
    for (int i = 0; i < n; i++) {
        if (i == cursor) printf("|");
        printf("%c", Get(L, i));
    }
    if (cursor == n) printf("|");
    printf("\n");
}
```

写进文件时Show要放在main前面，C语言要求函数先定义后使用。

**验证：跑2.1.1的会话**

编译运行，逐条输入2.1.1的会话：

```
i c       c|
i a       ca|
i t       cat|
l         ca|t
i x       cax|t
d         ca|t
r         cat|
q
```

右边的输出和2.1.1的一模一样，也和2.1.4纸上跑出来的屏幕一列一致。这就是编辑器1.0。

再看一眼main和Show：它们只调用了Init、Length、Get、Insert、Delete，从头到尾没有直接读写`text.data`和`text.length`。编辑器不知道、也不需要知道字符是怎么存的。这是2.5坚持传指针、不用全局变量的目的之一——后面把存储结构换掉时，这段main会原样保留。

## 2.7 顺序表的时间复杂度

> **本节问题**：编辑器1.0在一行几十个字符上每个动作都是瞬间完成。要是拿它编辑一个几万字的文档，哪个动作会变慢？能不能不靠跑，看代码就判断出来？

**先数一个例子**

在`cat`上做两次插入。在行尾追加s，Insert(3, 's')：挪动循环从j=3开始，j>3不成立，一次都不执行，挪0个。在行首插入b，Insert(0, 'b')：t、a、c依次后移，挪3个。

把表长换成一万。行尾追加还是挪0个；行首插入要挪一万个。表长再翻十倍，行尾还是0，行首变十万。行尾插入的工作量不随表长变化，行首插入的工作量和表长成正比——后者就是"几万字文档在开头打字会卡"的原因。

这个"数挪动次数、看它怎么随表长变化"的做法，就是第1章介绍的衡量方法，这里把它说完整。

**只看趋势：渐进时间复杂度**

衡量算法快慢不用秒，用步数——一次赋值、一次比较、一次挪动都算一步。步数和机器、语言无关，只和算法、和数据规模n有关。

真正关心的不是具体几步，而是**步数随着n增长，增长得有多快**。步数不随n变化的记作O(1)；和n成正比的记作O(n)；和n²成正比的记作O(n²)。至于是n步、2n步还是2n+3步，常数和零头一律抹掉，只留量级——因为n很大时，O(1)和O(n)之间的差距远比2n和3n之间的差距重要。因为只看n很大时的趋势，这种分析叫**渐进时间复杂度分析**，大O记号写出来的就是渐进时间复杂度。

用它量任何操作，规则是一样的：读写一个格子、一次比较、一次赋值，各算一步；数出步数和n的关系，只留量级。对顺序表的Insert和Delete，步数几乎全来自挪动元素的循环，所以数挪动次数就够。设表长为n，五个操作逐个看。

**五个操作**

Init、Length、Get都是固定几步，与n无关，O(1)。Get之所以快，就是2.5.2看到的那件事：数组连续，第i个元素的地址一次算出。

Insert的步数取决于挪动多少个元素。在位置i插入，要挪动第i个到第n−1个，共n−i个。i=n时挪0个，最好情况O(1)；i=0时挪n个，最坏情况O(n)。各位置机会均等时平均挪n/2个，仍是O(n)。

Delete同理，删第i个要挪n−i−1个，最坏和平均都是O(n)。

| 操作 | 顺序表 |
|---|---|
| Init、Length、Get | O(1) |
| Insert、Delete | O(n) |

**回到编辑器**

光标在行尾打字，每个字符都是追加，O(1)，很快；光标在行首打字，每敲一个字符都要把整行往后挪一遍，O(n)。几万字的文档，在开头打字就会明显卡顿。Show每显示一次要读n个字符，每次Get是O(1)，合起来O(n)——n个字符总要一个个打出来，这是无法避免的。

这个问题的根源是顺序存储"相邻格子放相邻元素"的约定本身——只要坚持这个约定，中间插入就必然要挪动。在顺序表的框架内没有办法，要换一种存储方式才能解决，这是2.9节的内容。在此之前，先解决一个更急迫的问题。

> **到这里你有了**：顺序表五个操作的复杂度表，以及编辑器1.0在行首打字慢的原因。
> **练一练**：（1）在长度为n的顺序表里，分别在位置0、位置n/2、位置n插入，各挪动多少个元素？它们的量级分别是什么？（2）从100个字符的表里连续删第0个直到删光，总共挪动多少次？（3）Show里的Get是O(1)，所以Show是O(n)。如果Get变成O(n)，Show会变成多少？

## 2.8 动态扩容：编辑器1.1

> **本节问题**：数组大小编译时就定死了。定100，第101个字符插不进去；定一万，大多数时候浪费。用户会输入多少事先不知道，怎么办？

**为什么不能就地变长**

先看问题有多真实。把`MAXSIZE`改成4，重新编译编辑器1.0，输入第5个字符时屏幕上打出"插入失败"。改回100也一样，只是要多敲96个字符。

最直接的想法是：满了就把数组变长。但数组在内存里是一段固定的格子，比如从100到103号。它后面的104号是谁的？可能已经被别的变量占了：

```
       data（4格，满了）          别的变量
  ┌───┬───┬───┬───┬───┬───┬───┐
… │ c │ a │ t │ s │ ? │ ? │ ? │ …
  └───┴───┴───┴───┴───┴───┴───┘
   100 101 102 103 104 105 106
```

要往104号写，就会把别人的东西覆盖掉。数组一旦定下来，两头的格子都不归它，没法就地变长。

**思路：换一块更大的**

既然原地不能长，就换地方：向系统申请一块更大的新空间，比如8格，把4个字符搬过去，然后把旧的4格还回去：

```
  旧空间（还回去）                新空间（8格）
  ┌───┬───┬───┬───┐              ┌───┬───┬───┬───┬───┬───┬───┬───┐
  │ c │ a │ t │ s │  搬过去 ──►  │ c │ a │ t │ s │   │   │   │   │
  └───┴───┴───┴───┘              └───┴───┴───┴───┴───┴───┴───┴───┘
   100 101 102 103                500 501 502 503 504 505 506 507
```

以后`data`指向500号而不是100号。这意味着`data`不能再是编译时定死的数组，而要是一个记着"当前那段空间在哪"的地址——也就是2.5.2学过的指针；还要另外记一个数：这段空间有多少格。剩下的问题是：怎么向系统申请空间、怎么搬家。

**需要的概念：向系统申请空间**

C语言在`<stdlib.h>`里提供三个函数，专门做这件事：

- `malloc(n)`：向系统申请n个字节的连续格子，返回第一个格子的地址。申请不到返回NULL。
- `free(p)`：把以前申请的、起始地址为p的那段空间还给系统。
- `realloc(p, m)`：申请一块m个字节的新空间，把p指向的旧空间里的内容复制过去，释放旧空间，返回新空间的地址。申请不到返回NULL，此时旧空间原样保留。

程序自己定义的变量和数组，大小在编译时就定了；`malloc`申请来的空间大小是运行时决定的，用完要自己`free`。上面图里"申请8格、搬过去、还回旧的4格"，`realloc`一个函数全包了。

**三步改动**

按这个思路改顺序表，只需改三处，其余操作一行不动。

第一步，结构体。`data`从定长数组变成指针，指向运行时申请的空间；新增`capacity`记录这段空间有多少格。`length`是"实际放了几个"，`capacity`是"最多能放几个"，始终length ≤ capacity：

```c
/* 原来 */
typedef struct {
    char data[MAXSIZE];
    int  length;
} SeqList;

/* 现在 */
#define INIT_CAPACITY 16

typedef struct {
    char *data;       /* 指向运行时申请的空间 */
    int   length;     /* 实际放了几个 */
    int   capacity;   /* 最多能放几个 */
} SeqList;
```

第二步，Init。原来数组是现成的，只需把长度清零；现在要先申请一块初始空间，16格。申请可能失败，所以Init改为返回是否成功：

```c
/* 原来 */
void Init(SeqList *L) {
    L->length = 0;
}

/* 现在 */
int Init(SeqList *L) {
    L->data = (char *)malloc(INIT_CAPACITY * sizeof(char));
    if (L->data == NULL) return 0;
    L->length = 0;
    L->capacity = INIT_CAPACITY;
    return 1;
}
```

第三步，扩容。写一个函数，把容量翻倍：

```c
int Expand(SeqList *L) {
    int newCap = L->capacity * 2;
    char *p = (char *)realloc(L->data, newCap * sizeof(char));
    if (p == NULL) return 0;
    L->data = p;
    L->capacity = newCap;
    return 1;
}
```

注意`realloc`的返回值先存进临时变量`p`，确认不是NULL再赋给`L->data`。如果直接写`L->data = realloc(...)`，一旦申请失败返回NULL，旧空间的地址就被覆盖丢掉了，里面的元素再也找不回来。

谁来调Expand？Insert在表满的时候。Insert只改一行：

```c
/* 原来 */ if (L->length == MAXSIZE)   return 0;
/* 现在 */ if (L->length == L->capacity && !Expand(L)) return 0;
```

满了先扩容，扩容成功再往下走，失败才返回0。Length、Get、Delete一行不改。

走一遍：从空行开始打字，Init申请了16格。前16个字符依次填入，length从0到16。第17个字符到来，Insert发现length等于capacity，调Expand：申请32格，把16个字符复制过去，释放旧的16格，capacity变32。第17个字符放进去。到第33个字符时再扩到64，以此类推。

**释放，以及为什么翻倍**

申请了就要还。补一个销毁操作，程序退出前调用：

```c
void Destroy(SeqList *L) {
    free(L->data);
    L->data = NULL;
    L->length = L->capacity = 0;
}
```

这是实现层面带来的需要，2.1.2的五个操作里没有它，但凡是动态申请空间的实现都得有。

Expand每次把容量翻倍，而不是每次多申请一格。如果每次只多一格，那么每插入一个元素都要复制整个表，追加n个元素总共要复制约n²/2次，把O(1)的追加变成了O(n)。翻倍的话，容量从16到32到64……复制只在这些时刻发生，追加n个元素总共复制不超过2n次，平摊到每次追加上仍是O(1)。代价是最多有一半空间暂时空着——用空间换时间，这类取舍后面还会反复遇到。

**验证：编辑器1.1，看见扩容发生**

编辑器这边改动很小：Init有了返回值，main开头改成`if (!Init(&text)) return 1;`，循环结束后加一行`Destroy(&text);`，其余原样。这就是编辑器1.1。

要亲眼看见扩容，在Expand里临时加一行打印，再把INIT_CAPACITY改成4：

```c
printf("[扩容] %d -> %d\n", L->capacity, newCap);
```

运行，输入五个以上的字符：

```
i c          c|
i a          ca|
i t          cat|
i s          cats|
i _          [扩容] 4 -> 8
             cats |
```

同样是第5个字符，1.0版失败，1.1版扩容后照常插入；再敲到第9个时会看到`[扩容] 8 -> 16`。用户完全感觉不到这些，只是一直在打字。看完把打印删掉。

> **到这里你有了**：不会满的编辑器1.1，应用层只改了两行。
> **练一练**：（1）改结构体、Init、Expand、Insert，加Destroy，改main两行，把INIT_CAPACITY改成4运行编辑器，确认第5个字符时看到`[扩容] 4 -> 8`。（2）把Expand改成每次只多一格（`newCap = L->capacity + 1`），在realloc处加计数器，追加1000个字符总共搬了多少次？和翻倍比。（3）删掉main里的`Destroy(&text)`，程序还能正常运行吗？那它有什么问题？（4）Expand里如果直接写`L->data = realloc(...)`，申请失败时表会怎样？
> **下一步**：表满的问题解决了，行首打字慢的问题还在，根源是顺序存储的约定本身——换一种存储方式。

## 2.9 链表：关系存哪里，用C怎么表示

> **本节问题**：2.2的问题再问一次——线性表怎么放进内存？第一次的答案是顺序表，代价是中间插入必须挪动后面所有元素（2.7）。这次放弃"相邻格子放相邻元素"这条约定，那么"谁在谁后面"的关系存到哪里？

### 2.9.1 放弃"相邻"约定，关系存哪里

顺序表把关系藏在位置里：a在c后面，就把a放在c的下一格。这条约定不占空间、按位置取元素一步到位，但也正是它逼着中间插入去挪动所有后面的元素。放弃它会怎样？

放弃之后，元素可以散落在内存的任何地方，插入时随便找个空格子放进去，不用挪动任何人。但马上出现新问题：关系没了。以`cat`为例，把三个字符分开存：c在100号，t在104号，a在108号：

```
┌───┬───┬───┬───┬───┬───┬───┬───┬───┬───┬───┬───┬───┬───┬───┬───┐
│ c │   │   │   │ t │   │   │   │ a │   │   │   │   │   │   │   │
└───┴───┴───┴───┴───┴───┴───┴───┴───┴───┴───┴───┴───┴───┴───┴───┘
 100 101 102 103 104 105 106 107 108 109 110 111 112 113 114 115
```

c确实在第一格，可是按位置往后找，找到的是t，不是a。位置已经不能告诉我们谁在谁后面了。要读出`cat`，得有别的办法知道：c的下一个是a，a的下一个是t。这些关系存在哪？

办法是把它们明确地记下来：在每个字符右边的格子里，写上下一个字符的地址。

```
┌───┬───┬───┬───┬───┬───┬───┬───┬───┬───┬───┬───┬───┬───┬───┬───┐
│ c │108│   │   │ t │ 0 │   │   │ a │104│   │   │   │   │   │   │
└───┴───┴───┴───┴───┴───┴───┴───┴───┴───┴───┴───┴───┴───┴───┴───┘
 100 101 102 103 104 105 106 107 108 109 110 111 112 113 114 115
```

右格里的108、104不是数据，是另一个格子的编号；t右边的0表示"没有下一个"——地址0不会住任何变量，所以用它做结束标记。现在每个元素占两格：一格存数据，一格存下一个元素的地址。这两格合起来叫一个**结点**，一个个结点用地址串起来，就是**链表**。

格子图看得清"分开存"，但看不清顺序。把三个结点按逻辑顺序重新摆一遍，右格里的地址画成箭头，方框下面标出它在格子图里的位置：

```
head = 100
  │
  ▼
┌───┬─────┐     ┌───┬─────┐     ┌───┬─────┐
│ c │ 108 │────►│ a │ 104 │────►│ t │  0  │
└───┴─────┘     └───┴─────┘     └───┴─────┘
    100             108             104
```

两张图是同一份数据的两种画法：格子图按内存位置排，箭头图按逻辑顺序排。右格里的数字就是箭头指向的方框的地址。`head`是另外记下的第一个结点的地址，没有它就不知道从哪开始。

在箭头图上读出`cat`：从head出发到100号，读到c；右格是108，顺着箭头到108号，读到a；右格是104，再到104号，读到t；右格是0，结束。走的路线是100→108→104，在内存里先往后跳、再往回跳，但读出来正好是`cat`。逻辑顺序不靠位置，靠的是箭头。

后面讲操作时一律用箭头图，大多数时候不再标地址数字——代码里我们永远看不到100、108这些数，地址存在指针变量里，箭头就是指针。只有讲插入和删除、需要看清"右格里的数字怎么变"的时候，才把数字标回来。

### 2.9.2 用C表示，手工搭一个

**结点。** 一个结点有两部分：一个字符，一个指向下一个结点的地址。用2.2学过的结构体表示：

```c
typedef struct Node {
    char         data;    /* 数据 */
    struct Node *next;    /* 下一个结点的地址 */
} Node;
```

有一处第一次见到的写法：结构体里有一个指向自己这种结构体的指针。`next`存的是"下一个结点的地址"，下一个结点也是Node，所以`next`的类型是"指向Node的指针"。名字写了两遍是因为定义`next`那一行时typedef还没完成，`Node`这个简写还不存在，只能用完整的`struct Node *`；定义结束后其他地方都可以用`Node`。

**结点从哪来。** 顺序表的格子是一次申请一整段；链表的结点是零散的，谁需要谁申请，2.8用过的`malloc`正好干这个事。写成一个小函数：

```c
Node *NewNode(char x) {
    Node *p = (Node *)malloc(sizeof(Node));
    if (p == NULL) return NULL;
    p->data = x;
    p->next = NULL;
    return p;
}
```

申请一个结点的空间，把字符填进`data`，`next`先置为`NULL`——这就是图里的0，C语言写作`NULL`。函数返回新结点的地址。

**手工搭出cat。** 只需要一个指针`head`记住第一个结点。造三个结点，用next把它们连起来，再顺着next走一遍打印：

```c
int main(void) {
    Node *head = NewNode('c');             /* 造 c，head 指向它 */
    head->next = NewNode('a');             /* 造 a，c 的 next 指向它 */
    head->next->next = NewNode('t');       /* 造 t，a 的 next 指向它 */

    for (Node *p = head; p != NULL; p = p->next)
        printf("%c", p->data);
    printf("\n");                          /* 输出 cat */
    return 0;
}
```

`head->next`是"head指向的结点的next"，也就是a的地址；`head->next->next`是a的next，也就是t的地址。for循环是链表最基本的动作：`p`从第一个结点开始，每次`p = p->next`跳到下一个，直到`p`变成`NULL`说明走到头了。这正是2.9.1在箭头图上走的那条路。

输出`cat`，三个字符在内存里散着放，关系靠next记着，读回来顺序没错。

当然，`head->next->next`这种写法只能演示，不能用来干活——插第100个字符要写100个箭头。怎么在任意位置插入、删除、取元素，是下一节的事。

> **到这里你有了**：结点的定义、造结点的函数，以及一个手工搭出`cat`再读回来的程序。
> **练一练**：（1）把2.9.2的程序敲出来运行，确认输出`cat`。（2）在打印循环里把`%c`改成`%p`打印`p`本身，三个地址相邻吗？相差多少？和2.9.1的图对照。（3）把三个NewNode的先后顺序打乱——先造t、再造a、最后造c，但next照旧连——输出变吗？为什么？（4）把t的next改成指向a（`head->next->next->next = head->next;`），打印循环会发生什么？
> **下一步**：把取元素、插入、删除写成通用的操作；第一个问题是操作的参数该是什么。

## 2.10 链表的初始化、插入、取元素：把cat造出来

> **本节问题**：手工搭表要写一串`->next`，不能用来干活。要有通用的操作，而且签名得和顺序表的五个函数一样，编辑器才能原样搬过来。第一个问题：操作的参数——"表"——该是什么？

### 2.10.1 整个表用什么代表：LinkList

顺序表由数组和长度两样东西组成，2.2把它们装进了一个结构体`SeqList`，五个操作的参数都是`SeqList *L`。链表照此办理。

链表最少只需要一个`head`，顺着next就能走完全表。但2.1.2定义的Length要返回长度，如果每次都从头数一遍，Length就成了O(n)；顺序表的Length是O(1)，链表没理由做得更差。所以再加一个计数器，和SeqList对称：

```c
/* 顺序表 */                      /* 链表 */
typedef struct {                  typedef struct {
    char *data;                       Node *head;     /* 第一个结点的地址 */
    int   length;                     int   length;   /* 结点个数 */
    int   capacity;               } LinkList;
} SeqList;
```

链表不需要capacity——它没有"容量"，结点是一个个申请的，用多少申请多少。空表就是`head`为`NULL`、`length`为0。上一节手工搭的`cat`，就是一个`head`指向c、`length`为3的LinkList。

从现在起，五个操作的参数都是`LinkList *L`，和`SeqList *L`只差类型名。

### 2.10.2 初始化、求长度、取第i个元素

**初始化。** 输入：无。输出：无。副作用：表变成空表。

```c
void Init(LinkList *L) {
    L->head = NULL;
    L->length = 0;
}
```

**求长度。** 输入：无。输出：长度。副作用：无。

```c
int Length(LinkList *L) {
    return L->length;
}
```

**取第i个元素。** 输入：位置i。输出：那个元素。副作用：无。

顺序表的Get是一次下标运算。链表没有下标，第i个结点在哪只有一个办法知道：从head出发，顺着next走i步。以`cat`为例，Get(L, 2)要取t，走0步是c，走1步到a，走2步到t：

```
head
  │
  ▼
┌───┬───┐     ┌───┬───┐     ┌───┬───┐
│ c │ ●─┼────►│ a │ ●─┼────►│ t │ ╱ │
└───┴───┘     └───┴───┘     └───┴───┘
  p 第0步       p 第1步       p 第2步
```

用一个指针`p`记当前走到哪，每走一步`p = p->next`，走够i步停下：

```c
char Get(LinkList *L, int i) {
    if (i < 0 || i >= L->length) return '\0';
    Node *p = L->head;
    for (int k = 0; k < i; k++)
        p = p->next;
    return p->data;
}
```

带入Get(L, 2)：`p`先指向c；k=0时走到a；k=1时走到t；k=2不满足k<2，循环结束，返回t。

"从head走到第i个结点"这个动作，插入和删除也要用，单独抽成一个函数：

```c
Node *NodeAt(LinkList *L, int i) {   /* 返回第i个结点的地址 */
    Node *p = L->head;
    for (int k = 0; k < i; k++)
        p = p->next;
    return p;
}
```

有了它，Get里的循环就可以交给NodeAt，自己只剩下检查位置和取数据：

```c
char Get(LinkList *L, int i) {
    if (i < 0 || i >= L->length) return '\0';
    return NodeAt(L, i)->data;
}
```

两个版本的Get做的事完全一样，只是走路那一段搬进了NodeAt。后面Insert和Delete也这样用它。

### 2.10.3 在第i个位置插入：三种位置

输入：位置i和元素x。输出：成功或失败。副作用：多了一个结点，长度加1——但和顺序表不同，不挪动任何已有结点，只改地址。改哪些地址取决于插入位置，分三种情况看。

**插在第0个位置。** 比如在`cat`最前面插入b。新结点b要成为第一个，那么b的next应该指向原来的第一个结点c，而head应该改为指向b：

```
head ──────────────┐
                   ▼
┌───┬───┐     ┌───┬───┐     ┌───┬───┐     ┌───┬───┐
│ b │ ●─┼────►│ c │ ●─┼────►│ a │ ●─┼────►│ t │ ╱ │
└───┴───┘     └───┴───┘     └───┴───┘     └───┴───┘
  ▲
  └── head 改为指向这里
```

空表也是这种情况：head是NULL，b的next得到NULL，正好是末尾标记；head改为指向b。

**插在中间。** 比如在a和t之间插入x，即Insert(L, 2, 'x')，结果应为`caxt`。要改的是x的next和a的next。但这里有一个顺序表没有的麻烦：手里只有head，a在哪并不知道。所以第一步不是改地址，而是找到a——NodeAt(L, 1)。找到之后才能改。下面几张图标出地址，看清右格里的数字怎么变。假设x放在102号。

第一步，从head走到第1个结点a，用prev记住它：

```
head = 100
  │
  ▼
┌───┬─────┐     ┌───┬─────┐     ┌───┬─────┐
│ c │ 108 │────►│ a │ 104 │────►│ t │  0  │
└───┴─────┘     └───┴─────┘     └───┴─────┘

                   prev
```

第二步，造出x结点，此时它的next还是0：

```
┌───┬─────┐     ┌───┬─────┐     ┌───┬─────┐
│ c │ 108 │────►│ a │ 104 │────►│ t │  0  │
└───┴─────┘     └───┴─────┘     └───┴─────┘

                   prev
                          ┌───┬─────┐

```

第三步，让x的next指向t。t的地址104现在记在prev的右格里，抄到x的右格：

```
                   prev          │

                          │ x │ 104 │
                          └───┴─────┘
                              102
```

第四步，让prev的next指向x。把a的右格从104改成102：

```
┌───┬─────┐     ┌───┬─────┐     ┌───┬─────┐
│ c │ 108 │────►│ a │ 102 │     │ t │  0  │

```

从head出发：100→108→102→104，读出`caxt`。c、t一个没动，只改了两个右格。

第三步和第四步的顺序不能反。如果先做第四步，把a的右格改成102，t的地址104就没人记着了——它原本只存在a的右格里。**先让新结点指向后一个，再让前一个指向新结点**，这是链表插入必须记住的顺序。

四步里只有后两步是真正的插入，第一步"找到前一个结点"是走出来的，位置越靠后走得越远。这一点量效率时会再说。

**插在末尾。** 比如在t后面插入s，Insert(L, 3, 's')。找到第2个结点t，让s的next指向t的next（是NULL），再让t的next指向s。和中间插入是同一套动作，只是"后一个"恰好是NULL。

所以三种情况其实是两种：第0个位置改head，其余位置找到第i−1个结点prev、改prev的next：

```c
int Insert(LinkList *L, int i, char x) {
    if (i < 0 || i > L->length) return 0;
    Node *q = NewNode(x);
    if (q == NULL) return 0;
    if (i == 0) {                     /* 插在最前面：没有前一个结点 */
        q->next = L->head;
        L->head = q;
    } else {
        Node *prev = NodeAt(L, i - 1);   /* 先找到前一个结点 */
        q->next = prev->next;            /* 先：新结点指向后一个 */
        prev->next = q;                  /* 后：前一个指向新结点 */
    }
    L->length++;
    return 1;
}
```

## 2.11 链表的删除与头结点

> **本节问题**：编辑器的退格要删掉一个字符。链表里删掉一个结点，它前后的结点怎么重新连上？删掉的结点去哪了？

### 2.11.1 删除第i个元素

输入：位置i。输出：成功或失败。副作用：少了一个结点，长度减1——同样不挪动任何结点，只改地址，最后把结点的空间还给系统。

以`caxt`为例，删掉位置2的x，回到`cat`。要做的只有一件事：让a的next越过x直接指向t。x没人指向了，free掉。

和插入一样，第一步先要找到前一个结点a，NodeAt(L, 1)。改之前，就是2.10插完x的样子：

```
head = 100
  │
  ▼
┌───┬─────┐     ┌───┬─────┐     ┌───┬─────┐     ┌───┬─────┐
│ c │ 108 │────►│ a │ 102 │────►│ x │ 104 │────►│ t │  0  │
└───┴─────┘     └───┴─────┘     └───┴─────┘     └───┴─────┘
    100             108             102             104
                   prev              q
```

第二步，用q记住要删的结点x（它是prev的next）。第三步，把a的右格从102改成104——这个104在x的右格里，抄过来：

```
head = 100
  │
  ▼
┌───┬─────┐     ┌───┬─────┐                     ┌───┬─────┐
│ c │ 108 │────►│ a │ 104 │────────────────────►│ t │  0  │
└───┴─────┘     └───┴─────┘     ┌───┬─────┐     └───┴─────┘
    100             108         │ x │ 104 │         104
                   prev         └───┴─────┘
                                    102
                                     q
```

x还在102号，右格还记着104，但从head出发已经走不到它了：100→108→104，读出`cat`。第四步，free掉102号。这正是插入的后两步倒着走：插入是把t的地址从a抄给x、再让a指向x；删除是把t的地址从x抄回a、再释放x。

第二步"用q记住x"不能省。改完a的右格之后，x就没人指向了，事先没记下它的地址，就再也找不到它，既拿不到104，也没法释放。free也必须放在最后：释放之后q指向的空间就不属于我们了，再读`q->next`是错误。先取用、后释放。

删末尾的元素是同一套动作，只是q的next恰好是NULL。删第0个又是特殊情况：它前面没有结点，改的不是某个结点的next，而是head——让head直接指向第二个结点。和插入一样，需要一个if分支：

```c
int Delete(LinkList *L, int i) {
    if (i < 0 || i >= L->length) return 0;
    Node *q;
    if (i == 0) {                     /* 删第一个：改head */
        q = L->head;
        L->head = q->next;
    } else {
        Node *prev = NodeAt(L, i - 1);   /* 第一步：找到前一个 */
        q = prev->next;                  /* 第二步：记住要删的 */
        prev->next = q->next;            /* 第三步：越过q */
    }
    free(q);                             /* 第四步：释放 */
    L->length--;
    return 1;
}
```

### 2.11.2 验证：插入x再删掉，再删第0个

接着2.10.4的程序：插入x得到`caxt`，删掉它回到`cat`，再删第0个得到`at`：

```c
int main(void) {
    LinkList L;
    Init(&L);
    Insert(&L, 0, 'c');
    Insert(&L, 1, 'a');
    Insert(&L, 2, 't');
    Insert(&L, 2, 'x');                   /* caxt */
    Delete(&L, 2);                        /* cat  */
    Delete(&L, 0);                        /* at   */

    for (int i = 0; i < Length(&L); i++)
        printf("%c", Get(&L, i));
    printf("\n");                          /* 输出 at */
    return 0;
}
```

跟踪Delete(&L, 2)：`prev = NodeAt(L, 1)`得到a；`q = prev->next`是x；`prev->next = q->next`把104赋给a的next；free掉102号；长度变3。跟踪Delete(&L, 0)：`q = L->head`是c；`L->head = q->next`，head变成108，指向a；free掉100号；长度变2。输出`at`。

五个操作到齐了。

### 2.11.3 头结点：去掉两个分支

Insert和Delete各有一个if分支：动第0个位置时改的是head，其余位置改的是某个结点的next。两处代码做的是同一件事——"改前一个的next"——只因为第0个前面没有结点，才不得不另写一遍。有个技巧能把分支去掉。

办法是在链表最前面固定放一个不存数据的结点，叫**头结点**。head永远指向头结点，真正的第0个元素是头结点的next：

```
head
  │
  ▼
┌───┬───┐     ┌───┬───┐     ┌───┬───┐     ┌───┬───┐
│   │ ●─┼────►│ c │ ●─┼────►│ a │ ●─┼────►│ t │ ╱ │
└───┴───┘     └───┴───┘     └───┴───┘     └───┴───┘
 头结点          第0个         第1个         第2个
```

这样第0个元素前面也有一个结点了。删第0个就是"找到它的前一个（头结点），改它的next"，和删其他位置一样；空表也不再是head为NULL，而是head指向一个next为NULL的头结点。

要改的地方：Init要造出头结点；NodeAt要能返回头结点；Insert和Delete的if分支消失。

Init现在要申请一个结点，申请可能失败，所以改为返回是否成功：

```c
int Init(LinkList *L) {
    L->head = NewNode('\0');          /* 头结点，数据无意义 */
    if (L->head == NULL) return 0;
    L->length = 0;
    return 1;
}
```

NodeAt现在从头结点出发。让k从−1开始数：k=−1时p是头结点，走一步k变0、p到第0个……走到k等于i时p就是第i个。这样NodeAt(L, −1)返回头结点，正好是"第0个的前一个"，Insert和Delete不用再区分i是不是0：

```c
Node *NodeAt(LinkList *L, int i) {   /* i=-1 时返回头结点 */
    Node *p = L->head;
    for (int k = -1; k < i; k++)
        p = p->next;
    return p;
}
```

Delete的分支没有了，删第0个时prev就是头结点，走的是同一条路：

```c
int Delete(LinkList *L, int i) {
    if (i < 0 || i >= L->length) return 0;
    Node *prev = NodeAt(L, i - 1);    /* i=0 时得到头结点 */
    Node *q = prev->next;
    prev->next = q->next;
    free(q);
    L->length--;
    return 1;
}
```

Insert请自己改，Get要注意跳过头结点。从现在起本章都用头结点版本。

**销毁。** 链表的结点是一个个申请的，也要一个个释放，包括头结点。这相当于把表删光，有个陷阱：free掉当前结点后就不能再从它读next了，要先记下下一个再释放当前：

```c
void Destroy(LinkList *L) {
    Node *p = L->head;
    while (p != NULL) {
        Node *next = p->next;         /* 先记下下一个 */
        free(p);
        p = next;
    }
    L->head = NULL;
    L->length = 0;
}
```

> **到这里你有了**：链表的五个操作全部实现（无头结点版），以及头结点的思路和Init、NodeAt、Delete、Destroy。
> **练一练**：（1）实现无头结点版的Delete，用2.11.2的程序运行，确认输出`at`。（2）改成头结点版：Init、NodeAt、Delete照本节，Insert去掉if分支，Get从头结点后开始。用同一个程序运行，输出应仍是`at`；程序末尾加上`Destroy(&L)`。（3）Delete(&L, 5)的返回值是多少？（4）把Delete里的free挪到`prev->next = q->next`之前，程序还能跑对吗？为什么不能这样写？

## 2.13 链表的时间复杂度

> **本节问题**：用2.7的方法量链表：五个操作的步数和表长n各是什么关系？编辑器2.0到底快没快？

**数什么**

规则和2.7一样：读写一个格子、一次比较、一次赋值各算一步。链表的操作里，步数几乎全来自"顺着next走"的循环——每走一步读一次next。所以量链表，数走了多少步就够。设表长为n。

**逐个操作**

Init造一个头结点，Length读一个计数器，都是固定几步，O(1)。

Get(L, i)的全部工作在NodeAt里：从头结点出发走i+1步。i最小是0，走1步；i最大是n−1，走n步。最坏O(n)，平均走n/2步，也是O(n)。这是链表和顺序表差别最大的地方：顺序表Get是一次加法算出地址，O(1)；链表没有地址可算，只能一站一站走。

Insert(L, i, x)分两段。第一段NodeAt(L, i−1)，走i步找到前一个结点，最坏O(n)；第二段造结点、改两个地址，固定几步，O(1)。加起来O(n)。Delete同理，定位O(n)，越过并释放O(1)，合计O(n)。

Destroy要释放每一个结点，O(n)。

**和顺序表放在一起**

| 操作 | 顺序表 | 链表 |
|---|---|---|
| Init、Length | O(1) | O(1) |
| Get | O(1) | O(n) |
| Insert、Delete | O(n) | O(n) |

Insert和Delete两边都是O(n)，但慢的原因不同。顺序表定位是O(1)，慢在挪动后面的元素；链表不挪动任何元素，改地址只要O(1)，慢在定位——要从头走到第i−1个。也就是说，**链表的插入删除本身是O(1)，前提是已经站在前一个结点上**。如果不需要从头走，链表就赢了；如果每次都要从头走，链表并没有比顺序表好。

Get则是链表单方面吃亏：顺序表O(1)，链表O(n)。这是"相邻格子放相邻元素"那条约定换来的好处，放弃约定就一并放弃了。

**回到编辑器**

编辑器2.0的光标是一个整数。每敲一个字符，Insert要先用NodeAt从头结点走到光标位置，再改两个地址——定位那一段和顺序表的挪动一样是O(n)。换了链表，每按一个键还是O(n)，2.7的问题并没有解决。

更糟的是显示。Show从0到n−1逐个Get，链表的每次Get都从头走，n次Get合计约n²/2步，O(n²)；顺序表的Show是n次O(1)的Get，O(n)。编辑器每处理一条指令都要Show一次，换成链表之后显示反而慢了一个量级——这正是2.7练一练（3）的答案。

问题出在哪？链表的优势是"站在前一个结点上时，插入删除O(1)"，而编辑器的光标是一个整数，每次都要重新从头走到那个位置，优势完全没用上。光标本来就一直停在编辑的位置，为什么不让它直接记住那个结点，而要记一个数字再从头找？这就是下一节要做的事。

> **到这里你有了**：链表五个操作的复杂度表，以及编辑器2.0并没有更快的结论。
> **练一练**：（1）在长度为n的链表上，在位置0插入和在位置n插入，NodeAt各走多少步？和顺序表的两种情况对照，哪头快、哪头慢正好怎样？由此回答2.12练一练（3）。（2）显示一个100字符的行，链表版的NodeAt总共走多少步？（3）如果Show不用Get，而是直接顺着next走一遍，Show是多少？这个改法和2.12练一练（2）的结论矛盾吗？
> **下一步**：让光标记住结点。

## 2.14 光标记住结点：编辑器2.1

> **本节问题**：让光标直接记住结点，每次插入就不用从头走了。可是五个操作只接受整数位置，光标手里拿着的是结点指针，调用不了它们。接口该怎么变？

### 2.14.1 光标记哪个结点

编辑器的插入点在`|`处。`|`前面那个字符的结点，正是"插入时的前一个结点"，让光标指向它最方便：敲字符就是在光标结点后面插入，然后光标移到新结点上。光标在行首时，`|`前面没有字符，让它指向头结点——头结点在这里又派上了用场，行首不再特殊。

```
                                cursor
                                  │
                                  ▼
┌───┬───┐     ┌───┬───┐     ┌───┬───┐     ┌───┬───┐
│   │ ●─┼────►│ c │ ●─┼────►│ a │ ●─┼────►│ t │ ╱ │
└───┴───┘     └───┴───┘     └───┴───┘     └───┴───┘
 头结点

屏幕显示：ca|t
```

### 2.14.2 接口要跟着变

现在的Insert(L, i, x)、Delete(L, i)只接受整数位置。这不是链表的问题，是2.1.2定义操作集时默认了"位置就是整数"——对顺序表天然合适，对链表就不合适：整数位置每次都要从头数，而链表真正擅长的是"站在一个结点上，一步改邻居"。

所以要给线性表增加一组以结点为位置的操作。按编辑器的五件事来定：敲字符要"在光标后面插入"，退格要"删掉光标这个结点"，左移右移要"前一个、后一个"，显示要"从头开始逐个取"。六个操作：

| 操作 | 含义 |
|---|---|
| Head(L) | 头结点，即第0个元素之前的位置 |
| Next(p) | p的后一个位置 |
| Prev(L, p) | p的前一个位置 |
| Data(p) | p处的元素 |
| InsertAfter(L, p, x) | 在p后面插入x |
| DeleteNode(L, p) | 删除p这个结点，p不能是头结点 |

原来的五个整数位置操作一个不少，而且可以用新操作改写：Insert(L, i, x)就是InsertAfter(L, NodeAt(L, i−1), x)，Delete(L, i)就是DeleteNode(L, NodeAt(L, i))。两套接口是一套东西，只是位置的表示不同。

要说明的是，2.12能做到"main一行不改"，是因为只换了实现、没动接口；这次main要改，是因为接口变了。接口本身也会影响效率，2.16会回头讨论。

### 2.14.3 在单链表上实现

前四个和InsertAfter都很直接，InsertAfter就是2.10的Insert去掉定位那一段：

```c
Node *Head(LinkList *L) { return L->head; }
Node *Next(Node *p)     { return p->next; }
char  Data(Node *p)     { return p->data; }

int InsertAfter(LinkList *L, Node *p, char x) {
    Node *q = NewNode(x);
    if (q == NULL) return 0;
    q->next = p->next;
    p->next = q;
    L->length++;
    return 1;
}
```

Prev和DeleteNode就没这么顺利。单链表的结点只记着后一个，前一个在哪没有任何记录，Prev唯一的办法是从头结点开始走，走到某个结点的next等于p为止。DeleteNode要把p从链上摘下来，必须改p前一个结点的next，所以它也得先调Prev：

```c
Node *Prev(LinkList *L, Node *p) {     /* 单链表上只能从头走 */
    Node *q = L->head;
    while (q->next != p) q = q->next;
    return q;
}

int DeleteNode(LinkList *L, Node *p) {
    Node *prev = Prev(L, p);           /* 这一步是O(n)的 */
    prev->next = p->next;
    free(p);
    L->length--;
    return 1;
}
```

要看清楚：这两个函数从外面看和其他操作一样，一次调用；但里面各藏着一个从头走的循环，O(n)。接口对了，代价还在。

### 2.14.4 验证：编辑器2.1

main只用这六个操作。光标是`Node *cursor`，初始指向头结点；显示顺着结点走一遍，走到光标结点时在它后面打`|`，光标是头结点时`|`打在最前面：

```c
void Show(LinkList *L, Node *cursor) {
    if (cursor == Head(L)) printf("|");
    for (Node *p = Next(Head(L)); p != NULL; p = Next(p)) {
        printf("%c", Data(p));
        if (p == cursor) printf("|");
    }
    printf("\n");
}

int main(void) {
    LinkList text;
    Node *cursor;
    char cmd, ch;

    if (!Init(&text)) return 1;
    cursor = Head(&text);                     /* 行首 */
    while (scanf(" %c", &cmd) == 1 && cmd != 'q') {
        switch (cmd) {
        case 'i':
            scanf(" %c", &ch);
            if (ch == '_') ch = ' ';
            if (InsertAfter(&text, cursor, ch)) cursor = Next(cursor);
            else printf("插入失败\n");
            break;
        case 'd':
            if (cursor != Head(&text)) {
                Node *dead = cursor;
                cursor = Prev(&text, cursor);
                DeleteNode(&text, dead);
            }
            break;
        case 'l':
            if (cursor != Head(&text)) cursor = Prev(&text, cursor);
            break;
        case 'r':
            if (Next(cursor) != NULL) cursor = Next(cursor);
            break;
        }
        Show(&text, cursor);
    }
    Destroy(&text);
    return 0;
}
```

退格里的顺序有讲究：先把光标退到前一个，再删原来的光标结点；反过来先删，就没法再问它的前一个是谁了。

输入2.1.1的会话，输出仍然是`c|`、`ca|`、`cat|`、`ca|t`、`cax|t`、`ca|t`、`cat|`。功能对了，再看效率：

| 动作 | 2.0 整数光标 | 2.1 结点光标 |
|---|---|---|
| 敲字符 | O(n) | O(1) |
| 右移 | O(1) | O(1) |
| 显示 | O(n²) | O(n) |
| 退格 | O(n) | O(n) |
| 左移 | O(1) | O(n) |

敲字符和显示好了，退格还是O(n)，左移反而从O(1)变成了O(n)——它们都要问"前一个是谁"，而单链表回答这个问题只能从头走。问题解决了一半。

> **到这里你有了**：结点位置的六个操作和编辑器2.1，敲字符、显示不再从头走。
> **练一练**：（1）实现六个操作，写出Show和main，输入2.1.1的会话，逐行核对输出。（2）光标在行尾时按一次`l`，Prev走多少步？光标在第2个字符后呢？（3）如果让光标记`|`右边那个字符而不是左边那个，敲字符时需要什么操作？行尾时光标记什么？（4）用InsertAfter和NodeAt重写Insert(L, i, x)，用2.10.4的程序验证。

## 2.15 双向链表：编辑器2.2

> **本节问题**：左移和退格都要问"p的前一个是谁"，单链表只能从头走一遍才能回答，O(n)。能不能让它也一步回答？

### 2.15.1 让结点也记住前一个

单链表的结点只记后一个，所以"后一个是谁"一步可答，"前一个是谁"要从头找。既然记一个地址就能一步找到后一个，那就再记一个地址，一步找到前一个：每个结点三格，中间是数据，两边各一个地址。这样的链表叫**双向链表**。头结点的prev是NULL，最后一个结点的next是NULL：

```
head
  │
  ▼
┌───┬───┬───┐    ┌───┬───┬───┐    ┌───┬───┬───┐    ┌───┬───┬───┐
│ ╱ │   │ ●─┼───►│ ●─┼ c │ ●─┼───►│ ●─┼ a │ ●─┼───►│ ●─┼ t │ ╱ │
│   │   │   │◄───┼─● │   │   │◄───┼─● │   │   │◄───┼─● │   │   │
└───┴───┴───┘    └───┴───┴───┘    └───┴───┴───┘    └───┴───┴───┘
    头结点
```

代价是每个结点多占一个地址的空间。换来的是：站在任何一个结点上，前一个和后一个都是一步可达。

接口不用变。2.14定的六个操作说的是"做什么"，双向链表只是换了一种"怎么做"——和2.12换存储结构是同一回事，所以编辑器的main应该又一次一行不改。要重写的只有四个实现：结点多了一根线，凡是接线、断线的函数都要照顾它。

### 2.15.2 重写四个实现

结点多一个成员：

```c
typedef struct Node {
    struct Node *prev;    /* 前一个结点的地址 */
    char         data;
    struct Node *next;    /* 下一个结点的地址 */
} Node;
```

NewNode多初始化一个prev：

```c
Node *NewNode(char x) {
    Node *p = (Node *)malloc(sizeof(Node));
    if (p == NULL) return NULL;
    p->prev = NULL;
    p->data = x;
    p->next = NULL;
    return p;
}
```

Prev一步完成。参数L用不上了，保留是为了签名和单链表版本一致，main不用改：

```c
Node *Prev(LinkList *L, Node *p) { return p->prev; }
```

InsertAfter在p后面插q，单链表接两根线，双向链表要接四根：q的prev和next，p的next，以及p原来的后一个（叫它r）的prev。p可能是最后一个结点，这时没有r，那一根不用接：

```
       p                q                r
  ┌───┬───┬───┐    ┌───┬───┬───┐    ┌───┬───┬───┐
  │   │ a │ ④─┼───►│ ① │ x │ ②─┼───►│ ③ │ t │   │
  │   │   │   │◄───┼── │   │   │◄───┼── │   │   │
  └───┴───┴───┘    └───┴───┴───┘    └───┴───┴───┘
  ① q->prev = p     ② q->next = r     ③ r->prev = q     ④ p->next = q
```

```c
int InsertAfter(LinkList *L, Node *p, char x) {
    Node *q = NewNode(x);
    if (q == NULL) return 0;
    q->prev = p;                              /* ① */
    q->next = p->next;                        /* ② */
    if (p->next != NULL) p->next->prev = q;   /* ③，p是末尾时跳过 */
    p->next = q;                              /* ④ */
    L->length++;
    return 1;
}
```

顺序仍然要注意：②③都要用到`p->next`，也就是r，所以改`p->next`的④放最后，否则r就找不到了。

DeleteNode不再需要从头找前一个：让p的前一个越过p指向p的后一个，让p的后一个（如果有）越过p指回p的前一个，然后释放p。头结点永远不会被删，所以`p->prev`一定存在：

```c
int DeleteNode(LinkList *L, Node *p) {
    p->prev->next = p->next;
    if (p->next != NULL) p->next->prev = p->prev;
    free(p);
    L->length--;
    return 1;
}
```

Head、Next、Data、Length、Get、NodeAt、Destroy都不用改。整数位置的Insert和Delete改成调用新操作，prev指针就自动维护好了：

```c
int Insert(LinkList *L, int i, char x) {
    if (i < 0 || i > L->length) return 0;
    return InsertAfter(L, NodeAt(L, i - 1), x);
}

int Delete(LinkList *L, int i) {
    if (i < 0 || i >= L->length) return 0;
    return DeleteNode(L, NodeAt(L, i));
}
```

### 2.15.3 验证：编辑器2.2，main一行不改

编辑器2.1的main和Show一个字不动，换上双向链表的实现重新编译，输入2.1.1的会话，输出完全相同。这就是编辑器2.2。

用这段会话跟踪一遍，看双向链表上光标怎么动：

- `i c`：光标在头结点，InsertAfter在头结点后面插c：c的prev是头结点、next是NULL，头结点的next改为c；光标移到c。显示`c|`。
- `i a`、`i t`：同理，光标依次到a、t。显示`cat|`。
- `l`：光标从t退到Prev(t)，一步读到a。显示`ca|t`。
- `i x`：在a后面插x：x的prev是a、next是t，t的prev改为x，a的next改为x；光标到x。显示`cax|t`。
- `d`：光标结点是x，先退到Prev(x)即a，再DeleteNode(x)：a的next改为t，t的prev改为a，释放x。显示`ca|t`。
- `r`：光标到Next(a)即t。显示`cat|`。

每一步都只动了光标附近的几根线，和整行有多长没有关系。

**时间复杂度。** 六个结点位置操作在两种链表上：

| 操作 | 单链表 | 双向链表 |
|---|---|---|
| Head、Next、Data | O(1) | O(1) |
| InsertAfter | O(1) | O(1) |
| Prev | O(n) | O(1) |
| DeleteNode | O(n) | O(1) |

编辑器的四个版本放在一起：

| 动作 | 1.1 顺序表 | 2.0 链表，整数光标 | 2.1 单链表，结点光标 | 2.2 双向链表，结点光标 |
|---|---|---|---|---|
| 敲字符 | O(n) | O(n) | O(1) | O(1) |
| 退格 | O(n) | O(n) | O(n) | O(1) |
| 左移 | O(1) | O(1) | O(n) | O(1) |
| 右移 | O(1) | O(1) | O(1) | O(1) |
| 显示 | O(n) | O(n²) | O(n) | O(n) |

2.7提出的问题——在行首打字慢——到这里才真正解决：不管光标在哪，敲一个字符、退格、移动光标都是O(1)。显示O(n)无法避免，n个字符总要一个个打出来。

回头看这一路：换成链表本身并没有让编辑器变快（2.0），让它变快的是"让光标记住结点"这个改动，而它要求接口能表达"结点位置"（2.1）；接口定对之后，单链表上还有两个操作藏着O(n)，最后为了前后都能一步走，把链表改成了双向（2.2）。存储结构、接口、应用三者是一起变的。

> **到这里你有了**：双向链表，以及敲字符、退格、移动光标都是O(1)的编辑器2.2。
