# 第4章 树

打开电脑里的"文档"文件夹。里面有工作、论文、照片、下载四个文件夹。"工作"里放着周报、合同，还有一个文件夹2025，里面是年终总结。"论文"里是初稿，"照片"里是两张照片，"下载"还是空的。

<TreeFigure folders tree="文档(工作(周报,合同,2025(年终总结)),论文(初稿),照片(1.jpg,2.jpg),下载/)" />

带折角的框是文件夹，没有框的是文件。

2.1节的练习里，文件夹目录被判为不能看成线性表。试着硬把它排成一列：

```
(文档, 工作, 周报, 合同, 2025, 年终总结, 论文, 初稿, 照片, 1.jpg, 2.jpg, 下载)
```

这一列只记得谁挨着谁。周报在哪个文件夹里？"工作"里直接有几项？"下载"是一个空文件夹，还是一个文件？从这一列里都看不出来。

一个文件夹里可以放好几项，它的后继不止一个。线性表记得住谁挨着谁，记不住谁装着谁。

公司的组织架构，一个经理管着几个人；一本书的目录，一章分成几节。它们也都是这样一层套一层。

在数据结构里，这样的数据叫**树**。

学完这一章，你会判断什么样的数据是树，用一套名词说清它的样子，把它放进内存，并把它的每个结点都走一遍。

要让程序管好这些文件夹，得先回答三个问题：

> **问题**：
> 1. 程序要记住文件夹之间的什么？
> 2. 怎样把每个文件都看一遍，一个不漏、一个不重？
> 3. 怎么把它放进内存？

先记住这三个问题。我们从第一个开始。要回答它，先得把"一层套一层"说精确。

## 4.1 树

**什么是树**

这个文件夹目录可以看成一棵**树**：最顶层只有一个"文档"，其余的东西一层套一层挂在它下面。

树的定义是这样的。树是n个**结点**的有限集合。n等于0时，叫**空树**。n大于0时：

1. 有且只有一个特定的结点，叫**根**；
2. 其余的结点分成m个互不相交的有限集合，每个集合本身又是一棵树，叫根的**子树**。

定义里用到了树自己：子树也是树。这就是3.8节的递归，一棵树用几棵小一点的树来说清楚。

放回文件夹里看。每个文件、每个文件夹都是一个结点，一共12个。根是"文档"。其余11个结点分成4组：

- 工作、周报、合同、2025、年终总结，5个；
- 论文、初稿，2个；
- 照片、1.jpg、2.jpg，3个；
- 下载，1个。

<TreeFigure folders tree="文档(工作(周报,合同,2025(年终总结)),论文(初稿),照片(1.jpg,2.jpg),下载/)" circle="工作 论文 照片 下载" />

每一组正好是"文档"里的一个文件夹，连同它里面的全部内容。每一组自己又是一棵树：工作这棵子树的根是"工作"；下载这棵子树只有一个结点。把"工作"整个拷到U盘上，拷走的就是一棵子树。

这个定义有三个要点，逐条看。

**有且只有一个根**。根只有一个，程序只要记住它，就能从它出发找到所有东西。电脑里的C盘和D盘各有自己的最顶层，放在一起就有两个根，不是一棵树：

<TreeFigure folders tree="C盘(系统,程序),D盘(资料,备份)" />

**互不相交**。除了根，每个结点只属于一组。假设周报同时放在"工作"和"论文"里：

<TreeFigure folders tree="文档(工作(周报,合同,2025(年终总结)),论文(初稿),照片(1.jpg,2.jpg),下载/)" extra="论文-周报" />

"工作"那组和"论文"那组都有周报，两组相交了，这就不是树。互不相交，"周报在哪个文件夹里"就只有一个答案，从根走到它只有一条路。

**每组又是一棵树**。只看最上面一层还不够。假设年终总结放在2025里，又直接放在"工作"里：

<TreeFigure folders tree="文档(工作(周报,合同,2025(年终总结)),论文(初稿),照片(1.jpg,2.jpg),下载/)" extra="工作-年终总结" />

看最上面一层，4组照样互不相交，年终总结只在"工作"这一组里。可是把"工作"这一组当成一棵树，再拆一层，"2025"那组和"年终总结"那组就相交了。所以判断是不是树，要一层一层拆到底，每一层都满足才行。

三个要点合起来，可以得到一个好用的结论：**除了根，每个结点恰好有一个上级**，而且从根出发往下走，能走到每一个结点。判断一样东西是不是树，看这一条最快。

**森林**

把根"文档"去掉，剩下的4棵子树就各自独立了：

<TreeFigure folders tree="工作(周报,合同,2025(年终总结)),论文(初稿),照片(1.jpg,2.jpg),下载/" />

m棵互不相交的树放在一起，叫**森林**。m可以是0。

树的定义里说，其余的结点分成m个互不相交的集合，每个又是一棵树。这说的就是：去掉根，剩下的是一片森林。反过来，给这4棵树加一个共同的上级"文档"，又成了一棵树。

树和森林只差一个根。上一页的C盘和D盘，合起来不是一棵树，而是一片有两棵树的森林。

程序也常常和森林打交道。后面把一棵树走一遍时，看完根以后，要接着走的正是它的子树组成的森林。

**例题：组织架构和先修课能看成树吗**

> **题目**：把每个人、每门课当作结点，下面两样东西能不能看成一棵树？
> 一家小公司：张总管着李经理和陈经理，李经理管着小王和小赵，陈经理管着小刘。
> 几门课的先修关系：学C语言和离散数学之前，要先学高中数学；学数据结构之前，要先学C语言和离散数学。

<TreeFigure tree="张总(李经理(小王,小赵),陈经理(小刘))" />

**分析**。先看公司，上级就是管着他的人。

1. 看根：只有张总没有上级。是。
2. 看互不相交：李经理、陈经理各管一组人。小王、小赵只在李经理那组，小刘只在陈经理那组，没有人同时在两组。是。
3. 看每组是不是树：李经理那组，根是李经理，小王、小赵各成一组，互不相交；陈经理那组也一样。是。

再看课程，上级就是要先学的课。

1. 看根：只有高中数学不需要先学别的课。是。
2. 看互不相交：高中数学下面分成C语言、离散数学两组。数据结构既要先学C语言，又要先学离散数学，两组都有它。否。到这里就能下结论。

<TreeFigure tree="高中数学(C语言(数据结构),离散数学)" extra="离散数学-数据结构" />

> **答案**：公司可以看成一棵树，根是张总。先修课不能，因为数据结构有两个上级，两组相交了。

两样东西都只有一个根，差别在互不相交这一条：一门课可以有好几门先修课，一个人却只有一个直接上级。

**双亲、孩子、兄弟、祖先、子孙**

这几个名词说的是结点和结点之间的关系，名字借自家谱。

一个结点的上级，叫它的**双亲**。它直接的下级，叫它的**孩子**。工作是周报的双亲；周报、合同、2025是工作的孩子。树里每个结点只有一个双亲，"双亲"这个词说的是一个结点，不是两个。

同一个双亲的孩子，互为**兄弟**。周报、合同、2025是兄弟。它们放在同一个文件夹里，所以不能重名。

从根走到一个结点，路上经过的结点都是它的**祖先**。年终总结的祖先是文档、工作、2025，一共3个。地址栏里的路径，写的正是它的全部祖先：

```
文档\工作\2025\年终总结
```

<TreeFigure folders tree="文档(工作(周报,合同,2025(年终总结)),论文(初稿),照片(1.jpg,2.jpg),下载/)" path="年终总结" />

反过来，一个结点下面的所有结点，都是它的**子孙**。工作的子孙是周报、合同、2025、年终总结，一共4个。删除"工作"文件夹时，一起被删掉的就是它的全部子孙：

<TreeFigure folders tree="文档(工作(周报,合同,2025(年终总结)),论文(初稿),照片(1.jpg,2.jpg),下载/)" hi="周报 合同 2025 年终总结" />

和2.1节的线性表对照一下：

```
线性表：除了第一个，每个元素恰好一个前驱；除了最后一个，每个元素恰好一个后继
树：    除了根，每个结点恰好一个双亲；孩子可以有任意多个
```

双亲像前驱，只有一个。孩子不像后继，可以有好几个。树就是把"后继只有一个"放开了。反过来，每个结点最多一个孩子的树，就是一个线性表。

<!-- 分页 -->

**度、叶子、分支结点**

一个结点有几个孩子，叫这个结点的**度**。打开一个文件夹，直接看到几项，它的度就是几：

<TreeFigure folders tree="文档(工作(周报,合同,2025(年终总结)),论文(初稿),照片(1.jpg,2.jpg),下载/)" label="文档:4 工作:3 2025:1 论文:1 照片:2 下载:0" />

度只数孩子，不数孩子的孩子。工作下面一共有4样东西，可它的度是3：年终总结在2025里，不是工作直接的孩子。文件里不能再放东西，度都是0。

各结点的度里最大的那个，叫**树的度**。这棵树的度是4，就是"文档"的度。

度为0的结点叫**叶子**，度不为0的结点叫**分支结点**。这棵树有7个叶子：6个文件，加上空文件夹"下载"。分支结点有5个：文档、工作、2025、论文、照片。

<TreeFigure folders tree="文档(工作(周报,合同,2025(年终总结)),论文(初稿),照片(1.jpg,2.jpg),下载/)" hi="周报 合同 年终总结 初稿 1.jpg 2.jpg 下载" />

"下载"是文件夹，可它里面什么都没有，度是0，所以也是叶子。叶子看的是有没有孩子，不是是不是文件。从根往下找东西，走到叶子，这条路就走到头了。

验算一下：7个叶子加5个分支结点，正好12个结点。所有结点的度加起来是4 + 3 + 1 + 1 + 2，等于11，比结点数少1。因为除了根，每个结点都是某一个结点的孩子，在度里恰好被数了一次。

<!-- 分页 -->

**层次、深度、高度**

根在第1层，根的孩子在第2层，孩子的孩子在第3层，依此类推。这叫结点的**层次**。

<TreeFigure folders levels tree="文档(工作(周报,合同,2025(年终总结)),论文(初稿),照片(1.jpg,2.jpg),下载/)" />

由层次，本书这样约定深度和高度：

- 结点的**深度**：从根往下数，就是它的层次。根的深度是1，年终总结的深度是4。
- 结点的**高度**：从它下面最深的叶子往上数，叶子的高度是1。2025的高度是2，工作的高度是3，文档的高度是4。
- 树的**高度**，也叫树的**深度**：最大的层次。这棵树的高度是4。空树的高度是0。

放回文件夹里：一个结点的深度，就是地址栏里有几段，`文档\工作\2025\年终总结`有4段。树的高度，就是最深的东西藏了几层：从"文档"开始，最多再点开3次文件夹，就能看到任何一个文件。

::: tip 另一种约定
很多英文教材和LeetCode按边数算：根的深度是0，叶子的高度是0，算出来都比本书少1。做题时先看清用的是哪一种。本书和国内教材、考研统考一样，按层数算。
:::

**有序树和无序树**。资源管理器里，文件可以按名称排，也可以按修改时间排。不管怎么排，周报还在工作里，目录还是同一个。孩子之间的先后不算数，这样的树叫**无序树**。

书的目录不一样。第一章、第二章、第三章的先后不能换，换了就是另一本书。孩子之间的先后算数，这样的树叫**有序树**。

回到本章开头的第一个问题：程序要记住文件夹之间的什么？这些文件夹可以看成一棵树，而树里除了根，每个结点恰好有一个双亲。所以程序要记住的，是每个结点的双亲是谁，或者反过来，每个结点的孩子是谁。有了这一条，层次、祖先、子孙、度、高度，都能算出来。

## 4.2 树的操作

**树的基本操作**

4.1节说的是树"是什么"。要用它，还得规定能对它做什么。1.3节说过，逻辑关系加上一组操作，就是抽象数据类型。这一节给树定下这组操作。

树常用的操作有很多，不同的程序用到的不一样。这里取最基本的八个，文件夹正好都要用。下面把树记作T，结点记作p，新结点的名字记作x。接着用4.1节那棵文件夹树：

<TreeFigure folders tree="文档(工作(周报,合同,2025(年终总结)),论文(初稿),照片(1.jpg,2.jpg),下载/)" />

**InitTree(T)：建立一棵空树**。一个文件夹都还没有的时候，先要有一棵空树。

**Root(T)：返回根**。一切从根开始找。在这棵树上，返回的是"文档"。空树没有根，返回NULL。

**Value(T, p)：返回结点p的名字**。拿到一个结点，要知道它叫什么，才能显示出来。

**Parent(T, p)：返回p的双亲**，也就是点一下"上一级"。根没有双亲，返回NULL。Parent(T, 周报)返回工作：

<TreeFigure folders tree="文档(工作(周报,合同,2025(年终总结)),论文(初稿),照片(1.jpg,2.jpg),下载/)" hi="周报 工作" label="周报:p 工作:返回" />

**FirstChild(T, p)：返回p的第一个孩子**，也就是打开文件夹，看第一项。p没有孩子时返回NULL。FirstChild(T, 工作)返回周报；FirstChild(T, 下载)返回NULL，因为"下载"是空的。

**NextSibling(T, p)：返回p的下一个兄弟**，也就是往下看一项。p后面没有兄弟时返回NULL。NextSibling(T, 周报)返回合同：

<TreeFigure folders tree="文档(工作(周报,合同,2025(年终总结)),论文(初稿),照片(1.jpg,2.jpg),下载/)" hi="周报 合同" label="周报:p 合同:返回" />

**InsertChild(T, p, x)：给p加一个孩子，名字是x，返回新结点**，也就是在文件夹里新建一项。新结点放在p的孩子最前面。4.1节说过，文件夹是无序树，孩子的先后不算数，放在哪里都还是这棵树。p写NULL时，表示往空树里放，x成为根。

**DeleteSubtree(T, p)：删除p和它的全部子孙**，也就是删除文件夹。DeleteSubtree(T, 工作)删掉的是工作、周报、合同、2025、年终总结，一共5个结点：

<TreeFigure folders tree="文档(工作(周报,合同,2025(年终总结)),论文(初稿),照片(1.jpg,2.jpg),下载/)" circle="工作" />

八个操作汇总如下：

| 操作 | 含义 | 文件夹里的动作 |
|---|---|---|
| InitTree(T) | 建立一棵空树 | 还没有任何文件夹 |
| Root(T) | 返回根 | 打开最顶层 |
| Value(T, p) | 返回p的名字 | 看这一项叫什么 |
| Parent(T, p) | 返回p的双亲 | 点"上一级" |
| FirstChild(T, p) | 返回p的第一个孩子 | 打开文件夹，看第一项 |
| NextSibling(T, p) | 返回p的下一个兄弟 | 往下看一项 |
| InsertChild(T, p, x) | 给p加一个孩子x | 新建一项 |
| DeleteSubtree(T, p) | 删除p和它的全部子孙 | 删除文件夹 |

和2.2节线性表的操作比，有三处不同。

**位置是结点，不是序号**。线性表说"第i个"。树没有第i个，一层有好几个结点，从左到右数也说不清它是谁的孩子。所以操作直接拿结点说话，就是2.16节的按结点操作。

**孩子一个一个地看**。一个文件夹里有几项，事先不知道。所以先用FirstChild拿到第一个，再用NextSibling一个一个往下看，看到NULL就完了。也可以定成"取第i个孩子"，这是一种取舍，这里选了更贴近打开文件夹的那种。

**删除连子孙一起删**。删掉一个结点，它的孩子不能悬空，总得有个去处。删除文件夹时，里面的东西一起没了，所以这里定成连子孙一起删。

常见的还有求高度、把每个结点都走一遍等操作，用到时再加。

## 4.3 树的存储与实现

**记双亲**

回到本章开头的第三个问题：怎么把树放进内存？

线性表好办，一个接一个，放在相邻的格子里，关系就有了。树不行：一个结点后面跟着好几个结点，相邻表示不出来。关系只能明着记下来。

4.1节的结尾说过，程序要记住每个结点的双亲是谁，或者每个结点的孩子是谁。两条路都试一试。每试一种，都看4.2节的操作要走几步、要占多少地方。

> **本节问题**：这棵12个结点的文件夹树，怎么存，操作才走得少，又不浪费地方？

先试记双亲。每个结点只有一个双亲，一个数就记下了。把12个结点放进一张表，parent记着双亲在第几行。根没有双亲，记成−1：

| 下标 | 名字 | parent |
|---|---|---|
| 0 | 文档 | −1 |
| 1 | 工作 | 0 |
| 2 | 论文 | 0 |
| 3 | 照片 | 0 |
| 4 | 下载 | 0 |
| 5 | 周报 | 1 |
| 6 | 合同 | 1 |
| 7 | 2025 | 1 |
| 8 | 初稿 | 2 |
| 9 | 1.jpg | 3 |
| 10 | 2.jpg | 3 |
| 11 | 年终总结 | 7 |

这种存法叫**双亲表示法**。每个结点只多记一个数，非常省地方。

Parent一步到位：周报在第5行，parent是1，第1行就是工作。

可是打开文件夹就慢了。FirstChild(T, 工作)要找parent等于1的行，只能从头往下扫。要确认"下载"是空的，得把12行都看完，才知道没有一行的parent是4。n个结点，就要看n行，是O(n)。

打开文件夹是最常做的事。所以再试另一条路：记孩子。

<!-- 分页 -->

**记孩子**

每个结点要记几个孩子？个数不定。先用最直接的办法：每个结点都留够格子。这棵树的度是4，那就每个结点留4格，放孩子的地址。

```
文档：工作  论文  照片  下载
工作：周报  合同  2025  空
论文：初稿  空    空    空
周报：空    空    空    空
……
```

FirstChild一步到位。可是算一算格子：12个结点，每个4格，一共48格。4.1节验算过，所有结点的度加起来是11，也就是只用了11格，空着37格。

一般地，n个结点、度为d的树，要n × d格，只用n − 1格。只有"文档"真需要4格，却让每个结点都留4格，连文件也不例外。

个数不定的东西，第2章有现成的办法：用链表串起来，有几个就申请几个。每个结点带一条孩子链表：

```
文档 ──► 工作 ──► 论文 ──► 照片 ──► 下载
工作 ──► 周报 ──► 合同 ──► 2025
论文 ──► 初稿
照片 ──► 1.jpg ──► 2.jpg
2025 ──► 年终总结
其余的结点：链表是空的
```

这种存法叫**孩子表示法**。链上一共11个小结点，一个不多。

可是它要两种东西：一张放12个结点的表，再加上11个链上的小结点。每个孩子都在表里存一次，又在链上出现一次。

<!-- 分页 -->

**孩子兄弟表示法**

再看上一页的孩子链表。周报出现在哪几条链上？只有"工作"这一条。

这不是碰巧。4.1节说过，除了根，每个结点恰好有一个双亲。所以每个结点最多出现在一条孩子链上。

既然只在一条链上，"链上的下一个"就只有一个，不用另外包一层小结点，直接记在结点自己身上就行。

于是每个结点只记两个地址：**first**，第一个孩子；**next**，下一个兄弟。下面的图里，向下的箭头是first，向右的箭头是next，没有箭头就是NULL：

<CsTreeFigure nodes="文档@0,0 工作@1,0 论文@1,3 照片@1,4 下载@1,6 周报@2,0 合同@2,1 2025@2,2 初稿@2,3 1.jpg@2,4 2.jpg@2,5 年终总结@3,2" first="文档>工作 工作>周报 2025>年终总结 论文>初稿 照片>1.jpg" next="工作>论文 论文>照片 照片>下载 周报>合同 合同>2025 1.jpg>2.jpg" />

这种存法叫**孩子兄弟表示法**。

打开"工作"：先走first到周报，再沿着next走到合同、2025，走到NULL就看完了。这正好就是FirstChild和NextSibling，各走一步。

数一数指针。12个结点，每个2个指针，一共24个。非空的是：first有5个，就是5个分支结点；next有6个。一共11个，正好n − 1。空着13个，比定长数组的37个少得多，而且结点大小固定，只有一种。

只差一个操作：Parent。沿着first和next只能往下、往右，回不到上一级。所以再加一个指针**parent**，记着双亲。图里为了清楚，没有画它。

::: tip 教材里的孩子兄弟表示法
教材和考研说的孩子兄弟表示法，每个结点只有两个指针：第一个孩子和下一个兄弟。这里多加的parent，是因为4.2节的操作集里有Parent。不需要找双亲的程序，可以不加。
:::

<!-- 分页 -->

**三种存法比一比**

n个结点，每个操作最多要走几步：

| 操作 | 双亲表示法 | 孩子表示法 | 孩子兄弟表示法（加parent） |
|---|---|---|---|
| Parent | O(1) | O(n) | O(1) |
| FirstChild | O(n) | O(1) | O(1) |
| NextSibling | O(n) | O(n) | O(1) |
| InsertChild | O(1) | O(1) | O(1) |
| 每个结点占的地方 | 名字、一个数 | 表里一格，加上链上的小结点 | 名字、三个指针 |

双亲表示法的NextSibling，要接着往下扫，找下一个parent相同的行。孩子表示法的Parent和NextSibling，都要先找到这个结点在哪条链上。

回到本节问题，也回到本章开头的第三个问题：怎么把树放进内存？要看常做的是什么。

只需要往上找、很少打开文件夹的程序，双亲表示法最省。文件夹上下都要走，所以这里选孩子兄弟表示法，再加一个parent。下面就用它把八个操作写出来。

<!-- 分页 -->

**用C语言表示树**

每个结点放一个名字和三个指针：

```c
typedef struct TNode {
    char name[20];          /* 名字 */
    struct TNode *parent;   /* 双亲 */
    struct TNode *first;    /* 第一个孩子 */
    struct TNode *next;     /* 下一个兄弟 */
} TNode, *Tree;
```

和2.10节的Node、LinkList一样，TNode是结点类型，Tree是指向结点的指针类型。一棵树，只要记住根的地址。

下面六个操作，每个只有一行。InitTree要改根，所以和3.4节一样，参数是`Tree *T`；其余五个照着写，只读一个指针或一个名字：

```c
void InitTree(Tree *T)                  { *T = NULL; }
TNode *Root(Tree *T)                    { return *T; }
char *Value(Tree *T, TNode *p)          { return p->name; }
TNode *Parent(Tree *T, TNode *p)        { return p->parent; }
TNode *FirstChild(Tree *T, TNode *p)    { return p->first; }
TNode *NextSibling(Tree *T, TNode *p)   { return p->next; }
```

Value、Parent这几个函数其实用不上T。留着它，是因为换成双亲表示法时就要用T去扫表。调用的写法不变，换存法时调用者不用改。

**InsertChild：新建一项**

"工作"里已经有合同、2025。现在InsertChild(T, 工作, "周报")。

**第一步：申请结点q，放名字**。q的双亲是工作；它刚建好，没有孩子，first是NULL：

```c
TNode *q = (TNode *)malloc(sizeof(TNode));
strcpy(q->name, x);
q->first = NULL;
q->parent = p;
```

**第二步：q指向原来的第一个孩子**：

```c
q->next = p->first;
```

<CsTreeFigure nodes="工作@0,1 周报@1,0 合同@1,1 2025@1,2" first="工作>合同" next="周报>合同 合同>2025" now="周报>合同" ptr="p>工作 q>周报" />

**第三步：p的第一个孩子改成q**：

```c
p->first = q;
```

<CsTreeFigure nodes="工作@0,1 周报@1,0 合同@1,1 2025@1,2" first="工作>周报" next="周报>合同 合同>2025" now="工作>周报" ptr="p>工作 q>周报" />

**先连上，再改first，顺序不能反**。先改first，合同的地址就丢了，合同和2025再也找不回来。这和2.12节在第0个位置插入，是同一件事。

往空树里放根时，p是NULL，没有孩子链可接，让T指向q就行。写成函数，返回新结点，申请不到时返回NULL：

```c
TNode *InsertChild(Tree *T, TNode *p, char *x) {
    TNode *q = (TNode *)malloc(sizeof(TNode));  /* 第一步：申请结点，放名字 */
    if (q == NULL) return NULL;
    strcpy(q->name, x);
    q->first = NULL;
    q->parent = p;
    if (p == NULL) {         /* 空树：q就是根 */
        q->next = NULL;
        *T = q;
    } else {
        q->next = p->first;  /* 第二步：q指向原来的第一个孩子 */
        p->first = q;        /* 第三步：p的第一个孩子改成q */
    }
    return q;
}
```

不用走，是O(1)。

<!-- 分页 -->

**DeleteSubtree：删除文件夹**

删除分两件事：先把p从孩子链上摘下来，再释放p和它的全部子孙。

**第一件事：摘下来**。先看简单的：删合同。它不是第一个孩子，要让前一个兄弟周报的next跳过它。前一个兄弟没有直接记着，只好从第一个孩子开始，沿着next找：

```c
TNode *q = p->parent->first;
while (q->next != p) q = q->next;   /* 找到前一个兄弟 */
q->next = p->next;
```

<CsTreeFigure nodes="工作@0,1 周报@1,0 合同@2,1 2025@1,2" first="工作>周报" next="周报>2025 合同>2025" now="周报>2025" hi="合同" ptr="q>周报 p>合同" />

如果p是第一个孩子，前面没有兄弟，要改的是双亲的first。删"工作"就是这样，把文档的first改成论文：

```c
p->parent->first = p->next;
```

如果p是根，整棵树都没了，让T变成NULL。一共三种情形。

**第二件事：释放**。p的孩子可能还有孩子，一层一层有多深，事先不知道。可是每个孩子下面都是一棵子树，释放子树和释放整棵是同一件事。这就是3.8节的递归：

```c
void FreeSubtree(TNode *p) {
    TNode *c = p->first;
    while (c != NULL) {
        TNode *after = c->next;   /* 先记下下一个兄弟 */
        FreeSubtree(c);           /* 释放这个孩子的子树 */
        c = after;
    }
    free(p);                      /* 孩子都释放了，再释放自己 */
}
```

规模变小：每次处理的都是一棵更小的子树。出口：没有孩子时，循环一次都不走，直接释放自己。

**先记下next，再释放，顺序不能反**。c释放之后，c->next读的是已经不归你的内存。**先释放孩子，再释放自己**，也不能反：自己先释放了，就读不到first，孩子全找不回来。

删除"工作"时，5个结点释放的先后是这样的：

<TreeFigure folders tree="工作(周报,合同,2025(年终总结))" label="周报:① 合同:② 年终总结:③ 2025:④ 工作:⑤" />

合起来：

```c
void DeleteSubtree(Tree *T, TNode *p) {
    TNode *f = p->parent;
    if (f == NULL) {                  /* p是根 */
        *T = NULL;
    } else if (f->first == p) {       /* p是第一个孩子 */
        f->first = p->next;
    } else {                          /* 找到前一个兄弟 */
        TNode *q = f->first;
        while (q->next != p) q = q->next;
        q->next = p->next;
    }
    FreeSubtree(p);
}
```

**把八个操作合起来**

再写一个main。InsertChild总是放在最前面，所以每个文件夹里的项要倒着建，看的时候才是图上的顺序。ShowChildren只用FirstChild和NextSibling，列出一个文件夹里的项：

```c
void ShowChildren(Tree *T, TNode *p) {
    TNode *c;
    printf("%s：", Value(T, p));
    for (c = FirstChild(T, p); c != NULL; c = NextSibling(T, c))
        printf("%s ", Value(T, c));
    printf("\n");
}

int main(void) {
    Tree T;
    TNode *doc, *work, *y2025, *report, *paper, *photo, *contract;
    InitTree(&T);
    doc = InsertChild(&T, NULL, "文档");
    InsertChild(&T, doc, "下载");
    photo = InsertChild(&T, doc, "照片");
    paper = InsertChild(&T, doc, "论文");
    work = InsertChild(&T, doc, "工作");
    InsertChild(&T, photo, "2.jpg");
    InsertChild(&T, photo, "1.jpg");
    InsertChild(&T, paper, "初稿");
    y2025 = InsertChild(&T, work, "2025");
    InsertChild(&T, y2025, "年终总结");
    contract = InsertChild(&T, work, "合同");
    report = InsertChild(&T, work, "周报");

    ShowChildren(&T, doc);
    ShowChildren(&T, work);
    printf("周报的上一级：%s\n", Value(&T, Parent(&T, report)));

    DeleteSubtree(&T, contract);
    ShowChildren(&T, work);

    DeleteSubtree(&T, work);
    ShowChildren(&T, Root(&T));
    return 0;
}
```

这个程序能列出一个文件夹里的项，却还列不出全部文件。本章开头的第二个问题，还没有回答。

完整的程序放在下面，可以直接复制运行：

```c
#include <stdio.h>
#include <stdlib.h>
#include <string.h>

typedef struct TNode {
    char name[20];
    struct TNode *parent;
    struct TNode *first;
    struct TNode *next;
} TNode, *Tree;

void InitTree(Tree *T)                  { *T = NULL; }
TNode *Root(Tree *T)                    { return *T; }
char *Value(Tree *T, TNode *p)          { return p->name; }
TNode *Parent(Tree *T, TNode *p)        { return p->parent; }
TNode *FirstChild(Tree *T, TNode *p)    { return p->first; }
TNode *NextSibling(Tree *T, TNode *p)   { return p->next; }

TNode *InsertChild(Tree *T, TNode *p, char *x) {
    TNode *q = (TNode *)malloc(sizeof(TNode));  /* 第一步：申请结点，放名字 */
    if (q == NULL) return NULL;
    strcpy(q->name, x);
    q->first = NULL;
    q->parent = p;
    if (p == NULL) {         /* 空树：q就是根 */
        q->next = NULL;
        *T = q;
    } else {
        q->next = p->first;  /* 第二步：q指向原来的第一个孩子 */
        p->first = q;        /* 第三步：p的第一个孩子改成q */
    }
    return q;
}

void FreeSubtree(TNode *p) {
    TNode *c = p->first;
    while (c != NULL) {
        TNode *after = c->next;   /* 先记下下一个兄弟 */
        FreeSubtree(c);           /* 释放这个孩子的子树 */
        c = after;
    }
    free(p);                      /* 孩子都释放了，再释放自己 */
}

void DeleteSubtree(Tree *T, TNode *p) {
    TNode *f = p->parent;
    if (f == NULL) {                  /* p是根 */
        *T = NULL;
    } else if (f->first == p) {       /* p是第一个孩子 */
        f->first = p->next;
    } else {                          /* 找到前一个兄弟 */
        TNode *q = f->first;
        while (q->next != p) q = q->next;
        q->next = p->next;
    }
    FreeSubtree(p);
}

void ShowChildren(Tree *T, TNode *p) {
    TNode *c;
    printf("%s：", Value(T, p));
    for (c = FirstChild(T, p); c != NULL; c = NextSibling(T, c))
        printf("%s ", Value(T, c));
    printf("\n");
}

int main(void) {
    Tree T;
    TNode *doc, *work, *y2025, *report, *paper, *photo, *contract;
    InitTree(&T);
    doc = InsertChild(&T, NULL, "文档");
    InsertChild(&T, doc, "下载");
    photo = InsertChild(&T, doc, "照片");
    paper = InsertChild(&T, doc, "论文");
    work = InsertChild(&T, doc, "工作");
    InsertChild(&T, photo, "2.jpg");
    InsertChild(&T, photo, "1.jpg");
    InsertChild(&T, paper, "初稿");
    y2025 = InsertChild(&T, work, "2025");
    InsertChild(&T, y2025, "年终总结");
    contract = InsertChild(&T, work, "合同");
    report = InsertChild(&T, work, "周报");

    ShowChildren(&T, doc);
    ShowChildren(&T, work);
    printf("周报的上一级：%s\n", Value(&T, Parent(&T, report)));

    DeleteSubtree(&T, contract);
    ShowChildren(&T, work);

    DeleteSubtree(&T, work);
    ShowChildren(&T, Root(&T));
    return 0;
}
```

**练习2：摘下来时少了一步会怎样？**

::: quiz 单选
有人写DeleteSubtree时，漏了前一个兄弟那一行：

```c
TNode *q = f->first;
while (q->next != p) q = q->next;
/* 漏了 q->next = p->next; */
```

"工作"里依次是周报、合同、2025。调用DeleteSubtree(&T, 合同)之后，再列出"工作"里的项，会怎样？

- [ ] 正常列出周报、2025
  周报的next没改，走到周报之后，下一步还是合同那个地址。
- [ ] 只列出周报，到此为止
  周报的next不是NULL，它还记着合同的地址。
- [x] 走到周报之后，去读已经释放的合同结点，读到什么说不准
  合同已经还给系统，可周报的next还指着它。程序可能打印乱码，也可能崩溃。

摘下来和释放是两件事。先让链上没有人再指着它，才能释放它。
:::

> **到这里你有了**：树的三种存法：双亲表示法记双亲，找孩子要扫；孩子表示法用链表记孩子；孩子兄弟表示法每个结点记第一个孩子和下一个兄弟。因为每个结点只有一个双亲，所以只在一条孩子链上。以及用孩子兄弟表示法加parent写出的八个操作，其中删除用递归释放子孙。
> **下一步**：孩子兄弟表示法的每个结点只有两个指针。每个结点最多连两个，这样的树就是二叉树。
