# 第4章 树

打开电脑里的"文档"文件夹。里面有工作、论文、照片、下载四个文件夹。"工作"里放着周报、合同，还有一个文件夹2025，里面是年终总结。"论文"里是初稿，"照片"里是两张照片，"下载"还是空的。

<TreeFigure folders tree="文档(工作(周报,合同,2025(年终总结)),论文(初稿),照片(1.jpg,2.jpg),下载/)" />

带折角的框是文件夹，没有框的是文件。

2.1节的练习里，文件夹目录被判为不能看成线性表。试着硬把它排成一列：

```
(文档, 工作, 周报, 合同, 2025, 年终总结, 论文, 初稿, 照片, 1.jpg, 2.jpg, 下载)
```

这一列只记得谁挨着谁。周报在哪个文件夹里？"工作"里直接有几项？"下载"是一个空文件夹，还是一个文件？从这一列里都看不出来。

一个文件夹里可以放好几项，它的后继不止一个。线性表记得住谁挨着谁，记不住谁装着谁。

公司的组织架构，一个经理管着几个人；一本书的目录，一章分成几节。它们也都是这样一层套一层。

在数据结构里，这样的数据叫**树**。

学完这一章，你会判断什么样的数据是树，用一套名词说清它的样子，把它放进内存，并把它的每个结点都走一遍。

要让程序管好这些文件夹，得先回答三个问题：

> **问题**：
> 1. 程序要记住文件夹之间的什么？
> 2. 怎样把每个文件都看一遍，一个不漏、一个不重？
> 3. 怎么把它放进内存？

先记住这三个问题。我们从第一个开始。要回答它，先得把"一层套一层"说精确。

## 4.1 树

**什么是树**

这个文件夹目录可以看成一棵**树**：最顶层只有一个"文档"，其余的东西一层套一层挂在它下面。

树的定义是这样的。树是n个**结点**的有限集合。n等于0时，叫**空树**。n大于0时：

1. 有且只有一个特定的结点，叫**根**；
2. 其余的结点分成m个互不相交的有限集合，每个集合本身又是一棵树，叫根的**子树**。

定义里用到了树自己：子树也是树。这就是3.8节的递归，一棵树用几棵小一点的树来说清楚。

放回文件夹里看。每个文件、每个文件夹都是一个结点，一共12个。根是"文档"。其余11个结点分成4组：

- 工作、周报、合同、2025、年终总结，5个；
- 论文、初稿，2个；
- 照片、1.jpg、2.jpg，3个；
- 下载，1个。

<TreeFigure folders tree="文档(工作(周报,合同,2025(年终总结)),论文(初稿),照片(1.jpg,2.jpg),下载/)" circle="工作 论文 照片 下载" />

每一组正好是"文档"里的一个文件夹，连同它里面的全部内容。每一组自己又是一棵树：工作这棵子树的根是"工作"；下载这棵子树只有一个结点。把"工作"整个拷到U盘上，拷走的就是一棵子树。

这个定义有三个要点，逐条看。

**有且只有一个根**。根只有一个，程序只要记住它，就能从它出发找到所有东西。电脑里的C盘和D盘各有自己的最顶层，放在一起就有两个根，不是一棵树：

<TreeFigure folders tree="C盘(系统,程序),D盘(资料,备份)" />

**互不相交**。除了根，每个结点只属于一组。假设周报同时放在"工作"和"论文"里：

<TreeFigure folders tree="文档(工作(周报,合同,2025(年终总结)),论文(初稿),照片(1.jpg,2.jpg),下载/)" extra="论文-周报" />

"工作"那组和"论文"那组都有周报，两组相交了，这就不是树。互不相交，"周报在哪个文件夹里"就只有一个答案，从根走到它只有一条路。

**每组又是一棵树**。只看最上面一层还不够。假设年终总结放在2025里，又直接放在"工作"里：

<TreeFigure folders tree="文档(工作(周报,合同,2025(年终总结)),论文(初稿),照片(1.jpg,2.jpg),下载/)" extra="工作-年终总结" />

看最上面一层，4组照样互不相交，年终总结只在"工作"这一组里。可是把"工作"这一组当成一棵树，再拆一层，"2025"那组和"年终总结"那组就相交了。所以判断是不是树，要一层一层拆到底，每一层都满足才行。

三个要点合起来，可以得到一个好用的结论：**除了根，每个结点恰好有一个上级**，而且从根出发往下走，能走到每一个结点。判断一样东西是不是树，看这一条最快。

**森林**

把根"文档"去掉，剩下的4棵子树就各自独立了：

<TreeFigure folders tree="工作(周报,合同,2025(年终总结)),论文(初稿),照片(1.jpg,2.jpg),下载/" />

m棵互不相交的树放在一起，叫**森林**。m可以是0。

树的定义里说，其余的结点分成m个互不相交的集合，每个又是一棵树。这说的就是：去掉根，剩下的是一片森林。反过来，给这4棵树加一个共同的上级"文档"，又成了一棵树。

树和森林只差一个根。上一页的C盘和D盘，合起来不是一棵树，而是一片有两棵树的森林。

程序也常常和森林打交道。后面把一棵树走一遍时，看完根以后，要接着走的正是它的子树组成的森林。

**例题：组织架构和先修课能看成树吗**

> **题目**：把每个人、每门课当作结点，下面两样东西能不能看成一棵树？
> 一家小公司：张总管着李经理和陈经理，李经理管着小王和小赵，陈经理管着小刘。
> 几门课的先修关系：学C语言和离散数学之前，要先学高中数学；学数据结构之前，要先学C语言和离散数学。

<TreeFigure tree="张总(李经理(小王,小赵),陈经理(小刘))" />

**分析**。先看公司，上级就是管着他的人。

1. 看根：只有张总没有上级。是。
2. 看互不相交：李经理、陈经理各管一组人。小王、小赵只在李经理那组，小刘只在陈经理那组，没有人同时在两组。是。
3. 看每组是不是树：李经理那组，根是李经理，小王、小赵各成一组，互不相交；陈经理那组也一样。是。

再看课程，上级就是要先学的课。

1. 看根：只有高中数学不需要先学别的课。是。
2. 看互不相交：高中数学下面分成C语言、离散数学两组。数据结构既要先学C语言，又要先学离散数学，两组都有它。否。到这里就能下结论。

<TreeFigure tree="高中数学(C语言(数据结构),离散数学)" extra="离散数学-数据结构" />

> **答案**：公司可以看成一棵树，根是张总。先修课不能，因为数据结构有两个上级，两组相交了。

两样东西都只有一个根，差别在互不相交这一条：一门课可以有好几门先修课，一个人却只有一个直接上级。

**双亲、孩子、兄弟、祖先、子孙**

这几个名词说的是结点和结点之间的关系，名字借自家谱。

一个结点的上级，叫它的**双亲**。它直接的下级，叫它的**孩子**。工作是周报的双亲；周报、合同、2025是工作的孩子。树里每个结点只有一个双亲，"双亲"这个词说的是一个结点，不是两个。

同一个双亲的孩子，互为**兄弟**。周报、合同、2025是兄弟。它们放在同一个文件夹里，所以不能重名。

从根走到一个结点，路上经过的结点都是它的**祖先**。年终总结的祖先是文档、工作、2025，一共3个。地址栏里的路径，写的正是它的全部祖先：

```
文档\工作\2025\年终总结
```

<TreeFigure folders tree="文档(工作(周报,合同,2025(年终总结)),论文(初稿),照片(1.jpg,2.jpg),下载/)" path="年终总结" />

反过来，一个结点下面的所有结点，都是它的**子孙**。工作的子孙是周报、合同、2025、年终总结，一共4个。删除"工作"文件夹时，一起被删掉的就是它的全部子孙：

<TreeFigure folders tree="文档(工作(周报,合同,2025(年终总结)),论文(初稿),照片(1.jpg,2.jpg),下载/)" hi="周报 合同 2025 年终总结" />

和2.1节的线性表对照一下：

```
线性表：除了第一个，每个元素恰好一个前驱；除了最后一个，每个元素恰好一个后继
树：    除了根，每个结点恰好一个双亲；孩子可以有任意多个
```

双亲像前驱，只有一个。孩子不像后继，可以有好几个。树就是把"后继只有一个"放开了。反过来，每个结点最多一个孩子的树，就是一个线性表。

<!-- 分页 -->

**度、叶子、分支结点**

一个结点有几个孩子，叫这个结点的**度**。打开一个文件夹，直接看到几项，它的度就是几：

<TreeFigure folders tree="文档(工作(周报,合同,2025(年终总结)),论文(初稿),照片(1.jpg,2.jpg),下载/)" label="文档:4 工作:3 2025:1 论文:1 照片:2 下载:0" />

度只数孩子，不数孩子的孩子。工作下面一共有4样东西，可它的度是3：年终总结在2025里，不是工作直接的孩子。文件里不能再放东西，度都是0。

各结点的度里最大的那个，叫**树的度**。这棵树的度是4，就是"文档"的度。

度为0的结点叫**叶子**，度不为0的结点叫**分支结点**。这棵树有7个叶子：6个文件，加上空文件夹"下载"。分支结点有5个：文档、工作、2025、论文、照片。

<TreeFigure folders tree="文档(工作(周报,合同,2025(年终总结)),论文(初稿),照片(1.jpg,2.jpg),下载/)" hi="周报 合同 年终总结 初稿 1.jpg 2.jpg 下载" />

"下载"是文件夹，可它里面什么都没有，度是0，所以也是叶子。叶子看的是有没有孩子，不是是不是文件。从根往下找东西，走到叶子，这条路就走到头了。

验算一下：7个叶子加5个分支结点，正好12个结点。所有结点的度加起来是4 + 3 + 1 + 1 + 2，等于11，比结点数少1。因为除了根，每个结点都是某一个结点的孩子，在度里恰好被数了一次。

<!-- 分页 -->

**层次、深度、高度**

根在第1层，根的孩子在第2层，孩子的孩子在第3层，依此类推。这叫结点的**层次**。

<TreeFigure folders levels tree="文档(工作(周报,合同,2025(年终总结)),论文(初稿),照片(1.jpg,2.jpg),下载/)" />

由层次，本书这样约定深度和高度：

- 结点的**深度**：从根往下数，就是它的层次。根的深度是1，年终总结的深度是4。
- 结点的**高度**：从它下面最深的叶子往上数，叶子的高度是1。2025的高度是2，工作的高度是3，文档的高度是4。
- 树的**高度**，也叫树的**深度**：最大的层次。这棵树的高度是4。空树的高度是0。

放回文件夹里：一个结点的深度，就是地址栏里有几段，`文档\工作\2025\年终总结`有4段。树的高度，就是最深的东西藏了几层：从"文档"开始，最多再点开3次文件夹，就能看到任何一个文件。

::: tip 另一种约定
很多英文教材和LeetCode按边数算：根的深度是0，叶子的高度是0，算出来都比本书少1。做题时先看清用的是哪一种。本书和国内教材、考研统考一样，按层数算。
:::

**有序树和无序树**。资源管理器里，文件可以按名称排，也可以按修改时间排。不管怎么排，周报还在工作里，目录还是同一个。孩子之间的先后不算数，这样的树叫**无序树**。

书的目录不一样。第一章、第二章、第三章的先后不能换，换了就是另一本书。孩子之间的先后算数，这样的树叫**有序树**。

回到本章开头的第一个问题：程序要记住文件夹之间的什么？这些文件夹可以看成一棵树，而树里除了根，每个结点恰好有一个双亲。所以程序要记住的，是每个结点的双亲是谁，或者反过来，每个结点的孩子是谁。有了这一条，层次、祖先、子孙、度、高度，都能算出来。

## 4.2 树的操作

**树的基本操作**

4.1节说的是树"是什么"。要用它，还得规定能对它做什么。1.3节说过，逻辑关系加上一组操作，就是抽象数据类型。这一节给树定下这组操作。

树常用的操作有很多，不同的程序用到的不一样。这里取最基本的八个，文件夹正好都要用。下面把树记作T，结点记作p，新结点的名字记作x。接着用4.1节那棵文件夹树：

<TreeFigure folders tree="文档(工作(周报,合同,2025(年终总结)),论文(初稿),照片(1.jpg,2.jpg),下载/)" />

**InitTree(T)：建立一棵空树**。一个文件夹都还没有的时候，先要有一棵空树。

**Root(T)：返回根**。一切从根开始找。在这棵树上，返回的是"文档"。空树没有根，返回NULL。

**Value(T, p)：返回结点p的名字**。拿到一个结点，要知道它叫什么，才能显示出来。

**Parent(T, p)：返回p的双亲**，也就是点一下"上一级"。根没有双亲，返回NULL。Parent(T, 周报)返回工作：

<TreeFigure folders tree="文档(工作(周报,合同,2025(年终总结)),论文(初稿),照片(1.jpg,2.jpg),下载/)" hi="周报 工作" label="周报:p 工作:返回" />

**FirstChild(T, p)：返回p的第一个孩子**，也就是打开文件夹，看第一项。p没有孩子时返回NULL。FirstChild(T, 工作)返回周报；FirstChild(T, 下载)返回NULL，因为"下载"是空的。

**NextSibling(T, p)：返回p的下一个兄弟**，也就是往下看一项。p后面没有兄弟时返回NULL。NextSibling(T, 周报)返回合同：

<TreeFigure folders tree="文档(工作(周报,合同,2025(年终总结)),论文(初稿),照片(1.jpg,2.jpg),下载/)" hi="周报 合同" label="周报:p 合同:返回" />

**InsertChild(T, p, x)：给p加一个孩子，名字是x，返回新结点**，也就是在文件夹里新建一项。新结点放在p的孩子最前面。4.1节说过，文件夹是无序树，孩子的先后不算数，放在哪里都还是这棵树。p写NULL时，表示往空树里放，x成为根。

**DeleteSubtree(T, p)：删除p和它的全部子孙**，也就是删除文件夹。DeleteSubtree(T, 工作)删掉的是工作、周报、合同、2025、年终总结，一共5个结点：

<TreeFigure folders tree="文档(工作(周报,合同,2025(年终总结)),论文(初稿),照片(1.jpg,2.jpg),下载/)" circle="工作" />

八个操作汇总如下：

| 操作 | 含义 | 文件夹里的动作 |
|---|---|---|
| InitTree(T) | 建立一棵空树 | 还没有任何文件夹 |
| Root(T) | 返回根 | 打开最顶层 |
| Value(T, p) | 返回p的名字 | 看这一项叫什么 |
| Parent(T, p) | 返回p的双亲 | 点"上一级" |
| FirstChild(T, p) | 返回p的第一个孩子 | 打开文件夹，看第一项 |
| NextSibling(T, p) | 返回p的下一个兄弟 | 往下看一项 |
| InsertChild(T, p, x) | 给p加一个孩子x | 新建一项 |
| DeleteSubtree(T, p) | 删除p和它的全部子孙 | 删除文件夹 |

和2.2节线性表的操作比，有三处不同。

**位置是结点，不是序号**。线性表说"第i个"。树没有第i个，一层有好几个结点，从左到右数也说不清它是谁的孩子。所以操作直接拿结点说话，就是2.16节的按结点操作。

**孩子一个一个地看**。一个文件夹里有几项，事先不知道。所以先用FirstChild拿到第一个，再用NextSibling一个一个往下看，看到NULL就完了。也可以定成"取第i个孩子"，这是一种取舍，这里选了更贴近打开文件夹的那种。

**删除连子孙一起删**。删掉一个结点，它的孩子不能悬空，总得有个去处。删除文件夹时，里面的东西一起没了，所以这里定成连子孙一起删。

常见的还有求高度、把每个结点都走一遍等操作，用到时再加。

## 4.3 树的存储结构

**记双亲**

回到本章开头的第三个问题：怎么把树放进内存？

线性表好办，一个接一个，放在相邻的格子里，关系就有了。树不行：一个结点后面跟着好几个结点，相邻表示不出来。关系只能明着记下来。

从这一节起，我们只关心树的结构，结点不再起名字，用字母代替。下面这棵树有10个结点：

<TreeFigure tree="A(B(E,F),C,D(G,H(J),I))" />

4.1节的结尾说过，程序要记住每个结点的双亲是谁，或者每个结点的孩子是谁。两条路都试一试。每试一种，都在这棵树上数一数，4.2节的操作要走几步。这一节只讲思路，代码放到下一节。

> **本节问题**：树的关系，记成什么样，操作才走得少，结点又好设计？

先试记双亲。每个结点只有一个双亲，一个数就记下了。把10个结点放进一张表，parent记着双亲在第几行。根没有双亲，记成−1：

| 下标 | data | parent |
|---|---|---|
| 0 | A | −1 |
| 1 | B | 0 |
| 2 | C | 0 |
| 3 | D | 0 |
| 4 | E | 1 |
| 5 | F | 1 |
| 6 | G | 3 |
| 7 | H | 3 |
| 8 | I | 3 |
| 9 | J | 7 |

这种存法叫**双亲表示法**。

表里每一行放一个结点。程序里，一个结点就用它所在的行号来代表；字母只是我们给它起的名字，记在这一行的data里。树图上每个结点旁边的小字，就是它的行号：

<TreeFigure tree="A(B(E,F),C,D(G,H(J),I))" label="A:0 B:1 C:2 D:3 E:4 F:5 G:6 H:7 I:8 J:9" />

拿"找B的孩子"完整走一次：

1. **B是第1行**。看图上B旁边的小字。
2. **找parent等于1的行**。从第0行往下看，第4行、第5行是。
3. **读这两行的data**，是E、F。B的孩子就是E、F。

<TreeFigure tree="A(B(E,F),C,D(G,H(J),I))" label="A:0 B:1 C:2 D:3 E:4 F:5 G:6 H:7 I:8 J:9" hi="B E F" />

第1步和第3步，只是因为我们用字母出题：先把字母换成行号，最后再把行号换回字母。程序手里拿的本来就是行号，4.2节的FirstChild、NextSibling返回的都是一个结点，在这里就是一个行号；程序从来不按字母去找结点。要显示名字时，读这一行的data就行。真正花工夫的，只有第2步：扫表。

下面就不再换来换去，结点直接写成"字母（第几行）"。

找双亲一步到位。J（第9行）的双亲是谁？读第9行的parent，是7，就是H（第7行）。不管树有多大，都只读一个数，是O(1)。

找孩子就慢了。D（第3行）的第一个孩子是谁？要找parent等于3的行，没有别的办法，只能从第0行往下看：第0行到第5行都不是，看到第6行才找到，是G。一共看了7行。

C（第2行）有没有孩子？要找parent等于2的行。10行全看完，一行都没有，才敢说C没有孩子。

n个结点，找孩子最多要看n行，是O(n)。

双亲这个关系，每个结点正好一个，好记；可它的方向朝上，往下找就得扫整张表。

<!-- 分页 -->

**记孩子**

再试记孩子。方向朝下了，可是每个结点有几个孩子？个数不定。

先用最直接的办法：每个结点都留够格子。这棵树的度是3，那就每个结点留3格，放孩子的位置：

```
A：B  C  D
B：E  F  空
C：空 空 空
D：G  H  I
H：J  空 空
E、F、G、I、J：空 空 空
```

算一算：10个结点，每个3格，一共30格。树有10个结点，就有9条边，也就是只用了9格，空着21格。

一般地，n个结点、度为d的树，要n × d格，只用n − 1格。孩子最多的那个结点，决定了所有结点的大小。

个数不定的东西，第2章有现成的办法：用链表串起来，有几个就申请几个。表里每个结点带一条孩子链，链上的每一格记一个孩子在第几行：

```
A ──► [B] ──► [C] ──► [D]
B ──► [E] ──► [F]
D ──► [G] ──► [H] ──► [I]
H ──► [J]
C、E、F、G、I、J：链是空的
```

这种存法叫**孩子表示法**。链上一共9格，一格不多。

结点还是放在表里，用行号代表。程序里，链上的格子记的是孩子的行号，比如[E]那一格记的是4；这里写成字母，是为了好读。

找孩子一步到位。D（第3行）的第一个孩子是谁？看第3行那条链的第一格，是G，是O(1)。

这回轮到找双亲慢了。J（第9行）的双亲是谁？谁的链上有J，谁就是它的双亲。只能从第0行的A开始，一行一行查它们的链：A的链上是B、C、D，不是；B的链上是E、F，不是；一直查到第7行H的链，才看到J。

最坏要把n行、n − 1格都看一遍，是O(n)。

还有一处别扭：这里要两种东西，一种是表里的结点，一种是链上的格子。

<!-- 分页 -->

**下一个兄弟记在哪里**

孩子表示法还有一个操作没看：NextSibling。拿E来问：E的下一个兄弟是谁？

答案是F。可是F这条信息，记在哪里？看B的那条孩子链：

<CsTreeFigure compact nodes="B@0,0 #E@1,0 #F@1,1 E@2,0 F@2,1" first="B>#E" next="#E>#F" refs="#E>E #F>F" hi="E" now="#E>#F" />

上面一行是B，中间是它链上的两格，下面是E、F两个结点，虚线箭头表示这一格记的是哪个孩子。"E的下一个是F"，记在E那一格到F那一格的箭头上。E结点自己身上，什么都没有。

所以，要找E的下一个兄弟，得这样找：

1. **先找E的双亲**。E身上没记，只能把每一行的链都查一遍，查到B的链上才看到E。这一步，就是上一页找双亲的那一大圈，O(n)。
2. **在B的链上，找到记着E的那一格**。从第一格往后走，走过的格子不会超过B的孩子数。
3. **看它的下一格**。下一格记的是F，答案就是F。

第一步就要O(n)。问的是E自己的事，答案却记在别人的链上，得先绕一大圈。

那就把它搬过来：E的下一个兄弟是F，就记在E自己身上。

<div class="figure-pair">
<CsTreeFigure compact nodes="B@0,0 #E@1,0 #F@1,1 E@2,0 F@2,1" first="B>#E" next="#E>#F" refs="#E>E #F>F" now="#E>#F" caption="记在链上的格子里" />
<CsTreeFigure compact nodes="B@0,0 E@1,0 F@1,1" first="B>E" next="E>F" now="E>F" caption="搬到E自己身上" />
</div>

搬得过来吗？4.1节说过，除了根，每个结点恰好有一个双亲，所以每个结点只出现在一条孩子链上，它在链上的"下一格"也只有一个。一个结点，一个"下一个兄弟"，一个指针就记得下。

**一步一步变过去**

把这个办法用到整棵树上，在树的样子上看。下面每一步，左边是原来的树，右边是变到这一步的样子。图里三种颜色的边：

**第0步：原来的树**。每个结点连着自己全部的孩子。A和D各连着3个孩子，B连着2个，H连着1个，每个结点连出去的线不一样多。

</div>

**第1步：只留长子边**。每个结点只留下通往第一个孩子的那条边，画成绿色。第一个孩子也叫长子。A留下A到B，B留下B到E，D留下D到G，H留下H到J。其余的孩子边画成橙色虚线，准备删掉。

**第2步：连上兄弟边**。同一个双亲的孩子，从左到右连起来，画成紫色：B到C到D，E到F，G到H到I。

**第3步：删掉橙色的边**。删了5条，加了5条，边的总数还是9。现在每个结点最多连出两条：一条往下，连着它的第一个孩子；一条往右，连着它的下一个兄弟。

</div>

规则只有一句：**双亲只连第一个孩子，其余孩子由兄弟一个接一个连起来**。

往下的那条线叫**first**，往右的那条线叫**next**。每个结点就记这两个地址，这种存法叫**孩子兄弟表示法**。画成结点图，向下的箭头是first，向右的箭头是next，没有箭头就是NULL：

<CsTreeFigure compact nodes="A@0,0 B@1,0 C@1,2 D@1,3 E@2,0 F@2,1 G@2,3 H@2,4 I@2,5 J@3,4" first="A>B B>E D>G H>J" next="B>C C>D E>F G>H H>I" />

记住一句话：first往下走一代，next往右找兄弟。

**两个指针就够了**

数一数。原来的树有9条边。留下的4条绿色边，就是4个first；新连上的5条紫色边，就是5个next。边的总数没变，只是换了连法。

再数指针。10个结点，每个2个指针，一共20个，用了9个，空着11个。比每个结点留3格时空着21格少，可这不是最要紧的。

最要紧的是：每个结点都只有两个指针，大小统一，再也不用为"有几个孩子"发愁。"一个结点有不定个孩子"，换成了"第一个孩子"和"下一个兄弟"，每个结点各只有一个，方向又都朝下。

再看操作要走几步。D的第一个孩子？读D的first，是G。E的下一个兄弟？读E的next，是F。都只读一个指针，是O(1)。上上页那一大圈不见了。

只差一个操作：Parent。沿着first和next只能往下、往右，回不到上一级。所以再加一个指针**parent**，记着双亲，Parent也就是读一个指针，O(1)。图里为了清楚，没有画它。

::: tip 教材里的孩子兄弟表示法
教材和考研说的孩子兄弟表示法，每个结点只有两个指针：第一个孩子和下一个兄弟。这里多加的parent，是因为4.2节的操作集里有Parent。不需要找双亲的程序，可以不加。
:::

**三种存法比一比**

三种存法，问的是同一个问题：树的关系，拆成什么来记。

| 存法 | 记什么 | 好在哪 | 难在哪 |
|---|---|---|---|
| 双亲表示法 | 双亲：每个结点一个，方向朝上 | 找双亲O(1)，每个结点只多一个数 | 找孩子要扫整张表 |
| 孩子表示法 | 孩子：个数不定，方向朝下 | 找孩子O(1) | 每个结点留够格子就浪费；改用链表，又要两种东西，找双亲、找兄弟都要查所有的链 |
| 孩子兄弟表示法 | 第一个孩子、下一个兄弟：每个结点各一个，方向朝下 | 结点统一成两个指针；找孩子、找兄弟都是O(1) | 找双亲要绕远，可以再加一个parent补上 |

前面几页在例子上数出来的步数，汇总在一起。n个结点，每个操作最多要走几步：

| 操作 | 双亲表示法 | 孩子表示法 | 孩子兄弟表示法（加parent） |
|---|---|---|---|
| Parent | O(1) | O(n) | O(1) |
| FirstChild | O(n) | O(1) | O(1) |
| NextSibling | O(n) | O(n) | O(1) |

双亲表示法的NextSibling，要接着往下扫，找下一个parent相同的行。孩子表示法的NextSibling，就是"下一个兄弟记在哪里"那一页绕的一大圈。

回到本节问题，也回到本章开头的第三个问题：怎么把树放进内存？要看常做的是什么。只需要往上找、很少找孩子的程序，双亲表示法最省。要上下都走，就用孩子兄弟表示法，再加一个parent。

> **到这里你有了**：树的三种存法。双亲表示法记双亲，找双亲O(1)，找孩子要扫整张表；孩子表示法记孩子，个数不定，要用链表，找双亲、找兄弟都要绕；孩子兄弟表示法把"不定个孩子"换成"第一个孩子"和"下一个兄弟"，每个结点统一成两个指针：first往下走一代，next往右找兄弟。从树的样子看，就是双亲只连第一个孩子，兄弟一个接一个连起来。
> **下一步**：把三种存法写成C语言。

## 4.4 树的存储结构的实现

**双亲表示法**

上一节把三种存法的思路、要走几步都讲完了。这一节把它们写成C语言，代码就是把那些步骤一句一句翻译过来。双亲表示法和孩子表示法，只写最能看出好坏的那几个操作；孩子兄弟表示法，把4.2节的八个操作全部写出来。

双亲表示法是一张表。结点在表里第几行，就用这个行号代表它：

```c
#define MAXSIZE 100

typedef struct {
    char data;       /* 结点的值 */
    int parent;      /* 双亲在第几行，根是-1 */
} PNode;

typedef struct {
    PNode nodes[MAXSIZE];
    int n;           /* 一共几个结点 */
} PTree;
```

找双亲，就是读这一行的parent：

```c
int Parent(PTree *T, int p) {
    return T->nodes[p].parent;
}
```

找第一个孩子，就是上一节那样从第0行往下扫，找parent等于p的行：

```c
int FirstChild(PTree *T, int p) {
    int i;
    for (i = 0; i < T->n; i++)          /* 把整张表扫一遍 */
        if (T->nodes[i].parent == p) return i;
    return -1;                          /* 没有孩子 */
}
```

上一节数出来的O(n)，在代码里就是这个for循环。Parent没有循环，是O(1)。

两个函数收的、返回的都是行号。上一节说的"换回字母"，在代码里就是读data：行号是i的结点，名字是`T->nodes[i].data`。

**孩子表示法**

孩子表示法要两种东西：表里的结点，和链上的格子：

```c
typedef struct CNode {      /* 孩子链上的格子 */
    int child;              /* 这个孩子在第几行 */
    struct CNode *next;     /* 链上的下一格 */
} CNode;

typedef struct {
    char data;              /* 结点的值 */
    CNode *first;           /* 孩子链的第一格 */
} CTBox;

typedef struct {
    CTBox nodes[MAXSIZE];
    int n;                  /* 一共几个结点 */
} CTree;
```

找第一个孩子，看链的第一格：

```c
int FirstChild(CTree *T, int p) {
    return T->nodes[p].first == NULL ? -1 : T->nodes[p].first->child;
}
```

找双亲，一行一行查它们的链，谁的链上有p，谁就是双亲：

```c
int Parent(CTree *T, int p) {
    int i;
    CNode *c;
    for (i = 0; i < T->n; i++)                                   /* 每一行 */
        for (c = T->nodes[i].first; c != NULL; c = c->next)      /* 查它的孩子链 */
            if (c->child == p) return i;
    return -1;                                                   /* 根没有双亲 */
}
```

找下一个兄弟，就是上一节"下一个兄弟记在哪里"的三步，一步一段：

```c
int NextSibling(CTree *T, int p) {
    int f = Parent(T, p);               /* 第一步：先找双亲，要查所有的链 */
    CNode *c;
    if (f == -1) return -1;             /* 根没有兄弟 */
    c = T->nodes[f].first;
    while (c->child != p) c = c->next;  /* 第二步：在双亲的链上找到p那一格 */
    return c->next == NULL ? -1 : c->next->child;   /* 第三步：下一格才是答案 */
}
```

Parent里套着两层循环，NextSibling一开头就调用Parent，所以都是O(n)。

**孩子兄弟表示法**

孩子兄弟表示法再加一个parent。每个结点放一个值和三个指针：

```c
typedef struct TNode {
    char data;              /* 结点的值 */
    struct TNode *parent;   /* 双亲 */
    struct TNode *first;    /* 第一个孩子 */
    struct TNode *next;     /* 下一个兄弟 */
} TNode, *Tree;
```

和2.10节的Node、LinkList一样，TNode是结点类型，Tree是指向结点的指针类型。一棵树，只要记住根的地址。

下面六个操作，每个只有一行。InitTree要改根，所以和3.4节一样，参数是`Tree *T`；其余五个照着写，只读一个指针或一个值。上一节说孩子兄弟表示法的这些操作都是O(1)，代码里也看得到，一个循环都没有：

```c
void InitTree(Tree *T)                  { *T = NULL; }
TNode *Root(Tree *T)                    { return *T; }
char Value(Tree *T, TNode *p)           { return p->data; }
TNode *Parent(Tree *T, TNode *p)        { return p->parent; }
TNode *FirstChild(Tree *T, TNode *p)    { return p->first; }
TNode *NextSibling(Tree *T, TNode *p)   { return p->next; }
```

Value、Parent这几个函数其实用不上T。留着它，是因为换成双亲表示法时就要用T去扫表。调用的写法不变，换存法时调用者不用改。

**第二步：q指向原来的第一个孩子**：

往空树里放根时，p是NULL，没有孩子链可接，让T指向q就行。写成函数，返回新结点，申请不到时返回NULL：

```c
TNode *InsertChild(Tree *T, TNode *p, char x) {
    TNode *q = (TNode *)malloc(sizeof(TNode));  /* 第一步：申请结点，放x */
    if (q == NULL) return NULL;
    q->data = x;
    q->first = NULL;
    q->parent = p;
    if (p == NULL) {         /* 空树：q就是根 */
        q->next = NULL;
        *T = q;
    } else {
        q->next = p->first;  /* 第二步：q指向原来的第一个孩子 */
        p->first = q;        /* 第三步：p的第一个孩子改成q */
    }
    return q;
}
```

不用走，是O(1)。

**DeleteSubtree：删除子树**

删除分两件事：先把p从兄弟链上摘下来，再释放p和它的全部子孙。

**第一件事：摘下来**。先看删H。H不是D的第一个孩子，要让前一个兄弟G的next跳过它。前一个兄弟没有直接记着，只好从第一个孩子开始，沿着next找：

```c
TNode *q = p->parent->first;
while (q->next != p) q = q->next;   /* 找到前一个兄弟 */
q->next = p->next;
```

<CsTreeFigure compact nodes="D@0,0 G@1,0 H@2,1 I@1,2 J@3,1" first="D>G H>J" next="G>I H>I" now="G>I" hi="H" ptr="q>G p>H" />

H连同它的孩子J，一起从D的孩子里摘了下来。

如果p是第一个孩子，前面没有兄弟，要改的是双亲的first。删B就是这样，把A的first改成C：

```c
p->parent->first = p->next;
```

如果p是根，整棵树都没了，让T变成NULL。一共三种情形。

**第二件事：释放**。p的孩子可能还有孩子，一层一层有多深，事先不知道。可是每个孩子下面都是一棵子树，释放子树和释放整棵是同一件事。这就是3.8节的递归：

```c
void FreeSubtree(TNode *p) {
    TNode *c = p->first;
    while (c != NULL) {
        TNode *after = c->next;   /* 先记下下一个兄弟 */
        FreeSubtree(c);           /* 释放这个孩子的子树 */
        c = after;
    }
    free(p);                      /* 孩子都释放了，再释放自己 */
}
```

规模变小：每次处理的都是一棵更小的子树。出口：没有孩子时，循环一次都不走，直接释放自己。

**先记下next，再释放，顺序不能反**。c释放之后，c->next读的是已经不归你的内存。**先释放孩子，再释放自己**，也不能反：自己先释放了，就读不到first，孩子全找不回来。

删除D时，5个结点释放的先后是这样的：

<TreeFigure tree="D(G,H(J),I)" label="G:① J:② H:③ I:④ D:⑤" />

摘下来时要找前一个兄弟，最多走过双亲的所有孩子；释放要把整棵子树走一遍。合起来：

```c
void DeleteSubtree(Tree *T, TNode *p) {
    TNode *f = p->parent;
    if (f == NULL) {                  /* p是根 */
        *T = NULL;
    } else if (f->first == p) {       /* p是第一个孩子 */
        f->first = p->next;
    } else {                          /* 找到前一个兄弟 */
        TNode *q = f->first;
        while (q->next != p) q = q->next;
        q->next = p->next;
    }
    FreeSubtree(p);
}
```

## 4.5 二叉树

**什么是二叉树**

4.1节的树，一个结点可以有任意多个孩子。这一节看一种更规整的树：每个结点最多两个孩子，而且两个孩子分左右。这样的树叫**二叉树**。

它的定义也是递归的。二叉树是n个结点的有限集合。n等于0时，叫**空二叉树**。n大于0时，它由一个根和两棵互不相交的二叉树组成，这两棵分别叫根的**左子树**和**右子树**。

::: side

<div class="figure-pair">

## 4.6 二叉树的性质

**第i层最多几个结点**

4.5节那棵二叉树，高度是3，有5个结点。图里还有两个虚线框空着。

<TreeFigure compact binary slots levels tree="A(B(D,),C(,G))" />

> **本节问题**：高度不变，这棵树里最多还能放几个结点？

要回答它，先一层一层看，每层最多能放几个。二叉树的每个结点最多两个孩子，所以下一层最多是这一层的两倍：

::: side
**第1层：1个**。第1层只有根。

<TreeFigure compact binary levels tree="A" />

**第2层：2个**。根最多两个孩子。

<TreeFigure compact binary levels tree="A(B,C)" />

**第3层：4个**。第2层的B、C，各自最多两个孩子，2 × 2 = 4。

<TreeFigure compact binary levels tree="A(B(D,E),C(F,G))" />
:::

每往下一层，最多的个数翻一倍：1、2、4、8……第i层是i − 1个2相乘，写作2ⁱ⁻¹。

这是二叉树的第一个性质：**第i层最多有2ⁱ⁻¹个结点**。第3层最多2²，也就是4个。

<!-- 分页 -->

**总共最多几个结点**

一层一层加起来，就是整棵树最多的个数：

::: side
**高度1：最多1个**。只有第1层。

<TreeFigure compact binary levels tree="A" />

**高度2：最多3个**。1 + 2 = 3。

<TreeFigure compact binary levels tree="A(B,C)" />

**高度3：最多7个**。1 + 2 + 4 = 7。

<TreeFigure compact binary levels tree="A(B(D,E),C(F,G))" />
:::

总数1、3、7，每个都加1看看：2、4、8，正好每次翻一倍。因为每加一层，新一层的个数正好等于原来的总数加1：第2层2个，是1加1；第3层4个，是3加1。

所以高度为h时，总数加1是2ʰ，总数是2ʰ − 1。

这是二叉树的第二个性质：**高度为h的二叉树，最多有2ʰ − 1个结点**。

回到本节问题。高度为3，最多2³ − 1 = 7个结点。现在有5个，还能放2个，正好是那两个虚线框。

把两个虚线框都放上结点：B的右孩子E，C的左孩子F。这棵树有7个结点，达到了高度3能放的最多个数。

高度为h、有2ʰ − 1个结点的二叉树，叫**满二叉树**。

::: side
**每一层都排满**。第1层1个，第2层2个，第3层4个，每一层都达到了最多。

<TreeFigure compact binary levels tree="A(B(D,E),C(F,G))" />

**叶子都在最下一层**。D、E、F、G都在第3层，上面两层没有叶子。

<TreeFigure compact binary tree="A(B(D,E),C(F,G))" hi="D E F G" />

**其余结点都有两个孩子**。A、B、C的度都是2，没有度为1的结点。

<TreeFigure compact binary tree="A(B(D,E),C(F,G))" hi="A B C" />

结点数不够排满时，就从最大的编号往前空。

<TreeFigure compact binary slots tree="A(B(D,E),C(F,))" label="A:1 B:2 C:3 D:4 E:5 F:6" />

<TreeFigure compact binary tree="A(B(D,E),C)" label="A:1 B:2 C:3 D:4 E:5" />

**4.5节那棵：不是**。它也有5个结点，可是G占着7号，5号、6号空着。编号对不上1到5。

<TreeFigure compact binary slots tree="A(B(D,),C(,G))" label="A:1 B:2 C:3 D:4 G:7" />

**满二叉树也是完全二叉树**。7个结点占着1号到7号，一个不空。

<TreeFigure compact binary tree="A(B(D,E),C(F,G))" label="A:1 B:2 C:3 D:4 E:5 F:6 G:7" />

编号连成一片、中间不空，还能看出两点：

::: side
**叶子只在最下面两层**。5个结点那棵，叶子是第2层的C，和第3层的D、E。

<TreeFigure compact binary tree="A(B(D,E),C)" hi="C D E" />

<TreeFigure compact binary slots tree="A(B(D,E),C(F,))" hi="C F" />
:::

程序为什么在乎：编号中间不空，按编号把结点放进数组，一格也不浪费。讲二叉树的存储时，会用到这些编号。

**叶子比度为2的结点多一个**

最后一个性质，讲的是度，和最多几个结点无关。

把二叉树的结点按度分成三类。叶子的度是0，有n₀个；度为1的有n₁个；度为2的有n₂个。

4.1节验算过：所有结点的度加起来，等于结点数减1。因为除了根，每个结点都是某个结点的孩子，在度里恰好被数了一次。

- 结点数是n₀ + n₁ + n₂；
- 度加起来是n₁ + 2n₂：度为1的每个算1，度为2的每个算2，叶子不算。

所以n₁ + 2n₂ = n₀ + n₁ + n₂ − 1。两边都减去n₁和n₂，得到：

```
n₀ = n₂ + 1
```

这是二叉树的第三个性质：**叶子比度为2的结点多一个**。用这一节的三棵树验算：

::: side
**4.5节那棵**。叶子是D、G，2个。度为2的只有A，1个。2 = 1 + 1。

<TreeFigure compact binary slots tree="A(B(D,),C(,G))" hi="D G" />

**满二叉树**。叶子是D、E、F、G，4个。度为2的是A、B、C，3个。4 = 3 + 1。

<TreeFigure compact binary tree="A(B(D,E),C(F,G))" hi="D E F G" />

**6个结点的完全二叉树**。叶子是D、E、F，3个。度为2的是A、B，2个。3 = 2 + 1。

<TreeFigure compact binary slots tree="A(B(D,E),C(F,))" hi="D E F" />
:::

度为1的结点，三棵树里分别有2个、0个、1个，都不影响结果。n₁在等式两边各出现一次，抵消了。

## 4.7 二叉树的存储结构

**按编号放进数组**

现在要把二叉树放进内存。要存的不只是每个结点的值，还有结点之间的关系：谁是谁的左孩子，谁是谁的右孩子。程序要靠这些关系，从一个结点走到另一个结点。

> **本节问题**：4.5节那棵二叉树有A、B、C、D、G五个结点。把它放进内存，要记下哪些东西？

先看最省事的办法。第2章的顺序表，把元素一个挨一个放进数组。二叉树的结点也可以这样放：按4.6节的编号，几号结点就放进几号格子。先拿6个结点的完全二叉树试：

::: side
**几号放进几号格**。A是1号，放进1号格；F是6号，放进6号格。数组的0号格空着不用，编号和下标就正好相同。

<div class="figure-pair">
<TreeFigure compact binary slots tree="A(B(D,E),C(F,))" label="A:1 B:2 C:3 D:4 E:5 F:6" />
<ArrayFigure zero cells="A B C D E F" />
</div>

**数组里只有值**。六个格子里，只有A到F六个字母。B的左孩子是谁？数组里没有写。

<ArrayFigure zero cells="A B C D E F" hi="2" />
:::

可是这棵树的形状并没有丢。只要知道一个结点的编号，就能算出它的孩子在几号格。

学完这一节，你能把二叉树按两种办法放进内存：按编号放进数组，或者用指针连起来；还能说出每种办法适合什么样的二叉树。

**从编号算出孩子和双亲**

编号是从上到下、每层从左到右排的。顺着这个排法，一步一步算：

::: side
**每层从几号开始**。第1层从1号开始，第2层从2号开始，第3层从4号开始。上面几层排满是2ᵏ⁻¹ − 1个，所以第k层从2ᵏ⁻¹号开始。

**反过来找双亲**。4号、5号的双亲是2号，6号的双亲是3号。孩子的编号除以2，去掉小数，就是双亲：5除以2是2.5，去掉小数是2。

<ArrayFigure zero cells="A B C D E F" hi="2 3" arcs="4-2 5-2 6-3" />
:::

一般地，编号为i的结点，前面有i − 1个位置，每个位置都排着两个孩子，占掉2号到2i − 1号。它自己的孩子接着往下编。所以：

- 左孩子是2i号，右孩子是2i + 1号。编号超过结点数n，就是没有这个孩子。
- 双亲是i除以2再去掉小数，记作⌊i/2⌋。1号是根，没有双亲。

层数也能算。第k层从2ᵏ⁻¹号开始，到2ᵏ − 1号结束。6号在4号和7号之间，在第3层。写成式子，编号i在第⌊log₂i⌋ + 1层，⌊log₂i⌋是2的几次方不超过i。n个结点的完全二叉树，最后一个是n号，所以高度是⌊log₂n⌋ + 1。6个结点，2²不超过6，高度是2 + 1 = 3。

数组里一个关系也没有存。关系藏在位置里，用下标算出来。把结点按编号放进一组连续的格子，叫二叉树的**顺序存储**。

::: tip 下标从0开始的写法
有的书让根放进0号格。那样编号为i的结点，左孩子是2i + 1，右孩子是2i + 2，双亲是⌊(i − 1)/2⌋。本书和考研统考一样，从1开始。
:::

**顺序存储：用C语言表示**

顺序存储就是一个数组，再记下用到的最大编号n。空着的格子放`'#'`。0号格不存结点，也放`'#'`，正好拿来表示"没有"。

三个函数，各算一个编号。没有这个结点时返回0，取出来就是`'#'`：

```c
#include <stdio.h>
#define MAXSIZE 16
#define NIL '#'                  /* 空着的格子 */

typedef struct {
    char data[MAXSIZE];          /* data[0]不用，i号结点放在data[i] */
    int n;                       /* 用到的最大编号 */
} SqBiTree;

/* 没有时返回0：0号格子不放结点，正好表示"没有" */
int LeftChild(SqBiTree *T, int i) {
    int c = 2 * i;
    return c <= T->n && T->data[c] != NIL ? c : 0;
}

int RightChild(SqBiTree *T, int i) {
    int c = 2 * i + 1;
    return c <= T->n && T->data[c] != NIL ? c : 0;
}

int Parent(int i) {
    return i > 1 ? i / 2 : 0;
}
```

找孩子要看两件事：编号有没有超过n，格子里是不是空的。找双亲不用看数组，只靠编号就算出来了。

把6个结点的完全二叉树和4.5节那棵都存进去，逐个打印每个结点的双亲和孩子：

```c
void Show(SqBiTree *T) {
    for (int i = 1; i <= T->n; i++) {
        if (T->data[i] == NIL) continue;
        printf("%c: 双亲%c 左孩子%c 右孩子%c\n", T->data[i], T->data[Parent(i)],
               T->data[LeftChild(T, i)], T->data[RightChild(T, i)]);
    }
}

int main(void) {
    SqBiTree T = { "#ABCDEF", 6 };     /* 6个结点的完全二叉树 */
    SqBiTree U = { "#ABCD##G", 7 };    /* 4.5节那棵：5号、6号空着 */
    Show(&T);
    printf("\n");
    Show(&U);
    return 0;
}
```

**把关系记在结点里**

顺序存储的浪费，根源是关系绑在位置上。那就不让位置说明关系，换一个办法：

::: side
**结点放在哪都行**。不再按编号排进一个数组。和第2章的链表一样，每个结点单独用malloc申请，系统给哪就放哪。

<TreeFigure compact tree="A,B,C,D,G" label="A:200 B:340 C:120 D:460 G:280" caption="五个结点，地址各不相同" />

**关系丢了**。位置不再说明任何事。340号的B是谁的孩子？它有没有孩子？只看地址，看不出来。

<TreeFigure compact tree="A,B,C,D,G" label="A:200 B:340 C:120 D:460 G:280" hi="B" />

**把孩子的地址记下来**。顺序存储靠下标算出孩子，现在算不出来，就明着记在结点里。4.5节说过，每个结点最多两个孩子，左右的位置是固定的。所以每个结点留两格：一格记左孩子的地址，一格记右孩子的地址。

<TreeFigure compact binary linked tree="A(B,C)" label="A:200 B:340 C:120" hi="A" />

**没有孩子就写NULL**。B只有左孩子D，右孩子那一格写NULL，图里画成∧。D没有孩子，两格都是NULL。

<TreeFigure compact binary linked tree="B(D,)" label="B:340 D:460" hi="B" />
:::

这样，每个结点有三格：中间放值，两边放左孩子、右孩子的地址。用这样的结点存二叉树，叫二叉树的**链式存储**，连起来的整体叫**二叉链表**。

<TreeFigure compact binary linked tree="A(B(D,),C(,G))" label="A:200 B:340 C:120 D:460 G:280" />

A左边那一格存着340，就是B的地址，图里画成从这一格指向B的箭头。两种说法是同一件事。

整棵树只要记住根A的地址200，就能顺着指针走到每一个结点。关系写在结点里，结点放在哪都不要紧，也不用给没有的结点留格子。

**链式存储：用C语言表示**

结点有三格，写成结构体。`BiTree`是指向结点的指针：拿着根的地址，就拿着整棵树。

```c
typedef struct BiTNode {
    char data;
    struct BiTNode *lchild, *rchild;   /* 左孩子、右孩子的地址 */
} BiTNode, *BiTree;
```

一个结点一个结点地搭出4.5节那棵树：

::: side
**第一步：申请A**。用malloc申请一个结点，放进A。它还没有孩子，两格都写NULL。T记着它的地址，T就是这棵树。

```c
BiTree T = (BiTNode *)malloc(sizeof(BiTNode));
T->data = 'A';
T->lchild = NULL;
T->rchild = NULL;
```

<TreeFigure compact binary linked tree="A" label="A:200" hi="A" />

**第二步：申请B，挂到A的左边**。前四行和A一样。最后一行把B的地址写进A的左孩子格。

```c
b->rchild = NULL;
```

**第三步：其余同理**。C挂到A的右边，D挂到B的左边，G挂到C的右边。每个都是申请、放值、两格写NULL，再把地址写进双亲的一格里。

完整程序搭好这棵树，再逐个打印每个结点的孩子：

```c
#include <stdio.h>
#include <stdlib.h>

typedef struct BiTNode {
    char data;
    struct BiTNode *lchild, *rchild;   /* 左孩子、右孩子的地址 */
} BiTNode, *BiTree;

void Show(BiTNode *p) {
    printf("%c: 左孩子%c 右孩子%c\n", p->data,
           p->lchild ? p->lchild->data : '#', p->rchild ? p->rchild->data : '#');
}

int main(void) {
    /* 第一步：A */
    BiTree T = (BiTNode *)malloc(sizeof(BiTNode));
    T->data = 'A';
    T->lchild = NULL;
    T->rchild = NULL;

    /* 第二步：B，挂到A的左边 */
    BiTNode *b = (BiTNode *)malloc(sizeof(BiTNode));
    b->data = 'B';
    b->lchild = NULL;
    b->rchild = NULL;
    T->lchild = b;

    /* 第三步：C挂到A的右边，D挂到B的左边，G挂到C的右边 */
    BiTNode *c = (BiTNode *)malloc(sizeof(BiTNode));
    c->data = 'C';
    c->lchild = NULL;
    c->rchild = NULL;
    T->rchild = c;

    BiTNode *d = (BiTNode *)malloc(sizeof(BiTNode));
    d->data = 'D';
    d->lchild = NULL;
    d->rchild = NULL;
    b->lchild = d;

    BiTNode *g = (BiTNode *)malloc(sizeof(BiTNode));
    g->data = 'G';
    g->lchild = NULL;
    g->rchild = NULL;
    c->rchild = g;

    Show(T);
    Show(b);
    Show(c);
    Show(d);
    Show(g);

    free(d);
    free(g);
    free(b);
    free(c);
    free(T);
    return 0;
}
```

**一共10个指针格**。5个结点，每个两格。

<TreeFigure compact binary linked nulls tree="A(B(D,),C(,G))" />

二叉链表还有一件事做不到：找双亲。顺序存储里，双亲是⌊i/2⌋，一步算出。二叉链表的结点只记着孩子，不记双亲。要找G的双亲，只能从根往下一个一个找。

**三叉链表**。经常要找双亲时，每个结点再加一格，记双亲的地址。根没有双亲，那一格是NULL。这样的结点有四格，连起来叫**三叉链表**。

**两种存法比一比**

两种存法记下的关系一样多，差在关系放在哪里。顺序存储放在位置里，链式存储写在结点里。

**空间**。完全二叉树用顺序存储，n个结点正好n格，一个指针也不用存。不是完全二叉树时，空着的位置也要留格子，最坏要2ʰ − 1格。二叉链表每个结点多两个指针，可是结点有几个就申请几个，形状再歪也不浪费格子。

**找孩子**。两种都是一步。顺序存储算2i、2i + 1；二叉链表读lchild、rchild。

**找双亲**。顺序存储算⌊i/2⌋，一步。二叉链表要从根往下找；加一格成三叉链表，又是一步。

| | 顺序存储 | 二叉链表 |
|---|---|---|
| 关系放在哪 | 位置里，用下标算 | 结点里，用指针记 |
| 空间 | 完全二叉树正好n格；最坏2ʰ − 1格 | 每个结点多两个指针，不留空位 |
| 找孩子 | 2i、2i + 1 | lchild、rchild |
| 找双亲 | ⌊i/2⌋ | 从根找；三叉链表一步 |
| 适合 | 完全二叉树 | 任何二叉树 |

回到本节问题。A、B、C、D、G这棵树，要记下五个值，还有四条父子关系。它不是完全二叉树，顺序存储要7格、空2格；二叉链表5个结点，每个记下值和两个孩子的地址。所以一般的二叉树都用二叉链表存，后面讲遍历也用它。

## 4.8 二叉树的遍历

**三种顺序从哪来**

第4章开头问过：层层嵌套的数据，怎么走遍？

线性表一个接一个，从头走到尾就行。二叉树会分叉：A下面有B、C两条路，走了B这边，C那边还得回头再走。所以要先约定一个顺序。

按某个顺序，把每个结点访问一次，而且只访问一次，叫**遍历**。访问可以是打印、比较、求和，这里就是写下它的名字。

> **本节问题**：4.5节那棵二叉树有A、B、C、D、G五个结点。怎样把每个结点都走到，而且只走一次？写下来是什么序列？

顺序从哪来？回到4.5节的递归定义：

::: side
**一棵二叉树是三样东西**。根，左子树，右子树。走遍整棵树，就是把这三样都走遍。

<TreeFigure compact binary slots tree="A(B(D,),C(,G))" hi="A" circle="B C" />

**根有三个位置**。三样东西排先后，约定左子树在右子树前面。根只剩三个位置：最前、中间、最后。

<div class="figure-pair">
<ArrayFigure cells="根 左 右" caption="根在最前" />
<ArrayFigure cells="左 根 右" caption="根在中间" />
<ArrayFigure cells="左 右 根" caption="根在最后" />
</div>

**子树也照这个顺序**。左子树、右子树本身又是二叉树，照同一个顺序走。走到空树，什么也不做，直接回来。

<TreeFigure compact binary slots tree="A(B(D,),C(,G))" hi="B" circle="B" />
:::

根在最前，叫**先序遍历**；根在中间，叫**中序遍历**；根在最后，叫**后序遍历**。三个名字说的，都是根的位置。

学完这一节，你能写出一棵二叉树的三种遍历序列，用递归函数实现它们，还能说出每种顺序适合做什么。

<!-- 分页 -->

**先序遍历**

先序遍历：二叉树是空的，什么也不做；否则先访问根，再先序遍历左子树，最后先序遍历右子树。

**写成函数**

遍历的规则本身就是递归的，写成函数也是递归的。用4.7节的二叉链表，访问就是打印结点的值：

```c
void PreOrder(BiTree T) {
    if (T == NULL) return;            /* 空树：什么也不做 */
    printf("%c", T->data);            /* 访问根 */
    PreOrder(T->lchild);              /* 先序遍历左子树 */
    PreOrder(T->rchild);              /* 先序遍历右子树 */
}

void InOrder(BiTree T) {
    if (T == NULL) return;
    InOrder(T->lchild);
    printf("%c", T->data);            /* 访问根：挪到两棵子树中间 */
    InOrder(T->rchild);
}

void PostOrder(BiTree T) {
    if (T == NULL) return;
    PostOrder(T->lchild);
    PostOrder(T->rchild);
    printf("%c", T->data);            /* 访问根：挪到最后 */
}
```

三个函数只差访问根的那一行放在哪，和第一页根的三个位置一一对应。

换个角度看同一件事。每个结点在函数里都要经过三个时刻：刚进来，左子树刚走完，右子树也走完。`printf`放在第一个时刻是先序，放在第二个是中序，放在第三个是后序。

调用`PreOrder(T)`的过程，就是先序遍历那一页一步一步走的过程。`PreOrder`拿到A，打印A，再调用自己去走B那棵。走到D的孩子，参数是NULL，函数立刻返回，这就是"空树什么也不做"。每一次返回，就是那一页里的"回到B""回到A"。这是3.8节的递和归。

**要多少时间和空间**。每个结点调用一次，4.7节数过的n + 1个空指针也各调用一次，一共2n + 1次，时间是O(n)。递归最深时，从根到当前结点一路上的调用都还没返回，深度不超过树的高度h，空间是O(h)。最坏排成一条链，h等于n。

**三种顺序各有用处**。用哪一种，看处理一个结点时，要它的子树先做完，还是后做：

::: side
**后序：先做完孩子，再做自己**。释放整棵树必须用后序：先释放两棵子树，最后释放根。要是先释放根，它的两个指针跟着没了，孩子再也找不到。

<TreeFigure compact binary slots tree="A(B(D,),C(,G))" label="D:1 B:2 G:3 C:4 A:5" caption="释放的先后" />

**先序：先做自己，再做孩子**。比如把一棵树一行一个结点打印出来，孩子缩进在双亲下面。双亲要出现在它的孩子前面，就用先序。

<TreeFigure compact binary slots tree="A(B(D,),C(,G))" label="A:1 B:2 D:3 C:4 G:5" caption="打印的先后" />

**中序：左边、自己、右边**。后面讲二叉排序树时会看到：每个结点左边的都比它小，右边的都比它大。中序走一遍，正好从小到大。

<TreeFigure compact binary tree="5(3(2,4),8)" caption="中序：2 3 4 5 8" />
:::

完整程序搭出4.5节那棵树，打印三种序列，最后用后序释放：

```c
#include <stdio.h>
#include <stdlib.h>

typedef struct BiTNode {
    char data;
    struct BiTNode *lchild, *rchild;
} BiTNode, *BiTree;

void PreOrder(BiTree T) {
    if (T == NULL) return;            /* 空树：什么也不做 */
    printf("%c", T->data);            /* 访问根 */
    PreOrder(T->lchild);              /* 先序遍历左子树 */
    PreOrder(T->rchild);              /* 先序遍历右子树 */
}

void InOrder(BiTree T) {
    if (T == NULL) return;
    InOrder(T->lchild);
    printf("%c", T->data);            /* 访问根：挪到两棵子树中间 */
    InOrder(T->rchild);
}

void PostOrder(BiTree T) {
    if (T == NULL) return;
    PostOrder(T->lchild);
    PostOrder(T->rchild);
    printf("%c", T->data);            /* 访问根：挪到最后 */
}

/* 释放也是后序：先释放两棵子树，再释放根 */
void Destroy(BiTree T) {
    if (T == NULL) return;
    Destroy(T->lchild);
    Destroy(T->rchild);
    free(T);
}

int main(void) {
    /* 搭出4.5节那棵树，做法和4.7节一样 */
    BiTree T = (BiTNode *)malloc(sizeof(BiTNode));
    T->data = 'A';
    T->lchild = NULL;
    T->rchild = NULL;

    BiTNode *b = (BiTNode *)malloc(sizeof(BiTNode));
    b->data = 'B';
    b->lchild = NULL;
    b->rchild = NULL;
    T->lchild = b;

    BiTNode *c = (BiTNode *)malloc(sizeof(BiTNode));
    c->data = 'C';
    c->lchild = NULL;
    c->rchild = NULL;
    T->rchild = c;

    BiTNode *d = (BiTNode *)malloc(sizeof(BiTNode));
    d->data = 'D';
    d->lchild = NULL;
    d->rchild = NULL;
    b->lchild = d;

    BiTNode *g = (BiTNode *)malloc(sizeof(BiTNode));
    g->data = 'G';
    g->lchild = NULL;
    g->rchild = NULL;
    c->rchild = g;

    printf("先序：");
    PreOrder(T);
    printf("\n中序：");
    InOrder(T);
    printf("\n后序：");
    PostOrder(T);
    printf("\n");
    Destroy(T);
    return 0;
}
```

```
中序：DBACG
后序：DBGCA
```

## 4.9 二叉树的属性计算

**结点数：先往下交，再往上合**

4.8节的遍历，每到一个结点做一件事，比如打印。这一节要的不是做事，而是一个数：整棵树有几个结点、几个叶子、有多高。

> **本节问题**：4.5节那棵二叉树有几个结点、几个叶子、高度是多少？程序怎么算出来？

先看结点数。A不知道整棵树有几个结点，可它知道一件事：二叉树是根、左子树、右子树三样东西。所以整棵树的结点数，等于左子树的结点数，加右子树的结点数，再加根自己这1个。

左右子树各有几个，交给它们自己去数。图里虚线的小箭头是往下交的问题，实线的小箭头是往上带回的答案：

::: side
**往下交：先问子树**。A问两棵子树：你们各有几个结点？B、C也不知道，再往下问。一路问到空树。往下走的这一路，一个数也算不出来。

<TreeFigure compact binary slots tree="A(B(D(,),),C(,G(,)))" ask="A B C D G" />

**空树先回答**。空树一个结点也没有，答0。这是第一个算得出来的数。

<TreeFigure compact binary slots tree="A(B(D(,),),C(,G(,)))" zero="B C D G" />

**往上合：D和G**。D收到两个0，加上自己，0 + 0 + 1 = 1，把1报给B。G同样算出1，报给C。

<TreeFigure compact binary slots tree="A(B(D(,),),C(,G(,)))" zero="B C D G" ret="D:1 G:1" hi="D G" />

**往上合：B和C**。B收到左边的1、右边的0，1 + 0 + 1 = 2，报给A。C收到0和1，也算出2。

<TreeFigure compact binary slots tree="A(B(D(,),),C(,G(,)))" zero="B C D G" ret="D:1 G:1 B:2 C:2" hi="B C" />

**往上合：A**。A收到两个2，2 + 2 + 1 = 5。整棵树有5个结点。

<TreeFigure compact binary slots tree="A(B(D(,),),C(,G(,)))" zero="B C D G" ret="D:1 G:1 B:2 C:2" hi="A" label="A:5" />
:::

问题是从上往下交下去的，答案是从下往上合回来的。往下的一路只管分，往上的一路才算出数来。

学完这一节，你能用"先往下交、再往上合"的办法，写出求结点数、叶子数、高度这类属性的递归函数。

**叶子数和高度：只换合的办法**

叶子数、高度和结点数一样：先往下交，问到空树；再往上合。往下交的路线完全一样，不同的只是往上合的时候怎么算。

::: side
**叶子数**。空树没有叶子，答0。D的两棵子树都是空的，D自己就是叶子，报1；G也报1。B收到1和0，自己不是叶子，只把两边加起来，报1；C也报1。A收到1和1，得2。

<TreeFigure compact binary slots tree="A(B(D(,),),C(,G(,)))" zero="B C D G" ret="D:1 G:1 B:1 C:1" hi="D G" label="A:2" />

**高度**。空树的高度是0。D收到0和0，取大的，再加上自己这一层，0 + 1 = 1。B收到1和0，取大的1，加1得2；C也是2。A收到两个2，得3。

<TreeFigure compact binary slots tree="A(B(D(,),),C(,G(,)))" zero="B C D G" ret="D:1 G:1 B:2 C:2" hi="A" label="A:3" />
:::

三个问题，合回来的办法各不相同：结点数是两边相加再加1；叶子数是叶子报1，别的结点只把两边相加；高度是两边取大的再加1。

回到本节问题。这棵树有5个结点、2个叶子，高度是3。

**递下去，归上来**

3.8节把递归分成两半：递，是一层一层调用下去；归，是一层一层返回上来。算二叉树的属性，两半各干各的事。递的时候，把问题交给两棵子树，一直交到空树；归的时候，把两棵子树带回的答案和根合起来。

写这类函数，只要回答三个问题：

1. **空树的答案是多少**？递到底时，直接返回它。
2. **根自己算多少**？
3. **两棵子树带回的答案，怎么和根合起来**？

后两问，都在归的时候做。三个属性的回答汇总起来：

| | 空树 | 根自己 | 怎么合 |
|---|---|---|---|
| 结点数 | 0 | 1 | 左 + 右 + 1 |
| 叶子数 | 0 | 是叶子算1，否则0 | 叶子直接报1，否则左 + 右 |
| 高度 | 0 | 一层 | 左、右里大的 + 1 |

**和遍历比一比**。4.8节的先序遍历，在往下走的路上就打印了，返回时什么也不带回来。函数是`void`，递归调用写成一条语句：

```c
PreOrder(T->lchild);
```

算结点数，答案要带回来交给双亲。函数返回`int`，递归调用写成一个值，放进算式里：

```c
return NodeCount(T->lchild) + NodeCount(T->rchild) + 1;
```

多出来的返回值，就是那条往上合的路。要先等两棵子树的答案回来，才能算根，这正是4.8节说的后序：先做完孩子，再做自己。只是这里的"做"，变成了"算"。

**写成函数**

用4.7节的二叉链表，三问各写成一行：

```c
int NodeCount(BiTree T) {
    if (T == NULL) return 0;                         /* 空树：0个 */
    return NodeCount(T->lchild) + NodeCount(T->rchild) + 1;
}

int LeafCount(BiTree T) {
    if (T == NULL) return 0;                         /* 空树：没有叶子 */
    if (T->lchild == NULL && T->rchild == NULL) return 1;   /* 自己是叶子 */
    return LeafCount(T->lchild) + LeafCount(T->rchild);
}

int Depth(BiTree T) {
    if (T == NULL) return 0;                         /* 空树：高度0 */
    int l = Depth(T->lchild);
    int r = Depth(T->rchild);
    return (l > r ? l : r) + 1;                      /* 大的那个，加上根这一层 */
}
```

每个函数的第一行回答第一问，最后一行回答后两问。`Depth`先把两边的答案存进`l`、`r`，再比大小，这样每棵子树只算一次。

**要多少时间和空间**。和4.8节的遍历一样，每个结点调用一次，空指针也各调用一次，时间是O(n)；递归最深等于树的高度，空间是O(h)。

完整程序搭出4.5节那棵树，算出三个属性：

```c
}

    Destroy(T->rchild);

    c->lchild = NULL;

    T->rchild = c;

    BiTNode *d = (BiTNode *)malloc(sizeof(BiTNode));
    d->data = 'D';
    d->lchild = NULL;
    d->rchild = NULL;
    b->lchild = d;

    g->data = 'G';
    g->lchild = NULL;
    g->rchild = NULL;
    c->rchild = g;

    printf("结点数：%d\n", NodeCount(T));
    printf("叶子数：%d\n", LeafCount(T));
    printf("高度：%d\n", Depth(T));

    return 0;
```

**写成函数**

每一步做的事都一样，写成一个递归函数。参数要说清这一步拿的是哪一段：先序从第i个开始，中序从第j个开始，各取n个。下标从0开始：

```c
/* 先序从pre[i]起、中序从in[j]起，各取n个，建出这棵子树 */
BiTree Build(char pre[], char in[], int i, int j, int n) {
    if (n == 0) return NULL;                         /* 没有结点：空树 */
    BiTNode *T = (BiTNode *)malloc(sizeof(BiTNode));
    T->data = pre[i];                                /* 先序的第一个是根 */
    int k = 0;
    while (in[j + k] != pre[i]) k++;                 /* 中序里找到根，左边有k个 */
    T->lchild = Build(pre, in, i + 1, j, k);                     /* 左子树 */
    T->rchild = Build(pre, in, i + 1 + k, j + k + 1, n - 1 - k); /* 右子树 */
    return T;
}
```

两次递归调用，就是切开的两段：

- **左子树**：先序从根的下一个`i + 1`开始，中序从`j`开始，各取`k`个。
- **右子树**：先序跳过根和左子树，从`i + 1 + k`开始；中序跳过左子树和根，从`j + k + 1`开始；剩下`n - 1 - k`个。

先建根，再建左右子树，这是4.8节的先序：先做自己，再做孩子。4.9节算属性用后序，要等孩子的答案；建树用先序，有了根，才能把孩子挂上去。

这个办法有个前提：结点的值各不相同。要是有两个A，在中序里就找不准根。

完整程序用本节的两个序列建树，再打印三种序列验算：

```c
#include <stdio.h>
#include <stdlib.h>

typedef struct BiTNode {
    char data;
    struct BiTNode *lchild, *rchild;
} BiTNode, *BiTree;

/* 先序从pre[i]起、中序从in[j]起，各取n个，建出这棵子树 */
BiTree Build(char pre[], char in[], int i, int j, int n) {
    if (n == 0) return NULL;                         /* 没有结点：空树 */
    BiTNode *T = (BiTNode *)malloc(sizeof(BiTNode));
    T->data = pre[i];                                /* 先序的第一个是根 */
    int k = 0;
    while (in[j + k] != pre[i]) k++;                 /* 中序里找到根，左边有k个 */
    T->lchild = Build(pre, in, i + 1, j, k);                     /* 左子树 */
    T->rchild = Build(pre, in, i + 1 + k, j + k + 1, n - 1 - k); /* 右子树 */
    return T;
}

void PreOrder(BiTree T) {
    if (T == NULL) return;
    printf("%c", T->data);
    PreOrder(T->lchild);
    PreOrder(T->rchild);
}

void InOrder(BiTree T) {
    if (T == NULL) return;
    InOrder(T->lchild);
    printf("%c", T->data);
    InOrder(T->rchild);
}

void PostOrder(BiTree T) {
    if (T == NULL) return;
    PostOrder(T->lchild);
    PostOrder(T->rchild);
    printf("%c", T->data);
}

void Destroy(BiTree T) {
    if (T == NULL) return;
    Destroy(T->lchild);
    Destroy(T->rchild);
    free(T);
}

int main(void) {
    char pre[] = "ABDEGCF";
    char in[] = "DBGEACF";
    BiTree T = Build(pre, in, 0, 0, 7);
    printf("先序：");
    PreOrder(T);
    printf("\n中序：");
    InOrder(T);
    printf("\n后序：");
    PostOrder(T);
    printf("\n");
    Destroy(T);
    return 0;
}
```

```
先序：ABDEGCF
中序：DBGEACF
后序：DGEBFCA
```

后序加中序的函数改三处：根取这一段后序的最后一个，`post[i + n - 1]`；左子树的后序从`i`开始，右子树的后序从`i + k`开始。因为后序里根在最后，不占前面的位置。

下面哪一组序列，不能唯一确定一棵二叉树？

  先序定根，中序分左右，能唯一确定。
- [ ] 后序和中序
  后序定根，中序分左右，能唯一确定。
- [x] 先序和后序
  两个都只能定根，没有一个能分左右。先序AB、后序BA，B在A的左边、右边都对。
- [ ] 三种组合都能唯一确定
  先序加后序就不行，B在左在右都对得上。

关键是有没有一个序列能分左右：只有中序能。
:::

> **到这里你有了**：由序列构造二叉树：先序（或后序）定根，中序分左右，再按中序给的个数把先序（或后序）切开，左右两边各自重复，交错往下，直到空。一定要有中序；先序加后序定不了左右。写成函数是先序：先建根，再建左右子树。
> **下一步**：一段文字里，常用的字符用短编码。怎样的二叉树能让编码最短？

## 4.11 哈夫曼树和哈夫曼编码

**一段文字要多少位**

计算机里，每个字符都要写成一串0和1。同样一段文字，用的位越少，存起来越省地方，传出去也越快。想办法少用几位，就是压缩。

> **本节问题**：把ABRACADABRA存起来，最少要多少位？

::: side
**数一数**。11个字符，只有5种：A出现5次，B、R各2次，C、D各1次。

<ArrayFigure plain cells="A B R A C A D A B R A" />

**定长编码**。5种字符，每种要一个不同的编码。2位只有00、01、10、11四种，不够；3位有8种，够了。每个字符都用3位：A=000，B=001，R=010，C=011，D=100。开头的ABR写成9位：

<ArrayFigure plain cells="0 0 0 0 0 1 0 1 0" groups="A:1-3 B:4-6 R:7-9" />
:::

11个字符，每个3位，一共11 × 3 = 33位。

定长编码的好处是解码简单：每3位一切，查一下是哪个字符就行。

<!-- 分页 -->

**常用的字用短码**

A出现了5次，C、D只出现1次，可它们都占3位。要是让常用的字符用短编码、少用的用长编码，总数就能少下来。先试一个最短的方案：

::: side
**一个最短的方案**。A=0，B=1，剩下三个用两位：R=00，C=01，D=10。出现5次的A，每次省下2位。

<ArrayFigure plain cells="0 1 0 0 0 1 1 0" groups="A:1 B:2 R:3-4 C:5-6 D:7-8" />

**可是读不回来**。收到一串010。它可以读成A、B、A，也可以读成C、A，还可以读成A、D。同一串位，三种读法。

<div class="figure-pair">
<ArrayFigure plain cells="0 1 0" groups="A:1 B:2 A:3" />
<ArrayFigure plain cells="0 1 0" groups="C:1-2 A:3" />
<ArrayFigure plain cells="0 1 0" groups="A:1 D:2-3" />
</div>
:::

毛病出在：A的编码0，是C的编码01的开头。读到一个0时，不知道该停下来当成A，还是接着往下读。

<!-- 分页 -->

**前缀编码**

要读得回来，就得避开这个毛病：任何一个字符的编码，都不是另一个字符编码的开头。这样的编码叫**前缀编码**。

::: side
**一个前缀编码**。A=00，B=01，R=10，C=110，D=111。挨个比一比：没有一个编码是另一个的开头。

<ArrayFigure plain cells="0 0 0 1 1 0 1 1 0 1 1 1" groups="A:1-2 B:3-4 R:5-6 C:7-9 D:10-12" />

**读得回来**。从头读，读出的几位一旦正好是某个编码，就是这个字符，接着往下读。比如0110：读到01是B，再读到10是R，不会有第二种读法。

<ArrayFigure plain cells="0 1 1 0" groups="B:1-2 R:3-4" />
:::

算一算总数：A 5次 × 2位，B、R各2次 × 2位，C、D各1次 × 3位，10 + 4 + 4 + 3 + 3 = 24位。比定长编码少了9位。

前缀编码有很多种，哪一种最短？要回答它，先换个角度看前缀编码。

<!-- 分页 -->

**前缀编码就是一棵二叉树**

把编码画成一棵二叉树：从根出发，读到0往左走，读到1往右走。一个编码走完，停在哪个结点，就把字符放在那里。图里每条边旁写着它代表的0或1：

::: side
**画出刚才的编码**。A=00是左、左；B=01是左、右；R=10是右、左；C、D多走一步。

<TreeFigure compact spread binary bits tree="·(·(A,B),·(R,·(C,D)))" label="A:00 B:01 R:10 C:110 D:111" />

**字符都在叶子上**。从根走到一个字符，路上不会经过别的字符。所以一个编码不会是另一个的开头，前缀编码的条件自动满足。

<TreeFigure compact binary bits tree="·(·(A,B),·(R,·(C,D)))" hi="A B R C D" />

**反例：字符不在叶子上**。上一页失败的方案画出来，A=0在根的左孩子，C=01在A的下面。从根走到C要经过A，A的编码就成了C的开头。

<TreeFigure compact binary bits tree="·(A(R,C),B(D,))" hi="A C" />
:::

反过来，任意一棵字符都在叶子上的二叉树，读出来都是前缀编码。找前缀编码，就是找这样一棵二叉树。

<!-- 分页 -->

**总长度就是带权路径长度**

一个字符的编码长度，就是从根走到它要经过几条边。从根到一个结点经过的边，叫这个结点的**路径**；边的条数，叫**路径长度**。路径长度按边数算，比4.1节的层次少1：第3层的结点，路径长度是2。

一个字符出现的次数，写在它的叶子上，叫这个叶子的**权**。权乘以路径长度，是这个叶子的**带权路径长度**。所有叶子的带权路径长度加起来，叫这棵树的**带权路径长度**，记作WPL。

::: side
**定长编码的树**。每个字符的路径长度都是3。WPL = (5 + 2 + 2 + 1 + 1) × 3 = 33，正好是定长编码的总位数。

<TreeFigure compact binary bits tree="·(·(·(A,B),·(R,C)),·(·(D,),))" label="A:5 B:2 R:2 C:1 D:1" />

**刚才的前缀编码**。A、B、R的路径长度是2，C、D是3。WPL = 5 × 2 + 2 × 2 + 2 × 2 + 1 × 3 + 1 × 3 = 24。

<TreeFigure compact binary bits tree="·(·(A,B),·(R,·(C,D)))" label="A:5 B:2 R:2 C:1 D:1" />
:::

编码的总位数，就是这棵树的WPL。要压缩得最多，就要找一棵字符都在叶子上、WPL最小的二叉树。

<!-- 分页 -->

**哈夫曼的办法：每次合并最小的两个**

WPL最小的二叉树，叫**哈夫曼树**，也叫最优二叉树。哈夫曼想出了构造它的办法。

出现最少的两个字符，编码应该最长，放在最下面，做一对兄弟。把它们合成一个结点，这个结点的权是两个权之和。这样问题就少了一个字符，再做同样的事：

::: side
**一开始**。五个字符各是一棵只有根的树，权写在旁边。

<TreeFigure compact binary tree="A,B,R,C,D" label="A:5 B:2 R:2 C:1 D:1" />

**合并C和D**。最小的是C、D，都是1。合成一个结点，权是1 + 1 = 2。

<TreeFigure compact binary tree="A,B,R,2(C,D)" label="A:5 B:2 R:2 C:1 D:1" hi="2" />

**合并B和R**。现在最小的有三个2：B、R，还有刚合出来的结点。挑哪两个都可以，这里挑B和R，合出4。

<TreeFigure compact binary tree="A,2(C,D),4(B,R)" label="A:5 B:2 R:2 C:1 D:1" hi="4" />

**合并2和4**。剩下5、2、4，最小的是2和4，合出6。

<TreeFigure compact binary tree="A,6(2(C,D),4(B,R))" label="A:5 B:2 R:2 C:1 D:1" hi="6" />

**合并A和6**。只剩5和6，合出11。只剩一棵树了，它就是哈夫曼树。

<TreeFigure compact binary tree="11(A,6(2(C,D),4(B,R)))" label="A:5 B:2 R:2 C:1 D:1" hi="11" />
:::

每合并一次，就少一棵树。5个字符合并4次，只剩一棵。根的权11，正好是字符的总个数。

为什么这样合出来的WPL最小，可以严格证明，本书不展开。直觉是：越少用的字符放得越深，越常用的放得越浅。

<!-- 分页 -->

**哈夫曼编码**

在哈夫曼树上，左边记0、右边记1，读出的编码叫**哈夫曼编码**。

::: side
**读出编码**。A=0，C=100，D=101，B=110，R=111。出现5次的A只用1位，只出现1次的C、D用3位。

<TreeFigure compact binary bits tree="11(A,6(2(C,D),4(B,R)))" label="A:0 C:100 D:101 B:110 R:111" />

**一共23位**。WPL = 5 × 1 + 2 × 3 + 2 × 3 + 1 × 3 + 1 × 3 = 23。

<TreeFigure compact binary bits tree="11(A,6(2(C,D),4(B,R)))" label="A:5 B:2 R:2 C:1 D:1" />

**解码：读到B**。收到的位以110开头。从根出发，1往右，1往右，0往左，走到叶子B。写下B，回到根。

<TreeFigure compact binary bits tree="11(A,6(2(C,D),4(B,R)))" path="B" />

**解码：读到A**。下一位是0，从根往左一步，就到叶子A。写下A，再回到根。

<TreeFigure compact binary bits tree="11(A,6(2(C,D),4(B,R)))" path="A" />
:::

整段ABRACADABRA编成`0 110 111 0 100 0 101 0 110 111 0`，一共23位。

回到本节问题。定长编码33位，手排的前缀编码24位，哈夫曼编码23位。哈夫曼树的WPL最小，用它编码，总位数最少。

数一数这棵哈夫曼树：5个叶子，合并4次合出4个结点，一共9个，是2 × 5 − 1。合出来的结点都有两个孩子，没有度为1的结点。叶子5个、度为2的4个，5 = 4 + 1，正是4.6节的性质。

**写成函数**

教材用一个数组存整棵哈夫曼树。n个叶子放在前n格，合出来的n − 1个结点依次放在后面，一共2n − 1格。每个结点记下权、双亲、左右孩子的下标。下标从1开始，0表示"没有"，所以0号格不用：

```c
typedef struct {
    int weight;                      /* 权：出现的次数 */
    int parent, lchild, rchild;      /* 双亲、左右孩子的下标，0表示没有 */
} HTNode;
```

每合并一次，要挑出两个"还没有双亲、权最小"的结点。没有双亲，说明它还是一棵树的根：

```c
/* 在HT[1..k]里，挑出没有双亲、权最小的两个：s1最小，s2第二小 */
void Select(HTNode HT[], int k, int *s1, int *s2) {
    *s1 = 0;
    for (int i = 1; i <= k; i++)
        if (HT[i].parent == 0 && (*s1 == 0 || HT[i].weight < HT[*s1].weight)) *s1 = i;
    *s2 = 0;
    for (int i = 1; i <= k; i++)
        if (HT[i].parent == 0 && i != *s1 && (*s2 == 0 || HT[i].weight < HT[*s2].weight)) *s2 = i;
}
```

合并就是填一格：两个孩子的双亲改成它，它的孩子是这两个，权是两者之和。

```c
/* n个叶子放在HT[1..n]，合出来的结点依次放在HT[n+1..2n-1] */
void CreateHuffmanTree(HTNode HT[], int w[], int n) {
    for (int i = 1; i <= 2 * n - 1; i++) {
        HT[i].weight = i <= n ? w[i] : 0;
        HT[i].parent = HT[i].lchild = HT[i].rchild = 0;
    }
    for (int i = n + 1; i <= 2 * n - 1; i++) {
        int s1, s2;
        Select(HT, i - 1, &s1, &s2);                 /* 挑最小的两个 */
        HT[s1].parent = HT[s2].parent = i;           /* 合成第i个结点 */
        HT[i].lchild = s1;
        HT[i].rchild = s2;
        HT[i].weight = HT[s1].weight + HT[s2].weight;
    }
}
```

读编码时，从叶子顺着`parent`往上走：自己是双亲的左孩子记0，右孩子记1，走到根为止。这样得到的位是倒着的，最后再翻过来。

完整程序算出ABRACADABRA每个字符的编码和总位数：

```c
#include <stdio.h>

#define N 5                          /* 字符有几种 */

typedef struct {
    int weight;                      /* 权：出现的次数 */
    int parent, lchild, rchild;      /* 双亲、左右孩子的下标，0表示没有 */
} HTNode;

/* 在HT[1..k]里，挑出没有双亲、权最小的两个：s1最小，s2第二小 */
void Select(HTNode HT[], int k, int *s1, int *s2) {
    *s1 = 0;
    for (int i = 1; i <= k; i++)
        if (HT[i].parent == 0 && (*s1 == 0 || HT[i].weight < HT[*s1].weight)) *s1 = i;
    *s2 = 0;
    for (int i = 1; i <= k; i++)
        if (HT[i].parent == 0 && i != *s1 && (*s2 == 0 || HT[i].weight < HT[*s2].weight)) *s2 = i;
}

/* n个叶子放在HT[1..n]，合出来的结点依次放在HT[n+1..2n-1] */
void CreateHuffmanTree(HTNode HT[], int w[], int n) {
    for (int i = 1; i <= 2 * n - 1; i++) {
        HT[i].weight = i <= n ? w[i] : 0;
        HT[i].parent = HT[i].lchild = HT[i].rchild = 0;
    }
    for (int i = n + 1; i <= 2 * n - 1; i++) {
        int s1, s2;
        Select(HT, i - 1, &s1, &s2);                 /* 挑最小的两个 */
        HT[s1].parent = HT[s2].parent = i;           /* 合成第i个结点 */
        HT[i].lchild = s1;
        HT[i].rchild = s2;
        HT[i].weight = HT[s1].weight + HT[s2].weight;
    }
}

/* 从叶子i往上走到根，是左孩子记0、右孩子记1，倒着写进code */
void GetCode(HTNode HT[], int i, char code[]) {
    char tmp[N];
    int len = 0;
    for (int c = i, p = HT[i].parent; p != 0; c = p, p = HT[p].parent)
        tmp[len++] = HT[p].lchild == c ? '0' : '1';
    for (int k = 0; k < len; k++) code[k] = tmp[len - 1 - k];
    code[len] = '\0';
}

int main(void) {
    char ch[N + 1] = { ' ', 'A', 'B', 'R', 'C', 'D' };
    int w[N + 1] = { 0, 5, 2, 2, 1, 1 };            /* ABRACADABRA里的次数 */
    HTNode HT[2 * N];                                /* HT[0]不用 */
    CreateHuffmanTree(HT, w, N);
    int total = 0;
    for (int i = 1; i <= N; i++) {
        char code[N];
        GetCode(HT, i, code);
        printf("%c 出现%d次，编码%s\n", ch[i], w[i], code);
        int len = 0;
        while (code[len] != '\0') len++;
        total += w[i] * len;
    }
    printf("总位数：%d\n", total);
    return 0;
}
```

```
A 出现5次，编码0
B 出现2次，编码110
R 出现2次，编码111
C 出现1次，编码100
D 出现1次，编码101
总位数：23
```

`Select`遇到权相等时，挑下标小的那个，所以第二次合并挑的是B和R，和前一页画的一样。
